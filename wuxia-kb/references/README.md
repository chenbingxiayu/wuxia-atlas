# references/ 支撑文档库（武侠版）· 索引与规范

## 二、命名规范

1. **文件模式**：`<主节点号><子号>_<主题>_武侠版.md`，例：`03c1_反思规律库_武侠版.md`（主节点 03c → 子库 03c1）。
2. **编号来源**：跟主 SKILL 节点号走（02ab→02ab1、03e→03e1、04f→04f1…），跨节点共享的库取"首个消费 SKILL"的编号，并在索引表注明"被 X/Y 引用"。
3. **不重名**：同一主题只设一个库；若需分卷，用 `03c1a_/03c1b_` 后缀，仍在同一索引行登记。
4. **语言/编码**：UTF-8（无 BOM）、LF、Markdown；中文标点；文件名保留中文主题词（与 skills/ 一致）。
5. **归档**：被取代的库移入 `references/archive/`（保留原文件名），索引表加"归档"标注；**不删除**（可追溯性）。

## 三、frontmatter 与条目 schema

### 3.1 文件 frontmatter（建议最小集）

```yaml
---
name: <库标识，如 ref-03c1>
title: <人类可读标题>
version: v0.1-draft        # v0.1-draft → v0.1 → v1.0（冻结）→ archived
last_updated: YYYY-MM-DD
scope: <一句话说明覆盖范围>
source: <设计稿/实践记录/迁移来源>
--- 
```

> `references/` 目前**不纳入** `scripts/lint_skills.py`（该工具只扫 `skills/SKILL_*.md`）；本规范为人工/后续脚本校验依据。

### 3.2 条目 schema（固定 8 字段 + 可选扩展）

```yaml
### <ID> · <一句话判据标题>
- 类别: A 类型判断 / B 跨书与管道 / C 边界与格式 / D 事件与动词 / E 结构与围栏 / F 工程与流程
- 现象: 可检索的错误模板（如 〖@X弟〗）或信号描述
- 判据: 判定规则（正例/反例 + 上下文条件 + 优先级 + 例外）
- 动作: 修法（机械命令 / 改哪份 SKILL 哪节 / 补哪张词表 / 摘管或改管 / 工具任务）
- 反例: ≥1 条"看似适用其实不适用"的反例（防过度泛化）
- 来源: 可回溯证据（书:回[段] 实测 + docs/xx §y + SKILL 章节 + 先例编号 DEF/BND/TRE/WL）
- 状态: 候选 / 已验证 / 已回写 / 已入库 / 待裁 / 废弃（见 §五）
```

**扩展字段规则**：需要时可在 8 字段后追加（如 `适用范围`、`关联条目`、`回归数据`），但**不得改变 8 字段语义/改名**；新增通用字段须先改本 README schema 并全库回填。

### 3.3 ID 规则

- 格式 `<区字母><两位序号>`（如 `A01`、`F07`）；区字母 = 类别字母，见上。
- **只增不复用**：编号不连续/跳号是历史正常现象（史记 03c1 v2 教训：不"整理"编号，避免引用失效）。
- 跨库引用用前缀区分：`03c1:A01`、`DEF-02`、`BND-04`、`TRE-03`、`WL-21`——references 内条目自引用可省略前缀。
- 合并/拆分时：保留原编号，正文改为指针（"并入 A04"/"见 A04，本条仅保留 X 专属部分"）。

### 3.4 来源标注纪律（禁止"印象来源"）

- 每条必须至少 1 条**实测证据**（`书:回[段]` + 原标注片段）或 1 条**定版条文**（SKILL §/docs §）；
- 引用批次记录时写 `docs/xx §y`；引用裁决先例时写条目名（如 docs/45 §三 #70）；
- "推论/建议"须在 `动作` 或 `现象` 明示"待验证/待裁"，不得写进 `判据` 伪装成定论。

## 四、状态机与流转

```text
                 ┌──────── 废弃（被取代/证伪，保留编号）
                 │
候选 ──复现≥2批/≥2书 或 1批+条文──→ 已验证 ──回写规则/词表/种子/工具 + 回归──→ 已回写 ──三件齐备──→ 已入库
  │
  └──涉及治理口径──→ 待裁（→ 用户/Lead 拍板后回 候选/已验证/废弃）
```

| 状态 | 进入条件 | 退出/动作 |
|---|---|---|
| 候选 | 单批首次发现，证据 1 条 | 补证据 → 已验证；或判为个案 → 废弃 |
| 已验证 | ≥2 批/≥2 书复现，或 1 批 + 定版条文支持 | 进入回写（R/W/S/F/G 至少一处） |
| 已回写 | 规范/词表/种子/工具/数据已改且回归通过 | 补齐条目+回写+回归证据 → 已入库 |
| 已入库 | "条目 + 回写点 + 回归证据"三件齐备 | 长期维护；被取代时 → 废弃 |
| 待裁 | 与现行规范冲突/涉及治理口径（类型归属/别名规则/政权朝代等） | 上抛拍板；禁止自行改规范 |
| 废弃 | 被新条目取代/证伪 | 保留编号，正文标注"并入 X/被 X 取代"，不删条目 |

## 五、去重、合并与防膨胀

1. 新建前按 类别 + 关键词 + 涉及的 SKILL 章节检索既有条目；
2. 同主题 ≥2 条 → 保留**信息最全**的一条为主条目，其余改指针（保编号）；
3. 与 03a DEF / 03f BND / 03e TRE 重叠：条目 `来源` 写引用号，正文不重复抄；
4. 每季度（或每批末）做一次"库体检"：重复组、错位条目、状态停滞（候选 >2 批未推进）清单化；
5. 条目总数 >120 条时考虑分卷（03c1a/03c1b）或压缩（史记 03c1 v2 从 3001 行压到 1330 行的做法：删历史叙述，留判据/反例/来源）。

## 六、贡献流程（反思 → 入库）

```text
① 发现（SKILL_03c 六问 / 03e / 03f / 批处理） 
   ↓ 写候选条目（状态=候选；证据 loc + 六问归属 + 四源）
② 复核（同批 ≥3 处？跨批/跨书复现？条文支持？）
   ↓ 
③ 回写（R→03a/04f/03b；W→wordlists+compile；S→few-shot 重建；F→02ab/脚本；G→工程任务）
   ↓ 回归（lint/accept/concordance；剥标断言；受影响书复跑）
④ 入库（状态=已入库；更新本 README 索引/条目数/版本行）
```

**禁止**：只写条目不改规则（或只改规则不写条目）；无证据改规范；跳过回归；重排/复用编号；把 references 当第二规范源。

## 七、与 skills/ 主文档的关系

- `skills/` 二级技能是**规范与 SOP**；`references/` 是**判据资产**，被 SKILL 引用（如 `SKILL_03c` §六 接口、`SKILL_03f` §九 沉淀）；
- SKILL 正文写入引用：`references/03c1_反思规律库_武侠版.md`（相对 `skills/` 为 `../references/...`，文档中写仓库相对路径即可）；
- 主 SKILL 的"相关文档"节应列其支撑库；支撑库的 frontmatter/索引应标对应主 SKILL；
- `skills/README.md` 的索引是否纳入 references 由 Lead/维护者决定（本 v0.1 未改 README）。
