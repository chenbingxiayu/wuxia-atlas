## A 区 · 三层关系与 55 谓词

### RP01 · 三层关系 = KG 的边：事件关系 / 实体关系 / 人物关系
- 类别: 三层关系与谓词
- 现象: 把事件边的因果（causal）当人物边；或实体"持有"链与人物"转移"事件混为一条边。
- 判据: 关系分三层：事件关系（E→E）、实体关系（P/T/O/L/I 间）、人物关系（人↔人）；每层有独立谓词集与
  证据要求（关系 SKILL §1.1/§二/§三/§四）；跨层不混写。
- 动作: 抽取时先判层再选谓词；事件层走 04a/EX-5，实体/人物层走 N5；落库 schema `relations-v0.1`。
- 反例: "转移"（实体关系，物+人）与"赠"事件（事件层）相关但不同边；不能合并成一条人物边。
- 来源: `SKILL_关系体系` §1.1/§二-§四；N5 实测 `registry/relations/*.json`。
- 状态: 已验证

### RP02 · 55 条 SPO 谓词白名单 + 4 条离线接口行（行内不设符号）
- 类别: 三层关系与谓词
- 现象: 自造谓词（如"打斗/认识/喜欢"）；或把离线情感/恩义/背叛/主仆塞进行内符号体系。
- 判据: 谓词总表=**55 条 SPO（三层合并接口）＋4 条离线接口行**（情感/恩义/背叛/主仆，表外不计入 SPO 数）；
  行内不设情感类符号（01g §9.2 铁律）；新增谓词须过 §7.4 命名一致性检查（关系 SKILL §7.2/§7.4）。
- 动作: 抽取只用白名单；EX-4 边 kind 直接取 predicate；离线四类写离线表（relation 边关联谓词指针）。
- 反例: "一次交手"自动升级为"敌对"——违反 RP16 铁律；白名单里 interaction 与 opposition 分离。
- 来源: `SKILL_关系体系` §7.2（55 SPO+4 离线）/§7.4；`SKILL_01g` §9.2；N5 谓词分布实测 16 种有向边。
- 状态: 已验证

### RP03 · 事件关系：8 类直迁 + concurrent 重定义 + 3 类新增
- 类别: 三层关系与谓词
- 现象: 事件因果/承接/并置不区分；跨书呼应当因果。
- 判据: 事件关系 8 类直迁（sequel/causal/cross_causal/part_of/opposition/cross_ref/co_person/co_location）；
  concurrent 由"同时"重定义为**书内时序对齐**（两端时点键对齐）；新增 inherit/foreshadow/cross_book_ref
  （关系 SKILL §2.1-§2.3）。
- 动作: N5 事件边需 tp 对齐（concurrent）；cross_book_ref 待 #7 跨书治理接；因果四步检查（§2 表）。
- 反例: 同书两事件先后出现≠因果（causal 需四步检查）；跨书"续看"是 cross_book_ref 不是 causal。
- 来源: `SKILL_关系体系` §2.1/§2.2/§2.3；EX-5 事件层（docs/59）；N5 实测。
- 状态: 已验证

### RP04 · 实体关系：地点/武功层级/兵器链/异名四类
- 类别: 三层关系与谓词
- 现象: 门派山门写进地点树 kind；武功层级与品类混；兵器链与神兵表 chain 口径不一。
- 判据: 实体关系四类：地点（辖属/山门/练功地/决战地）、武功层级（层级隶属/创派/归属/掌握/修习）、
  兵器-持有链（持有/制造/转移，对接神兵表 chain）、异名（条件性，§3.4 三情形）（关系 SKILL §3.1-§3.4）。
- 动作: 实体边走 N5；兵器链与 `kb/神兵表.json` chain 对齐；异名条件=同实体异称/称号/简称，须有出处。
- 反例: "异名"不是"别名表"——alias 归 registry，relation 异名边只登记有叙事依据的称号替换。
- 来源: `SKILL_关系体系` §3.1-§3.4；N5 实测"转移/点穴/任职"等；EX-6 兵器链。
- 状态: 已验证

### RP05 · 人物关系类型总览与承载位置（SPO vs 离线）
- 类别: 三层关系与谓词
- 现象: 所有人物互动都造谓词；或情感/恩义等无承载。
- 判据: 人物关系主类型（师承/结义/敌对/配偶/婚约/收养/亲属/仇怨/冒名/杀害/治愈/投毒/拘押/解救/押送/
  交手/点穴/同行/传授/同门）走 SPO；情感/恩义/背叛/主仆四类走离线表（关系 SKILL §4.1/§6.1）。
- 动作: 先判承载（SPO/离线）；离线四类只给候选与关联谓词，不建正式边。
- 反例: "爱慕"不进 SPO≠不记录——离线表有 states 参考链；但不得生成人物边供图谱消费。
- 来源: `SKILL_关系体系` §4.1/§6.1；`SKILL_01g` §9.2；N5 实测交付（无情感类边）。
- 状态: 已验证

### RP06 · 情义层离线表 schema 与 04f 联动边界（待裁）
- 类别: 三层关系与谓词
- 现象: 04f 联动候选（授/受、恩/仇）落位不清，离线表与 SPO 边界漂移。
- 判据: 离线表 schema（type/子型/direction/states/manner/conf/关联谓词）定版（关系 SKILL §6.2/§6.3）；
  与 04f 联动候选的边界按 §6.4 裁决表处理；涉及"哪些联动词可升 SPO"的治理项待裁。
- 动作: 离线表随人物卡/关系报告输出；联动候选落位对照表（§7.3）逐词挂载；边界争议上抛 Lead。
- 反例: 把"传功"直接当师承边（04f V3-2 明确不自动建师承）；离线表记"恩义"不代师承。
- 来源: `SKILL_关系体系` §6.2/§6.3/§6.4/§7.3；`SKILL_04f` V3-2；docs/45 judgment。
- 状态: 待裁

## B 区 · 人物关系与双树

### RP07 · 师承：徒→师，5 子型，辈分标签不生成直连边
- 类别: 人物关系与双树
- 现象: 所有"传授"自动建师承；师承链直接连成图（辈分边爆炸）。
- 判据: 师承=徒→师单向；子型=正式拜师/逐出/叛门/自立门户（关系 SKILL §4.2）；辈分标签**不生成直连边**
  （§5.3）；时段唯一正式师门；拜师<叛门/逐出<再拜。
- 动作: N5 只落师承边；辈分推导走双树标签；传授（师→徒武功）单独谓词，不自动建师承（RP04/04f V3-2）。
- 反例: "指点一招"不建师承（04f V3-2）；"代师传授"仍以正式拜师为准。
- 来源: `SKILL_关系体系` §4.2/§5.3/§7.2 #35-36；`SKILL_04f` V3-2；N5 实测"师承×39"。
- 状态: 已验证

### RP08 · 结义：N 元组，子型八拜/金兰/反目，states 唯一
- 类别: 人物关系与双树
- 现象: 两人结义写成两两边丢失"同组"语义；反目后旧结义边失效未记状态。
- 判据: 结义=G 组（N 元）双向；子型=八拜结义/金兰结义/反目；一对 states 唯一；结拜<交恶<反目
  （关系 SKILL §4.3）。
- 动作: 组级边落库（members 列表）；反目作为 states 流转，不删原边。
- 反例: 多人结义拆成两两边会造成图谱重复计数；须保留组语义。
- 来源: `SKILL_关系体系` §4.3/§7.2 #37；N5 实测"结义×11"。
- 状态: 已验证

### RP09 · 情缘：配偶/婚约走 SPO，爱慕/暗恋走离线
- 类别: 人物关系与双树
- 现象: 爱慕/单恋当配偶边；婚约与成婚不分。
- 判据: 配偶/婚约为 SPO（active 唯一；婚约<成婚<丧偶/离异）；爱慕/暗恋/单恋/被拒/悔全走离线情感表
  （关系 SKILL §4.4）；情敌为推导。
- 动作: 情缘判承载；婚约到期/解除记终态；离线情感表给 states 参考链。
- 反例: "指腹为婚"未成婚=婚约（可解除），不是配偶；单恋不得生成双向配偶边。
- 来源: `SKILL_关系体系` §4.4/§7.2 #40-41；`SKILL_01g` §9.2；N5 实测"婚约×13"。
- 状态: 已验证

### RP10 · 仇怨：必须关联因果事件（event_ids 必填）
- 类别: 人物关系与双树
- 现象: 因一次交手或一句狠话建仇怨；仇怨无事件依据。
- 判据: 仇怨=人→人或 mutual；子型=灭门/夺爱/夺秘籍/杀父/伤折；**event_ids 必填**；结怨事件≤存续；
  与恩义/情缘可并存（关系 SKILL §4.5/§7.2 #44）。
- 动作: N5 落仇怨边须回链事件（EX-5）；无事件 ids 的候选降级/放弃。
- 反例: 一次交手不自动敌对（01g 铁律）；仇怨与敌对是两个谓词（敌对可无具体事件但需持续行动记述）。
- 来源: `SKILL_关系体系` §4.5/§7.2 #44；`SKILL_01g` 铁律；N5 实测。
- 状态: 已验证

### RP11 · 同门：派生关系不直接登记（随师承边）
- 类别: 人物关系与双树
- 现象: 把同门当独立人工边登记，与师承链断链/矛盾。
- 判据: 同门=人↔人，derived **不直接登记**；随师承边派生（关系 SKILL §4.6/§7.2 #45）；置信默认中。
- 动作: N5 先落师承，再由派生规则生成同门（derived 标记）；EX-4 边可带 derived 标记。
- 反例: 师承未知时不能凭"同门"补师承——派生方向是师承→同门，不是反向。
- 来源: `SKILL_关系体系` §4.6/§7.2 #45；N5 汇总"派生 16"；EX-4 §对接（derived 标记）。
- 状态: 已回写

### RP12 · 双树同构：师承树 ↔ 血缘树（机制映射）
- 类别: 人物关系与双树
- 现象: 师承树与血缘树两套逻辑；辈分口径不统一。
- 判据: 两棵树同构（关系 SKILL §5.1/§5.2 同构映射表）：节点=人、边=师承/血缘、层级=辈分；师承树机制
  照搬血缘树（收徒=生子、逐出=出继等语义映射），保证辈分推导口径一致。
- 动作: 辈分推导只在一处实现（双树共用）；标签写回人物卡/关系报告，不写 intrinsics。
- 反例: 两套辈分算法会给出冲突辈分——必须单源。
- 来源: `SKILL_关系体系` §5.1/§5.2；`SKILL_07b_姓氏辈分推理_武侠版`（下游消费）。
- 状态: 已验证

### RP13 · 双树交叉裁决：父子/师徒同人、叛门/出继、多重辈分
- 类别: 人物关系与双树
- 现象: 一个人同时是师父又是生父；叛门后辈分是否保留；多重师承辈分冲突。
- 判据: 双树交叉裁决表（关系 SKILL §5.4）：血缘与师承分别成立可并存；叛门/逐出后师承树断边但历史辈分
  保留标签；多重正式师门按时段分段；冲突按"正式拜师优先、义父/养父次之"裁决。
- 动作: 交叉案例入 §4.9 边界索引；辈分冲突显式登记，不静默择一。
- 反例: 叛门不等于血缘断——两棵树各自记录，不能互相覆盖。
- 来源: `SKILL_关系体系` §5.4/§4.9；`SKILL_07b`（辈分推理）；docs/59。
- 状态: 已验证

## C 区 · 证据与置信

### RP14 · 证据三级：明=明文 / 动=动作+共现 / 推=推导
- 类别: 证据与置信
- 现象: 仅共现就给 strong；推导边伪装成明文。
- 判据: 证据三级（关系 SKILL §8.1）：明=明文（"拜师/结为兄弟"等直证）→ strong；动=动作+共现→ok；
  推=推导→weak/derived；55 谓词表逐条标注默认证据级别与置信档（§7.2）。
- 动作: N5 落库带 evidence 类型/rule/locs；EX-4 边 n=证据数；报告分列 strong/ok/weak。
- 反例: "两人多次同场"→co_location/co_person 候选（weak），不得直接给师承/敌对 strong。
- 来源: `SKILL_关系体系` §8.1/§7.2 证据列；N5 实测 strong 105/ok 711/weak 94。
- 状态: 已验证

### RP15 · 传闻与视角降权；多叙述源消歧
- 类别: 证据与置信
- 现象: 转述/传闻当事实；同一事件多叙述源不一致时随意择一。
- 判据: 传闻/视角降权（关系 SKILL §8.3）：转述/猜疑/敌方宣传降一档；多叙述源消歧（§8.5）：同实体/事件
  按 META-12 L3 事件对齐思想合并，冲突登记不静默择一。
- 动作: evidence 增加 source_type（叙述/传闻/视角）；冲突入冲突表；降权后边仍保留但置信降档。
- 反例: 书中人物亲口"听说"不是叙述者事实——降权，但若多方引述同一传闻可升级为"公认"仍非事实边。
- 来源: `SKILL_关系体系` §8.3/§8.5；`SKILL_04a` §7 叙述可靠性；N5 报告放弃原因分类。
- 状态: 已回写

### RP16 · 一次交手不自动敌对（01g 铁律）
- 类别: 证据与置信
- 现象: 交手边（对手/切磋/救援）被当敌对边，图谱出现错误阵营。
- 判据: 一次交手不自动敌对（01g 铁律；关系 SKILL §7.2 #53 互斥约束）：交手（A↔B 战斗ID）与敌对
  （持续对抗）是两个谓词；敌对需持续行动/立场记述。
- 动作: N5 只落交手；敌对判定走敌方宣言/持续冲突/阵营归属；EX-4 边 kind 保持交手。
- 反例: 比武切磋/误伤/救援中的交手≠敌对；一次交手后仍可能结义（反目再结义）。
- 来源: `SKILL_关系体系` §7.2 #53；`SKILL_01g` 铁律；N5 实测交手×433（最大类）。
- 状态: 已验证
