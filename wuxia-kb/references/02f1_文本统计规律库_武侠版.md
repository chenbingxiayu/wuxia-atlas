## A 区 · 分母纪律

### ST01 · 正文分母 := 块类型=正文段 的 PN 数（回内）
- 类别: 分母纪律
- 现象: 把回目/围栏/套语计入分母，密度曲线被非叙事文本稀释，34 部对比失真。
- 判据: **正文分母 := 块类型=正文段 的 PN 数（回内）**；排除：回目 `[0]`；全部围栏块（词/诗/歌/对联/
  回末对/回末/书信/告示/口诀/说书）（02ab §9.2 原文照录，02f §2.1）。
- 动作: 统计脚本统一从结构产物取"正文段 PN 数"；复用 `extract_paragraph_structure.py` 的块类型；报告注明分母定义。
- 反例: "正文段占比 >90%"不代表分母正确——须按块类型逐类排除；围栏漏识别会混入分母（先查结构）。
- 来源: `SKILL_02ab` §9.2；`SKILL_02f` §2.1；`scripts/extract_paragraph_structure.py`。
- 状态: 已回写

### ST02 · 密度分子 = 04f 触发词计数（数触发词，不数回合/实体）
- 类别: 分母纪律
- 现象: 用"三百回合"、招式名或实体计数当密度分子，打斗密度虚高。
- 判据: 密度分子 = 04f 六域触发词令牌数（⟦⊞⊠⊡⊟▣■⟧），按域分列；招式名 `〖☆〗` 照标但**不计入动词
  密度**；"数触发词，不数'回合'与实体"（04f §9 FAQ）；否定/条件/未发生不入分子（04f §3.6）。
- 动作: 密度统计只数触发词令牌；连续交锋按合并标注后的起止+关键结果计数（04f §6.1）。
- 反例: `☆` 招式名与 `@` 人物令牌不是触发词；"三百回合"是数量（`$` 层）绝不入触发词。
- 来源: `SKILL_02f` §2.2；`SKILL_04f` §3.6/§6.1/§9；`SKILL_01g` 负规则六。
- 状态: 已回写

### ST03 · 分子分母对称排除：回末套语既不进分母也不贡献触发词
- 类别: 分母纪律
- 现象: 回末套语段进了分母或分子之一，密度被"且听下回分解"类公式稀释。
- 判据: 套语段（文本模式=套语）**既不进分母也不贡献触发词**（02ab §9.2）；回末围栏整块同样排除；
  宿主的正文引出句在分母内但其动词非打斗触发词，天然不影响。
- 动作: 结构层标记"套语"；统计脚本按块类型双排除；出入账表逐身份核对（ST05）。
- 反例: "且说"切换词若在正文段内是叙事过渡，不属套语；套语判定以 02ab §6.2 词族模板为准。
- 来源: `SKILL_02f` §2.1/§2.2；`SKILL_02ab` §6.2/§9.2。
- 状态: 已验证

### ST04 · 观察类围栏（告示/口诀/说书）暂不入正式统计口径
- 类别: 分母纪律
- 现象: 观察类围栏被当正式围栏统计，或内容被当正文计入。
- 判据: 观察类围栏内容**暂不计入正式统计口径**（02ab §4.1）；晋升评审通过后才回溯追认；统计报告中单列并注明。
- 动作: 统计表分"正式类/观察类"两列；观察类晋升后重跑回溯；不混入 E14 正式阈值判定。
- 反例: 口诀内的武功名/时间词可标但不贡献正文密度；不能因"可标"就当正文。
- 来源: `SKILL_02f` §2.1/§2.4；`SKILL_02ab` §4.1。
- 状态: 已验证

### ST05 · lint 钩子 E14/E17：统计异常多是结构错误的投影
- 类别: 分母纪律
- 现象: 发现 E14（韵文密度异常）或 E17（正文分母完整性）告警后直接调阈值消警。
- 判据: E14=单回韵文块 >5 或韵文段占比 >20% → warning；E17=正文段占比 <50% → warning（阈值待试点校准）；
  处置路径=先查围栏/套语误判（漏围/错围），再查 PN 结构；**禁止在统计层调阈值消警**（02f §2.4）。
- 动作: E14/E17 告警进存疑清单，回投 02ab 结构侧；修结构后复跑统计。
- 反例: 某书 E17 集中告警可能是该书回末对特别多（合法），需人工确认而非改阈值。
- 来源: `SKILL_02f` §2.4；`SKILL_02ab` §9.1。
- 状态: 已验证

## B 区 · 指标与密度

### ST06 · 基础规模指标：34 部 / 1,378 回 / 结构块约 20 万段
- 类别: 指标与密度
- 现象: 拍脑袋报"全库字数/段数"；或统计脚本自行扫目录导致书目不一致。
- 判据: 部书数=34（`config.py` `books()`，唯一来源）；总回数=1,378（逐书 chapters）；纯汉字=逐书累计
  （C12 分书跑通回填）；结构块数=PN 顶级块+围栏块（预估约 20 万段）；数据源禁止自行拼路径扫目录。
- 动作: 统计脚本 import `config.books()`；分书表逐书列回数；未跑通指标不报数（02f §1.1 明示）。
- 反例: "34 部 × 平均 40 回"估算总回数——与真实 1,378 回不符（回数悬殊）；必须逐书累加。
- 来源: `SKILL_02f` §1.1/§3.1；`scripts/config.py`（books/BOOK_OVERRIDES）。
- 状态: 已验证

### ST07 · 分布指标六类：长度/围栏占比/正文占比/密度/套语频次
- 类别: 指标与密度
- 现象: 只报总字数不报分布，无法做书风对比与 E14/E17 数据源。
- 判据: 02f §1.2 六类分布指标：文本长度（回字数/段字数/句长）、围栏占比（韵文段占比/书信占比）、
  正文占比（正文段 PN/全 PN）、密度（打斗/杀伐/传艺/行踪曲线）、套语频次（回末套语/且说切换）。
- 动作: 分书分回统计；指标随 C12 扩展；报告列公式与分母（ST01）。
- 反例: 只报"平均回字数"会把围栏密集章节与纯叙事章节混为一谈；须分长度分布。
- 来源: `SKILL_02f` §1.2；§2.2 密度口径。
- 状态: 已验证

### ST08 · 对比纪律：用率不用量、回数不齐不插值
- 类别: 指标与密度
- 现象: 34 部用总量排名（长书占优）；缺回/未标书被补齐估算。
- 判据: 对比一律用率（每回均值、每千字密度），禁止用总量排名；缺回/未标书在表中显式标"未达"，
  不做补齐估算（02f §3.2）。
- 动作: 对比表列率与分母；未达书单列；围栏类型分布作书风指纹单独列。
- 反例: 用"总触发词数"排名会得出"七剑第一"的误导结论（书长/回多）；应看密度。
- 来源: `SKILL_02f` §3.2/§1.3。
- 状态: 已验证

### ST09 · 34 部跨书对比：对比单位=书；围栏分布=书风指纹
- 类别: 指标与密度
- 现象: 照搬史记五体分组；或忽略书间文体差异。
- 判据: 武侠版对比单位=**书**（34 部平行语料）；围栏类型分布（词牌密度/书信占比/口诀次数）是"说书体浓度"
  的量化入口（02f §3.1/§3.2）。
- 动作: 分书统计表；跨书对比发现的结构异常回投 02ab 存疑清单，不在统计层裁决。
- 反例: 把"七剑"与"白发"的密度直接比而不控制围栏占比——词牌多的书正文分母更小，密度自然偏高。
- 来源: `SKILL_02f` §3.1/§3.2。
- 状态: 已验证

### ST10 · 实体密度延后记录（实体层未铺完报数即误导）
- 类别: 指标与密度
- 现象: 在实体层未铺完时报"人物密度/器物密度"，被当作质量指标。
- 判据: 02f §1.3 明示：实体密度**延后**——实体层未铺完，报数即误导；词法工具未建前不报字频/虚词频；
  对话占比/标点密度保留为规划项（02f 附录 B 负纪律）。
- 动作: 相关指标标"deferred"并写依赖（C12 扩展/实体层覆盖）；不参与质量结论。
- 反例: 用"实体密度 6.36/100 字"（docs/47）当全库基线——那是单书单批的实测，不是全库指标。
- 来源: `SKILL_02f` §1.3；docs/47（实体密度 5.98→6.36 单批实测）。
- 状态: 已验证

## C 区 · 覆盖与实测

### ST11 · 汉字覆盖率实测：江湖三女侠 21.98%（类型占比见报告）
- 类别: 覆盖与实测
- 现象: 覆盖率口径不一（是否含动词/修辞层、是否剔 Markdown），跨批数字不可比。
- 判据: 已标注汉字=所有 `〖TYPE 显示串〗`（15 类实体）+ `⟦VERB 显示串⟧`（6 域动词）+ `〘※…〙` 标注中
  显示串部分的汉字数之和；总字数剔除 Markdown 结构（标题/段号/列表/围栏标记/表格分隔）；类型码不在定版内的
  令牌不计入（跳过 0，由 lint 把关）（logs/coverage 报告口径）。
- 动作: `scripts/compute_annotation_coverage.py` 分书跑；报告列口径说明；跨批对比先核口径。
- 反例: 把围栏标记行/段号 `[N]` 计入总字数会低估覆盖率；口径必须与 ST01 分母纪律一致。
- 来源: `logs/coverage/汉字标注覆盖率统计报告_20261105.md`（江湖 48 回：511,541 汉字 / 112,417 标注 /
  21.98%；类型占比 人物 55.46% / 器物 6.28% / 行踪 5.90% / 战斗 5.51% …）；`scripts/compute_annotation_coverage.py`。
- 状态: 已验证

### ST12 · 韵文围栏实测：5 书 26 篇围栏整块不计入正文统计
- 类别: 覆盖与实测
- 现象: 韵文围栏被逐段拆入正文分母，或围栏内时间/动词被当正文。
- 判据: 围栏整块不计入正文分母（ST01）；`logs/yunwen` 实测 5 书共 **26 篇**韵文围栏（词/诗/歌/回末对），
  逐篇按书/回定位；围栏内动词字样不进分子。
- 动作: `scripts/extract_yunwen.py` 分书产出；统计时按围栏块排除；新增围栏后重跑 E14/E17。
- 反例: 章首词是围栏（不计），但宿主引出句"朗声吟道："在正文分母内（其动词非打斗触发词，不影响密度）。
- 来源: `logs/yunwen/yunwen.md`（26 篇）；`logs/yunwen/yunwen.json`；`SKILL_02f` §2.1。
- 状态: 已验证

### ST13 · 字数口径：剔除 Markdown 结构后才计"总字数"
- 类别: 覆盖与实测
- 现象: 统计出的总字数包含段号/标题/围栏标记，覆盖率与密度分母都被污染。
- 判据: 总字数需剔除 Markdown 结构（标题、段号 `[N]`、列表符、围栏标记行、表格分隔行等）（coverage 报告
  说明）；统计范围=`tagged/<书>/NNN.tagged.md` 剥标后的正文汉字。
- 动作: 统一由 `scripts/symbols.py` strip_markup + 结构剥离；统计脚本复用同一入口。
- 反例: 不能用 `struct` 文件计字数（结构标记多）；也不能用原始底本（未剥标）与标注后文本混算。
- 来源: `logs/coverage/汉字标注覆盖率统计报告_20261105.md` 说明；`scripts/symbols.py` strip_markup。
- 状态: 已验证

## D 区 · 工具与流程

### ST14 · 工具链：分书统计四件套（C12/C14/结构提取/词表）
- 类别: 工具与流程
- 现象: 统计脚本各自实现分母/剥标，口径漂移。
- 判据: 02f §四 工具表：`compute_annotation_coverage.py`（C12 分书覆盖率）、`extract_yunwen.py`（C14 分书
  韵文）、`extract_paragraph_structure.py`（结构块）、`generate_entity_stats_report.py`（实体统计），均分书
  统计并复用同一剥标入口。
- 动作: 新统计需求优先扩展现有脚本而非另写；口径变更需同步 02f 与 04f；报告注明脚本与参数。
- 反例: 临时脚本自行 strip_markup 会与 symbols.py 漂移（管道/括号处理差异），导致覆盖率不同。
- 来源: `SKILL_02f` §四；`scripts/compute_annotation_coverage.py`/`extract_yunwen.py`/`extract_paragraph_structure.py`。
- 状态: 已回写

### ST15 · 统计异常处置路径：结构 → 统计，不对调阈值
- 类别: 工具与流程
- 现象: 统计漂移（某书密度异常）时先调阈值或改口径，掩盖结构问题。
- 判据: 处置路径固定：① 查围栏/套语误判（漏围/错围）→ ② 查 PN 结构 → ③ 修复后重跑统计；统计层不裁决
  结构问题（ST05；02f §2.4）；跨书对比发现的结构异常回投 02ab 存疑清单（ST09）。
- 动作: 异常报告写"结构侧疑点"清单并指派到结构修复；统计报告只列现象不调值。
- 反例: 把 E17 阈值从 50% 降到 20% 让告警消失——分母完整性未变，只是掩盖。
- 来源: `SKILL_02f` §2.4/§3.2；`SKILL_02ab` §9.1。
- 状态: 已验证

### ST16 · 报数纪律：无产物不报数、未跑通不报数
- 类别: 工具与流程
- 现象: 报告写"约/估计 20 万段""预计 57 万字"被当作实测。
- 判据: 02f §1.1 明示"数字待试点书跑通后回填，禁止拍脑袋报数"；所有数字须来自脚本产物（日志/JSON）并
  可复算；估算值须标"预估"且不进结论表。
- 动作: 报告数字附来源路径与命令；预估与实测分列；未跑通指标写 deferred。
- 反例: 引用历史 docs 的旧数字（如 docs/47 实体密度）当全库基线——须注明单批/单书口径（ST10）。
- 来源: `SKILL_02f` §1.1；`SKILL_02f` 附录 B；docs/47。
- 状态: 已验证
