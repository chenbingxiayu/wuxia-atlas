````text
# SKILL 08a: 知识颗粒度管理（规划）

> 定义统一的知识单元标准，包含SKU（Standard Knowledge Unit）设计，确保知识的模块化和可复用性。

---

## 一、功能概述

知识库中的知识应该如何切分和组织？过细则碎片化难以理解，过粗则不便复用。本功能计划建立知识粒度管理体系，实现：

- **粒度标准**：定义不同类型知识的合适粒度
- **SKU设计**：标准知识单元的结构和字段
- **组织方式**：知识单元的分类和索引

---

## 二、核心概念

### 2.1 什么是知识颗粒度

知识颗粒度（Knowledge Granularity）指知识单元的大小和复杂度：

- **原子级**：不可再分的最小知识单元（如单个三元组）
- **分子级**：组合多个原子的小型知识单元（如人物简介卡片）
- **聚合级**：主题性的大型知识单元（如完整的人物传记）

### 2.2 SKU标准知识单元

SKU（Standard Knowledge Unit）是标准化的知识产品单元，类似商品库存单位：

- 统一的结构schema
- 明确的字段定义
- 标准化的元数据
- 可独立分发和复用

---

## 三、粒度设计原则

### 3.1 MECE原则

**Mutually Exclusive, Collectively Exhaustive**（互斥且完备）：
- 不同SKU之间无重叠
- 所有知识都能归入某个SKU
- 避免知识冗余和遗漏

### 3.2 用途驱动

**根据使用场景设计粒度**：
- 阅读场景：段落级（Purple Numbers）
- 查询场景：实体级（人物卡片）
- 学习场景：主题级（知识专题）
- 应用场景：功能级（技能卡、策略卡）

### 3.3 可组合性

**知识单元应支持灵活组合**：
- 小单元可组成大单元
- 大单元可拆解为小单元
- 支持多维度的组织方式

---

## 四、SKU类型设计

### 4.1 Factual SKU（事实型）

**定义**：描述客观事实的知识单元

**示例类型**：
- 人物卡片：姓名、生卒年、主要事迹、关系
- 事件卡片：时间、地点、参与者、经过、结果
- 地点卡片：位置、沿革、重要事件
- 制度卡片：名称、设立时间、内容、演变

**粒度标准**：
- 单个实体级别
- 包含核心属性和关键关系
- 200-500字说明

### 4.2 Procedural SKU（过程型）

**定义**：描述方法、策略、模式的知识单元

**示例类型**：
- 军事策略：背水一战、围魏救赵
- 治国方略：休养生息、重农抑商
- 外交手段：合纵连横、远交近攻
- 政治手腕：垂帘听政、挟天子以令诸侯

**粒度标准**：
- 单个策略/方法级别
- 包含背景、步骤、案例、效果
- 300-800字说明

### 4.3 Relational SKU（关系型）

**定义**：描述关系网络的知识单元

**示例类型**：
- 人物关系图：某人物的社会网络
- 事件因果链：某事件的前因后果
- 地理关系网：某地区的行政归属
- 概念关系图：某概念的上下位关系

**粒度标准**：
- 以某实体为中心的关系网
- 包含直接关系和一级间接关系
- 可视化图形+文字说明

---

## 五、SKU Schema设计

### 5.1 通用字段

所有SKU的共同字段：

```json
{
  "id": "SKU-类型-名称",
  "type": "factual/procedural/relational",
  "title": "标题",
  "summary": "一句话摘要",
  "tags": ["标签1", "标签2"],
  "source": {
    "chapters": ["章节号"],
    "paragraphs": ["段落ID"]
  },
  "created": "创建时间",
  "updated": "更新时间"
}
```

### 5.2 类型特定字段

**Factual SKU额外字段**：
```json
{
  "entity_type": "person/place/event/concept",
  "attributes": {"key": "value"},
  "relations": [{"type": "关系类型", "target": "目标实体"}]
}
```

**Procedural SKU额外字段**：
```json
{
  "domain": "领域",
  "steps": ["步骤1", "步骤2"],
  "cases": ["案例1", "案例2"],
  "effectiveness": "效果评估"
}
```

**Relational SKU额外字段**：
```json
{
  "center": "中心实体",
  "nodes": ["节点列表"],
  "edges": [{"from": "A", "to": "B", "type": "关系"}],
  "visualization": "图形数据"
}
```

# SKILL_08e：表格数据反思迭代提取方法

## 1. 核心挑战

### 1.1 表格数据的特殊性

史记"十表"（章节013-022）与其他章节有本质区别：

**挑战**：
1. **数据零散**：年表中的信息是碎片化的，单个条目缺乏上下文
2. **隐性关联**：王侯名字常省略，需要跨章节印证（如"赵武灵王"在年表中可能只写"武灵王"）
3. **时间跨度**：同一张表覆盖数百年，难以从局部看到整体规律
4. **结构复杂**：多维度交织（时间×地理×人物×事件）
5. **洞察隐藏**：表面是数据，深层是历史规律（如权力传承模式、地缘政治演变）

**传统a2o-lite的不足**：
- 直接提取事实 → 提取技能 → 生成洞察
- 对表格数据，这种线性流程会遗漏大量隐藏规律
- 需要**多轮迭代、逐步深入**的反思过程

### 1.2 META方法论映射

| META方法 | 在表格提取中的应用 | 具体操作 |
|----------|-------------------|----------|
| **META-00** | 识别问题的元问题 | "这张表想回答什么历史问题？我们应该问哪些问题？" |
| **META-01** | 反思提取过程本身 | "第1轮问题是否太表面？哪些维度被忽略了？" |
| **META-02** | 关联跨章节知识 | "这个王侯在本纪/世家/列传中的描述能否解释年表中的异常？" |
| **META-03** | 发现非显性规律 | "数据背后的深层机制是什么？哪些模式可以跨时代应用？" |

## 3. 第1轮：描述性问题 + 跨章节事实挖掘（META-00）

### 3.1 目标

**核心目标**：
1. **识别表格的元问题**：这张表的存在是为了回答什么历史问题？
2. **🔥 NEW: 挖掘每个条目背后的故事**：每个事件/人物在其他章节中的详细记载

**重要原则**：
- ⚠️ **第1轮不是"抄录表格"**，而是**用表格作为索引，去其他章节挖掘完整故事**
- 📖 **特别适用于封侯表（017/018/021/022）**：每次封侯都有背后的战功/政治事件
- 🔗 **建立"表格条目→章节故事"的映射**

### 3.2 操作步骤

#### Step 1: 阅读表格标题和序言

```markdown
**输入**：章节013《三代世表》

**元问题识别**：
- 司马迁为什么要做这张表？
- 标题"三代世表"的"世"是什么意思？（世系、世代）
- 这张表要展示什么？（夏商周三朝的传位关系）
```

**输入**：章节018《高祖功臣侯者年表》

**元问题识别**：
- 司马迁为什么要记录功臣封侯？
- "功臣五品"（勋/劳/功/伐/阅）如何区分？
- 为何"太初百年之间，见侯五，余皆坐法陨命亡国"？

#### Step 2: 提出基础描述性问题

**问题模板**（6个基本问题）：

1. **WHO**：表中涉及哪些人物/国家/组织？
2. **WHAT**：记录了哪些事件/现象？
3. **WHEN**：时间跨度是什么？分几个阶段？
4. **WHERE**：地理范围如何？
5. **HOW MANY**：有哪些关键数字？（如国家数量、年份跨度、人物数量）
6. **STRUCTURE**：表格的维度是什么？（如"时间×诸侯国""帝王×在位年数"）

#### 🔥 Step 3: 【NEW】跨章节事实挖掘

**目标**：对于表格中的**每个重要条目**，去相关章节挖掘完整故事。

**特别适用于**：
- 封侯表（017/018/021/022）：每个侯爵的封侯原因、战功、政治背景
- 诸侯年表（014/015/016）：每个重大事件的详细过程
- 六国年表（015）：每场战争的详细记载

**操作流程**：

##### 3.1 列出表格中的所有条目

**示例（章节018《高祖功臣侯者年表》）**：

```markdown
表格共记录143位功臣侯爵，包括：
1. 平阳侯曹参（中涓从起沛，以左丞相击齐魏）
2. 信武侯靳歙（中涓从起宛朐，击项羽，定江陵）
3. 清阳侯王吸（中涓从起丰，为骑郎将入汉）
...
143. （最后一位侯爵）

**初步统计**：
- 封侯时间：主要在高祖六年（前201）
- 户数范围：最高16,600户（曹参），最低500户
- 封侯原因：战功为主
```

##### 3.2 标注每个条目在其他章节的关联

**建立映射表**：

| 年表条目 | 关联章节 | 具体段落/事件 |
|---------|---------|--------------|
| 平阳侯曹参 | 《曹相国世家》(054) | 详细生平、从军经历、为相事迹 |
| 信武侯靳歙 | （可能在列传） | 需查找 |
| 淮阴侯韩信 | 《淮阴侯列传》(092) | 完整传记 |
| 酂侯萧何 | 《萧相国世家》(053) | 详细生平 |
| 绛侯周勃 | 《绛侯世家》(057) | 详细生平 |
| ... | ... | ... |

**工具**：使用`grep`或`Glob`工具搜索人名在其他章节的出现

```bash

# 搜索"韩信"相关章节

```

##### 3.3 读取关联章节，提取完整故事

**针对每个重要条目**（优先级：侯位高、事迹重要、有单独列传/世家）：

1. **读取关联章节**（使用Read工具）
2. **提取关键信息**：
   - 封侯前的经历（出身、早期事迹）
   - 封侯原因（具体战功、政治贡献）
   - 封侯后的发展（官职、爵位变化、子孙情况）
   - 国除原因（如有）
3. **创建Fact**：
   - `fact_00X_侯名_complete_story.md`（完整故事）
   - 包含年表简记 + 章节详细记载

**示例**：

```markdown

### 为相事迹
- 惠帝二年为相国

## 4. 第2轮：对比性问题（META-01）

### 4.1 目标

**反思第1轮的局限**：单纯罗列数据无法发现规律，需要对比分析。

### 4.2 反思提示

```
META-01反思：
- 第1轮只是"抄录"了表格内容，没有产生新知识
- 哪些维度可以对比？（朝代间、帝王间、时期间）
- 什么异常值得注意？（超长/超短在位、传位异常、事件密集期）
```

### 4.3 操作步骤

#### Step 1: 跨维度对比问题

**对比问题模板**（6类）：

1. **时间对比**：不同时期的X有何不同？
   - 夏商周的平均在位年数有何差异？
   - 朝代早期vs晚期的传位方式有何变化？

2. **实体对比**：A与B有何异同？
   - 夏启、商汤、周武王的"开国之君"有何共同点？
   - 夏桀、商纣的"亡国之君"是否有相似模式？

3. **指标对比**：哪个最大/最小/最频繁？
   - 在位最长的帝王是谁？为何如此长？
   - 传位最混乱的时期在何时？

4. **趋势对比**：X随时间如何变化？
   - 传位方式从"禅让→世袭→兄终弟及"的演变
   - 中央集权程度的变化

5. **异常检测**：什么是outlier？
   - 商朝为何有9次"九世之乱"？
   - 周朝为何有"共和行政"14年无天子？

6. **关联分析**：X与Y是否相关？
   - 在位年数与朝代稳定性是否相关？
   - 传位方式与朝代寿命是否相关？

#### Step 2: 跨章节印证

**操作**：
1. 查找年表中提到的人物在本纪/世家/列传中的详细描述
2. 用详细描述解释年表中的简略记录
3. 发现矛盾或补充信息

**示例**：
```markdown
// fact_003_传位方式对比分析.md

## 三代传位方式演变

### 统计分析
- **夏朝**：父子传位 14次（82%），兄终弟及 2次，篡位 1次
- **商朝**：父子传位 18次（58%），兄终弟及 10次（32%），隔代 3次
- **周朝**：父子传位 34次（92%），兄终弟及 2次，共和 1次

### 跨章节印证
**盘庚迁殷**（见《殷本纪》）：
- 年表记录："盘庚，五迁都"
- 本纪详述：盘庚力排众议，从奄迁都于殷，克服贵族阻力
- **洞察**：商朝前期多迁都、兄终弟及，导致权力不稳定

**周召共和**（见《周本纪》）：
- 年表记录："厉王出奔，周召二公行政，号曰共和"
- 本纪详述：厉王暴政被逐，周定公、召穆公共同执政14年
- **洞察**：周朝首次出现"无王"时期，贵族集体执政的实验
```

**第2轮产出**：
- 3-5个对比分析Facts
- 跨章节关联表
- 异常事件详细分析

## 5. 第3轮：机制性问题（META-02）

### 5.1 目标

**从对比中提炼方法论**：为什么会出现这些规律？背后的机制是什么？

### 5.2 反思提示

```
META-02反思：
- 第2轮发现了"传位方式与朝代稳定性相关"，但为什么？
- 能否从这些规律中提炼出可复用的方法/策略？
- 古人是否意识到这些规律？（如司马迁的评论）
```

### 5.3 操作步骤

#### Step 1: 因果机制分析

**问题模板**（5W1H深化版）：

1. **WHY发生**：X为什么会导致Y？
   - 商朝"兄终弟及"为何导致九世之乱？

2. **WHY有效**：X为什么能解决问题Y？
   - 周朝为何确立"嫡长子继承制"？效果如何？

3. **HOW实现**：X是通过什么步骤/策略达成的？
   - 盘庚如何说服贵族迁都？（见《殷本纪》原文）

4. **HOW失败**：X为什么没能阻止Y？
   - 周天子的分封制为何最终失控？

5. **WHAT IF**：如果改变X，Y会如何？
   - 如果商朝早期确立父子继承，是否能避免动荡？

#### Step 2: 提炼Skills

**Skill模板**：

```markdown
---
name: ancient-succession-system-design
description: 古代王位继承制度设计方法（从夏商周三代经验提炼）
---

## 概述
从夏商周1800年的传位实践中，提炼出设计稳定继承制度的方法论。

## 适用场景
- 家族企业传承规划
- 组织领导力继任计划
- 政治权力交接设计

## 核心理念
**权力传承的三大目标**：
1. 合法性（legitimacy）：继任者被接受的程度
2. 稳定性（stability）：避免争夺导致内乱
3. 能力保证（competence）：选出有能力的领导者

**三代的不同选择**：
- 夏朝：优先稳定性（父子继承），牺牲能力选拔
- 商朝：尝试平衡（兄终弟及），但导致混乱
- 周朝：系统化方案（嫡长子+分封制+礼乐约束）

## 实施步骤

### 步骤1：确定继承原则（3选1或混合）

**选项A：能力优先（禅让制）**
- 优点：选出最有能力者
- 缺点：容易引发争夺（如尧舜禹后失败）
- 适用：初创期、危机期

**选项B：稳定优先（父子继承）**
- 优点：规则明确，减少争议
- 缺点：无法保证能力
- 适用：成熟期、和平期

**选项C：兼顾方案（嫡长子+备选）**
- 优点：稳定为主，保留能力调整空间
- 缺点：需要强大的制度约束
- 适用：长期规划

### 步骤2：建立配套制度

**周朝的系统方案**：
1. **明确规则**：嫡长子继承，写入礼制
2. **培养体系**：太子教育（太傅、太保）
3. **分流机制**：其他子弟分封诸侯，避免争夺
4. **监督约束**：礼乐制度规范行为
5. **应急预案**：嫡长子不适任时的废立程序

### 步骤3：预防常见风险

**风险矩阵**（从夏商周失败案例提炼）：

| 风险 | 案例 | 预防措施 |
|------|------|----------|
| 继承人无能 | 夏太康失国 | 建立教育+考核机制 |
| 多继承人争夺 | 商九世之乱 | 明确顺位+分流其他人 |
| 权臣篡位 | 后羿代夏 | 分权制衡+贵族制约 |
| 外戚干政 | 周幽王废嫡立庶 | 礼法约束+大臣谏议 |
| 制度失效 | 春秋礼崩乐坏 | 定期强化+刷新合法性 |

### 步骤4：执行与调整

**商朝的教训**：
- 初期未确立明确规则 → 300年反复调整
- 盘庚迁殷后才稳定 → 制度需要配合现实

**周朝的成功**：
- 800年基本稳定 → 制度化+文化认同
- 失败案例（如幽王）反而证明制度重要性

## 决策点

**Q1: 组织处于什么阶段？**
- 初创期 → 能力优先，灵活调整
- 成熟期 → 稳定优先，明确规则

**Q2: 继承人数量？**
- 独子 → 重点培养
- 多子 → 需要分流机制（分封、分家、分业务）

**Q3: 外部压力大小？**
- 竞争激烈 → 保留能力选拔空间
- 环境稳定 → 可以更注重稳定性

## 现代应用

### 企业传承

**成功案例**：

**历史现象**：
- 夏朝：父子继承规则明确，但缺乏能力筛选 → 太康失国

**深层机制**：
继承制度面临"**明确性-灵活性悖论**"：
- 规则越明确 → 稳定性越高，但适应性越差
- 规则越灵活 → 能力筛选越好，但争夺风险越高

**数学表达**（博弈论视角）：
- 明确规则：降低争夺成本C，但无法筛选能力A
- 模糊规则：可以筛选A，但争夺成本C激增
- **最优解**：明确主规则（如嫡长子）+ 有限灵活性（如废立程序）

**现代应用**：

1. **企业传承**：
   - BAD：完全按资历/血缘（明确但僵化）
   - BAD：完全能力竞争（灵活但内耗）

2. **政治制度**：
   - 君主世袭：明确性极高，灵活性为0
   - 民主选举：灵活性极高，但选举成本高
   - 君主立宪：保留世袭稳定性，实权由选举产生

3. **组织管理**：
   - CEO继任：提前2-3年明确候选人，但保留董事会否决权

**量化指标**：
- 明确性指数：规则的可预测程度（0-1）
- 争夺成本：内部竞争导致的资源消耗（金钱、时间、关系）
- 能力优化：继任者能力与前任的相对水平（-1到+1）

**跨时代验证**：

- 周朝800年稳定 → 证明明确规则的长期价值

## 9. 方法论总结

### 9.1 核心创新

1. **从线性到螺旋**：不再是"读→提取→输出"，而是"读→问→思→深问→输出→再问"
2. **从孤立到关联**：每轮都要回顾前轮，跨章节印证
3. **从数据到智慧**：从表格数字（第1轮）到决策工具（第5轮）的跃迁
4. **从历史到现代**：每个规律都要找到现代应用场景

### 9.2 质量检验

**好的表格SKU应该包含**：

✅ **数据完整性**：第1轮的基础Facts覆盖表格主要内容
✅ **洞察深度**：第4轮的Eureka不是显而易见的，而是"反直觉"的
✅ **方法实用性**：第3/5轮的Skills可以直接应用，有检查清单
✅ **跨域连接**：每轮都有跨章节/跨学科的关联
✅ **历史现代对话**：古代案例与现代理论/案例对照

### 9.3 避免的陷阱

❌ **第1轮陷阱**：只是"复制粘贴"表格，没有结构化
❌ **第2轮陷阱**：对比流于表面，未发现真正的异常
❌ **第3轮陷阱**：方法论过于抽象，缺乏可操作性
❌ **第4轮陷阱**：洞察过于显而易见，缺乏深度
❌ **第5轮陷阱**：工具设计过于复杂，用户无法使用

## 附录C：Eureka质量检验清单

**好的Eureka应该满足**：

✅ **非显性**：不是一眼就能看出的结论
✅ **有机制**：解释"为什么"，而非仅仅描述"是什么"
✅ **可验证**：提供历史案例或数据支持
✅ **跨时代**：连接古代与现代，或不同领域
✅ **反直觉**：挑战常识或提供新视角
✅ **可应用**：指导现代决策或行动

**Bad案例**：
❌ "夏朝有17位帝王" （太显性）
❌ "传位方式影响稳定性" （太笼统）

**Good案例**：
✅ "继承制度的明确性-灵活性悖论"（有机制、反直觉）
✅ "共和行政作为权力真空的集体解决方案"（跨时代、可应用）
````
