````text
**3.1 上游已定版契约摘要**

**SKILL_01g 武侠版（v0.3-draft）结构层相关**：
- 结构层最低字段（不可减）：作品 ID、回 ID 与本书回号、段落 ID、块类型、文本模式（正文/回目/诗词/歌词/口诀/书信/告示）、叙述模式（正常叙事/回忆/梦境/转述）、叙事线 ID、原文区间；
- 定位规则："第三回"使用作品 ID 与回号联合定位，"把全宇宙的第三回当成一个唯一回目"是错误；
- 原则零：结构字符（标题符、段号、链接、目录）不作语义标注；文学内容（诗词/口诀/书信）**不机械豁免**——按真实指称与文本模式判断；
- 负规则十一：诗词意象不当事实（诗中"剑斩浮云"不登记斩杀事件；明确人物/作品/技术提及可标，且保留韵文模式）；
- 负规则十二：书信内容不自动核实（信中声称身亡不生成确定死亡；实体可标，来源与可信状态必须保留）；
- 负规则十三：回目预告与回末套语不抽事件（"欲知后事如何"不生成下一回事实）；
- FAQ Q14：韵文提及默认不计入正文事件密度。

**SKILL_04f 武侠版（v0.3-draft）接口**：
- 事件统计口径："数触发词，不数回合与实体"；韵文块不计入打斗密度（依赖本任务的韵文判定）；
- 回末套语/回目预告不抽事件（04f 错误模式继承 01g 负规则十三）。

**3.2 前人标注实验的四条结论**（提示词维护原则，适用于本任务的规则写作）：
1. 漏标/过标大部分可靠规范文字修复——正规则显式清单有效；
2. 枚举式规则无效，few-shot 示例立竿见影——每条规则配真实示例；
3. 规范自身矛盾提示词解决不了——规则间必须自检无冲突；
4. 词表正则是系统盲区的兜底——套语词表分级设计是本任务的词表交付物。

**3.3 章回体结构实测**（《白发魔女传》32 回 grep + 抽样观察，设计必须逐条回应）：

| 信号 | 频次 | 解读 |

| 但见 | 39 | 多为叙事动词（"但见剑光"），伪信号为主 |
| 只见 | 190 | **绝大多数是叙事动词**，最强伪信号 |
| 却说 | 5 | 低频切换信号 |
| 欲知后事 | 27 | 回末强信号（32 回近乎每回必有） |
| 正是（行首） | 31 | 回末对句/回中评点引出词，高频 |
| 调寄 | 1 | 词牌署名存在但极稀少，只可作加分信号 |
| 有诗为证 / 花开两朵 / 不在话下 | 0 | **水浒型说书套语在梁书缺位**——任务清单起点枚举需按数据裁剪 |
| 看官 | 1 | 说书人旁白极低频 |

- 回目格式实测：`第一回　铁矢神弓　少年扶巨宦　金鞍宝马　大盗震虚声`（第N回 + 两联对句，全角空格分隔）；

- 章首词为长短句词牌（沁园春，分上下阕）——verse_score 四言支路必漏检；
- 回末结构实测：对句（"正是：XXX，XXX。"）+ 套语（"欲如后事如何？请听下回分解。"）——**变体"欲如"与"欲知"并存**；
- 武功口诀全文极少见（多为"传了口诀"式叙述提及）；
- 书信多为行内引语，成段书信全文较少。

# SKILL 02a: 古籍章节切分与编号 — Purple Numbers与语义分段

> 从《史记》130篇的章节结构化实践中提炼，适用于大规模古籍的篇章拆分、段落编号和小节划分。

## 一、核心概念

### 1.1 三层结构

古籍文本需要三层结构化：

```
篇章（Chapter）    130个独立文件，三位数编号
  └─ 小节（Section）  语义段落组，二/三级标题
      └─ 段落（Paragraph）  带Purple Numbers的原子文本单元
```

### 1.2 Purple Numbers（紫色编号）

**定义**：每个段落的唯一、永久、不可变标识符。

```
[0]      篇名段
[1]      第一段
[1.1]    第一段的第一子段
[1.1.1]  三级子段（可选，用于复杂章节）
[2]      第二段
```

**为什么叫"Purple Numbers"**：
- 源自Project Xanadu的概念 — 文档中每个段落都有永久地址
- 一旦分配，永不改变（即使周围内容重组）
- 渲染时显示为可点击的锚点链接

**为什么重要**：
- 跨文档引用：`092_淮阴侯列传#pn-3.1` 永远指向同一段文字
- 实体索引关联：`entity_index.json` 中每个实体引用格式为 `[chapter, paragraph_id]`
- 事件索引关联：事件定位到具体段落
- 搜索定位：精确到段落级别的全文检索

- [references/SKILL_02a1_Purple_Numbers编号详细规范.md](references/SKILL_02a1_Purple_Numbers编号详细规范.md) — 编号层级、策略选择、父子关系、连续性验证

## 二、阶段1：篇章拆分

### 2.1 拆分规则

将完整古籍文本按卷/篇拆分为独立文件。

**命名规范**：`{三位编号}_{篇名}.txt`

```
001_五帝本纪.txt
002_夏本纪.txt
...
130_太史公自序.txt
```

**《史记》的体裁分布**：

| 体裁 | 篇数 | 编号范围 | 特征 |
|------|------|---------|------|
| 本纪 | 12 | 001-012 | 帝王编年，时间跨度大 |
| 表 | 10 | 013-022 | 表格数据，结构特殊 |
| 书 | 8 | 023-030 | 制度专题，论述为主 |
| 世家 | 30 | 031-060 | 诸侯/功臣，叙事+编年 |
| 列传 | 70 | 061-130 | 人物传记，叙事为主 |

### 2.2 拆分脚本逻辑

```python
# 识别篇章边界：标题行以体裁关键词结尾
CHAPTER_PATTERNS = ['本纪', '表', '书', '世家', '列传', '太史公自序']

def split_by_chapter(full_text):
    chapters = []
    current = []
    for line in full_text.split('\n'):
        if any(line.strip().endswith(p) for p in CHAPTER_PATTERNS):
            if current:
                chapters.append(current)
            current = [line]
        else:
            current.append(line)
    return chapters
```

**注意事项**：
- 编号补零到3位，确保文件系统排序正确
- 保持原文完整性，不做任何修改
- 表类篇章（013-022）可能需要特殊处理（表格结构）

## 三、阶段1.5：段落修复（误分段合并）

原始文本拆分后，常因源文件换行位置不当而产生误分段（一个句子被截断为两行）。需在段落编号之前修复。

### 误分段特征

```
於是九州攸同，四奥既居，九山     ← 行末无句末标点
旅，九川涤原，九泽既陂...       ← 下一行直接续前句
```

### 合并规则（4条）

| 规则 | 条件 | 操作 | 理由 |
|------|------|------|------|
| 1 | 当前行以句末标点结尾（。！？」』：；…） | 不合并 | 完整句子 |
| 2 | 当前行或下一行为空 | 不合并 | 段落分隔 |
| 3 | 当前行很短（<10字符） | 不合并 | 可能是标题或小节标记 |
| 4 | 其他情况 | 合并 | 行末无句末标点，很可能是误分段 |

### 合并算法

```python
ending_marks = ['。', '！', '？', '」', '』', '：', '；', '…']

def should_merge(current_line, next_line):
    if not current_line.strip() or not next_line.strip():
        return False                          # 规则2
    if len(current_line.strip()) < 10:
        return False                          # 规则3
    if current_line.rstrip()[-1] in ending_marks:
        return False                          # 规则1
    return True                               # 规则4：合并

# 循环合并：当前行可能需要与连续多行合并
merged = current_line
while should_merge(merged, next_line):
    merged += next_line
    # 继续检查下一行
```

### 扩展到其他古籍

句末标点列表需按古籍标点系统调整。未标点的古籍（如原始刻本）不适用此规则，需先完成标点再修复。

## 四、阶段2：段落编号（Purple Numbers）

> **详细规范参考**：本节为快速指南，完整的Purple Numbers编号规范（包括三级编号、编号策略选择、特殊情况处理等）请参考：
>
> [references/SKILL_02a1_Purple_Numbers编号详细规范.md](references/SKILL_02a1_Purple_Numbers编号详细规范.md)

### 4.1 编号格式与规则

#### 4.1.1 基本格式

Purple Number采用**层级点分格式**：

```
[0]        篇名（固定）
[1]        一级段落（顶级）
[1.1]      二级段落（子段落）
[1.1.1]    三级段落（子子段落，可选）
[2]        一级段落
[2.1]      二级段落
```

**格式要求**：
- 方括号 `[]` 包裹
- 纯数字，用 `.` 分隔层级
- 行首位置，紧跟一个空格
- 不允许字母或中文：❌ `[1.a]`、❌ `[一]`
- 支持最多三级编号（复杂章节可使用三级结构）

#### 4.1.2 父子关系规则（重要）

**核心规则**：必须有父段落才能有子段落。

❌ **错误示例**（缺少父段落）：
```markdown
## 某节标题
[67.1] 子段落内容...
[67.2] 子段落内容...
```

✅ **正确示例**（有父段落）：
```markdown
## 某节标题
[67]               ← 父段落（可以为空）
[67.1] 子段落内容...
[67.2] 子段落内容...
```

**空父段落是允许的**：
- 当一个小节下全是子段落时，可以只有编号 `[67]`，无内容
- 父段落作为子段落的"容器"存在

**检查与修复工具**：

```bash
# 检查缺失的父段落编号
python scripts/check_missing_parent_pn.py

# 自动修复（插入缺失的父段落）
python scripts/fix_missing_parent_pn.py
```

### 4.2 编号的连续性

#### 4.2.1 同层级必须连续

**规则**：同层级编号不允许跳跃。

❌ **错误**：
```markdown
[1] 第一段
[3] 第三段    ← 缺少[2]
[3.1] 子段
[3.3] 子段    ← 缺少[3.2]
```

✅ **正确**：
```markdown
[1] 第一段
[2] 第二段
[3] 第三段
[3.1] 子段
[3.2] 子段
```

#### 4.2.2 检查工具

`lint_markdown.py` 会检查编号连续性，报告跳跃的编号。

### 4.3 何时使用子编号

#### 4.3.1 长段落拆分

**原则**：一段超过500字，按语义边界拆分为子段落。

```markdown
[5]                        ← 空的父段落
[5.1] 第一个语义单元...
[5.2] 第二个语义单元...
[5.3] 第三个语义单元...
```

#### 4.3.2 对话段落

**原则**：包含多人对话时，每句对话独立编号。

```markdown
[12]
- [12.1] @尧@曰："谁可顺此事？"
- [12.2] @放齐@曰："嗣子@丹硃@开明。"
- [12.3] @尧@曰："吁！顽凶，不用。"
```

详细规则见 §8.2 对话段落。

#### 4.3.3 列表项处理

**短列表**（方位、物品名等）：不需要子编号

```markdown
[2]
- 东至于=海=，登=丸山=，及=岱宗=。
- 西至于=空桐=，登=鸡头=。
- 南至于=江=，登=熊=、=湘=。
```

**长列表**（完整句子、对话）：需要子编号

```markdown
[12]
- [12.1] @尧@曰："谁可顺此事？"
- [12.2] @放齐@曰："嗣子@丹硃@开明。"
```

#### 4.3.4 引用块

**原则**：引用块（`> "..."`）不独立编号，从属于上一段。

```markdown
[1] 太史公曰：余登箕山，其上盖有许由冢云。

> "余以所闻由光义至高，其文辞不少概见，何哉？"

[2] 孔子序列古之仁圣贤人...
```

### 4.4 编号的不可变性

**核心原则**：Purple Numbers一旦分配，永不更改。

**为什么**：
- 外部引用依赖编号：实体索引中每个实体的 `paragraph_id` 字段
- 事件索引依赖编号：事件的段落位置
- 跨文档引用：`092_淮阴侯列传#pn-3.1` 永远指向同一段

**插入新段落时**：使用子编号，不改变已有编号

```markdown
[3] 原有段落
[3.1] 后续插入的段落（新增）
[4] 原有段落（编号不变）
```

### 4.5 特殊编号格式

#### 4.5.1 篇名编号

**固定格式**：每篇开头的篇名固定使用 `[0]`

```markdown
# [0] 五帝本纪

[1] 黄帝者，少典之子...
```

#### 4.5.2 表格行编号（十表专用）

**格式**：表格行使用 `[rN]` 格式（`r` = row）

```markdown
| 国名 | 侯功 | 元光 | 元朔 |
| --- | --- | --- | --- |
| [r1] 翕。 | 匈奴相降，侯。 | 三。四年七月壬午... |
| [r2] 持装。 | 匈奴都尉降，侯。 | ... |
```

详见 §8.3 表类篇章。

### 4.6 编号放置位置

**标准格式**：`[编号]` + 空格 + 内容

```markdown
[1] 太史公曰：余登箕山，其上盖有许由冢云。

[1.1] 孔子序列古之仁圣贤人，如吴太伯、伯夷之伦详矣。
```

**列表项格式**：`- ` + `[编号]` + 空格 + 内容

```markdown
- [12.1] @尧@曰："谁可顺此事？"
- [12.2] @放齐@曰："嗣子@丹硃@开明。"
```

## 五、阶段3：语义小节划分

### 4.1 小节层级

```markdown
# [0] 篇名                    ← 一级标题（每篇唯一）

## 大节标题                    ← 二级标题（主要叙事段落）

### 小节标题                   ← 三级标题（细分主题）

[1.1] 正文段落...
```

### 4.2 分节标题规则

#### 4.2.1 标题不应包含段落编号

**重要规则**：二级和三级标题（##、###）不应包含段落编号。

**错误示例**：

```markdown
## [6] 论法家        ← 错误！标题不应包含编号
### [2.1] 历法起源   ← 错误！标题不应包含编号
```

**正确示例**：

```markdown
## 论法家           ← 正确！标题只包含文字
### 历法起源        ← 正确！标题只包含文字
```

**例外**：一级标题 `# [0] 篇名` 可以包含编号（用于篇章标识）。

**检查与修复工具**：

```bash
# 检查标题中的编号
python scripts/lint_heading_numbers.py

# 自动修复（去除标题中的编号）
python scripts/fix_heading_numbers.py
```

#### 4.2.2 标题位置规则

**重要规则**：分节标题（##、###）必须出现在顶级段落之前，不应出现在非顶级段落（子段落）之前。

**错误示例**：

```markdown
[4] 黄帝二十五子，其得姓者十四人。
### 后裔与世系    ← 错误！标题在子段落之前
[4.1] 黄帝居轩辕之丘...
```

**正确示例**：

```markdown
### 后裔与世系    ← 正确！标题在顶级段落之前
[4] 黄帝二十五子，其得姓者十四人。
[4.1] 黄帝居轩辕之丘...
```

**修复方法**：

1. 如果顶级段落（如[4]）已存在，将标题移到顶级段落之前
2. 如果顶级段落不存在（如缺少[2]，直接从[2.1]开始），在标题后、子段落前插入空的顶级段落：

```markdown
### 秦国疆域与大臣
[2]           ← 插入空的顶级段落
[2.1] 当是之时...
```

**检查与修复工具**：

```bash
# 检查分节位置错误
python scripts/lint_section_position.py

# 自动修复（插入缺失的顶级段落）
python scripts/fix_section_position.py
```

### 4.4 两种小节格式

**格式A：标题带编号**

```markdown
## [1] 早年困顿
[1.1] @淮阴侯@韩信@者，=淮阴=人也...
[1.2] @信@钓於城下...

## [2] 投奔项羽与汉王
[2.1] 及@项梁@渡=淮=...
```

锚点直接取自标题中的编号：`#pn-1`、`#pn-2`。

**格式B：标题不带编号**

```markdown
## 项羽早年
### 项氏家世
[1.1] @项籍@者，=下相=人也...

## 起兵反秦
### 斩会稽守
[7.1] &秦&%二世元年七月%...
```

锚点取自该节第一个段落的编号：`#pn-1.1`、`#pn-7.1`。

### 4.5 按体裁定制小节策略

| 体裁 | 划分原则 | 典型小节 |
|------|---------|---------|
| 本纪 | 按帝王/时期 | "黄帝"、"帝颛顼"、"帝喾" |
| 世家 | 按诸侯世代 | "太伯奔吴"、"寿梦立"、"阖闾争位" |
| 列传（单传）| 按人生阶段 | "早年"、"拜将"、"封王"、"陨落" |
| 列传（合传）| 按人物分段 | "管仲"、"晏婴" |
| 列传（类传）| 按人物分段 | "总论"、"循吏某某"、"循吏某某" |
| 书 | 按制度主题 | "礼之起源"、"三代之礼"、"秦汉之变" |
| 表 | 按表格结构 | 保留原表，可能需特殊处理 |

### 4.6 小节标题规范

**好的标题**：
- "鸿门宴" — 具体事件
- "萧何月下追韩信" — 经典典故
- "背水之战" — 著名战役

**差的标题**：
- "第一部分" — 无信息量
- "段落1-10" — 纯位置描述
- "内容" — 过于笼统

**标题中清理实体标记**：小节标题在 `sections_data.json` 中存储时，去除所有实体标记符号：

```python
def clean_title(title):
    """去除标题中的实体标记"""
    for ch in ['@', '=', '$', '%', '&', '^', '~', '*', '!', '〖+', '〗', '〖?', '#']:
        title = title.replace(ch, '')
    return title.strip()
```

### 4.7 自动小节生成

对于没有明确分段的章节（约41篇），使用启发式算法生成建议：

```python
def auto_generate_sections(paragraphs, chunk_size=10):
    """每10段为一组，分析前3段内容生成标题"""
    sections = []
    for i in range(0, len(paragraphs), chunk_size):
        chunk = paragraphs[i:i+chunk_size]
        sample = ' '.join(chunk[:3])
        title = infer_title(sample)
        sections.append({"anchor": chunk[0].pn, "title": title})
    return sections

def infer_title(text):
    """基于关键词的启发式标题推断"""
    if '曰' in text or '云' in text: return '评论与论述'
    if '年' in text or '月' in text: return '编年记事'
    if '战' in text or '伐' in text: return '战争与征伐'
    if '封' in text or '侯' in text: return '封赏与爵位'
    if '太史公' in text: return '太史公评论'
    return '叙事'  # 默认
```

**重要**：自动生成的标题仅为建议，必须人工审核后使用。

### 9.1 "赞"段落（太史公评论）

每篇末尾通常有"太史公曰"或"赞"段落，格式特殊：

```markdown
## 赞
[N] 太史公曰：...评论文字...
多行评论合并为一个段落编号
不需要每行单独编号
```

**修复工具**：`fmt_fix_zan.py` — 将多编号的赞合并为单编号，各句换行但不分段。

### 9.2 对话段落

包含多人对话的长段落需要拆分，拆分后每行转为列表项（`- ` 开头）：

```markdown
# 拆分前：
[5] 齐王曰："寡人闻之。"晏子对曰："臣请言之。"

# 拆分后：
- [5.1] 齐王曰："寡人闻之。"
- [5.2] 晏子对曰："臣请言之。"
```

**修复工具**：`fmt_split_dialogues.py` — 在"X曰:"边界处自动拆分。

详细规则与示例见 [SKILL_02a_章节切分与编号.md §五](SKILL_02a_章节切分与编号.md)。

#### 9.2.1 嵌套引号的拆分规则

将包含嵌套引号的长段落拆分为列表项时，**必须保持原文的引号层级**，不得将内层单引号 `'...'` 改为外层双引号 `"..."`。

```markdown
# 原文（一整段）：
作汤诰："维三月，王自至於东郊。告诸侯群后：'毋不有功於民，勤力乃事。予乃大罚殛女，毋予怨。'曰：'古禹、皋陶久劳于外，...先王言不可不勉。'曰：'不道，毋之在国，女毋我怨。'"以令诸侯。

# ✗ 错误拆分（内层引号被改为双引号）：
- [8.1] "维三月，...毋予怨。'"
- [8.2] 曰："古禹、皋陶...不可不勉。"    ← 错：'→"
- [8.3] 曰："不道，...女毋我怨。"          ← 错：'→"

# ✓ 正确拆分（保持内层单引号）：
- [8.1] "维三月，...毋予怨。'
- [8.2] 曰：'古禹、皋陶...不可不勉。'
- [8.3] 曰：'不道，...女毋我怨。'"
```

**原则**：拆分只改变物理换行，不改变原文的任何字符（包括引号类型）。外层 `"` 的开闭仍然在首段和末段，内层 `'` 保持不变。

### 9.3 表类篇章（十表 013-022）

年表（013-022）以表格形式呈现，每行数据对应一个历史条目（侯国、诸侯、君主、将相等），**必须为每行分配独立 Purple Number**，以支持精确引用和事件链接。

#### 9.3.1 行号格式

表格行使用 `[rN]` 格式（`r` 前缀区别于段落编号 `[1.1]`），章内全局递增，跨多张表格连续计数：

```markdown
| 国名 | 侯功 | 元光 | 元朔 | … |
| --- | --- | --- | --- | … |
| [r1] 翕。 | 匈奴相降，侯。 | 三。四年七月壬午，侯赵信元年。 | … |
| [r2] 持装。 | 匈奴都尉降，侯。 | … |
| [r5] 长平。 | 以元朔二年再以车骑将军击匈奴… | … |
```

渲染器读取 `[rN]` 并生成锚点 `id="pn-r5"`，HTML URL 为 `020_建元以来侯者年表.html#pn-r5`。

#### 9.3.2 生成脚本

`scripts/add_table_row_pn.py` 可一键为十表 MD 文件添加 `[rN]` 标记：

```bash
python scripts/add_table_row_pn.py          # 处理全部 013-022 章
python scripts/add_table_row_pn.py 020       # 只处理 020 章
```

已有 `[rN]` 的行会自动跳过，支持幂等运行。

#### 9.3.3 在事件索引中引用

十表来源的事件，`段落位置` 字段应使用 `r{N}` 格式，而非 `表（X条目）`：

```markdown
- **段落位置**: r5          ← 对应 #pn-r5（长平侯条目）
- **段落位置**: r8          ← 对应 #pn-r8（平津侯/公孙弘条目）
```

多行事件可记为范围 `r12-r15`。

#### 9.3.4 CSS 渲染

行号列（`<td class="row-pn-col">`）样式在 `docs/css/shiji-styles.css` 中定义，与段落 `.para-num` 使用相同颜色（淡紫色 `#C8A8FF`）。表格其余样式（全视口宽度、sticky 表头、间隔行色）由 `.shiji-table-wrapper` / `.shiji-table` / `.even` / `.odd` 控制，也在同一 CSS 文件中。

### 9.4 超长小节

如果一个小节超过20个段落，应进一步拆分：

```python
MAX_SECTIONS_PER_CHAPTER = 15  # 小节上限
MIN_PARAGRAPHS_PER_SECTION = 3  # 太短的小节应合并
MAX_PARAGRAPHS_PER_SECTION = 20 # 太长的小节应拆分

## 十一、经验教训

1. **编号是基础设施** — Purple Numbers是整个知识系统的定位基础（实体索引、事件索引、跨文档引用都依赖它），设计必须在最早期确定且不可变。

2. **语义分段优于机械分段** — "每500字切一段"远不如"按帝王更迭切一段"有价值。小节标题是读者的导航地图。

3. **体裁决定结构** — 本纪按时间、列传按人生、世家按世代，不同体裁的最佳分段策略完全不同。

4. **自动生成只是起点** — 启发式规则生成的小节标题准确率约60%，必须人工审核。但它大幅降低了从零开始的工作量。

5. **小节数量要克制** — 每篇5-15个小节是合理范围。太多（>20）等于没有分段，太少（<3）等于只有标题。

6. **两种标题格式都要支持** — 有些章节天然适合"## [N] 标题"格式（列传），有些适合无编号格式（本纪），工具链必须兼容两者。

7. **锚点格式统一** — `#pn-{number}` 作为唯一锚点格式贯穿整个系统（源文件、HTML、索引、API），避免多套ID体系。

8. **先切分后标注** — 先完成篇章拆分和段落编号，再做实体标注。如果顺序反过来，每次修改编号都要重新关联所有实体引用。

## 一、问题定义

《史记》每篇末尾通常有两部分：

1. **太史公曰**（散文评论）— 司马迁的史论
2. **赞**（韵文总结）— 四字为主的押韵评语

这两部分需要用 Pandoc Fenced Div 语法（`::: tag` / `:::`）标注为语义块，使渲染器能：
- 应用不同的 CSS 样式（边框、背景、字体）
- 韵文保持硬换行（每句一行，`<br>` 分隔）
- 标签显示为 tooltip（`title` 属性），而非标题

---

## 二、Fenced Div 语法

### 2.1 基本格式

```markdown
::: 标签名
内容...
:::
```

- 开头 `::: 标签名`，标签名为中文语义标记
- 结尾 `:::` 单独一行
- 块内内容无需 `>` 前缀，直接书写

### 2.2 标签类型

| 标签          | CSS 类           | 用途           |
| ------------- | ---------------- | -------------- |
| `太史公曰`    | `.note-太史公曰` | 史论散文评论   |
| `赞`          | `.note-赞`       | 韵文总结       |
| `诗歌`        | `.note-诗歌`     | 篇中出现的诗歌 |
| `谏言`        | `.note-谏言`     | 大臣谏言       |
| `策论`        | `.note-策论`     | 纵横家论述     |
| `制度`        | `.note-制度`     | 制度性文献     |
| `传说`        | `.note-传说`     | 神话传说       |
| `宋昌说辞` 等 | `.note-box`      | 自定义标签     |

### 2.3 渲染规则

```
::: tag → <div class="note-box note-{tag}" title="{tag}">
内容    → <p>...</p>
:::     → </div>
```

关键设计决策：
- **标签不渲染为 `<h4>` 标题**，而是 `title` 属性（鼠标悬停显示 tooltip）
- **赞/诗歌块**内连续行用 `<br>` 连接（`flush_para()` 函数），保持硬换行
- CSS 使用 `white-space: pre-line` + `line-height: 2.0`

## 三、核心规则

### 3.1 区块不跨节

**规则**: `::: 块必须在 `##` 或 `###` 标题之前关闭，不可跨越节边界。

[21] 韩襄遗孽...
:::

# 正确 ✓
::: 太史公曰
[20] 太史公曰：...
:::

## 赞
::: 赞
[21] 韩襄遗孽...
:::
```

### 3.2 太史公曰结构

标准模式（大多数篇目）：
```markdown

## 四、韵文检测

### 4.1 赞的特征

赞是四言韵文，典型特征：
- **句式整齐**：以四字（偶有三字或五字）为一个语义单元
- **对仗工整**：上下句结构对称
- **押韵**：偶数句末字韵脚相同

```
韩襄遗孽，始从汉中。
剖符南面，徙邑北通。
穨当归国，龙雒有功。
```

### 4.2 verse_score 评分函数

**完整实现版本**（scripts/detect_hidden_yunwen.py）：

```python
def verse_score(line):
    """
    计算一行文本的韵文得分 (0.0 - 1.0)

    返回值：
        0.95: 四字句占比 > 50% (强韵文/典型赞)
        0.80: 3-5字句占比 > 70% (中强韵文)
        0.75: 5-7字句且方差小 (五言/七言诗)
        0.70: 4-7字句占比 > 70% (诗歌可能)
        0.30: 其他情况
        0.10: 平均句长 > 10字 (明确散文)

    阈值：> 0.6 判定为韵文
    """
    clean = clean_text(line)  # 移除标注符号
    if not clean:
        return 0.0

    segments = split_by_punctuation(clean)
    if not segments:
        return 0.0

    lengths = [len(s) for s in segments]
    total = len(lengths)
    avg_length = sum(lengths) / total if total > 0 else 0

    # 统计各类型句长占比
    four_char = sum(1 for l in lengths if l == 4)
    near_four = sum(1 for l in lengths if 3 <= l <= 5)
    mid_range = sum(1 for l in lengths if 4 <= l <= 7)

    # 评分规则
    if four_char / total > 0.5:
        return 0.95  # 典型赞（四字句为主）
    if near_four / total > 0.7:
        return 0.8   # 中强韵文
    if mid_range / total > 0.7:
        return 0.7   # 诗歌可能
    if 6 <= avg_length <= 8:
        # 五言/七言诗：句长一致且方差小
        variance = sum((l - avg_length) ** 2 for l in lengths) / total
        if variance < 2.0:
            return 0.75
    if avg_length > 10:
        return 0.1   # 长句 = 散文
    return 0.3
```

**关键设计**：
1. **多维度判断**：不仅看四字句，也识别5-7字的诗歌
2. **方差检测**：五言七言诗的特征是句长整齐（方差小）
3. **阈值设计**：0.6作为分界线，兼顾精确率和召回率

### 4.3 文本清洗的重要性

**⚠️ 关键**：标注符号会严重干扰verse_score计算

**问题示例**：
```python
原文：〖@颇〗、〖@牧〗不用，〖;王迁〗囚虏。

不清洗：
  字符数 = 20字（包含符号）
  verse_score = 0.1（判定为散文）❌

清洗后：
  字符数 = 10字（颇、牧不用，王迁囚虏）
  句长 = [4, 4]
  verse_score = 0.95（判定为赞）✅
```

**clean_text() 清洗规则**：
1. 移除段落编号：`[N]`, `[N.M]`
2. 移除实体标注：`〖TYPE text〗` → `text`
3. 处理消歧语法：`〖TYPE 显示名|规范名〗` → `显示名`
4. 移除动词标注：`⟦TYPE⟧` → 内容

**实现**：详见 scripts/detect_hidden_yunwen.py 的 `clean_text()` 函数

### 4.4 verse vs prose 判断

- **整组判断**（majority vote）：组内所有行的 verse_score 平均值 > 0.6 → 韵文
- **散文陷阱**：某些古文散文也有四字节奏（如"荆王王也，由汉初定"），需整段判断而非逐句
- **滑动窗口**：使用3-20行的滑动窗口检测连续的韵文区块

## 七、关键经验

### 7.1 核心原则

1. **区块绝不跨节** — 标题是结构边界，区块必须在标题前关闭。违反此规则会导致 HTML 嵌套错误。

2. **韵文检测用整组投票** — 逐句判断会被古文散文的四字节奏误导（如"及汉兴，依日月之末光"），整组平均分更可靠。

3. **verse_score 阈值**: 0.6 是分界线 — >0.6 韵文，<0.4 散文，0.4-0.6 需人工确认。

4. **标签用 tooltip 不用标题** — `<h4>` 标签会破坏文档结构和目录层级，`title` 属性既提供信息又不干扰布局。

5. **年表不包裹** — 017/018 整章就是太史公曰，加 `:::` 包裹反而多余。

### 7.2 深度挖掘经验（2026-04-06）

6. **标注符号必须清洗** — 〖@人物〗等标注符号会使句长增加2-3倍，不清洗会导致95%以上的韵文被误判为散文。

7. **手工标题需要保护机制** — 自动提取算法会覆盖手工命名（如"垓下歌"→"项羽本纪诗"），必须建立优先级机制：手工>Markdown>自动>默认。

8. **统一标题格式很重要** — 赞用"章节名+赞"格式（如"五帝本纪赞"），诗歌/赋用历史通用名（如"泰山刻石"、"怀沙赋"），便于检索和引用。

9. **verse_score需要多维度判断** — 不仅识别四字赞，也要识别5-7字诗歌；方差检测可识别五言七言诗（句长整齐）。

10. **滑动窗口防止遗漏** — 使用3-20行的滑动窗口检测，避免因固定窗口大小而遗漏不同长度的韵文。

### 7.3 工作流经验

11. **深度挖掘能发现大量隐藏韵文** — 通过verse_score算法，发现了28篇隐藏的赞（从97篇增至125篇），提升29%。

12. **自动脚本后必须人工抽查** — 特别关注：散文伪装成韵文的章节（如051荆燕世家）、书类章节（太史公曰在开头）、有褚先生补注的章节（058/060）。

13. **格式错误需要批量修复** — 常见问题：全角冒号（`：：：赞`）、错误标记类型（`::: 太史公曰`应为`::: 赞`）、缺失标记。

14. **完整报告很重要** — 详细记录工作过程、算法设计、问题解决，便于后续参考和知识传承。详见 [docs/reports/yunwen_extraction_complete_report.md](../docs/reports/yunwen_extraction_complete_report.md)

# Purple Numbers (PN) 编号规范

## 概述

Purple Numbers (PN) 是为《史记》每个段落分配的唯一标识符，格式可以是 `[N]`、`[N.M]` 或 `[N.M.K]`，用于精确引用和链接文本。

## 基本格式

### 多级编号系统

Purple Numbers支持最多三级的层级编号：

- **一级编号**: `[N]` - 顶级section编号
- **二级编号**: `[N.M]` - section内的子section或段落编号
- **三级编号**: `[N.M.K]` - 子section内的段落编号（可选）

**二级结构示例**（简单章节）:
```
[1]           ← 顶级section的父编号
[1.1] 段落1   ← 第一段
[1.2] 段落2   ← 第二段

[2] 单段内容  ← 只有一段的section

[3]           ← 多段section的父编号
[3.1] 段落1
[3.2] 段落2
```

**三级结构示例**（复杂章节）:
```
[1]                    ← 顶级section父编号
[1.1]                  ← 子section父编号
[1.1.1] 段落1          ← 子section的第一段
[1.1.2] 段落2          ← 子section的第二段

[1]                    ← 同一顶级section（可能对应不同markdown标题）
[1.2]                  ← 另一个子section父编号
[1.2.1] 段落1          ← 另一个子section的段落

[2]                    ← 下一个顶级section
[2.1]
[2.1.1] 段落1
```

### 选择二级还是三级

根据章节的复杂度和逻辑结构选择：

**使用二级编号** `[N.M]`:
- 章节结构简单，每个markdown标题独立成section
- 不需要对段落进行二级逻辑分组
- 示例：列传、本纪等叙事性章节

**使用三级编号** `[N.M.K]`:
- 章节结构复杂，多个markdown标题需要归属同一个逻辑大section
- 需要对段落进行二级分组
- 示例：八书（礼书、历书等）、十表等结构性章节

## 编号分配规则

### 1. 顶级编号分配策略

有两种策略：

**策略A：每个标题一个顶级编号**（二级结构）
- 每个 `###` 或 `####` 标题开始一个新的顶级section
- 适用于结构简单的章节

```markdown
### 历法起源与意义          ← 分配 [1]
[1]
[1.1] 昔自在古...
[1.2] 於时冰泮...

### 改正朔的重要性          ← 分配 [2]
[2] 王者易姓受命...         ← 单段

### 黄帝建历               ← 分配 [3]
[3]
[3.1] 太史公曰...
```

**策略B：逻辑分组的顶级编号**（三级结构）
- 多个相关的 `###` 或 `####` 标题共用一个顶级section编号
- 每个标题对应一个二级section `[N.M]`
- 适用于结构复杂、有明显逻辑分组的章节

```markdown
### 历法起源与意义          ← 第一个二级section [1.1]
[1]
[1.1]
[1.1.1] 昔自在古...
[1.1.2] 於时冰泮...

### 改正朔的重要性          ← 第二个二级section [1.2]
[1]
[1.2]
[1.2.1] 王者易姓受命...

### 黄帝建历               ← 新的顶级section，第一个二级section [2.1]
[2.1]
[2.1.1] 太史公曰...
```

### 2. 单段与多段区分

#### 二级结构中

**单段section**: 只有1个段落
- 编号格式: `[N]` (内容直接跟在编号后)
- 示例: `[2] 王者易姓受命，必慎始初...`

**多段section**: 有2个或更多段落
- 编号格式: `[N]` (父编号，独立一行) + `[N.1]`, `[N.2]`, ... (子编号)
- 示例:
  ```
  [1]
  [1.1] 昔自在古...
  [1.2] 於时冰泮...
  [1.3] 物乃岁具...
  ```

#### 三级结构中

**单段子section**: 只有1个段落
- 编号格式: `[N.M.1]` (可以省略 `[N]` 和 `[N.M]` 父编号行)
- 示例: `[1.2.1] 王者易姓受命...`

**多段子section**: 有2个或更多段落
- 编号格式:
  - 必须有 `[N]` 父编号（顶级section父编号）
  - 必须有 `[N.M]` 父编号（子section父编号）
  - 然后是 `[N.M.1]`, `[N.M.2]`, ... (段落编号)
- 示例:
  ```
  [1]           ← 顶级section父编号
  [1.1]         ← 子section父编号
  [1.1.1] 昔自在古...
  [1.1.2] 於时冰泮...
  [1.1.3] 物乃岁具...
  ```

### 3. 父编号规则

#### 二级结构

对于多段section，必须有父编号 `[N]`:
- 父编号独立一行
- 紧接着第一个子编号 `[N.1]`
- 父编号和第一个子编号之间没有空行

```
[3]          ← 父编号
[3.1] 内容1  ← 第一个子编号
[3.2] 内容2
[3.3] 内容3
```

#### 三级结构

对于多段子section，必须有两级父编号 `[N]` 和 `[N.M]`:
- 顶级父编号 `[N]` 独立一行
- 子section父编号 `[N.M]` 独立一行
- 然后是段落编号 `[N.M.1]`, `[N.M.2]`, ...
- 父编号之间和父编号与第一个段落之间都没有空行

```
[1]              ← 顶级父编号
[1.1]            ← 子section父编号
[1.1.1] 内容1    ← 第一个段落
[1.1.2] 内容2
[1.1.3] 内容3

[1]              ← 同一顶级section的另一个子section
[1.2]            ← 另一个子section父编号
[1.2.1] 内容1
```

**注意**: 同一顶级section `[N]` 的不同子section会重复出现 `[N]` 父编号行。

### 4. 无内容标题不编号

如果某个标题下面没有直接的内容段落，只有下级标题，根据使用的策略：

**二级结构**: 不分配编号
```markdown
### 上古历法传统（黄帝至尧舜）  ← 无直接内容，不编号
#### 黄帝建历                    ← 有内容，分配 [3]
[3]
[3.1] 太史公曰...
```

**三级结构**: 作为逻辑分组的容器，不需要独立编号
```markdown
### 上古历法传统（黄帝至尧舜）  ← 逻辑分组，对应顶级 [2]
#### 黄帝建历                    ← 对应 [2.1]
[2.1]
[2.1.1] 太史公曰...
```

## 连续性要求

### 顶级编号连续性

顶级编号必须从 `[1]` 开始连续递增：
- ✅ `[1]`, `[2]`, `[3]`, `[4]`, ...
- ❌ `[1]`, `[2]`, `[5]`, `[7]`, ... (跳号)

### 子编号连续性

同一父编号下的子编号必须从 `[N.1]` 开始连续递增：
- ✅ `[3.1]`, `[3.2]`, `[3.3]`, ...
- ❌ `[3.1]`, `[3.3]`, `[3.5]`, ... (跳号)

## 特殊情况处理

### 1. 章节标记符号

原文中的章节标记（如 `◎历术甲子篇`）保留但不分配PN编号。

```markdown
## 历术甲子篇       ← markdown导航标题
◎历术甲子篇        ← 原文标记，不编号
### 历法术语说明    ← 下一个section开始编号
[16] 太初元年...
```

### 2. 太史公赞

太史公在篇末的韵文赞语作为独立section，通常是单段：

```markdown
## 太史公赞
::: 赞
[38] 历数之兴，其来尚矣。
重黎是司，容成斯纪。
...
```

### 3. 术语解释段

"右XXX书"格式的术语解释段作为独立section：

```markdown
## 历法术语释义
[37]
[37.1] 右历书：大馀者，日也。小馀者，月也。
[37.2] 端蒙者，年名也。
```

# SKILL 02b1: 韵文识别规则 — 自动检测、分类与标题提取

> 从《史记》130篇的韵文提取实践中提炼，适用于赞、诗歌、赋的自动识别与结构化。
>
> **前置**: 区块已用 `::: 标签` 标注完成，详见 [SKILL_02b_区块与韵文处理.md](SKILL_02b_区块与韵文处理.md)。

## 一、问题定义

《史记》中的韵文散布在130篇中，包括：

1. **赞**（110篇）— 章末的韵文评价，四字为主
2. **诗歌**（11篇）— 历史人物作品或刻石铭文
3. **赋**（5篇）— 长篇韵文，如屈原赋、司马相如赋

**核心挑战**：
- 某些章节的赞嵌入在"太史公曰"散文块中，需分离
- 诗歌和赋的标题需从上下文提取，不能用通用格式"章节名+诗/赋"
- 需要内容特征匹配来确定具体作品名称

## 二、韵文类型识别

### 2.1 赞的识别模式

#### 文本特征

**典型特征**：
- 4-6个汉字为一句（主要是4字句）
- 每句末尾带标点符号：`，。：；！？`
- 至少连续3行符合上述模式
- 对仗工整，押韵明显

**示例**：
```
韩襄遗孽，始从汉中。
剖符南面，徙邑北通。
穨当归国，龙雒有功。
```

#### 检测算法（verse_score函数）

**核心逻辑**：
1. 移除标注符号，保留纯文本内容
2. 按标点符号拆分成句子
3. 统计句子长度分布
4. 计算韵文得分（0-1）

**评分规则**：
- 4字句占比 > 50%：得分0.95（强韵文）
- 3-5字句占比 > 70%：得分0.8（中强韵文）
- 4-7字句占比 > 70%：得分0.7（诗歌可能）
- 平均句长6-8字且方差小：得分0.75（五言七言诗）
- 平均句长 > 10字：得分0.1（散文）

**阈值**：得分 > 0.6 视为韵文

### 2.2 赞与散文的边界识别

#### 典型场景

某些"太史公曰"块包含：
1. 前半部分：散文评论（长句、议论性）
2. 后半部分：赞体韵文（短句、四字为主）

**分离规则**：
1. 检测起点：在"太史公曰"块内，找到第一个连续3行符合赞特征的位置
2. 切分点：该位置前一行的末尾
3. 编号处理：分离后的赞块获得新的段落编号（`[N+1]`）
4. 人工确认：自动分离后需人工检查，确保语义完整

### 2.3 诗歌与赋的识别

**诗歌特征**：
- 句长4-7字，五言或七言为主
- 历史人物作品，出现在叙事中
- 标注方式：`::: 诗歌`

**赋特征**：
- 篇幅较长（通常100字以上）
- 有明确的作品名称
- 标注方式：`::: 赋`

## 三、标题提取规则

### 3.1 基本原则

**禁止使用通用格式**：
- ❌ 错误：秦始皇本纪诗、屈原贾生列传赋
- ✅ 正确：泰山刻石、怀沙赋

**标题来源优先级**：
1. 文中明确提到的作品名（最高优先级）
2. 历史事件名称（如"垓下歌"）
3. 地点相关名称（如"泰山刻石"）
4. 特征性内容关键词（如"大人赋"）

## 五、HTML渲染优化

### 5.1 唯一ID系统

**问题**：同一章节的多个韵文共用章节号作为锚点ID，导致链接错误

**解决方案**：为每个韵文分配唯一ID（`yunwen-0`, `yunwen-1`, ...）

```python
# 在 render_yunwen_html.py 中
for idx, item in enumerate(yunwen_data):
    item['_unique_id'] = f"yunwen-{idx}"

# TOC链接
html += f'<a href="#{unique_id}">{title}</a>'

# 内容锚点
html += f'<div id="{unique_id}">'
```

### 5.2 标题显示优先级

1. 具体标题（如"泰山刻石"） — 优先显示
2. 章节标题 + 韵文类型（如"秦始皇本纪 · 诗歌"）
3. 仅章节标题（如"秦始皇本纪"）

## 七、关键经验

1. **标题必须具体化** — "秦始皇本纪诗"不是有效标题，必须提取到"泰山刻石"这样的具体名称

2. **内容特征优先** — 当文中明确提到作品名时，优先使用；否则根据地点、事件命名

3. **检查顺序很重要** — 识别赋标题时，先检查更具体的特征（如"大人赋"），再检查通用特征（如"子虚"）

4. **唯一ID解决重复锚点** — 同一章节的多个韵文不能共用锚点ID，必须用序号区分

5. **散文/韵文边界需人工确认** — 自动分离算法可能误判，特别是古文散文中出现四字节奏时

6. **verse_score阈值**：0.6是韵文/散文分界线，>0.9为强韵文（主要是4字赞）

7. **深度挖掘发现隐藏赞** — 2026-04-06通过verse_score算法在33篇"无赞"章节中发现了17篇隐藏的赞，将赞总数从97篇提升到110篇

## 一、类型定义

| 类型 | 典型示例 | 关键触发短语 |
|------|----------|--------------|
| **诏令** | 文帝遗诏（010）、武帝封禅诏（028）、景帝制诏将军（106） | "诏曰"、"制诏御史"、"手诏曰"、"制曰" |
| **奏疏** | 李斯谏逐客书（087，功能上为上书）、主父偃上书（112）、徐乐严安上书（112） | "上书曰"、"乃上疏曰"、"奏曰"、"上言曰" |
| **书信** | 冒顿与文帝国书（110）、吴王濞遗诸侯书（106）、乐毅报燕王书（080） | "遗X书曰"、"报X书"、"与X书" |
| **檄文** | 司马相如谕巴蜀檄（117）、酷吏檄告（122） | "移檄"、"为檄告"、"谕X曰" |
| **策论** | 广武君献策（092）、张良八难（055）、孙武练兵对（065） | "对曰"+长引文、"献策曰" |

### 与其他索引的边界

- **论赞（太史公曰）** → 已由 `SKILL_02b1` 韵文集处理；散文集**不重复收录**
- **赋/诗歌/韵文赞** → 韵文集专属
- **短对话 / 说辞** → 阈值 `MIN_CHARS=120`（纯文本去标注后字数），低于不收
- **议论 vs 策论**：策论是臣对君的建议；议论是作者脱离情节的思辨（如过秦论）

## 二、工作流（三步）

```
chapter_md/*.tagged.md
    ↓ scripts/scan_sanwen_candidates.py
labs/planning/sanwen_candidates.{json,tsv,md}   ← 人工审阅
    ↓ scripts/build_sanwen_manifest.py（+ 手工补充）
data/sanwen_manifest.json
    ↓ scripts/extract_sanwen.py
data/sanwen.json + data/sanwen.md
    ↓ scripts/render_sanwen_html.py
docs/special/sanwen.{html,pdf,json,md}
```

### 2.1 扫描（自动）

`scan_sanwen_candidates.py`：
- 两条路径：**触发短语**（如"乃上书曰"）+ **H2 标题**（如 `## 谏逐客书`）
- 跳过 `::: 太史公曰` 等 fenced block 内的匹配
- 长度阈值 `MIN_CHARS=120`，去重策略：重叠区间只保留第一个
- 输出 TSV 供表格工具审阅

### 2.2 策划 manifest（半自动）

`build_sanwen_manifest.py`：
- 自动采纳：诏令、奏疏、书信、檄文（质量稳定）
- 过滤规则：策论只保留 `>=400 字` 且 H2 标题非通名
- `MANUAL_ENTRIES` 手工补充扫描器遗漏或切分不准的名篇（如过秦论三部）
- `DROP` 白名单剔除误判

**过秦论特别说明**：位于 fenced `:::太史公曰` 块后接多个 `## 贾谊过秦论X` 小节，跨 23 个段落（[117]-[139.4]）。扫描器难以自动识别整体边界，必须手工写入 manifest。褚先生在 048 章的引用版本独立成条。

### 2.3 抽取（自动）

`extract_sanwen.py`：
- 按 `chapter_num + start_para..end_para` 段落区间抽取
- 支持子段号（如 `17.99` 作为"覆盖所有 [17.x]"的上界）
- 段号比较：`"17" < "17.1" < "17.99"`，使用 tuple 顺序

## 三、段落边界规则

### 3.1 起点

- 优先用 `##` / `###` H2/H3 段落标题的紧接下一个 `[N]` 段
- 次选：触发短语所在段（如"乃上书曰"所在段）

### 3.2 终点

- 优先用下一个 `##` H2 小标题前的最后一段
- 次选：原文中的"书奏"、"上览之曰"、"上善之"等收束标志
- 诏令：常在"其议之"、"布告天下"收尾

### 3.3 跨段子段号

《史记》tagged 文件中常见 `[117]`、`[117.1]`、`[117.2]` … 结构。抽取时：
- `start=117, end=117.99` → 抽 `[117]` 及全部 `[117.x]`
- `start=117, end=124.2` → 从 `[117]` 到 `[124.2]` 之间所有子段号
````
