# SKILL 07c: 反常推理 — 不符合常识的事实检测与解读

> 识别"反常事实"：单条记载本身没有矛盾，但违反常识、违反制度规则、或在当时语境下极为罕见。定位：异常检测器，输出研究线索清单。vs SKILL_07 矛盾检测（两处记载互相打架）；vs SKILL_07e 真实性推理（本件只做**异常识别+初步分类**，07e 做**深度可信度评估+真伪判断**）。工作流：07c → 输出异常清单 → 07e → 输出可信度评级。

**一、反常类型清单（4 大类 16 子型）**：
- **数字反常**：兵力异常（单支军队超过 50 万，或双方兵力差距 >10:1——长平之战赵军四十余万降卒）；年龄异常（记载行为时年龄超出生理极限或常规——廉颇八十余岁仍欲为将）；时间异常（事件发展速度违反地理/行军常识——数日内跨越千里）；财富异常（赏赐/财富数量超出国家财政常规——陶朱公三致千金）。
- **行为反常**：身份越轨（庶民/女性/奴隶做了通常只有贵族/男性/自由人才能做的事——吕后临朝称制）；亲情反常（父杀子、子弑父、手足相残且无明显动机——晋献公杀申生）；忠奸反转（正面评价的人物做反道德的事，或反之）；动机缺失（重大行为找不到合理动机，或现有解释自相矛盾）。
- **制度反常**：礼制违反（违反当时已知周礼/汉制明文——诸侯僭用天子礼乐）；继承异常（世系/王位继承跳过嫡长子制等通常规则且无记载原因）；封赏异常（封号/爵位/赏赐规格与功绩明显不相称）；刑罚异常（同类罪行处置轻重悬殊）。
- **叙事反常**：沉默异常（重要人物/事件在相关章节完全缺席——秦始皇无皇后记载）；详略失衡（次要事件大书特书，重要事件一笔带过）；评价矛盾（太史公曰与正文叙事态度相反）；时序倒置（叙述顺序与事件时序明显不符且无明显原因）。

**二、检测流程**：结构化数据+常识库规则扫描（数字阈值/制度违反/关系缺失）→ 候选反常清单 → LLM 评估（真反常？有无常见解释？研究价值高/中/低）→ 输出 anomaly_report.json（type/subtype/confidence/possible_explanations/research_value/follow_up）。常识库支撑：数字/制度/社会/军事等 10 大类常识。规则检测示例：军队规模>阈值；人物年龄>80 且仍有军事行动；嫡长子未继位且无废嫡记载；重要人物（出现频次>N）无死亡事件。

**三、§七 常识推断方法（Meta-Skill：反思迭代）——六轮常识提取流程（逐步完整保留）**：
```
【第1轮：案例收集】输入:已完成的反常检测案例(如长平之战、廉颇老矣) → 提问:"这些案例违反了什么共同的规律?" → 输出:候选常识条目列表
【第2轮：普适性检验】提问:"这条规律是否适用于多个案例?" "是否有明确的时代边界?" "是否可量化/可验证?"
  反思: ✅ 若适用于3+案例 → 保留；✅ 若有时代标注 → 保留；✅ 若可量化 → 保留
        ❌ 若仅适用单一案例 → 丢弃；❌ 若无法验证 → 标记为"推测性"
  输出: 精炼后的常识条目
【第3轮：来源标注】提问:"数据来源是什么?" "置信度如何评估?" → 标注来源(出土文献/传世典籍/学界共识/统计归纳)+置信度(高/中/低) → 输出:规范化常识条目
【第4轮：规则化编码】提问:"如何转化为可自动检测的规则?" → 数字类常识→阈值规则(如"单支军队>50万→异常")；制度类常识→违规规则(如"嫡长子未继位 且 无废嫡记载→异常")；关系类常识→缺失规则(如"君主 无 配偶关系→异常") → 输出:可执行的检测规则
【第5轮：实战验证】在全部130篇《史记》批量扫描 → 提问:"产生多少候选异常?" "假阳性率是多少?" "是否需调整阈值?"
  反思: ✅ 若假阳性<20% → 规则有效,录入常识库；⚠️ 若假阳性20-50% → 调整阈值,重新验证；❌ 若假阳性>50% → 规则失效,重新设计
【第6轮：持续更新】输入:新的研究成果、考古发现、案例分析 → 提问:"现有常识是否需要修正?" "是否有新的常识需要补充?" → 定期审核(季度/年度) → 输出:更新后的常识库版本
```

**实例演示（从案例到常识）**：案例1 长平之战→兵力规模常识：第 2 轮检验巨鹿/垓下/井陉等战役，归纳"**单支军队常规规模 5-20 万，超过 30 万为异常大军**"（✅ 适用于多个案例；时代边界先秦至汉）；第 4 轮编码 `if 军队规模>300000 → 兵力异常`；第 5 轮扫描 130 篇发现 5 处候选、假阳性 1 处（20%）→ 规则有效，录入 [1.1 人口与兵力规模]。案例2 廉颇老矣→老将年龄常识：归纳"**将领出征年龄通常 <65 岁，超过 70 岁仍征战为罕见**"（✅ 适用于多个案例；例外：赵充国、廉颇——但被视为异常）；第 5 轮 3 处候选、假阳性 0 → 录入 [1.2 年龄与时间跨度]。

**反思提示词模板（九问）**：普适性检验（Q1 违反什么共同规律 / Q2 是否适用其他案例，列举 2-3 个验证案例 / Q3 时代边界先秦/秦/汉/通用 / Q4 是否可量化）；来源标注（Q5 数据来源六选：出土文献/传世典籍/考古实证/学界共识/统计归纳/推测性 + Q6 置信度高/中/低）；规则化编码（Q7 IF [条件] THEN [标记为异常]，如 IF 军队规模>30 万 THEN"兵力异常"）；假阳性检验（Q8 是否产生过多假阳性 / Q9 是否需添加例外条件）。

# SKILL 07e: 真实性推理 — 可信度评估与真伪判断

> 在史源溯源（07d）基础上，多维度推理评估记载可信度与真实性。07c=异常检测器（"这很奇怪"，批量扫描），07e=深度分析器（"这是真是假？"，输出可信度评级，也可独立使用）。

**一、A-E 五级评分（定义完整保留）**：

| 等级 | 定义 | 史源+真实性 | 典型特征 |
|------|------|-----------|---------|
| **A** | 高度可信 | 明确档案+多源验证+逻辑自洽 | 官方档案、亲历者口述、无矛盾 |
| **B** | 较为可信 | 家传口述+时间近+逻辑合理 | 传承链清晰、符合常理、核心事实可信 |
| **C** | 存疑 | 时间远或细节可疑+部分逻辑通 | 核心事实可能可信，细节存疑 |
| **D** | 低可信度 | 来源不明+逻辑矛盾+动机可疑 | 违背常理、受益者存疑、可能是谣言 |
| **E** | 几乎肯定伪史 | 科学/法律/医学鉴定不通 | 明显违背客观规律、政治宣传 |

**二、分层评估原则（完整保留）**：同一事件的不同层面可信度可能不同。鸿门宴：核心事实（鸿门宴发生）**A 级** / 基本经过（樊哙闯帐）**B 级** / 具体对话细节 **C-D 级**。评估维度：核心事实（事件是否发生）/ 基本经过（主要人物行动）/ 具体细节（对话、神态、心理描写）。

**三、七大推理方法（模板清单）**：
1. **医学/科学鉴定法**：应用医学科学常识验证是否符合客观规律（生理常识：怀孕周期、生育年龄；时间常识：距离与速度；数量常识：人口容量、军队规模）。案例：秦始皇身世——"大期"=十个月足月怀孕，若吕不韦献姬时已孕 2 月应 8 月生产（早产），"大期时生"说明足月、从子楚娶姬算起正好十个月 → 医学证据支持嬴政是子楚之子。可机器化 ★★★★☆。
2. **法律/制度鉴定法**：检验是否符合法定程序（法律程序/违法成本/制度约束）。案例：献有孕之姬的合法性——血统纯正性 ❌ 违背宗法；继承程序 ❌ 无法通过"刻玉符"严格登记；违法后果 ❌ 废除继承权、杀身之祸；商人理性 ❌ 不符合吕不韦投资逻辑 → 可信度 D-E 级（几乎肯定是谣言）。可机器化 ★★★★★。
3. **动机分析法**：分析利益诉求，找"谁是受益者"（趋利避害）。假设 A（传说为真）：吕不韦泄露真相自毁前程 ❌、子楚颜面尽失 ❌、嬴政正统性受损 ❌；假设 B（假消息）：吕不韦巩固地位 ✅、反秦势力质疑正统性 ✅、司马迁展示权力黑幕 ✅ → 假设 B 更符合各方利益，D 级（政治谣言）。★★★☆☆。
4. **逻辑自洽性检验**：时间/因果/人物行为/叙事四维逻辑（与 07c 区别：07c 关注违反常识的单条记载，07e 关注记载内部逻辑一致性）。案例：怀孕 10 个月无法隐瞒 vs "姬自匿有身"；足月 vs 早产矛盾（两种对立解释无法确定）；秦国官方始终沉默——沉默本身可能说明是谣言。★★★☆☆。
5. **沉默证据法**：应有而未有的记载本身就是证据。沉默三型：偶然失载/刻意隐瞒/本来就不存在。案例：若"献有孕之姬"为真，应有秦国官方承认或澄清、子楚反应、嬴政回应、吕不韦被诛时的此项罪名、宗室质疑——✗ 全部缺失 → D 级。★★☆☆☆。
6. **排除法**：嫌疑对象有限时逐一排除。秦始皇生父之谜：医学鉴定 ✅"大期时生"符合 vs ❌"大期"矛盾；法律 ✅ vs ❌ 违背继承法；动机 ✅ vs ❌ 违背利益；沉默证据 ✅ vs ❌ 关键证据缺失；官方记载 ✅"庄襄王子也" vs ❌ 秦国从未承认 → 排除"吕不韦之子"，"子楚之子"最可能，但承认不确定性：真相不可知。★★★★☆。
7. **临场体验法**：设身处地用人性常理判断（空间/时间/心理/社会体验；依赖共情，难机器化）。案例：扶苏为何不验证诏书真伪——仁孝谨慎性格、秦朝君父权威、赵高限时紧迫感、边疆信息不对称 → 从人性角度可能，但仍存在记载失真可能，需结合其他证据。★☆☆☆☆。

**四、综合评估流程**：07d 史源溯源（史源类型/传播链/传播层级）→ 第一层客观规律检验（医学/法律）→ 第二层人性逻辑检验（动机/自洽/沉默/临场）→ 第三层综合判断（排除法）→ 最终输出：可信度评级（A/B/C/D/E）+ 分层评估（核心事实 vs 细节）+ 多种解释（承认不确定性）。

**五、评级决策矩阵**：A=✅ 史源档案文献或亲历者口述+传播链 2 层以内+科学/法律检验通过+动机分析合理+无明显矛盾；B=✅ 家传口述+2-3 层+核心事实逻辑自洽，⚠️ 细节可能有文学加工；C=⚠️ 二手传闻+3-5 层+部分逻辑通部分存疑；D=❌ 来源不明+逻辑矛盾+动机可疑+可能是谣言或政治宣传；E=❌ 医学/科学/法律鉴定明确不通+明显违背客观规律+政治宣传或神话色彩。

**六、典型案例**：荆轲刺秦=亲历者口述（夏无且，传播链 2 层）→ **A 级**（《史记》中史源最明确、最可信的案例之一）；秦始皇身世=二手传闻/政治谣言（3-5 层多源混杂）→ **D-E 级**，立场：存疑但"子楚之子"（解释 A）更合理；沙丘之谋=知情者泄密（3-4 层）→ 核心事实 B 级、基本阴谋 B-C 级、具体对话 C-D 级。

**七、可自动化程度**：法律鉴定 90% 最高；医学 75%、排除法 70%；逻辑自洽 65%、综合评级 65%、动机 60%；沉默证据 50%、临场体验 30% 最低。最佳流程：机器初判+人工精炼。方法论来源：李开元《秦谜》系列+钱大昕/王国维等传统辨伪学。

# 元技能10: 质量控制 — 自动化质检体系与工具链设计

> 质量控制（QC）= 用自动化脚本在数据生成/修正的每个环节做格式/逻辑/一致性检查，及早发现错误。QC 是反思（Reflection）的前置环节。**QC vs 反思**：规则脚本自动化（lint/validate，秒级执行、无 LLM 成本、100% 可解释、输出 PASS/FAIL+错误位置+修复建议） vs Agent 智能审查（分钟级、有 LLM 成本、部分可解释、输出修正建议+新错误模式）。协同关系：①QC 先行——每次修正后先跑 lint，格式错误必须 100% 消除才能进反思；②反思发现的**可规则化错误模式**沉淀为新的 QC 规则；③QC 验证反思成果（修正应用后再跑 lint）。

**一、质量控制的五个层次（L1-L5 职责完整保留）**：
```
L5 跨工序一致性（Cross-Phase Consistency）
   ├─ 实体索引 ↔ 标注文本一致性
   ├─ 事件年代 ↔ 年表数据一致性
   └─ 关系三元组 ↔ 实体存在性验证
L4 业务逻辑验证（Business Logic Validation）
   ├─ 时序合理性（后序事件不应早于前序）
   ├─ 年份区间合理性（生年≤卒年）
   └─ 引用完整性（人物ID必须存在于实体库）
L3 数据完整性（Data Integrity）
   ├─ 必填字段非空
   ├─ 字段值域约束（如年份范围 -3000~2000）
   └─ 枚举值合法性（如事件类型必须在11种之内）
L2 语法正确性（Syntax Correctness）
   ├─ 标注边界完整（〖〗成对闭合）
   ├─ JSON/Markdown格式合法
   └─ 正则表达式匹配（如段落编号格式）
L1 文本完整性（Text Integrity）
   ├─ 编码正确性（UTF-8无乱码）
   ├─ 原文不变性（去标记后与原文逐字相同）
   └─ 文件存在性（必需文件齐全）
```
**检查优先级原则**：从 L1 到 L5 **逐层执行**，低层级未通过时不执行高层级检查（避免噪音）。

**二、工具设计规范**：命名——`lint_*.py`（单一工序内格式/语法）、`validate_*.py`（数据完整性和业务逻辑）、`cross_validate_*.py`（跨工序一致性）。输出：✅ PASS→返回码 0；❌ FAIL→返回码 1+错误详情（文件/行号/位置/建议）。错误分级：ERROR（❌ 必须修复，否则数据不可用，阻断发布=是）/ WARNING（⚠️ 应该修复，不影响基本功能，=否）/ INFO（ℹ️ 信息性提示，=否）。工具实例：`lint_markdown.py`（L1-L2：〖〗成对闭合/不允许嵌套/空标注/段落编号连续不跳跃不回退）；`lint_ce_years.py`（L3-L4：年份格式合法/范围 -3000~100 外警告/时序倒退超 3 年容差报错/年份跳跃 >100 年警告/已知年份交叉验证——孔子出生 -551、秦始皇统一 -221、项羽自刎 -202，偏差 >2 报错）；`validate_tagging.py`（L1 原文不变性：去标记后与原文逐字比对，找首个差异位置）。

**三、为新工序设计 QC 工具（四阶段清单）**：Phase 1 定义质量标准（输入输出格式/必填字段/值域约束/业务规则/跨工序依赖）→ Phase 2 按 L1-L5 五层逐层设计检查项 → Phase 3 实现工具（分层检查函数+✅/❌/⚠️ 输出+exit code）→ Phase 4 集成到工作流（Makefile 一键执行/Git hooks 提交前检查/CI-CD 每次 push 触发/写入 SKILL 文档验证步骤）。

**四、常见陷阱（每条含正误例）**：
1. **过度检查**——❌"这个人名看起来不太对"（太主观，留给反思）；✅"人名标注包含标点符号"（明确违反格式规则）。
2. **检查不独立**——❌ `lint_B.py` 依赖 `lint_A.py` 生成的中间文件；✅ 直接读取源数据文件。
3. **输出不友好**——❌"检查失败"；✅"第42行：未闭合的人名标注，建议补全〗符号"。
4. **没有容差**——❌ 年份相差 1 年就报错；✅ 年份相差 >3 年才报错（古代纪年本身有歧义）。
5. **忽略边界情况**——空文件应报 warning 而非 crash；数据为空数组应报 info；年份为 0 要注意公元 1 年前后没有公元 0 年。

**五、最佳实践与质量指标**：设计原则五条——快速失败（Fail Fast，低层错误立即阻断）/ 清晰反馈（位置+原因+建议修复）/ 分级输出（ERROR 必须修复、WARNING 建议修复、INFO 仅提示）/ 批量模式（--all）/ CI-CD 友好（exit code 0=PASS, 1=FAIL）。核心指标：Lint 通过率 100%；错误密度 <0.1%（错误数/总字符数）；警告清零率 >80%；跨工序一致性 >95%。总结：L1-L2（格式层）拦截 80% 低级错误、L3-L4（逻辑层）拦截 15% 中级错误、L5（一致性层）拦截 5% 高级错误；核心洞察：**质量控制≠反思**（规则驱动 vs 语义驱动）、自动化优先（能用规则检测的不要用 LLM）、分层递进、持续监控。
