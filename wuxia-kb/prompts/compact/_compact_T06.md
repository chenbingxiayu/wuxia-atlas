**任务：武侠关系类型学总设计（产出 = 武侠关系体系设计文档）**

**Q1 事件关系**（event↔event）：
- 史记 9 类型中 8 个直迁确认：sequel（先后）/causal（因果）/cross_causal（跨事件因果）/part_of（部分）/opposition（对立）/cross_ref（互参）/co_person（同人物）/co_location（同地点）——每个给武侠定义、识别信号、1 组正误例；
- **concurrent 重定义**为"书内时序对齐"：两事件在叙事线内时间对齐（同刻/同段），格式对接任务 #5 时点键（r{N} 回锚+相对刻度）；
- **新增三类**：①传承关系（武功/称号/门派的传承源——跨事件的"this 继承自 that"，对接武功页传人链）；②伏笔-回收（武侠特有叙事结构：前文埋设→后文揭示，给识别信号与置信处理——回收端证据强、埋设端常需推导）；③跨书设定引用（人物/设定跨书呼应，对接任务 #7，本任务只留谓词与字段）。

**Q2 实体关系**（entity↔entity）：
- 地点关系：练功地/山门/决战地/辖属（谓词建议+识别信号）；
- **武功层级关系（武侠本体核心）**：招式∈武功∈心法三层归属——层级判定信号（01g §9.3 技术层级已列：技术体系/功法/子式/变式/组合技/阵法）、与"降龙十八掌第十三式"式命名的对齐（01g 已定子式整体标注、父子层级登记层表达——你定登记层的层级边谓词）；
- **兵器-持有链**：对接神兵表 chain 模式（实测结构见 3.6：chain=[{verb,persons,book,loc,conf}]）——持有链=⊟物件变化事件流的序列化视图；定版 chain 的事件回链格式与"同名神兵归并需传递链证据"（01g 已定）的衔接；
- 异名关系：绰号↔本名——直接变成映射数据（对接别名表 surface/canonical），本任务定版"异名"作为关系边的字段（什么情况下是关系边、什么情况下只是别名表行）。

**Q3 人物关系**（重点，person↔person）：
- 类型学重写：**师承**（拜师/逐出/叛门/自立门户 子型）、**结义**（八拜结义/反目）、**情缘**（夫妻/恋人/单恋/情敌）、**仇怨**（灭门/夺爱/夺秘籍——须关联因果事件）、**同门**（同师/同辈分——推导关系）；
- 每类给五项验证属性：**方向性**（单向/双向）/ **对称性**（A 师承 B ⇔ B 是 A 的徒弟？）/ **可传递性**（师承可传递→辈分；结义不可）/ **互斥性**（同一时段只能有一个正式师门？）/ **时序约束**（叛门在拜师之后）——并给每项的反例演示验证如何拦截错误边；
- 辈分推导（师祖/师叔伯/同门师兄妹）规则表——与 Q4 双树衔接。

**Q4 双树设计**（G7 硬缺口）：
- L2 关系层拆"**血缘树+师承树**"两棵树：血缘树（亲属/婚姻/收养）+师承树（师承/逐出/叛门）；
- **证明同构可行**：血缘树已验证的传递推理/无环检测/辈分推导机制映射到师承树（父子↔师徒、兄弟↔同门、祖先↔师祖）——给同构映射表；
- **推导规则表**：师祖（师父的师父）、师叔伯（师父的师兄弟）、同门（同师父或同师门辈分）、辈分序（谁辈分高）——每条规则给推导示例与边界（"同师门不同师父算同门吗"由你裁决）；
- 双树交叉点裁决：父子同为师徒（家传武功）、夫妻同门、血缘辈分与师承辈分冲突时显示哪棵树。

**Q5 情义层承载决策**：
- **最终裁决：内联标注 vs 离线关系表**（doc 02 已倾向离线：救/叛/赠/辱/爱/恨 不进内联不进 lint——你给最终建议与完整理由）；

- **四类子类型学定版**：情感（爱慕/暗恋/单恋/情侣/被拒/悔）、恩义（救命之恩/赠宝之恩/知遇/收留/欠债）、背叛（叛门/叛友/出卖/反目）、主仆依附——每子型：定义/识别信号/自动推导度（01g 已定"情感与恩义类自动推导度低：语式正则初解只作候选，须人工裁定；对话贬称不得作为生成依据"）；
- 与 04f 联动表的边界：哪些 04f 候选直接进离线表（救→恩义候选），哪些进正式人物关系（杀伤→敌对？由你裁决并给理由）。

**3.1 上游契约摘要**

**01g §9.2（不可减基线）**：关系最低集合九组（师承与正式拜师/传授与修习/亲属婚姻收养/结义结盟敌对/组织成员任职继任退出/群组成员/杀伤救治拘押解救/持有制造夺取赠借/到达离开所在同行）+ 情感/恩义/背叛/主仆四类（登记层离线，direction/states/manner/conf 草案）。关系约束：正式师承与单次传授分开；一次交手不自动永久敌对；一次救助不自动长期友盟；情感恩义类自动推导度低（语式正则初解只作候选须人工裁定，考订 TSV 稳定键机制；对话贬称不得作为生成依据）；关系有时间/视角/证据状态；不从共同出现推断亲属同门阵营。示例已定：情感 states 时序"相识→定情→误会→决裂→相望，direction=mutual,conf=ok，各态附定位符"；对话贬称（"妖女"）不得登记为情感或敌对永久别名。

**04f 联动表（候选来源，已定版 27 行）**：与人物关系直接相关的谓词——师承(徒,师)、结义(人物组)、配偶(甲,乙)、任职(人物,职衔[,组织])、隶属终止(人物,组织)、死亡(死者)/杀害(凶手,死者)、治愈(医者,伤者)、投毒(施者,被害人)、转移(赠者,受者,物)/转移(夺者,失者,物)、押送(押者,被押者,讫地)、交手(A,B[,战斗ID])、点穴(施者,受者,穴道)、掌握(人物,武功)、传授(师,徒,武功)；强度两档（强制/建议），候选须语义角色核验。**04f 明确移交**：正式师承与单次传授分开、传授不自动建立拜师关系、情感/恩义/背叛/主仆不设行内符号不进联动。

# SKILL 05a: 事件关系发现 — 从孤立事件到关系网络

> 基于《史记》130篇3,185个事件、7,652条关系的实践提炼；整合全项目关系发现规则的唯一权威文档。（本版为方法论忠实缩写：类型体系、因果四步检查、跨章因果、合并去重规则不减。）

## 一、关系类型体系（9 类，完整保留）

| 类型 | 方向 | 来源 | 数量 | 定义 |
|------|------|------|------|------|
| sequel | A→B | LLM | 1,623 | B是A的直接后续发展 |
| causal | A→B | LLM | 407 | A是B的直接原因（章内，A不发生则B不发生） |
| cross_causal | A→B | LLM | 352 | 跨章因果：含direct_cause/prerequisite/background/trigger/precedent五种子类型 |
| part_of | 子→父 | LLM | 107 | A是B的子事件/组成环节 |
| opposition | A↔B | LLM | 50 | 对立双方的行动 |
| cross_ref | A↔B | 自动 | 294 | 不同章节记述同一事件 |
| co_person | A↔B | 自动 | 969 | 跨章事件共享>=2个人物 |
| co_location | A↔B | 自动 | 705 | 跨章事件共享地点+>=1人物 |
| concurrent | A↔B | 自动 | 230 | 同一公元年+共享>=1人物 |

**识别信号（每类一句）**：
- sequel：只针对直接后续，不跳跃（❌ 陈胜起义→垓下之战，跳跃太远）。
- causal：严格因果"A不发生则B不发生"（✅ 商鞅变法→秦国强大）。
- cross_causal：跨章且分5种子类型（见三）。
- part_of：A是B的一个环节且粒度同量级（✅ 四面楚歌 part_of 垓下之围；❌ 长平之战 part_of 秦灭六国，粒度差太大）。
- opposition：双方行动都有明确记述（✅ 荥阳相持↔项羽拔荥阳；❌ 秦攻赵↔赵抵抗，赵方无具体记述）。
- cross_ref：名称相似度>=0.6+共享人物；置信分级=名称完全相同(1.0)+共享2+人物 > 近似(0.6-0.9)+共享1人物（✅ 长平之战 005-135↔043-025，相似度1.0，共享白起）。
- co_person：人物匹配须经别名合并（刘邦=沛公=高祖）。
- co_location：纯地点相同但无共人的不算；高频地名（出现>100）需更严格共人条件。
- concurrent：同年+跨章+共享>=1人物。

**核心分工原则**：章内语义关系用LLM，跨章结构关系用自动算法，跨章因果关系用LLM二次推理（以自动关系候选对为输入）。自动产出5,126条；LLM产出2,188条章内关系+352条跨章因果。

**LLM四关系判断问题**：sequel"B是A的直接后续吗"；causal"A不发生，B还会发生吗"；part_of"A是B的一个环节吗"；opposition"双方行动都有明确记述吗"。

**causal vs sequel 边界**：斩宋义→项羽拜上将军=causal；垓下之战→项羽乌江自刎=causal；鸿门宴→刘邦汉中称王=sequel（项羽分封才是充分原因）；陈胜起义→垓下之战=不建立。

## 二、章内 causal 四步检查（完整保留）

```
① 时序检查：A 是否早于 B？（必要条件，时序颠倒直接否定）
② 充分性检查：A 不发生，B 是否仍然可能发生？
   - 若 B 有其他独立路径 → 降级为 sequel（时序关联）
   - 若 B 完全依赖 A → 确认 causal
③ 直接性检查：A 到 B 之间是否有跳跃的中间事件？
   - 若中间有 3+ 个独立事件 → 降级为 sequel 链（分多段记录）
   - 若直接相连或仅有一步过渡 → 确认 causal
④ 章内限定：跨章因果不用 causal，改用 cross_causal（见 三）
```

## 三、跨章因果推理（cross_causal，LLM二次推理）

| 类型 | 定义 | 典型案例 |
|------|------|---------|
| direct_cause | A直接导致B发生（充分条件） | 田光荐荆轲自刎→荆轲刺秦王（conf 0.95） |
| prerequisite | A是B得以发生的必要前提 | 萧何荐曹参→曹参入相（conf 0.95） |
| background | A构成B的历史背景条件 | 吕氏封侯擅权→诸吕之乱平定（conf 0.80） |
| trigger | A成为B的导火索（时间紧密相连） | 韩信袭齐→郦生被烹（conf 0.90） |
| precedent | A为B提供历史先例或模板 | 孔子作春秋→左丘明作左氏春秋（conf 0.85） |

候选对筛选：从cross_ref/co_person/co_location取跨章对；cross_ref双向取时序较早者为source；同年co_person不做因果推断；时序颠倒判no_causal。
判断原则：①cross_ref≠因果（同一事件跨章重复记载，相似度再高也no_causal）；②时序颠倒判no_causal；③空描述判no_causal；④同年共人的平行独立行动判no_causal而非background；⑤并行多链因果分别记录（同一后果可同时有direct_cause与background）。
实测规模：候选1,490→分析1,457→确认因果352（24.2%），高置信度(≥0.8)177，涉及102/130章。

## 四、关系合并与去重（完整保留）

1. 按(source, target)去重；2. 同一对存在多种关系类型时全部保留（如A→B既是sequel又是causal）；3. 同一对同一类型重复时优先保留LLM结果（有reason字段）；4. cross_ref保留相似度最高的记录。

## 五、其余要点（压缩）

- 质量验证：cross_ref两端公元年差<=3年；causal的source早于target；sequel两端无遗漏中间事件；高频人物跨章事件按时间有序。
- 十表（批量事件）发现率低：表事件名批次性、人物标注稀疏→用年代精确匹配+关键词（封侯/国除/反）+跨表同事件补充；制度因果链时间跨度可到50年。
- 经验：事件链比孤立事件更有价值（提取时LLM同时输出2-5条因果链，直接成为sequel/causal初始数据）；体裁决定粒度；保留实体标记（共人/共地直接从标记提取）；先提取后标注后关联，逆序返工。

# SKILL 05c: 人物关系构建 — 从共现到家谱的多层次人物关系网络

## 一、三层关系体系（完整保留）

人物关系构建采用**从弱到强、从浅到深**的三层递进架构：

```
Layer 1: 共现关系（弱关联）
  ↓ 提供候选关系对
Layer 2: 家族关系（强关联，可推理）
  ↓ 传递推理扩展
Layer 3: 政治社会关系（强关联，需上下文）
```

| 层次 | 子任务 | 输入 | 输出 | 方法 |
|------|-------|------|------|------|
| **L1: 共现** | 05c1 人物共现关系 | `*.tagged.md` | `person_cooccurrence.json` | 滑动窗口+PMI |
| **L2: 家族** | 05c2 家族关系推理 | 共现+关键词 | `family_relations.json`, 帝王家谱 | 规则+传递推理 |
| **L3: 政治社会** | 05c3 政治社会关系 | 共现+上下文 | `political_relations.json`, `social_relations.json` | 规则+LLM |

## 二、关系类型体系与规模（压缩）

- 家庭关系（01-06）：父子/母子/兄弟/夫妻/祖孙/叔侄（✅ 黄帝→玄嚣 父子、黄帝↔嫘祖 夫妻）。

- 社会关系（21-31）：师徒/友人/敌对（✅ 孔子↔颜回 师徒；❌ 一人有两个生父——"单一父母"规则拦截）。

## 三、关系验证规则（完整保留）

### 3.1 共现关系质量控制

### 3.2 家族关系质量控制

| 验证规则 | 说明 |
|---------|------|
| 无环检测 | 家族树不应有循环（A→B→C→A） |

| 单一父母 | 每人最多一父一母（不能有两个生父） |
| 兄弟对称性 | A是B的兄弟 → B是A的兄弟 |

## 三、实体层面融合（L2）· 多数投票与人工覆盖

四层启发式消歧（层1前置邦国标记→层2邻近邦国提及→层3章节主题邦国→层4共现全名查找）结果综合：
- **多数投票**：全部一致（count == len(candidates)）→ 采纳，高置信度；≥2/3 多数（count >= len(candidates) * 0.67）→ 采纳，中等置信度；票数分裂 → 人工审查。
- **人工覆盖**：MANUAL_CORRECTIONS 表优先级最高，格式 (章节, 短名) → 规范名，如 ('004','元王'):'周元王'（覆盖nearby_state=楚的误判）。

## 四、事件层面融合（L3）

### 4.1 跨章事件对齐（cross_ref）

同一事件的多章记述（005"秦赵长平之战"/015"长平之役"/043"赵括代廉颇,秦将白起坑降卒"）→ 识别为同一事件，建立 cross_ref。
多因子匹配判据（需同时满足多个条件）：①名称相似度≥阈值（|shared_chars|/min(|a|,|b|)，先做异体字归一化+去标注）②共享人物≥N个 ③年份接近（如有CE标注）。
置信度：name_sim>=0.8 且共享>=1人物 → conf 0.95；name_sim>=0.6 且共享>=2人物 且年差<=5 → conf 0.85；否则跳过。

## 六、冲突解决策略

### 6.1 冲突类型分类

| 类型 | 示例 | 来源 |
|------|------|------|
| **年份冲突** | 事件A在章节X标注为-260,在章节Y标注为-259 | 跨章记述差异 |
| **伤亡数冲突** | 同一战争,来源A说40万,来源B说45万 | 史料记载不一 |
| **身份冲突** | "武王"在不同章节指不同人 | 短名歧义 |
| **关系冲突** | 两个事件,来源A说有因果,来源B说无关 | 推理差异 |
| **时序冲突** | 事件A的year < 事件B的year,但描述说B在A之前 | 标注错误 |

### 6.2 解决策略矩阵

| 冲突类型 | 策略 | 实施 |
|---------|------|------|
| **年份冲突(小)** | 取众数(majority voting) | `Counter(years).most_common(1)[0]` |
| **年份冲突(大)** | 保留所有,标注`year_conflicts` | 记录在JSON,人工review |
| **伤亡数冲突** | 保留所有,标注来源 | `casualties: [{source, number}, ...]` |
| **身份冲突** | 上下文消歧 | 四层启发式策略 |
| **关系冲突** | 置信度加权 | 保留高置信度关系 |
| **时序冲突** | 约束检查 | lint检测,人工修正 |

### 6.3 冲突记录模式

**原则**：不强制解决，记录所有观点。示例（长平之战）：年份 -260 得2票(005-042,043-067)、-259 得1票(015-108) → majority_vote 采用 -260 并记录冲突 ✅；伤亡 45万(斩首) vs 40万(坑杀) → keep_all 双保留，可能统计口径不同 ✅。
