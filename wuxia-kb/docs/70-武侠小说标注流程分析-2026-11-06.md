## 三、全链路详解：一次标注的生命周期

### 3.1 L0 底本层：先锁死「不可改的原文」

- **来源与组织**：`../章回版/<书>/NNN　回目.txt`，34 部书各自成目录、回号零补三位；`scripts/config.py` 用 `discover_books()` 自动发现（`config.py:86-108`）。
- **指纹锁的现状（注意）**：`BOOK_OVERRIDES` 只登记了 **2 部书**的 sha256 组合指纹（`config.py:54-60`），其余 32 部（含 7 部已标注书）尚未回填；且 config **不做运行时复算**——底本被替换不会自动报警。因此「底本锁定」目前是**声明式纪律为主、密码学校验为辅**（pipeline_report §2.3/§9.3 R2）。
- **红线**：底本只读。标注、结构、修复任何环节都不得改原文——连疑似讹字（"欲如后事如何"）也必须保留（`SKILL_02a_02b:353`）；「顺手改对」= 违反可逆性。
- **例外与流程**：允许的底本修正只有**格式转换残留**，且必须走「备份 → 修 → 受影响 struct 重生成 → 回灌」：docs/49 书名行 8 部、docs/67 半角标点 154 处、docs/68 间隔号 `?`→`·` 5 处，均留 `backup/corpus_*` 证据。
- **为什么值得**：底本锁死 + 三层可逆，使任何标注错误都可以**只重跑标注层**而不动原文；这是整个流程可复跑、可审计的前提。

### 3.2 L1 结构层：把「一段文字」变成「可引用的块」

生成器 `scripts/generate_pn_wuxia.py`（520 行）是确定性脚本，只做三件事：加 `# [0] 回目`、给每块加 `[N]`、给韵文/套语块加 `::: 类型` 围栏。

| 规则 | 定版 | 证据 |
|---|---|---|
| PN 只用两级 | `[0]` 回目 / `[N]` 顶级块 / `[N.M]` 对话子段（仅纯对话段 ≥3 轮且 ≥500 字才拆） | `SKILL_02a_02b:237-264` |
| PN 不可变 | 插段只加子号不改旧号；回内从 [1] 重数 | 同上 |
| 围栏 10 类 | 正式 7：词/诗/歌/对联/回末对/回末/书信；观察 3：告示/口诀/说书 | `symbols.py:66-84` |
| 围栏铁律 | 成对闭合、不跨回、不嵌套、整块一个 PN、禁半角标点 | `SKILL_02a_02b:347-353` |
| 回末三块 | 回末对（`::: 回末对`）+ 回末套语（`::: 回末`）分块、各占一个 PN | `SKILL_02a_02b:165-201` |
| 韵文检测 | 三支路：四言整齐评分 / 长短句词牌 / 对联；灰区进 `doubts` 不硬判 | `SKILL_02a_02b:426-571` |
| 回末套语 | 词族正则 `欲[知/如/看] + 0-24 字 + (请听/且听/且看)?下回(分解/再/见)?`，检测/生成共用一个定义 | `symbols.py:106-113` |
| 可逆性 | 剥 PN+围栏行后与底本逐字符一致，否则 `SystemExit` | `generate_pn_wuxia.py:451-466` |

**实测**：273 个 `struct.json` 全部 `reversibility=pass`；全库 17,594 个 PN；围栏实际只实例化 6 类（回末 209、回末对 204、词 12、诗 3、歌 3、对联 4），观察类 3 类零实例；`doubts` 113 条、`warnings` 66 条（全部是「回末套语容缺」）。

### 3.3 L2 标注层：LLM 只做「语义判断」，其余全交程序

#### 3.3.1 生产执行器是一次「受控的 LLM 调用」

`scripts/annotate_chapter_llm.py`（930 行）的实际流程：

1. `ensure_struct` → 缺结构层就先调 N1；
2. `build_chunks` 分块（执行器默认 1,100 字/块，规范建议 700 字；few-shot 独立约束 ≤800）；
3. `context_pack` 注入**上下文包**：书名 / 回号 / 块号 / 规则版本 /《已核准映射表》（人物别名→规范名）；
4. **两遍同提示词**：P1 首标 → P2 把 P1 稿塞回 user，要求「自检补标与类型校正」（`annotate_chapter_llm.py:586-642`）；
5. **回锚保真（reanchor）**：用 difflib 把模型输出映射回原文，位置+长度+内容三重校验，锚不上或重叠即丢弃；`strip != original` 则整段回退（`:486-535`）；
6. 确定性修复（层码归一、管道归一、闭合符修复、标点外置）；
7. 修辞层后置：词表 49 条精确匹配候选 → LLM 逐处裁决 → 程序插入（`annotate_rhetoric_llm.py`）；
8. `final_verify` 逐段断言 `strip_all == struct`，计费落 `logs/token_usage/`。

> **一个常见误解需要纠正**：所谓「两遍标注」的主模式是**同一 SYSTEM_PROMPT 跑两遍（P1 首标 + P2 自检补标）**——P2 的 user 消息里塞入 P1 稿并追加 `P2_INSTRUCTION`（补器物/地点/数量/时间/技艺/概念/文书/组织/职衔/身份，复核类型码与管道、复核动词边界），代码见 `annotate_chapter_llm.py:586-591,640-642`；`--prompt-e/--prompt-v`（E/V 分层）只存在于片段执行器 `scripts/annotate_llm.py`，是困难章 fallback，不在章回量产器里。

#### 3.3.2 输入/输出契约（不可谈判的 6 条）

`SKILL_03a:86-92`：只输出标注后正文；**删掉标记与管道元数据后必须逐字符恢复输入**（含空白/换行/标点/弯引号/段号/围栏行）；显示串必须是原文连续区间；管道 `|` 后是元数据、原文字符不得搬入管道；段号与围栏行原样保留；标点引号留在标记外。

#### 3.3.3 提示词是一份「可版本锁定的运行产物」

- SYSTEM_PROMPT 正文在 `skills/SKILL_03a_实体标注.md` §二，v1.9 约 **12,570 字符**；
- 15 块 few-shot（FS1-FS15）由 `scripts/build_03a_fewshot.py` 从 **6 粒过审种子**（001 v2、003、015、017、018、019）字节级注入，构建时跑 **10 项断言**（类型码 15/6 与 symbols 一致、逐字+剥标一致、块长≤800、语法解析、索引 claims、覆盖报告、对照引文、反向断言旧标记不回流、哈希锁、版本一致性）；
- 文末「版本锁定」回填 prompt/ruleset/symbols/种子的 sha256，**规则改在 docs、示例改在种子、提示词只随种子再生成**（`SKILL_03a:333-338`）。

#### 3.3.4 符号系统：三种令牌、四层管道

| 层 | 括号 | 示例 | 语义 |
|---|---|---|---|
| 实体（15 类） | `〖〗` | `〖@卓一航〗`、`〖;值殿武师〗`、`〖%凉秋九月\|时点〗` | 这段文字指什么对象 |
| 动词（6 域） | `⟦⟧` | `⟦⊞挡⟧`、`⟦⊠害死⟧`、`⟦■绑架⟧` | 这里是什么事件入口 |
| 修辞（1 类） | `〘〙` | `〘※说时迟、那时快〙` | 这里用了什么固定表达 |

管道 `|` 按层定义（`SKILL_03a:134-138`）：人物=规范名映射（**只能用随块《已核准映射表》或本回文内证据，无映射不猜**）；时间=受控标签 `|时点/|时长/|年龄`；动词=完成状态或词义注记（`|司法拘押`、`|劫夺未遂`）；其他实体不挂管道。同一区间只属一层，禁嵌套/重叠。

### 3.4 L3 结构门：三关 + 五门（自动化，可 100% 复跑）

| 关卡 | 内容 | 失败后果 |
|---|---|---|
| 阶段 3 · 语法关 | 令牌类型码白名单、成对闭合、管道合法、无嵌套 | 重标/修复 |
| 阶段 3 · 保真关 | `strip(parsed_output) == source` 逐字符 | 重标（相似度只用于诊断，不做放行门） |
| 阶段 3 · 结构关 | 段号、围栏、段落顺序与输入一致 | 重标 |
| 阶段 4 · 五门 | `lint_purple_numbers`（E1-E17）/`lint_text_integrity`（对锁定底本逐字对账）/`lint_symbol_conflicts`/`lint_markdown`/`lint_fence_format` | 任一非 0 即门未过 |

一条命令：`python -X utf8 scripts/pipeline_wuxia.py <书> check`（顺序即执行顺序，逐项记录退出码）。五门全 0 → 状态 `structurally_valid`。

> **两个实现细节**（据 `logs/qa/_flow_analysis/qa_gates.md` §1/§4）：
> ① `lint_text_integrity.py` 对「实质差异」只写报告、**main 恒 `return 0`**——它是证据生成器而不是阻断门；真正会拦的硬门是紫数/符号/Markdown/围栏四门 + accept 的 `hard_errors`。
> ② `structurally_valid` 是**文档状态机里的状态名**；代码里没有这个字段——`accept_batch` 落盘的是 `structural: pass/fail` + `status: accepted/needs_fix`（`accept_batch.py:1215-1216`）。做自动化时不要依赖字符串状态名。
> ③ 单回 `check` 时 `symbol-lint`/`md-lint` **不接收 chapter 参数、仍扫全库**（`pipeline_wuxia.py:112-115`），所以「单回 check」耗时与全书同量级。

### 3.5 L4 语义验收：唯一通往 `accepted` 的通道

`scripts/accept_batch.py`（1,950 行），设计要点：

- **8 类高风险全查**（报告 `risk_stats` 固定 8 类）：① 管道（@ 映射来源/冲突）② 层-码错位 ③ 括号/标点 ④ 围栏/套语 ⑤ 动词域高风险（拘押/判刑/处死/域冲突）⑥ 时间/数量边界 ⑦ D1/谦辞/纯亲属（抽样段）⑧ 计划/否定/假想语境动词；
- **10% 确定性抽样**：`sample_size = min(段数, max(3, round(段数×ratio)))`；每书每回独立 `random.Random(sha256(书|回|seed))` 取段（`seed=20261104`），完全可复现；随后 `coverage_swap` 在不改变抽样数的前提下确定性替换，保证每类实体/每域动词至少出现一次（`accept_batch.py:1200-1285`）；
- **状态判定**：`hard_errors == 0` 且抽样硬违例 0 → `accepted`；**judgment 项不阻塞**（进终签队列）；
- 输出：`registry/acceptance/<书>_<区间>.json`，字段含 `global_gate`（五门退出码）、`summary`（accepted/needs_fix/hard/warnings/judgment/pipe_unsourced/E/V/R 计数）、`chapters_data`（逐回）、`risk_stats`、`pipe_sources`（每条 @ 管道的证据来源）。

**实测**：15 份验收报告覆盖 9 书，`accepted 273/273`、hard 0；judgment 残留合计 **339**（老 5 书 153 + 冰川 51 + 新 3 书 135）；warnings 集中在新增 3 书（257，全部 `pipe_mapping_conflict`）与冰川（77/29）；`pipe_unsourced` 残留 27（还剑 7 / 萍踪 16 / 散花 4）。

### 3.6 L5 终签：把「边界争议」变成可复跑的规则

`scripts/finalize_judgment.py`（129KB）是 judgment 的「机械化裁决器」：

- **四类处置**：`应摘 / 改域 / 保留 / 需人工`；
- **六类规则族**（**36 条判定规则 + 2 条守卫**，每条带规则 ID）：`R-Q1..Q5` 数量边界、`R-P1..P10` 计划/否定语境、`R-T1..T7` 时间边界、`R-D1..D7` 动词域风险、`R-W1..W2` 词表候选、`R-F1..F5` 围栏限实指；守卫 `R-UNK`（未知类别→人工）与 `R-DOC`（与 docs 既有终签冲突 → 一律转人工，不覆盖）；
- **安全机制**：默认 dry-run，`--apply` 才写；`APPLY_BOOKS` 白名单（7 书）；备份 + 剥标断言 + 幂等复跑（二次运行 0 token）+ 回放审计；
- **实际效果**：docs/45 使 020-032 judgment 85→27；docs/54 落地 3 书 75 token；docs/69 对三书 10 摘 + 4 保留落盘。

## 四、标注规范：判断顺序与典型边界

### 4.1 判断顺序（`SKILL_01g` §8.1，标注工作页）

> **先结构与文本模式 → 再当前指称 → 再边界 → 再身份 → 最后事件与事实状态。**

15 条原则的骨架：结构字符不标但文学内容不机械豁免；标具体对象不标普通名词；人物/组织/职衔**可分则分**；完整绰号法号不碎拆；本名优先、不凭常识猜名；管道只为本次所指、不扩大别名表；对白与叙述同规则；个人/固定群组/组织/家族分开；职位与身份按制度作用分；组织前缀拆开；技术/文本/物件副本分层；技术名内部数字不拆；边界不含谓词/副词/标点；嵌套拍平、内部关系转登记层；动作/结果/可信状态分别判断。

### 4.2 三条最容易踩的边界

| 边界 | 正 | 反 | 依据 |
|---|---|---|---|
| D1 对话称呼 | `〖@卓兄\|卓一航〗`（本名/法号/完整绰号/带姓名称谓） | 纯礼貌（先生/前辈）、纯关系词（父亲/师兄）、评价代称（女魔头）、描述性代称（那汉子）、当面尊称（陛下） | `03a:140-144` |
| 通名 vs 专名 | 插图中的 `〖#武师〗`、`〖•骡车〗`、`〖$一辆〗`（具体指称/信息承载） | 泛称"武功"不入 `^`；"身法步法"并列通名不标；"少女/老头"不标 | `03a:96-109`、`01g:1722+` |
| 动词域归属 | `⟦⊠害死⟧`（死亡/致残结果）、`⟦⊡囚禁\|司法拘押⟧`（司法地位变化）、`⟦■绑架⟧`（强制移动） | 姿态微动作（转身/退半步）不标；纯计划/否定不标；信息传递/差遣（告诉/派遣）不标 | `03a:111-132`、`04f:60-96` |

### 4.3 动词密度纪律（武侠特有）

武打段动词密度是史传的十倍以上，因此定了「合并标注」：同一交手单元内**只标交锋起止与关键结果**，招式名 `☆` 每现必标（但不算触发词），姿态微动作不标；主干叙事每段触发词经验区间 **1-6 处**，>10 处几乎必是逐招误标（`04f:771-788`）。全库实测 V 密度 1.45/百字，与金标准 1.51 同档。

### 4.4 围栏内标注按「文本模式」豁免

`symbols.py:87-92` 的豁免表直接驱动 lint：词/诗/歌/对联/回末对 → 实体限实指、动词不标；回末 → 全不标；书信/告示 → 实体可标、事件不核实；口诀 → 技术名可标；说书 → 可标、不抽事件。**回末套语内出现任何令牌 = hard**（`tao_token`）。

### 4.5 示例解剖（节选 `tagged/白发魔女传/001.tagged.md:11`）

```text
〖%凉秋九月|时点〗，〖=北地〗草衰，……〖=川陕〗两省边界的〖=大巴山脉〗，放马⟦■西行⟧。
行在前头的是几个雄赳赳的〖#武师〗，中间〖$一辆〗敞篷〖•骡车〗，坐着一个〖%年近六旬|年龄〗的
〖#绅士〗，〖•皮袄〗〖•披风〗，态度雍容，〖$一骑〗〖+高头大马〗，……
```

逐 token 依据：时间用受控标签 `|时点/|年龄`；地点含区域方位与山名；职业称呼归 `#`；数量按「信息承载原则」——`一辆/一骑` 承载情节信息故标，名词可不标；器物全量召回（皮袄/披风/骡车）；行踪动词只标行程级 `西行`，不管"放马/坐着"。**没有一处改动原文**，剥标后可逐字符还原。

## 五、质量体系：两级门、四状态、五个闭环

### 5.1 状态机

```text
generated → structurally_valid → semantically_reviewed → accepted
   ↑                ↑                      ↑
 标注完成        五门 lint 全 0        accept_batch hard 0 + 10% 抽样
```

**关键设计**：结构门通过**不构成**语义正确的证明——边界过长、错类型、漏标、错误规范名都能通过结构门。所以 03a 明确写成两级门（`03a:56-61`），且 `accepted` 的唯一通道是语义验收（`03a:245-250`）。

> **一句话评价**（据 `logs/qa/_flow_analysis/qa_gates.md` §4）：这套体系**形式门强、语义门弱且抽样化**——质量实际靠「结构 lint 清零 + 规则终签 + 人工兜底」三段式支撑，而不是统一的可计算语义判据。这解释了为什么流程里要保留大量人工终签与外部评审环节。

### 5.2 缺陷模式库（实测沉淀，DEF-01~14）

两粒种子 + 六批实战提炼的 14 类缺陷，每类带拦截手段，例如：DEF-01 闭合符误写（`⟧→〗`）；DEF-02 管道吞原文（`⟦⊠遭|横死⟧`）；DEF-03 触发词分词错误；DEF-10 规则文本与种子漂移（→ 版本锁）；DEF-11 工具误报（相邻同码位字符跨标签误配对）；DEF-14 草稿占位符泄漏（`〦`/`___FSn___` 进入产出，曾致批量损坏）。**这是流程里最有复用价值的方法论资产之一。**

### 5.3 反思闭环：问题 → 规则 → 示例 → 门

```text
外部评审 / 语义验收 / 抽样发现
        │
        ├─→ 缺陷入 DEF 库（拦截手段落 lint/脚本）
        ├─→ 口径裁定入 docs（G-xx / R-xxx / P3-x）
        ├─→ 新裁定先入「种子」（人工过审）
        │       └─→ build_03a_fewshot 再生成（10 项断言 + 版本锁）
        └─→ 规律库 S-03c1（48 条）/ 词表 / 负例表
```

真实案例：docs/26/27 的 G/R 系列 → 03a v1.2-v1.7；docs/35 修辞 53 条核定 → `rhetoric.json` 49 条 → 79/79 落标；docs/47 语义召回分析 → C25 标定补标 +944 token；docs/54/69 复核 → judgment 人工终签 + C18 别名补标。

## 八、观察与结论

### 8.1 这套流程做对了什么（可复用资产）

1. **三层加法 + 可逆性**是地基：底本只读、struct 只加结构行、tagged 只加令牌，任一层都能剥离还原。所有写 tagged 的工具都必须过「剥标断言」。
2. **两级门 + 状态机**：结构门机械可全自动，语义门只留「高风险全查 + 10% 抽样」，并用状态机把「过结构门」与「过语义门」分开——避免了「lint 全绿就以为标对了」的常见误判。
3. **规则/示例/提示词的三层治理 + 版本锁**：规则写 docs、示例来自过审种子、提示词由构建器再生成并跑 10 项断言；这解决了通用「提示词腐化」问题。
4. **缺陷模式库 + 反思闭环**：14 类 DEF 各有拦截手段；每次外部评审的问题都会回写成规则/种子/词表，并触发全量回溯检查（docs/33）。
5. **judgment 规则化**：把边界争议沉淀为 6 族约 40 条规则 + 先例表，人工只处理真正冲突项；这使语义债可收敛。
6. **成本与保真工程**：回锚保证原文永不采信模型转写；逐回计费/缓存命中/幂等复跑/备份回放审计，使批量可重复。

### 8.2 结构性张力（按影响排序）

| # | 张力 | 证据 | 影响 |
|---|---|---|---|

## 九、问题清单

### P0（影响正确性/可信度）

1. **跨书映射治理缺口（S-03b）**：257 条 pipe conflict + 27 条 unsourced + 跨书别名碰撞（docs/55 §五.1 ×72）→ 需要「书域语境注记」数据结构与消费端改造。
2. **judgment 队列 339 条无 SLA**：不阻塞 accepted，但人工终签无限期挂账会累积语义债；`APPLY_BOOKS` 白名单使部分书的历史残留（七剑 70、白发 15）不再被自动处理。
3. **剥标口径统一**：lint 家族与 accept_batch 的 strip 实现不同（C1 事故教训）；写侧工具必须复用验收器同一函数，否则「全绿却不能入库」。

### P1（影响规模化/质量上限）

4. **底本指纹锁名存实亡**：`BOOK_OVERRIDES` 只登记 2 部书的 sha256，其余 32 部（含 7 部已标注书）未锁；且无运行时复算——底本被替换不会自动发现（`config.py:54-60,106`，pipeline_report §2.3/§9.3 R2）。
5. **章节文件发现漏计**：`CHAPTER_FILE_RE` 不匹配楔子 /「第一○○回」类文件名（实测七剑按 30 回计，000 楔子需 `_oneshot/make_struct_prologue.py` 单独适配）；`structure --all` 只按 `books().chapters` 循环，**漏计回不会生成**（pipeline_report §9.3 R3）。
6. **补标工艺未批次标准化**：C18/C25 目前是「批次临时脚本 + 人工裁决」，C25 写死 `BOOK="白发魔女传"`（`apply_gold_calibrated_recall.py:53`）；应固化为每本必跑的两轮补标。
7. **结构层余量**：`doubts` 113 条、套语容缺 warning 66 条、还剑 14 回真容缺；E12 只给 warning，缺「容缺白名单」机制。
8. **词表资产薄**：verbs 165 条全部 `status=待审`（批量禁用）、quantity 36、fossil 3、rhetoric 49 —— 词表驱动召回的上限低，导致通名缺口压给 LLM。
9. **文档治理**：README 索引缺号/重号（两篇 69、多篇 67/68）、`SKILL_00` 称「现 6 书」（实为发现 34 部/已标注 9 部）、`finalize_judgment` docstring 仍称 `--apply` 未实现（实际已实现）、02ab 版本号未递增。

### P2（工程/下游/成本）

10. **单文件过大 + 无测试框架**（T6）；建议至少把 symbols/剥标/断言抽成公共库并加 pytest。
11. **一次性脚本未转正**：`logs/_oneshot/`、`logs/_prep_mapping_*.py`、`logs/_strip_fence_tokens.py` 等仍是批次资产，换书时依赖「找到并复用上批脚本」。
12. **下游覆盖不均**：04a 事件层未量产（现事件由 heuristics 抽取）、EX-8 audit 5 书、atlas 5 书；`~` 族群 few-shot 零覆盖但全库已产出 207 处（教学不一致）；下游只有 N4 进了 pipeline 阶段表，其余均为独立 CLI、无统一编排。
13. **成本/预算**：无预算告警与配额；高峰计价 ×2 只在批次文档里提示，工具未强制非高峰。
14. **lint 口径盲区**：`lint_markdown` 的 PN 正则只匹配行首 `[N]`，不匹配 `- [N.M]` 列表项；与紫数门 `PN_LINE_RE`（含 `(-\s*)?`）口径不同（`qa_gates.md` §4.9，**未运行验证**，需补测）。
15. **发布包不在 GO 链**：`release_site.py` 通过 =「站点 GO」，不等于「发布包已产出」；`build_release_artifact.py` 需另跑（pipeline_report §6.5）。另 `annotate_chapter_llm.py` 对已存在的 tagged 文件在无 `--force` 时会 abort，但**退出码仍为 0**——批处理脚本不能只看退出码。
