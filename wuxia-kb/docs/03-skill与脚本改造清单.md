## 一、审计方法与总体结论

### 1.1 硬编码审计数据（228 个脚本）

| 审计项 | 命中数 | 含义 |
|---|---|---|
| 引用 `chapter_md` 路径 | 109 | 写死标注层路径 |
| 引用 `tagged.md` 文件名模式 | 111 | 写死 `NNN_篇名.tagged.md` 命名 |
| **import 集中配置 config.py** | **仅 3** | **108 个脚本各自写死路径——config 是"应然"不是"实然"** |
| 内嵌实体/动词符号表（`〖@`/`⟦◈`/`〘※` 字面量） | 50 | 改类型表就要碰这些 |
| 引用"太史公曰/赞"围栏 | 24 | 围栏体系 shiji 特化 |
| 引用三家注 | 18 | 史记特有，整体不移植 |
| 引用十表/表格 | 26 | 史记特有，整体不移植 |

### 1.2 总体结论（三句话）

1. **方法论层零成本**：14 个 META 技能 + 机制类 skill（反思循环/覆盖度/成本/治理）100% 照搬——它们不含有史记内容；
2. **管线 skill 改的是"内容"不是"骨架"**：约 1/3 必须重写领域内容（标注提示词、判断原则、体裁清单），骨架（流程/输入输出/检查清单）全部照搬；约 1/4 是史记特有产物，直接不移植；
3. **脚本层最大的系统性改造只有一个：单书模型 → 多书模型**（130 章平铺 → 34 书 1,378 回嵌套），它影响全部 109 个路径脚本；其余改造是符号表加项（50 个）、围栏扩展（24 个）、领域裁剪。**改造量最小化的关键策略：shiji 的 19 类符号尽可能原样保留（不用的类型零成本），只新增武侠必需类型——这样 50 个符号脚本的改动是"加一行"而不是"重构"。**

## 二、最大的系统性改造：多书模型（先于一切脚本移植）

shiji 的章节寻址模型：`int 1..130` + 平铺目录 `chapter_md/NNN_篇名.tagged.md` + 语料 `corpus/archive/chapter/NNN_篇名.txt`。
武侠必须是复合键：`(书, 回)`，如 `章回版/白发魔女传/001　第一回　...txt`。**每个回的编号在 34 部书里都从 001 重新开始，平铺目录必然键冲突**，所以：

**改造方案（移植第一天就定，不容变通）：**

1. 重写 `scripts/config.py` 为**集中注册表**：`BOOKS = [34 部书名]`、`iter_chapters(book=None)` 迭代器产出 `(book, num, corpus_path, tagged_path)`、`get_corpus_file(book, num)` / `get_tagged_file(book, num)` 寻址函数；
2. **铁律：移植的每个脚本必须 `import config`，禁止本地写死路径**——这是 shiji-kb 的反面教训（config.py 建了，只有 3 个脚本用，导致 108 个脚本各自为政）；
3. 目录映射（保持 shiji 惯例命名，武侠语料侧沿用现有"章回版"不动）：

| shiji-kb | 武侠版 | 说明 |
|---|---|---|
| `corpus/archive/chapter/NNN_篇名.txt` | `章回版/<书>/NNN　第N回　回目.txt`（现有，只读） | 底本 |
| `chapter_md/NNN_篇名.tagged.md` | `chapter_md/<书>/NNN_第N回.tagged.md`（新建） | 标注层，**沿用 `chapter_md` 目录名**让未移植脚本少改一处 |
| `kg/entities|events|relations/` | `kg/<书>/...` 或 `kg/<主题>/<书>.json` | 图谱层，按主题分域 + 书维度 |

> 注意：武侠文件名带全角空格（`001　第一回`），tagged 层建议用下划线命名 `001_第一回.tagged.md`（shiji 惯例），config 层做两种文件名模式的映射。
