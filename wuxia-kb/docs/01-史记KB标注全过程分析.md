## 一、项目概况

《史记》57 万字 / 130 章 → 15,331 实体（19 类名词 + 4 类动词）、126,101 次标注、3,198 事件（98.7% 有公元纪年）、7,637 事件关系、约 10 万条 SPO 事实、751+ SKU（标准知识单元）。全程 Claude Code 人机协作约 120 小时、约 55 亿 tokens。

作者的核心隐喻：**这是一座"化工厂"**。语料是原料，`chapter_md/` 的标注文件是主生产线，`kg/`、`wiki/`、`app/` 是下游车间，**skills/ 是工艺规程，scripts/ 是管道和阀门，CLAUDE.md 是厂规**。这个隐喻决定了脚本与 skill 的分工方式（见第五、六节）。

## 四、标注格式规范（v3 现行版）

### 4.1 三层语义标注（互斥，严禁嵌套）

**① 名词实体 `〖TYPE 内容〗`**（U+3016/3017 白色六角括号），19 类：

| 符号 | 类型 | 符号 | 类型 | 符号 | 类型 |
|---|---|---|---|---|---|
| `@` 人名 | `=` 地名 | `;` 官职 | `#` 身份 | `%` 时间 |
| `&` 氏族 | `◆` 邦国 | `~` 族群 | `+` 生物 | `•` 器物 |
| `{` 典籍 | `:` 礼仪 | `[` 刑法 | `^` 名物 | `$` 数量 |
| `!` 天文 | `_` 思想 | `?` 神话 | | |

**② 动词标注 `⟦TYPE 动词⟧`**（U+27E6/27E7），4 类（SKILL_04f 定版）：`◈` 军事（17 词表）/ `◉` 刑罚（15 词表）/ `○` 政治 / `◇` 经济。支持消歧 `⟦◈伐|征伐⟧`。

**③ 修辞/成语 `〘※成语〙`**（U+3018/3019 白色龟甲括号），如 `〘※生而神灵〙`。

符号设计原则（SKILL_01g，"符号设计宪法"）：稀有 Unicode 括号 + 与 Markdown 语法 Disjoint（`;` 曾因撞 Markdown math 从 `$` 改来）+ 形状系列分离。演化历史 v1.0（HTML span）→ v2.0（`$`官职）→ v2.5（`$`数量）→ v2.7（内联消歧）→ v2.8（`•`从`*`迁来）→ v3.0（`◆`从`'`迁来），每次符号迁移都有专用 migrate 脚本（见 5.5）。

### 4.2 结构标记（非语义层）

- **Purple Numbers 段落编号** `[1]` / `[1.1]` / `[1.1.2]`：段级+句级双层，**永久不可变**，是反思循环的寻址单位、SKU 的 source 定位、跨章引用的锚点；
- 小节标题 `##`/`###`；`::: 赞 … :::` 围栏块（太史公曰/赞诗，围栏内不标）；
- `（CCC-PPP）` 原文引用号与 `[CCC-PPP]` 事件编号两体系**互相独立，禁止联动修改**。

### 4.3 内联消歧语法（v2.7）

`〖TYPE 显示名|规范名〗`：显示文本不变，索引/链接用规范名。如 `〖@台|吕台〗`、`〖%二十|年龄〗`（时间数量消歧）、`〖%七十载|时长〗`。优先级高于外挂的 `disambiguation_map.json`。

### 4.4 真实样例（`chapter_md/001_五帝本纪.tagged.md`）

```
[1] 〖@黄帝〗者，〖@少典〗之子，姓〖&公孙〗，名曰〖@轩辕〗。〘※生而神灵〙，弱而能言……

[1.2] 〖@蚩尤〗作乱，不用帝命。於是〖@黄帝〗乃徵师〖#诸侯〗，与〖@蚩尤〗⟦◈战⟧於〖=涿鹿之野〗，遂⟦◈擒⟧⟦◉杀⟧〖@蚩尤〗。

[25] 〖@舜〗年〖%二十|年龄〗以孝闻……践帝位〖%三十九年|时长〗，南〖^巡狩〗，⟦○崩⟧於〖=苍梧之野〗。
```

### 4.5 核心铁律（SKILL_03a §1.4 原文）

1. **标注只能添加标记符号，不得修改原文字符**——硬校验："去掉所有标记后必须与原文逐字相同"；
2. 禁止拆合称（"文成"不得拆成 `〖@文公〗〖@成公〗`，会插入原文没有的字）；
3. 标题行/编号/`:::` 标记本身不标注（原则零）；
4. **掩码匹配**：对已标注文本做增量标注时，先掩码现有标注区，避免嵌套；
5. 三层标注互斥，严禁嵌套。

## 五、脚本体系：脚本做什么、skill 怎么用脚本

### 5.1 分工哲学

**机械的、可确定性判定的事归脚本；语义的、需要判断的事归 agent；边界 = "能否机械判定对错"。** SKILL 文件是两者的粘合剂：每个 SKILL 的"工具与脚本"一节列出关联脚本表（路径/功能/输入/输出 + 使用示例），并规定执行顺序（如"每次 Edit 后立即 `grep -n` 验证 + 跑 `lint_text_integrity.py`"）。

### 5.2 lint 家族（质量闸门，跑在每一步改动之后）

| 脚本 | 职责 | 被引用次数 |
|---|---|---|
| `lint_text_integrity.py` | **去标记逐字比对**：`strip_markup()` 按序剥离全部标记→`to_flat()` 去空白→与 `corpus` 底本 `difflib.SequenceMatcher` 逐字比对；`_norm()` 消除 14 组等价变体（於/于、後/后等）；差异三分类（实质差异必须修/标点规范化可忽略/编码规范化可忽略）；白名单机制 `scripts/lint_whitelist.txt` 登记已确认的正确校勘；报告写入 `logs/lint/` | **15 个 SKILL 引用，全仓库最高频** |
| `lint_markdown.py` | 标注语法：未闭合标记、空标注、编号跳跃、标题层级跳跃、超长行 | 6 个 SKILL 引用 |
| `lint_purple_numbers.py` | PN 编号连续性/父级存在性 | |
| `lint_symbol_conflicts.py` | 标注符号冲突检测 | |
| `lint_halfwidth_punct.py` | 半角标点检测（配合 `fix_halfwidth_quotes.py` 批量修复） | |
| `lint_zan_format.py` / `lint_zan_in_chapters.py` | 赞文围栏格式 | |
| `lint_skills.py` | **SKILL 文档自身的 lint**（元质量管理） | |

### 5.3 fix 家族（机械修复，不碰语义）

`fix_nested_annotations.py`（嵌套拍平）、`fix_halfwidth_quotes.py`（半角引号，CLAUDE.md 明文规定批量修复用此脚本而非手工）、`fix_missing_parent_pn.py`、`apply_annotation_patches.py` / `apply_manual_fixes.py`（**TSV 补丁批量应用**——人工裁定以 `data/patches/*.tsv` 为唯一载体，脚本幂等回填）。

### 5.4 词表标注家族（规则先行，LLM 只做剩余部分）

`tag_new_entity_types.py`、`tag_quantity_entities.py`、`tag_identity_words.py`、`tag_kinship_words.py`——词表驱动标注（掩码 + 长词优先）；候选发现靠 `find_candidate_entities.py`、`scan_untagged_aliases.py`、`infer_single_char_names.py`。**理念（M04 柳叶刀）：能用词表/正则解决的不花 LLM tokens。**

### 5.5 migrate 家族（符号系统级演化）

`migrate_to_lenticular.py`、`migrate_dynasty_to_feudal.py`、`migrate_official_to_identity.py`、`migrate_country_symbol.py`——历史上有三代符号方案，每次迁移都是"专用脚本 + 全量 lint 对账"，保证旧版本可升级。**这是 schema 能安全演化的关键机制。**

### 5.6 统计/审计家族

`compute_annotation_coverage.py`（覆盖度）、`generate_entity_stats_report.py`、`build_entity_concordance.py`、`analyze_error_patterns.py`、`token_tracker.py`（成本跟踪）。**所有对外口径数字由脚本生成，文档不手写计数**——这是覆盖度口径一致性的保障（SKILL_08b）。

## 六、Skill 如何组织工作

### 6.1 SKILL 文件模板（`skills/templates/SKILL_template.md`）

六节 + 附录：①快速开始（何时使用/核心步骤 3-7 步/成功标准 checklist）→ ②详细说明（关键概念/禁止事项❌/推荐做法✅）→ ③工具与脚本（关联脚本表 + 使用示例）→ ④检查清单（执行前/中/后）→ ⑤FAQ → ⑥故障排查 → 附录（上下游 Skill、变更历史）。硬性要求：≤500 行、"快速开始"必须在前 3 屏、**至少关联 1 个可运行脚本**。SKILL 自身质量由 `lint_skills.py` 把关。

### 6.2 SKILL_03a 实体标注（977 行，最重的技能）

内含**可直接复制的 SYSTEM_PROMPT Python 代码**（标注 agent 的完整提示词）、temperature=0、断点续传经验、每类符号的判断原则（每条带正误对照表）、三代方案演化史、"新增类型四步法"、19 条经验教训。**agent 标注的提示词不是临场发挥，是版本化的资产。**

### 6.3 SKILL_03c 按章反思 + 规律库（质量的核心引擎）

- **输入**：一章 tagged 文件 + 规律库 `references/SKILL_03c1-v2-rules.md`（**134 条**：A 区按符号分 8 子区 / B 邦国氏族 / C 单字消歧 / D 领域专项 / E 格式残留）；
- **流程**：Step 0 读规律库（按体裁激活特定规律子集——本纪/年表/河渠/医学章各有清单）→ 跑 lint 与边界 grep → 逐段审查"标错的+漏标的"→ 输出修正；
- **硬约束**：每个 agent 只处理一章，禁止批量；
- **质量基线（原文）**："正常章节（300-1000行）预期 30-80 处修正。若低于 20 处，需再次逐段复查"；
- **历史轮次**：R1 约 1,913 处修正积累 40+ 规律 → R2 提深度 → R3 引入消歧 → R4 导出 34 条新规律，总修正约 8,684 处（平均 66.8/章）；
- **闭环**：每轮反思的发现沉淀进规律库（10f：日志→SKILL），规律库又喂给下一轮——**经验是累积的，不是一次性提示词**。

### 6.4 SKILL_03e 按类型反思（路由模式）

正文极短，是个路由器：对比 03e1（跨类型迁移——源头整类标错时"词表自动替换→歧义词 TSV 上下文审查→新词扫描"三阶段）vs 03e2（类型标对但内部子类错归），"场景判断三问"+组合原则："**先 03e1 清源头，再 03e2 做反思纠错——不在错误源头上反思**"；"新增实体类型前先做 03e1 存量清理"（实证：存量迁移 1,894 处 > 新标 690 处）。"每轮改动后必跑 lint"。

### 6.5 SKILL 的演化机制（M06 + 10f）

新技能不是设计出来的，是**从工作日志里提炼出来的**：干完活 → 写日志（10b）→ 日志里反复出现的操作提炼成 SKILL（10f，有模板库和精简案例）→ 用 `lint_skills.py` 保持质量 → 过时的移入 `archive/`。

## 七、治理规则（CLAUDE.md，15KB）

会话启动强制清单：读 CLAUDE.md → 读 `.claude/settings.json`（技术层禁令，含 `.claudeignore`、`.githooks/`）→ 查 `git status`。

1. **禁自动 commit（最高优先级）**：任何形式的 `git commit` 不得自动执行；用户说 commit 时只准备 commit 信息草稿并明确询问。禁 `git add -A`/`git add .`、`git push --force`。
2. **禁破坏性 Git 命令**：`git checkout <commit> -- <file>`、`git restore`、`git reset --hard` 一律禁止，附两次"血泪教训"（checkout 覆盖 69/64 个文件的修复成果）。安全替代：`git diff` 查看 → 手动 Edit → Python 脚本提取 → `git stash` 保护。
3. **内容保护原则（宪法 §1.1）**："✅ 目标字段不存在 → 可追加新建；✅ 字段为空 → 可填入；❌ **字段已存在 → 批量导入时必须跳过，不得覆盖**（单条精细编辑可提升）"。血泪教训：`update_page_content()` 整节替换导致 136 个页面手写引文丢失。
4. **严禁修改原文字符**：只加标记；**严禁引入半角引号**（原文全角 `""`，Edit 工具易自动转半角，每次 Edit 后立即 grep 验证 + 跑 lint；批量修复用脚本）；
5. **pn 与 event_ids 互相独立**，禁止联动修改；
6. **目录决策树**：docs/（定稿公开）→ labs/（实验草稿）→ data/（核心资产）→ scripts/（可复用）→ logs/daily/（工作记录）→ skills/（规范）；
7. **反思流程全自动**：每章的反思循环不需要用户逐步确认；对话以中文为主；
8. **Skill 工程化**：核心内容 200-500 行，必须有 YAML frontmatter、快速开始、工具与脚本、检查清单。

## 八、SKU 标准知识单元（知识库的"分装出厂"）

两代实现：

## 九、可直接引用的方法论要点

1. **四层复用金字塔**（00-META-00）：脚本工具 90%+ 可复用（微调参数）→ 项目 SKILL 60-80%（需适配）→ META 技能 100% 跨项目 → 元元方法 100% 跨领域；
2. **好东西都是总结出来的**：不凭空设计，分解任务、小步快跑、分析中间结果、及时总结（OTF + JIT）；
3. **标注不改正文**：原文与图谱永远可对账，标注错误不污染文本，版本 diff 干净；
4. **质控是核心**：lint 硬门槛 + 反思软循环 + 规律库累积，三层质量体系；
5. **schema 演化靠 migrate 脚本**：符号系统三代更迭无一弃库；
6. **成本可管理**：token_tracker + 08c 成本节约技能 + 按类型成本报告。
