## 一、决策正文（三条承诺）

1. **新管线为唯一真源**：`wuxia-kb/scripts/pipeline_wuxia.py` + `tagged/`（struct/tagged）+ `registry/` + `concordance/` + `acceptance/` 是此后唯一生产链；不再向旧 `kb/tagged/` 写标注、不再用旧 5 码符号体系产出新数据。
2. **旧站点消费层冻结**：父仓 `Wuxiaxiaoshuo/scripts/` 的 44 个 .py（`pipeline.py` 11 阶段、`lint_annotation.py`、`repair_tags.py`、`build_*.py` 等）自 2026-11-05 起**冻结**——不再修 bug、不再加功能、不再作为发布数据来源；旧 `kb/tagged/` 与旧 `site/data/*.json` 作为历史产物只读归档。**旧 kb/ 的 7 个全局考订资产继续作为只读数据源**（迁移输入，见 §五），不在此冻结范围。
3. **新建薄导出适配层（EX 组）**：在 `wuxia-kb/scripts/` 新增 8 个导出器，把新管线产物按 `site/data/` 现有 14 个 JSON 契约导出，桥接期**Astro 38 页零改动**；W 组仍按新 schema 设计、不依赖导出器；W 组落地后导出器退役（见 §七）。

> 一句话：**旧的冻住，新的继续跑，中间加一层可退役的导出器让站点不断更。**

## 二、为什么选 C（决策依据）

| 方案 | 工作量 | 优点 | 否决理由 |
|---|---|---|---|
| A 改造旧 44 件（E1-E11 原计划） | ≥1-2 周纯工程 | 站点契约不变、数据合流 | 旧逻辑复用率低（旧 5 码→新 15+6、事件/关系/评分/gazetteer/互文锚点 schema 全变）；新 schema 仍在演进，改完可能再改；`docs/42` 已判"工作量大" |
| B 冻结 + W 组直接重建 | W 组 38 节点 + 38 页适配 | 最干净、一次到位 | N4-N10 落地前站点数据冻结 1-2 周+；页面契约需改；与当前"站点已在线上（11-02 构建）"的现状冲突 |
| **C 冻结 + 薄导出层（选定）** | 阶段 1 约 1-2 天；阶段 2 3-5 天（依赖上游） | 站点不断更；不碰旧脚本；E 组从 11 改造节点缩为 8 个薄脚本；与 N4-N11 并行 | 过渡期双 schema 维护，导出器有沉没成本（W 组后退役）——可接受 |
| D 暂缓 | 0 | 最省事 | 站点停更、两套并行扩大，越晚越贵 |

**C 的关键收益**：`E1/E2/E3` 直接**裁撤**（新管线已自带 pipeline/lint/repair 能力）；`E4-E11` 从"改造旧件"重定义为"从新产物导出"，**避免触碰旧 44 脚本**，同时把 E 组对 G3 上线门的阻塞降为"阶段 1 即可部分解除"。

## 五、站点数据契约（桥接层验收基线）

| 文件 | 顶层 | 记录级关键字段（节选） |
|---|---|---|

| `chapters.json` | meta + 每书 | chapters/lit/kb |
| `characters.json` | meta + entities | type/canonical/books/total/cross_book |

| `sects.json` | meta + sects | canonical/books/cross_book/arts_by_pred/members/tenures/lineage_gaps |

## 七、验收标准

1. **站点可用**：`site` 构建成功、38 个 Astro 页面可访问，控制台无数据契约报错。
2. **字段完整**：14 个 JSON 字段集合 ⊇ 2026-11-02 基线（新增字段允许，缺失字段必须有 `meta.field_gaps` 说明）。
3. **数据可核**：characters/books/chapters 三表抽样 10%，逐条可回溯到 `registry/concordance`/tagged 位置。
4. **幂等**：每个导出器复跑产出确定性一致（时间戳字段除外）；默认 `--dry-run`，`--apply` 前自动备份 `site/data/`。
5. **零旧写入**：导出器不写 `wuxia-kb/tagged`、`registry`；不运行父仓旧脚本；旧脚本 mtime 保持冻结前状态。
6. **差异报告**：每次导出产出 `logs/export/site_diff_<date>.md`（新旧量级、字段缺口、异常样本）。

## 八、风险与回滚

| 风险 | 应对 |
|---|---|
| 旧站语义字段无新数据对应（如 ratings ELO、dossiers LLM 摘要、matches 五值） | 阶段 1 只导出"有把握"的表；缺数据字段置 null + `field_gaps`；不伪造 |
| 旧 `build_*` 内含非机械逻辑（考订表派生） | 旧考订**数据表**继续只读复用（§4.2），脚本冻结；不重复造轮子 |
| 并发会话同时写 `site/data` | 导出器默认写 staging（`logs/export/staging/`），人工/构建流程切换；与站点构建互斥 |
| W 组设计若与导出器冲突 | 导出器契约以 site 现有 schema 为准，**不反向约束 W 组**；W 组新 schema 落地即替换 |
| 回滚 | `backup/site_data_20261105/` 一键恢复；旧脚本未删（仅冻结），必要时可临时重跑 |
