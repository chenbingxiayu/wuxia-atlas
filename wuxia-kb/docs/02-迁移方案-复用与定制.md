## 一、总原则

1. **搬"化工厂"，不搬"化工产品"**——复用的是方法（管线、格式、质控、治理），武侠的本体、事件模型、时间轴按小说领域重构。
2. **存量是资产不是负债**：现有 v0.2 标注语法与 shiji 语法同源（本来就是按 shiji-kb 经验分析的初稿设计的），76,848 处标注、139 个 tagged 文件、四书全层表全部保留，迁移 = 升级（v0.2 → v1.0），不是重标。
3. **补的是方法层**：现有体系缺的不是标注本身，而是 shiji-kb 的五件套——**skills/ 体系（现为零）、反思循环+规律库（现为零）、Purple Numbers 编号（现为零）、集中治理 CLAUDE.md（现散落）、lint 家族（现有 1 个）**。
4. **不凭空设计（M00/M03）**：规范矛盾的裁决用数据说话（反思循环跑一轮看分布），新技能从工作日志提炼，试点先行再滚动。

## 四、六大定制点详细设计

### 4.1 实体类型体系：10 类定版（L2，最重要决策）

现状 10 类 vs shiji 19 类的完整映射与裁决建议：

| 武侠现码 | 现定义 | shiji 对应 | 裁决建议 |
|---|---|---|---|
| `@` | 人物 | `@`人名 | 保持。补登记表属性：历史/虚构、绰号组（"练霓裳=白发魔女"式规范名归并已跑通） |
| `=` | 地点 | `=`地名 | 保持（真实地理挂 gazetteer，fiction 3 处已有字段） |
| `◆` | 组织/门派/朝代/民族/军队 | `◆`邦国 + `~`族群（shiji 分两类） | **暂不拆分**。shiji 教训（M08+03e1）：新增/拆分类型前先做存量清理，实证"存量迁移 > 新标收益"。跑一轮 R1 反思后看 `◆` 混淆分布再议 |
| `;` | 职衔/称谓 | `;`官职 + `#`身份（shiji 分两类：官职=任命的职位，身份=社会地位如天子/诸侯/百姓） | **暂不拆分**，但用规律库 + 词表把"大内侍卫（朝廷职衔）vs 总镖头（江湖职衔）vs 大侠（身份）"的判断写清楚；这是实验中 LLM 最大盲区（deepseek 仅标 1 处 vs 人工 63） |
| `%` | 时间/纪年 | `%`时间 + `$`数量（shiji 用 `〖%九岁|时长〗` 消歧） | 保持；**引入 `|时长`/`|年龄` 内联消歧约定**（直接照搬 shiji v2.7 机制，解决时间/数量混淆——盘点 P1 人物状态时间线依赖此消歧） |
| `☆` | 武功/招式/阵法 | （无对应，shiji `^`名物 仅部分覆盖） | 武侠特色类型。按 shiji"新增类型四步法"补齐支撑：词表（与招式表.json 226 条联动）+ few-shot（实验已验证：引号内招式示例后 ☆ 6→13）+ 反思子规律 |
| `•` | 兵器/暗器/宝物/名物 | `•`器物 | 保持，与神兵表 226 条联动 |
| `§` | 丹药 | （无对应） | 保持（v0.2 已加） |
| `+` | 坐骑/灵兽 | `+`生物 | 保持（现库仅 1 处，观察是否值得保留；shiji 同码生物类高频，武侠语料稀疏——若 R1 反思确认无价值可裁，走 migrate 脚本降级为不标） |
| `[` | 秘籍/文书/书信/书画 | `{`典籍 | 保持（"书 vs 功法"分离：`[`秘籍是物，`☆`武功是法——与旧经验分析一致） |

**成语层 `〘※〙`（决策 D3）**：shiji 引入是为文风模仿应用。武侠"说书人点评"应用暂未立项，**建议暂不引入，保留符号位**；若后续立项，按 03e1 三阶段法做存量扫描，不新开内联任务。

**对话称呼 / 集体泛称（决策 D1/D2，规范层未裁决矛盾）**：这是实验证明"提示词解决不了"的唯二问题。裁决方式照 shiji M08：**拍板进 SKILL_01g 武侠版**，写入判断原则正误对照表，同步更新任务书 v1；此后同类问题进规律库累积，不再改规范。

### 4.2 动词与关系层：5 类 + 三层关系法

- 动词 5 类保持（◉杀伐 ◈交战 ○拜认结盟 ▲擒控 ◇传艺）。**每类建动词词表**（shiji 04f：◈17 词/◉15 词的词表驱动模式）——实验中"动词超标"（deepseek 24 vs 人工 23、qwen 37）的根治手段是词表白名单而非提示词。
- 盘点 P1 建议的 救/叛/赠/辱 四动词：**不进内联不进 lint**（维持冻结），走离线关系表（第三层情义），与 shiji 05c"政治层关系走 SPO 不走内联"同构。
- 关系层照 05c 三层法重建：共现（自动）→ 家族/师承（从 ◇/○ 锚点自动推导——盘点已指出"师承可从 ◇○ 高自动推导"）→ 情义（人工裁定 TSV 稳定键）。站点侧私补的 graph.json"救助/恩义"边、build_stories.py 极性词表**全部退役**，统一由关系层 v2 供数。

### 4.3 时间与事件模型：双层时间轴

- shiji 98.7% 事件有公元纪年（04c 年代推断 + 04d 审查 + 04e 消歧）；武侠只有书内相对时间。
- 设计：**事件表 v3 主键 =（作品，书内相对顺序）**；清代系列（17 部）可挂真实朝代纪年；最终合成"武侠宇宙编年"（系列谱系表 14 时代段已是雏形）。
- 推理技能改造：07a 生卒年 → **年龄/辈分一致性检查**（build_audit.py R1 死亡一致性扩展）；输出进"穿帮雷达"，与"作者有意的前后呼应/翻案"区分（前者要修数据，后者是资产要标注）。

### 4.4 跨书连续性（武侠宇宙独有，新编号段 SKILL_11）

- 正文互文"（事见拙著《萍踪侠影录》）"→ 跨书引用边：已自动化（build_intertext.py，1,904 边），SKILL 化并补"bare 引用消歧"反思子规律（1,775 条 bare 是噪声大头）；
- 系列链（天山系列等 6 线）：系列谱系表已建，SKILL 化维护规则（conf 分级 strong/ok/todo 已有）；
- 跨书人物同一性：kb_discovery.py 已做规范名归并，补"同一人物多书形象差异"反思（对应 shiji 03b 人名消歧的跨书版）。

### 4.5 校勘层（网络流传本 vs 精校本）

shiji 底本是维基文库精校本，01 系列做的是句读/繁简/三家注；武侠底本是网络流传本，实际问题是整章重复排印、书名错字、"○/零"混用。设计：

- **原文层（章回版/）保留原貌不动**（现状正确，维持"任何情况下不修改"铁律）；
- 校勘记录独立成层（各书 校勘记录.md 已有，升格为结构化 `data/variants.tsv`：稳定键=（书，回，错字变体，规范形），供互文扫描与 lint 白名单共用）；
- 标注层只挂在校勘语义版上——错字变体挂 `|规范名` 管道是现有正确实践，写入 SKILL_01g 武侠版判断原则。

### 4.6 治理规则武侠化（CLAUDE.md 项目特有段）

照搬 shiji 骨架后，项目特有段重写为：

1. 章回版/ 任何情况下不修改；kb/tagged/ 是真理之源，改动必经 lint_annotation.py + diff_detail.py 双门槛；
2. schema 冻结纪律：语法改动必须走"提案→试点一回→迁移脚本→全量 lint 对账→版本号 v0.x→v0.(x+1)"五步流程（现状已立，升格入 CLAUDE.md）;
3. 版权红线：正文全文（含 tagged）不出仓库；发布只经 copyright_gate；
4. LLM 标注纪律：标注类 LLM 调用必须使用 SKILL_03a 武侠版内置 SYSTEM_PROMPT（版本化），禁临场发挥提示词；每次 LLM 批量任务后必跑 lint + 抽样对比；
5. 口径铁律：文档中的统计数字一律标注来源脚本，禁止手写计数；
6. 反思循环全自动（照搬 shiji：每章反思不需用户逐步确认）。

## 五、存量数据迁移策略（76,848 处标注怎么办）

**不重标。分四步升级：**

1. **v0.2 → v1.0 版本升级**：写 `scripts/migrate_v1_0.py`（先例：migrate_v0_1/v0_2）。内容 = §4.1 裁决产生的机械变更（如 `%` 消歧补 `|时长`、`+` 类处理）+ YAML 头 schema 字段更新。全量 139 回跑完后 lint 100% PASS 才算完成。
2. **PN 编号回补**：新写 `scripts/generate_pn_wuxia.py`（仿 `generate_pn_mapping.py`）：段落级 [n] 按空行分段机械生成；句级 [n.m] 按句号/问号/叹号切分（围栏内、书信内不编号）。**风险点**：触碰每一行 → 必须配合 lint"剥标=原文"校验跑全量对账（PN 属于可剥离结构标记，剥离后不影响逐字比对——shiji 的 strip_markup 序已验证此模式）。
3. **反思循环 R1**：用 SKILL_03c 武侠版跑四书 139 回，每 agent 一章；发现全部沉淀为规律库条目 + 修正直接入 tagged（全自动，CLAUDE.md 授权）。**预期产出**：参照 shiji R1 基线（30-80 处/章），武侠对话密集体预估 20-60 处/章；规律库首批预计 50-100 条（种子：四书判例.md、边界案例库.md、校订规则.md、对比实验四结论的全部机械可执行项）。
4. **口径统一**：`scripts/build_kb_stats.py` 一次生成全部对外数字（实体数/标注数/事件数/关系数/类型分布），README 与各文档引用之，人工手写数字全部退役——直接清偿盘点 §2.8 的四处口径债。

**顺序依赖**：1 → 2 → 3 → 4 严格串行（反思循环必须在 PN 回补后跑，否则寻址单位不稳定）。
