# 39 · 020-032 回标注缺口归因与补标方案

> **问题**：020-032 机器初稿实体密度 5.98/100 字，仅为 001-019 人工金标准 9.77 的 61%。
> 本文用**可复现的脚本**（`scripts/analyze_annotation_gap.py`）把缺口拆到类、拆到词，
> 给出归因（5 条，附本次实测证据）与分层解决方案（S1-S5，含预期收益/成本/风险）。
> **核心结论**：缺口 ≠ 均匀的"模型少标了"，而是 **(a) $/# 两类占 56% 的结构性缺口**、
> **(b) 部分"缺口"其实是金标准旧口径 over-tag**、**(c) 继续加 LLM 轮次已到边际收益 0**，
> 必须换成"词表召回 + LLM 裁决 + 人工验收"的工艺。

### 1.2 "应标通名"的裸文候选标注率（真正反映召回）

裸文候选＝该词在未被任何标记覆盖的位置出现；标注率＝其中被同类型标注的比例。

| 词表 | 金标准 | 机器初稿 | 可回收估计* |
|---|---|---|---|
| `#` 应标身份（饥民/女兵/官军/弟子/掌柜…） | 70.2% | **25.4%** | ~158 处 |
| `#` D1 描述性代称（少女/老人/少年/汉子…**规范应不标**） | 19.4%（旧口径 over-tag） | 0.0% | —（不应回收） |
| `=` 场所指代（宫/院/店/山 + 中/里/内/外…） | 26.2% | **0.8%** | ~33 处 |
| `•` 器物（剑/石/花/马/信/灯…） | 20.6% | **10.3%** | ~113 处 |

\* 仅这四个小词表的上限；全量通名词表扩容后可达 1200-2000 处。

**关键发现**：`=` 类机器初稿对"X中/里/内"这种最典型的场所指代几乎全漏（0.8% vs 26.2%），
`#` 应标身份只标到金标准的 1/3；而 D1 描述性代称机器初稿一个没标（**更符合现行规范**）——
金标准里 19.4% 的 D1 标注是旧口径残留。**所以"密度差"里混着"口径正确性优势"**。

### 1.3 金标准自身也不是"全标"

金标准对 `=` 裸文候选只标 26.9%、对 `•` 裸文候选只标 20.6%。说明规范里"具体指称才标、
通名/转喻不标"的边界本身有大量灰色地带，**用金标准密度当唯一目标会把旧口径和灰色裁决一起学回来**。

## 二、归因（5 条，附证据）

### R1 模型行为：按情节显著性选标，不是"提及级全量"
- 019 回金标准对照重标（同一执行器）：整体 recall 0.446 / precision 0.793；`#`/`•` 标注率
  分别为金标准的 1/3-1/2；同段内已标过的实体在下一次提及时常被跳过。
- 抽读 022[5]：`掌柜`（×4）、`官差` 等应标 `#` 全裸；`客店`/`信` 等"高显著性"物体已标。
- 这正是 flash 级模型的共性行为：**它像人一样"抓重点"，而标注规范要求穷尽**。

### R2 提示词"规则密、示例稀"的漂移（最可修的一条）
- 现行 SYSTEM_PROMPT 的 few-shot 只取自 001/003 两粒早期种子（`docs/24`、`SKILL_03a §五.3`
  再生成纪律），而 004-019 的金标准通名密度是在后续多轮评审中涨上去的。
- **量化证据（本次实测）**：9 块 few-shot 段落平均 **E/100 = 6.74**（最稀的 003[38] 只有 3.2），
  而 020-032 机器初稿 **5.98**、后期金标准 012-016 为 **11.06**、017-019 为 **12.33**——
  **模型产出密度几乎贴着 few-shot 示例密度走，而不是贴着规则走**。
- 这正是 DEF-10（规则文本与种子漂移）的又一次显形：规则升级了，示例没升级，模型学示例。
- 且规则文本与示例存在冲突案例：规则要求"提及级每次照标"，示例段落里并非每次都标。

### R3 通名标注必须逐处语境裁决，模型倾向"宁漏勿错"
- 标/不标边界是语境性的：`饥民`→`#` 标 / `少女`→D1 不标；`武当山`→`=` / 裸`山`多为通名；
  `剑`作器物→`•` / `剑法`→`☆`；`宫中`→`=`（场所指代）。
- 模型对这类"低信息量通名"保守跳过；金标准自身在 `=` 上也只有 26% 标注率，说明边界模糊，
  模型更保守（0.8%）。

### R4 工具链缺口：本该由词表/正则解决的量，全压给了 LLM
- 项目设计原则明确"**能用词表/正则解决的不花 LLM tokens**"（`docs/01` §脚本族）。
- 现状：只有 `tag_quantity_entities` 一个词表跑通（本次还修了单字量词误标 bug），且
  `quantity.json` 仅 26 个量词 + 10 个整串模式，覆盖不了金标准的 `$` 用法
  （bare 数词如 `〖$一〗`、`〖$一声〗`、依附计数）。
- `tag_identity_words` / 场所后缀规则 / 器物词表**尚未移植或未建**（`docs/05` 待办清单）。
- 现成可用的资产：`kb/` 旧库有神兵表/招式表，可作 `•`/`☆` 词表种子；`registry/entities.json`
  可扩别名。

### R5 工艺差距：金标准是多轮评审产物，本批是单遍初稿
- 金标准演进：001 v2（158E）→004 798E→835E→005 1005E→006 修订→…→019 942E；密度从
  002-006 的 6.5-7.3 涨到 012-019 的 10.6-12.7，是 **Review→修订→再生成 few-shot** 循环
  的结果（docs/25/29/31/32/33）。本批 = 两遍过 + 一次机械修复，没有人工评审轮。
- 因此 5.98 基本等于"金标准初稿水平"；要追平必须补工艺轮次，而不是换更长的提示词。

### 本次已实测的"加轮次/换策略"实验（均为 019 回金标准对照，可复现）

| 策略 | recall | 说明 | 结论 |
|---|---|---|---|
| 单遍 non-thinking | 0.34-0.55（分段） | P1 | 基线 |
| 两遍（P1+自检补标） | **0.53-0.55** | 现采用 | +10-20pt，性价比最高 |
| 单遍 thinking | 0.38-0.58 | 5-6k reasoning token/段、慢 6 倍 | 与两遍相当，不采用 |
| 第三遍"通名专类补标" | 0 增益 | 模型输出不变 | ❌ 无效 |
| gap-fill（只输出漏标 JSON） | 失败 | 模型把已标当漏标，12/13 被重叠过滤 | ❌ 无效 |
| 词表数量补标（修复后） | +20 处/回 | 只覆盖"数词+量词" | 覆盖 `$` 缺口的 ~12% |

→ **继续加 LLM 轮次的边际收益已为 0**，缺口必须靠"词表召回 + LLM 裁决 + 人工验收"补。

## 三、解决方案（按性价比排序）

### S1 词表/正则补标（首选；**$0 API 成本**，1-2 天）
| 动作 | 内容 | 预期回收（13 回） |
|---|---|---|
| `$` 扩表 | `quantity.json` 量词扩到 ~50（人/声/眼/场/阵/口/掌/拳/步/回/次/遍/番/层/截/段/只/条/根/枝/片/股/堆/群/队/伙/年/月/日/里/丈/尺/寸/斤/两/石…）；补 bare 数词与"数+量+名"模式；**加负规则**（习语量：一起/一并/一同/一口/一时/一见/一臂之力/千里迢迢；事件量：一掌/一声喊；纯泛指：一个） | +400-700 |
| `#` 词表 | 新建 `wordlists/identity.json`（职业/处境身份 ~200 条，带 status/tier）；结合"前有数词/后有们、等"语法线索 | +200-350 |
| `=` 规则 | 场所后缀 `{宫/殿/院/房/店/楼/寨/寺/观/庙/庄/阁/桥/洞/谷/崖/城/镇/村/关}` + 方位后缀（中/里/内/外/上/下/前/后）+ 排除表（山水/江湖 转喻）；具名地名仍由 LLM | +100-250 |
| `•` 词表 | 从 `kb/` 神兵表 + 高频器物表建 ~150 条；与 `☆`（剑法/刀法）、`◆`（门派）用最长匹配+负规则消歧 | +250-400 |
| **标定流程（必须）** | 先在 **gold 001-019 上跑**补标器，与金标准同位置比对算 precision/recall；目标 **precision ≥0.85** 才放行到 020-032 | — |

**收益**：实体密度 5.98 → **7.2-7.7**（+1200-2000 token），且未来所有章回免费复用。
**风险**：通名歧义（`山` 通名 vs 方名、`剑` 器物 vs 剑法）→ 用负规则 + 标定控制；漏标比误标安全，
可先"高精度低召回"分波放开。

### S2 few-shot 再生成（治根；**$0.3** 重跑 13 回，0.5 天）
- 从 007-019 金标准里挑 **4-6 段通名密集段落**（覆盖 `#`/`$`/`=`/`•` 每类至少 1 段）+ **4 组
  "标 vs 不标"对照**（`饥民` vs `少女`、`武当山` vs 裸`山`、`剑` vs `剑法`、`宫中` vs `宫中»转喻），
  用 `scripts/build_03a_fewshot.py` 按 §五.3 纪律再生成 SYSTEM_PROMPT。
- 预期单遍召回 +10-15pt → 密度 **7.0+**；与 S1 叠加 **8.0-8.5**。
- 前提：所选段落需人工确认（种子纪律），建议同步把"通名密度"写进 03a §二示例选择原则。

### S3 把 LLM 从"生成器"降级为"裁决器"（结构性改进；$0.1-0.2，1 天）
- 流程改为：**词表/正则产候选 → LLM 只输出 标/不标 的 JSON**（完全复刻修辞层 `〘※〙` 已验证的
  稳定模式：候选精确匹配 + LLM 裁决 + 机械插入 + 回读断言）。
- 优点：召回由词表保证、精度由 LLM 保证、输出短、成本低、可增量（只处理候选）、不会扰动既有区间；
  缺点：候选质量决定上限（需 S1 词表先做好）。
- 该模式在本次修辞层 10 回 36 处落标中零失败，工程上已验证。

### S4 质量门升级：把 P/R 评估纳入门（$0，半天）
- 现有门只看"结构合格"（五门 lint），无法发现密度缺口——本次 5.98 vs 9.77 就是门绿灯下的盲区。
- 建议：建 **500 段 gold 测试集**（从 001-019 分层抽样，人工确认口径），每次迭代跑
  `scripts/analyze_annotation_gap.py` + 逐段 P/R，目标 **E ≥8.5/100 且 precision ≥0.9** 才算
  "可交付初稿"；把结果写进批次报告（复现：`python scripts/analyze_annotation_gap.py`）。
- 本次该脚本已落盘：`logs/qa/gap_analysis.md`。

### S5 人工语义验收（不可省；1-2 天，按状态机）
- 只查四类通名（`#`/`$`/`=`/`•`）+ 高风险项（人物管道、动词域归属、回末/围栏边界），
  抽样 10%；通过 → `accepted`；漏标回填缺陷库 → 再更新 few-shot（闭环）。
- 目标不是 100% 追平金标准（其中含旧口径），而是**按现行 v1.8 口径的一致性**；
  D1 代称 19.4% 的旧口径 over-tag 应作为"负样本"清理，而不是回收。
