# SKILL 08b 武侠版：覆盖度评估 — 用"全文覆盖"替代"外库对比"

> **上游声明**：本文从 shiji-kb `SKILL_08b_覆盖度评估` 移植重造（🔵 中度 65:35），移植依据见 `docs/05-管线技能与脚本逐项改造分析.md` §2.5（**"权威外库对比法"失效（无《汉书》对应物）→ 改用 W13 式全文覆盖**；10 组问题体系按武侠维度重造）与 `docs/03-skill与脚本改造清单.md` §3.9（08b 覆盖度 ✅ 照搬）。
> **设计源（权威/接口）**：`SKILL_02a_02b_章回结构与韵文处理.md` §9.2 正文分母；`SKILL_02f_文本统计_武侠版.md` §二 分母纪律；`SKILL_01g_标注符号集合原则.md` §9.8 网站功能覆盖；`SKILL_词表体系规划_武侠版.md`（D09）WL-01~20 与词表覆盖率；`SKILL_03l_出现统计_武侠版.md`（L3 跨书聚合口径）。

> **核心原则**：**覆盖度不是"标注了多少字"，而是"该有的知识对象有没有、能不能用"。** 没有权威外库，就用全文分母 + 类型目录 + 页面需求三面镜子互相照。

## 一、定位与边界

### 1.1 工序位置

```text
03a/03b 标注 · 05 关系 · N4/N5/N8 产物 · 词表编译 · N10 SKU · concordance
        ↓
08b 覆盖度评估（本文）→ 覆盖报告/缺口清单 → 批次优先级（P1/P2）→ 补标/词表/登记任务
        ↓
08d 正确性评估 · W13 全文覆盖 · 页面功能覆盖（01g §9.8）
```

### 1.2 本文做什么

1. **五维覆盖度**：实体类型/实体登记/回章/词表/页面功能 + 证据覆盖；
2. **10 组问题体系**：覆盖问题按对象与用途分组（§四）；
3. **分母纪律**：正文分母/全文分母分开，不混算；
4. **缺口分级**：阻断型（下游无法工作）/质量型（可用但不可靠）/长尾型；
5. **产物 schema 与批次回写**。

### 1.3 本文不做什么

| 不做 | 归属 |
|---|---|
| 具体标注/补标执行 | 各标注工序（03a/03b/05 等） |
| 正确性判定 | 08d/07e |
| 词表内容填充 | D09 词表任务 |
| 页面实现 | W 组/S-09 |
| 统计数字口径本身 | 03l / 02f |

### 1.4 关键约束

- **无权威外库**：不能拿"尧舜禹本纪"式外库比对，覆盖分母只能来自**语料自身 + 类型目录 + 页面需求**；
- **全文覆盖（W13 式）**：对每个"应有对象"（实体/关系/事件/页面字段）检查是否在语料中有覆盖，不依赖外库；
- **覆盖≠正确**：覆盖度只答"有没有"，正确性归 08d/07e/N8。

## 三、五维覆盖度定义

| 维 | 覆盖对象 | 分母 | 数据源 | 覆盖率算法 |
|---|---|---|---|---|
| **D1 实体类型覆盖** | 15 类实体是否各有足量实例/无空类 | 实体令牌总数 | concordance/entity stats | 非空类型数 / 15；各类占比 |
| **D2 实体登记覆盖** | 已标注实体是否进登记层（approved/proposed/pending） | concordance scope 实体 | concordance+registry | registered / scope；unregistered 分列 |
| **D3 回章覆盖** | 回/章的结构层与标注层是否齐 | config 章数 | pipeline status/acceptance | 已完成回 / 总回（分 tagged/struct/accepted） |
| **D4 词表覆盖** | 词表驱动的检查/补标是否覆盖目标域 | 目标词表条目/域 | wordlists 编译表 | 已编译表 / 计划表；词表 vs 语料命中 |
| **D5 页面功能覆盖** | 01g §9.8 页面所需数据是否齐 | 页面/字段清单 | 01g §9.8 + EX/SKU | 有数据字段 / 必需字段 |
| **D6 证据覆盖** | 每条知识是否有证据/定位（A-E 非 E） | 知识条目（边/卡/事实） | N5/N8/N10/07e | 有证据条目 / 总条目 |

### 3.1 分母纪律（引 02ab §9.2 / 02f §二）

- **正文分母**：块类型=正文段的 PN 数/字数（排除回目/围栏/套语）；
- **全文分母**：含围栏/回目的全部文字（用于"空间覆盖"类）；
- **密度类指标**只能用正文分母；**覆盖计数**须声明分母类型；
- 同一报告内不得混用两种分母而不标注。

## 五、缺口分级与优先级

| 级 | 定义 | 例（当前） | 处置 |
|---|---|---|---|
| **阻断型** | 下游工序无法工作 | 其余 29 书无 struct；事件层未上线 | 最高优先（结构/事件批次） |
| **质量型** | 可用但不可靠 | N8 C/B 级；identity 词表待审；判断弱 | 次优先（复核/词表） |
| **长尾型** | 大量个案、不影响主链 | unregistered 长尾；未挂叶 | 批量工具+抽样 |

### 5.1 优先级排序法

```text
① 阻断型先清（结构/事件/登记主链）
② 质量型按"影响页面/问答"排序
③ 长尾型批量自动化（propose/apply、normalize、词表补标）
④ 每批报告记录前→后覆盖率
```

## 十、FAQ（首批 6 问）

**Q1 没有《汉书》式外库，覆盖度怎么算？**
用三面镜子：语料自身分母（全文覆盖）、类型目录（15 类/64 叶/55 谓词/20 词表）、页面字段需求（01g §9.8）；不做外部权威对比。

**Q2 覆盖率高是不是就质量好？**
不是。覆盖只答"有没有"；正确性/可信度归 08d/07e/N8。

**Q3 unregistered 算不算缺口？**
算，且要分列：它是"已标注但未登记"，不是"没出现"；处置走 03b propose/apply。

**Q4 为什么其余 29 书是阻断型缺口？**
无 struct 就无法做结构/时间/关系/页面覆盖，整条下游链无法工作。

**Q5 长尾缺口要不要全补？**
不。批量工具+抽样，ROI 优先；报告中标注"长尾不阻断"。

**Q6 与 W13 全文覆盖什么关系？**
W13 是"句子级覆盖查验"的机制先例；本文借其"全文逐点核对"思路做武侠五维评估（W 组尚未启动，本文先落方法）。

## 结语

覆盖度评估的诚实之处在于：**没有外库就不装外库，用全文、类型目录与页面需求三面镜子照自己。** 先分清"有没有"（覆盖）与"对不对"（正确性），再用阻断/质量/长尾三级排序，覆盖工作才不会被数字幻觉带偏。
