## 一、定位与边界

### 1.1 工序位置（反思环中的"类型轴"）

```text
S-03a 标注 ──→ S-03b 消歧 ──→ accept/QA 报告（类型分布/边界错误）
                                   ↓
             S-03c 按章反思（章级：漏标/误标/边界）──┐
             S-03e 按类型反思（类型轴：体系问题）  ──┼──→ 类型反思提案 → 五原则评估 → 试点/裁决 → 回写 01g
             S-03f 边界反思（边界轴：吞/粘/拆）    ──┘
                                   ↓
                        META-10 QC 指标（类型准确率/一致性）
```

### 1.2 本文做什么

1. **识别类型体系问题**：新增（该设未设）、合并（两类型不可分）、废弃（无下游/长期零用）、改名（语义漂移）；
2. **五原则评估**：每个提案必须逐条打分，禁止"感觉需要"；
3. **易混类型裁决**：门派↔帮会↔世家、武功↔招式等高频混淆方向的裁决卡；
4. **试点与回写**：试点→diff→双人裁决→回写 `SKILL_01g` 附录 B-1（不直接改 01g 正文）；
5. **监控**：类型分布长尾/覆盖率/准确率进入 META-10 指标。

### 1.3 本文不做什么（越界即错）

| 不做 | 归属 |
|---|---|
| 直接改 `SKILL_01g` 类型表/符号表 | 01g 附录 B-1 裁决记录（用户/Lead 拍板） |
| 逐章逐句检查漏标/误标 | S-03c 按章反思 |
| 吞词/粘字/拆分等边界错误 | S-03f 边界反思 |
| 质量 lint 规则实现 | META-10 / lint 家族 |
| 词表条目填充 | SKILL_词表体系规划_武侠版（WL-01~20 运营） |

### 1.4 与 QC / 反思的边界（引 META-10 §零）

| 维度 | QC（META-10） | 本文（类型反思） |
|---|---|---|
| 检查对象 | 格式/边界/完整性/规则违反 | **类型体系是否合理**（该不该有这个类型） |
| 执行方式 | 规则脚本（lint） | Agent + 统计证据 + 人工裁决 |
| 输出 | PASS/FAIL + 修复建议 | 类型提案 + 五原则评分 + 试点 diff |
| 关系 | 本文发现的可规则化项**沉淀为 QC 规则**；QC 指标是本文的触发信号 | — |

## 四、五原则评估（每个提案必须逐条过）

> v0.1 说明：以下五原则为武侠版归纳（依 META-08 类型三维度 + 01g §八 + 下游覆盖需求），与 shiji 原版五原则的逐条对照见附录 A/B（待补）。

| 原则 | 问题 | 通过标准 | 不通过后果 |
|---|---|---|---|
| **P1 频次** | 该类型/边界在语料中有多少真实实例？ | ≥30 处跨 ≥3 书（新增）；≥90% 实例归并后无歧义（合并） | 类型空转、页面无数据 |
| **P2 正交** | 同一词汇在任何上下文是否只属一个类型？（01g §三 Disjoint） | 两类型有可执行判别信号（词表/句式/字段） | 标注员每次靠猜，误差沿管线放大 |
| **P3 边界可判** | 正/负例能否写成规则或词表？ | 能给出 ≥5 条正例 + ≥5 条负例 + 1 条冲突兜底 | 类型不可自动/半自动，成本失控 |
| **P4 下游增益** | 新类型/合并后哪个页面/字段/统计变好？ | 至少 1 个具体下游（页面字段/统计口径/SKU 字段） | 为分类而分类，知识库不增值 |
| **P5 成本可回收** | 迁移/重标/词表/脚本改动的成本？ | 变更影响 ≤1 个波次、可脚本化迁移、有回滚 | 一次类型改动拖垮整批标注 |

### 4.1 评分卡（提案必填）

```text
提案ID：TE-2026MMDD-01
类型动作：新增 | 合并 | 废弃 | 改名
现象与证据：<3+ 处语料 loc + 统计数字>
P1 频次：__/5   P2 正交：__/5   P3 边界：__/5   P4 下游：__/5   P5 成本：__/5
总分（≥18 才进入试点；12-17 挂 watch；<12 关闭）
试点方案：抽样范围/diff 口径/回滚点
```

### 4.2 决策规则

- **新增**：总分 ≥18 且 P2/P3 均 ≥4（边界不可判的类型禁止新增）；
- **合并**：合并后实例覆盖率 ≥95% 且不丢失下游字段；否则保类型、改文档说明；
- **废弃**：该书类型零实例且无下游消费 ≥2 批；废弃不等于删符号（符号保留但标"停用"）；
- **改名**：仅语义漂移且旧名有歧义时；改名必须给旧名→新名映射表与迁移脚本（禁止静默重命名）。

## 五、四类动作的标准流程

### 5.1 新增类型（照 META-08 类型新增五步法）

| 步 | 动作 | 产出 |
|---|---|---|
| 1 侦察 | 从 S1-S7 信号确认候选；统计跨书频次与同形实例 | 候选卡 |
| 2 设计 | 定类型定义/判别信号/正负例/与相邻类型的 Disjoint 声明 | 设计稿（≤2 页） |
| 3 试点 | 抽样 ≥3 书 30 回 apply 候选词表/规则 → diff（新增/误报/漏报） | 试点 diff 报告 |
| 4 批量 | 全量词表 + 5 书回归 + accept 复跑 | 回归报告 |
| 5 文档 | 回写 01g 附录 B-1 + 词表规划 WL 条目 + README/索引 | 裁决记录 |

### 5.2 合并类型

```text
① 候选：A、B 两类型实例在 ≥90% 语境不可分（判别信号同时命中/互斥失败）
② 方案：保留 B（下游字段更全）→ 并入 A，A 降为 B 的子类/属性
③ 迁移：旧标 A 的令牌 → 重标 B（脚本化 + 剥标断言），无法自动的进人工清单
④ 验证：合并前后类型准确率抽检、accept 不退化
⑤ 回写：01g §八 类型表 + 子类表 + 错误模式库补"旧 A 标法"反例
```

### 5.3 废弃类型

- 触发：零实例 ≥2 批 + 无下游消费 + 有替代类型；
- 动作：符号保留但 `status=deprecated`（symbols.py 白名单标注），历史语料不重标（只在新批次禁用）；
- 回写：01g 附录 B-1 + META-08 类型表状态列。

### 5.4 改名（语义漂移）

- 触发：类型名与语料主流语义不符（如某类型 80% 实例实为另一义）；
- 动作：旧名→新名映射表 + 全库检索替换（只改文档/词表/登记，不改历史标注令牌的类型码——类型码是身份不是名字）；
- 回写：01g §八 类型表 + 下游 schema 兼容说明。

## 六、首批预判易混方向（docs/05 §2.3 指定）

### 6.1 门派 ↔ 帮会 ↔ 世家（`◆` 内部切分）

| 判别 | 门派 | 帮会 | 世家 |
|---|---|---|---|
| 组织基础 | 师徒传承 + 武学体系 | 江湖势力/行业联盟 | 血缘/婚姻 + 家学 |
| 典型信号 | 掌门/弟子/辈分/开山祖师 | 帮主/堂口/地盘/帮规 | 家族/世系/家传武功/嫡庶 |
| 例 | 武当派、少林派 | 丐帮、龙门帮 | 铁家庄、慕容世家 |
| 边界 | "武当"=门派；"武当派"同 | "帮"字族多帮会，但"帮主"可泛称 | "庄/堡/寨"不自动=世家（风砂堡=地点，docs/53 §1.3） |
| 常见误标 | 把朝廷机构（锦衣卫）标门派 | 把门派标帮会 | 把"世家"当门派、把"堡"当家族 |

> 处理纪律（v0.1）：在 01g 类型表未细分子类前，`◆` 不强行切三型；子类问题进分类树（D08 `SKILL_分类树五件套_武侠版.md` §五），标注层只保证 `◆` 与 `=`/`&`/`;` 的正交。

### 6.2 武功 ↔ 招式（`☆` 内部层级）

| 判别 | 武功/功法 | 招式 |
|---|---|---|
| 层级 | 可包含多式的体系（心法/剑法/掌法） | 单式/单招（可被"一招X"引出） |
| 信号 | "练成/传授/秘笈/心法/剑法" | "一招/一式/使出/撮指成剑" |
| 例 | 天山剑法、达摩剑 | 横江飞渡、排山倒海 |
| 边界 | 父术+子式双层双标（03a G-29） | 招式名边界（含数字/引号/整体 vs 拆分，01g G1） |
| 误标 | 招式升为独立武功（层级膨胀） | 通名动作当招式（"一掌打去"不是招式） |

> 处理纪律（v0.1）：武功谱系层级（招式∈武功∈心法）归 D08 `SKILL_分类树五件套_武侠版.md` §六 树，标注层只判"是否专名技艺/招式"；同形异类（小李飞刀）按 01g §八 判定顺序。

### 6.3 其他易混对（watch 清单）

| 对 | 风险 | 当前口径 |
|---|---|---|
| `;` 职衔 ↔ `#` 身份 | 职业/任命/处境混标 | 03a DEF-05；01g §八 |

## 七、试点与 diff 规范

1. **样本**：≥3 书、每书 ≥10 回、覆盖类型密集章与稀疏章；
2. **diff 口径**：新增/减少/改判三类计数 + 逐条 loc + 抽样人工复核 ≥30 条；
3. **指标**：类型准确率（抽检）、实例覆盖率（相对候选词表）、accept 的 hard/judgment 不升；
4. **回滚**：词表/规则回滚点 + tagged 备份（如涉及重标）+ 文档版本；
5. **禁止**：未 diff 直接全量 apply；试点结果只报"感觉更好"无数字。

## 九、错误模式库（TRE 系列，首批 8 条）

| # | 错误 | 检测 | 修正 |
|---|---|---|---|
| TRE-01 | 凭感觉新增类型（无频次证据） | 提案卡 P1 无数字 | 退回补充 ≥30 实例跨 3 书 |

## 十、检查清单

### 提案前
- [ ] 信号有量化来源（报告路径/数字），非主观；
- [ ] 同形/边界实例已逐条核对原文；
- [ ] 与既有类型表（01g §八）无重复/冲突。

### 试点中

## 十一、与反思循环挂钩

1. **输入**：S-03c 按章反思的"类型级"归纳、S-03f 边界报告、accept/QA 类型分布、词表覆盖率；
2. **输出**：类型提案与裁决记录；通过后的规则化项交 META-10 沉淀为 QC 检查；
3. **与 03c 分工**：03c 管"这一章标得对不对"，03e 管"这个类型该不该存在/怎么切"；同一现象先归因（边界错误→03f；类型体系→03e）；
4. **节奏**：每批标注收口后跑一次类型反思（≥1 批间隔），避免边标边改类型；
5. **指标**：类型准确率/一致性进入 META-10 §九质量指标，按批记录。

## 十二、FAQ（首批 6 问）

**Q1 新增一个类型能不能只改 SKILL，不动历史语料？**
可以（向后兼容原则：新类型只用于新批次），但必须在 01g 附录 B-1 记录"历史语料待迁移/不迁移"的裁定；不得静默让同一现象跨批两种类型。

**Q2 类型合并后旧令牌怎么办？**
脚本化重标（剥标断言 + 备份）；无法自动的进人工清单；历史标记不丢，可查旧类型。

**Q3 门派/帮会/世家到底设不设子类？**
v0.1 不设标注子类（`◆` 保持单层），子类在分类树（D08 §五）表达；若后续页面需要分列，走本文新增/合并流程。

**Q4 武功/招式要不要拆两个类型？**
不拆（都是 `☆`），层级归 D08 武功谱系树（招式∈武功∈心法）+ 03a G-29 双层双标；拆类型会破坏符号表与下游。

**Q5 类型反思和 01g 谁说了算？**
01g 是权威文本，03e 是提案机制；只有用户/Lead 拍板后由 01g 附录 B-1 固化，03e 不能直接改 01g。

**Q6 多久做一次？**
每批标注收口（accept 完成）后 ≥1 次；无新信号时可只看 watch 列表。

## 结语

类型反思的价值不在"多设几个类型"，而在**用证据阻止类型膨胀或类型僵化**：该设的设（有频次、可判、有下游），该并的并（不可分的类型只会制造标注噪声），该废的废（零用的类型是维护负担）。每一条变更都要能回答：**它让哪一个下游变好了？**
