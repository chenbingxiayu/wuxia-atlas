# SKILL 04 武侠版：事件分析层总览

> **上游声明**：本文是 P2 事件层的**总览与工序索引**，不是新规范。事件类型学、36 字段总表、五状态矩阵、战斗专项 Schema 的判定细则全部由 **D03 = `SKILL_04a_事件识别.md`**（v0.3-draft，1,100+ 行）定版；动词域与联动候选由 **`SKILL_04f_动词标注.md`**（D02）定版；符号与主域铁律由 **`SKILL_01g_标注符号集合原则.md`**（D01）定版；时间槽位由 **`SKILL_时间体系_武侠版.md`**（D05）与 N4 定版；关系谓词由 **`SKILL_关系体系_武侠版.md`**（D06）与 N5 定版。本文只回答"事件层怎么排工序、谁产出什么、怎么验、缺什么"。
> **移植依据**：`docs/05-管线技能与脚本逐项改造分析.md`（04a 事件类型学、05e 战争事件专项的迁移判定）、`docs/17-技能脚本改造实现图与拓扑排序.md` §2.5（S-04 总览属"框架"档，←D03）。
> **核心原则**：**事件层是"触发词 → 知识单元"的组装车间，不是第二个动词层**。动词层管"标不标、归哪域"，事件层管"这一串触发词构成哪个事件、字段填什么、能不能被下游消费"。两层不得互相越权。


### 1.2 本文做什么（四件事）

1. **排工序**：给出事件层从动词标注到下游消费的执行顺序与门（§四）；
2. **给索引**：13 类事件、36 字段、五状态、战斗专项分别在 04a 的哪一节，避免执行者重复读全稿（§三、§五）；

4. **守门**：事件层质量门与检查清单（§七、§九）。

### 1.3 本文不做什么（边界，越界即错）

- **不重定义事件类型**：13 类的定义/判定信号/边界对照见 04a §3.4，本文只给一句话速查；
- **不重抄 36 字段表**：字段必填性与来源见 04a §5.1，本文只给分组视图与对接字段；
- **不替代 05e**：战争/战斗专项的 Schema 细则是 `SKILL_05e_战争事件_武侠版.md` 的职责，本文只索引；
- **不建事件库**：事件表产物与字段落盘格式由 E5（未对接）与 W 组消费层决定，事件层只保证"字段齐、状态对、可引用"。

### 3.2 36 字段分组视图（逐字段必填性见 04a §5.1）

| 组 | 字段（编号承 04a §5.1） | 事件层关注点 |

| 质量与版本 | 32 事件描述、33 原文引用、34 降级待审标记、36 规范与数据版本 | 可审计、可复跑 |

### 3.3 五状态与消费许可（04a §7.1 矩阵）

五状态 = **发生状态（六值）／完成状态（四值）／信息来源（六值）／可信状态（四值）／叙述模式（五值）**。消费侧只认矩阵，不认单字段：

- **问答**只取「已核实」格；**评分**只取「已核实」格；**编年**按传闻轨/存疑轨分流；**索引**全收但标注层级（传闻层/自称层）。
- 人物发言/书信/告示的「来源声称」格**不关闭生存状态**（负规则十二）；「相互冲突」一律不入问答/评分，交穿帮雷达矛盾登记。
- 叙述模式≠正常叙事（回忆/梦境/假想/戏中戏）的事件**照常解析时间、隔离于主轨**（时间侧细则见 `SKILL_04d_年代审查_武侠版.md`）。

### 5.2 联动候选 → 事件字段

- 04f §4.1 的 27 行联动是**三元组候选生成器**，不是定论：`⟦⊠救活⟧` + 伤者 → `治愈(医者,伤者)` 候选 → 落事件「参与方及语义角色」（字段 6）与关系层（N5）。
- **强制档缺失即降级**：事件记录打 `待审` 标记（字段 34），不进问答/评分。
- **四类人物关系（情感/恩义/背叛/主仆）不进联动**：行内不设符号，走离线表（见 `SKILL_05_关系分析总览_武侠版.md` §六）。
- **防共现误推**：一次交手不自动敌对；师父同桌吃饭不生成任何三元组（01g §9.2 铁律）。

## 六、事件记录与下游接口

### 6.1 event_id 与定位

- `event_id` 格式承 04a §8.1（书内唯一稳定键，建议 `{书码}#{回}-{序号}`），**battle_id = event_id**（不设第二套编号，04a §6.1 裁决）。
- 定位字段（13）必须落 `{作品ID}#pn-r{N}.{X}` 段锚，多区间允许（拆分三判见 04a §2.3）；不得漂移到统计区（时间体系错误模式 23）。
- 跨回/跨书引用走事件链槽位（字段 31）与 cross_book_ref 谓词，不复制记录。

### 6.2 与 N4 时间轴的对接

- 事件「故事时间槽位」（字段 14）填 **tp_id**（如 `bainv-T001`），原始表达/偏移/精度与 `registry/time/<书>.json` 同名字段同源，**一处解析、两处引用**，禁止两套推算（时间体系错误模式 2/15/31）。
- 回指型事件（重复提及）的时间指向**首叙事件的时点**，不新建 tp。

### 6.3 与 N5 关系层的对接

- 事件层输出给 N5：事件 id、类型、参与方角色、outcome、时间槽位、定位；N5 用它们生成事件关系边（sequel/causal/part_of/opposition）与 SPO 边。
- 边 schema 见 `registry/relations/<书>.json`（字段：subject/subject_type/predicate/object/object_type/confidence/evidence/loc…）；事件层不直接写关系表。

### 6.4 与验收/下游的对接

- `accept_batch.py` 的 8 类高风险中，④围栏/套语、⑤动词域、⑥时间数量、⑧计划/否定与事件层直接相关；`judgment_items` 不阻塞 accepted，但事件层应把这些列为人工复核输入。
- 下游 E5（事件页）、E9（评分）、穿帮雷达（N8）**尚未对接**：当前事件表产物是"字段就绪、消费层未接"状态（docs/50 §三）。
