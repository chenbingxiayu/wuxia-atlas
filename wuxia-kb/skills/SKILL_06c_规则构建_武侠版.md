# SKILL 06c: 规则构建（规划）

> 定义基于本体的推理规则，将历史学领域知识形式化为可执行的推理规则。

---

## 一、功能概述

本体定义了类、属性和关系的结构，但复杂的领域知识需要通过规则来表达。本功能计划构建推理规则系统，实现：

- **领域规则**：武侠语料与跨书治理特有的知识规则
- **推理规则**：从已知事实推导新知识
- **验证规则**：检查数据的合理性和一致性

---

## 二、核心功能

### 2.1 领域规则

**目的**：将历史学和史记领域知识形式化

**规则类型**：

**时代规则**：
- 如果人物的时点键落在该书纪年轴之外，则 N4 报越界（书内相对纪年口径）
- 如果人物在改朝换代事件（如明亡清兴）前后均活跃，则时点键跨轴、身份主值须复核
- 如果事件发生在系列交集回目（如白发→七剑的传递回），则跨书实体须挂 D07 双层 canonical

**身份规则**：
- 如果人物称谓带"陛下/皇上"且叙述语境，则身份挂宗室帝胄叶（#树）
- 如果人物受雇守护宅院且无朝廷任命，则身份归护卫保镖（非职衔树侍卫）
- 如果人物以受雇行刺为业且有契约情节，则身份归刺客杀手（稀疏预警叶）

**关系推理规则**：
- 如果A是B的师父，B是C的师父，则A是C的师祖（师承传递）
- 如果A是B的掌门，C是B的门下弟子，则C与A是同门上下级（门派层级推导）
- 如果A与B敌对、B与C敌对，不传递——敌对关系不闭包（江湖阵营非传递）

**地理规则**：
- 如果地点A的=链挂到区域X（C0b 地点链），则A继承X的区域归属
- 如果事件发生在地点A且A属虚构地（nature 字段，D10），则地图呈现按 gazetteer 虚实分层

**应用场景**：
- 自动标注人物时代和身份
- 补全缺失的关系
- 推断事件的地理归属

### 2.2 推理规则

**目的**：从已知事实推导新知识

**推理类型**：

**生卒年推断**：
- 如果人物在某年任官，则该年人物活着
- 如果人物A是人物B的师父，且B书内年龄为X（%管道），则A的年龄段应≥X+合理师徒龄差（N4 年龄键核验）
- 如果人物参与某事件，则在事件发生时活着

**关系推断**：
- 如果A和B同门且同代（辈分树），则A和B是同门关系（姓氏/辈分推理 07b 联动）
- 如果A与B比武且A胜（N5 outcome 五值），则A与B是对手关系（matches 记录）
- 如果A授B武艺/收B为徒（04f 传授图），则A与B是师承关系

**事件关系推断**：
- 如果事件A是事件B的原因，事件B是事件C的原因，则A间接导致C
- 如果事件A和B同时发生，地点相邻，人物重叠，则可能是同一事件

**应用场景**：
- 补全知识图谱的空缺
- 发现隐含的关系
- 丰富实体属性

### 2.3 验证规则

**目的**：检查数据的合理性

**验证类型**：

**时间一致性**：
- 人物初登场回不能晚于其"已成名"叙事回（N4 叙事单调性）
- 事件发生时间不能早于参与者的生年
- 师承／效力关系必须在双方在世（书内时点）区间重叠

**关系一致性**：
- 父子关系不能成环
- 一个人不能同时是另一个人的师父与弟子（师承环检测）
- 对手关系应该是对称的

**逻辑一致性**：
- 同一人物不能同时出现在相距超过一日脚程的两地（N4 时点+gazetteer 距离）
- 事件的参与者必须已登场（初登场回≤事件回）
- 门派职衔的授予者必须是该门派掌门/长辈（世系表联动，07 组）

**应用场景**：
- 数据导入时验证
- 定期数据质量检查
- 发现标注错误

## 三、技术基础

### 3.1 规则语言

计划使用的规则表达方式：

- **SWRL（Semantic Web Rule Language）**：标准的语义Web规则语言
  - 与OWL本体集成
  - 支持推理引擎执行
- **SPARQL Rules**：基于SPARQL的规则定义
- **Python规则引擎**：灵活的自定义规则实现

### 3.2 数据准备

本功能依赖已完成的工作：

- **本体模型**：类、属性、关系定义（见 `SKILL_06a_本体总览_武侠版.md`、`SKILL_06b_属性关系约束构建_武侠版.md`）
- **实体数据**：已标注的实体和关系（见 `SKILL_03a_实体标注.md`、N5 `relation_validator`）
- **领域知识**：批次裁定记录（docs/NN）与 07e 真实性评级、references 规律库

## 七、规则示例

以下为规则的概念性示例（非实际代码）：

### 示例1：祖父关系推理
```
IF 人物A 是 人物B 的父亲
AND 人物B 是 人物C 的父亲
THEN 人物A 是 人物C 的祖父
```

### 示例2：先秦人物标记
```
IF 人物X 时点键 越出该书纪年轴
THEN N4 报 E 类越界错误
```

### 示例3：时间一致性验证
```
IF 人物A 初登场回 > 其"已成名"回
THEN 报错 "叙事单调性矛盾"（N4 口径）
```
