## 一、定位与边界

### 1.1 工序位置（实体层与关系层的桥）

```text
03a 标注（实体令牌）→ 03b 消歧（规范名/管道/登记层）
        ↓
02i 指代消解（本文）──→ registry/coref/<书>.json（指称链/先行词/置信）
        ↓
04a 事件（谁做了什么）· 05 关系（谁与谁）· 03l 统计（他/她归到谁名下）
        ↓
L2.5 跨书全局人物索引（本文 L3 层，服务系列页/搜索/问答）
```

### 1.2 本文做什么

1. **指代识别**：代词/称谓/省略主语/群体指代/跨书指代五类；
2. **先行词消解**：按四层架构给出 antecedent 与置信（strong/ok/todo）；
3. **回级默认指代**：建立"场景在场人物表"，为"掌门/师父/师兄/老贼"给出回级默认；
4. **L2.5 跨书索引**：把书内 canonical 挂到系列身份（消费 03b/D07），支持跨书指代与同名异人限定；
5. **产出指称链**：`registry/coref/<书>.json`，供事件/关系/统计/问答消费。

### 1.3 本文不做什么（边界）

| 不做 | 归属 |
|---|---|
| 标注实体令牌/改管道 | SKILL_03a / SKILL_03b（本文只读 tagged） |
| 人名消歧（称名→canonical） | SKILL_03b |
| 关系/事件抽取 | 04a/05（本文只供"谁"） |
| 跨书身份最终归并 | D07 `series_identities`（本文 L3 层消费其成员） |
| 标点/结构/围栏处理 | 02ab |
| 语义角色标注（施事/受事） | 关系层（本文只在必要时给"动作主语"证据） |

### 1.4 关键约束

- **只读输入**：tagged/struct/registry 只读；输出写 `registry/coref/`（v0.1 约定）或日志；
- **链不相交**：同一 mention 只能挂一个 antecedent；歧义即 `todo` + 候选列表；
- **置信分级必须可解释**：strong=语法/同位/明示；ok=回级默认+唯一性；todo=多候选/跨书推断；
- **不改写原文**：指称链是旁挂索引，剥标正文零变化。

## 三、消解对象类型学

| 类 | 形态 | 例 | 首选证据 |
|---|---|---|---|
| C1 人称代词 | 他/她/其/之/他们/她们/我等/咱们 | "他提剑上山" | 句法邻近 + 性别/人数一致 |
| C2 文言/礼貌称谓 | 兄台/前辈/阁下/老丈/先生/姑娘/施主 | "前辈有何吩咐" | 对话对象 + 回级场景 |
| C3 身份/角色默认指代 | 掌门/师父/师兄/师姐/帮主/舵主/总镖头 | "师父说得是" | **回级场景在场人物表**（§五） |
| C4 省略主语/零代词 | "（他）提剑便刺" | 连续动作句 | 上句主语延续（同段优先） |
| C5 群体指代 | 群豪/众弟子/各派掌门/众人/两人 | "群豪齐声喝彩" | 群体类型（◎/◆ 或"各派"集合）+ 回级在场 |
| C6 跨书指代 | "当年白发魔女如何如何""拙著《萍踪》中那位大侠" | 互文引用 | L3 系列索引 + D07 互文表（authorial/quoted） |
| C7 描述性代称 | 那汉子/白衣少女/老者/少年 | "那汉子退了一步" | 回级唯一性（03a D1：描述代称不标实体，但可消解） |
| C8 同形异人 | 两个"铁掌"、孪生姐妹 | 见 03b §六 | 同名组 + 回级身份线索 |

> 注意 C7：D1 告示"描述性代称不标实体"是标注层规则；指代层可把其挂到已标实体（如"那汉子"→前文 `〖@某甲〗`），但**不得因此回标实体令牌**。

## 四、四层消解架构

### 4.1 层与规则

| 层 | 名称 | 规则 | 置信上限 |
|---|---|---|---|
| **L1** | 句法邻近 | 同句优先：同位语（"X，这位…"）、并列主语、代词紧邻先行词；邻句次之；同段再次 | strong/ok |
| **L2** | 回级映射与默认指代 | ①已核准映射表（绰号→本名，03b）；②称谓表 + 回级场景在场人物（§五）；③同名异人限定词 | strong（映射直证）/ok（唯一默认） |
| **L3** | 跨书全局人物索引（L2.5 新层） | 书内 canonical → 系列身份（D07 members）+ 互文引用表（authorial/quoted）；跨书指代与检索 | ok/todo（跨书只降不升） |
| **L4** | 人工裁决 | 多候选/冲突/历史疑难；输出人工队列 | — |

### 4.2 置信度三级（照搬 + 武侠化）

| 档 | 条件 | 处置 |
|---|---|---|
| strong | L1 同位/明示判同；L2 已核准映射直证 | 可直接入链，抽检 |
| ok | 回级唯一默认（同一场景唯一"掌门"）；L2 称谓表唯一 | 入链，标注"默认指代" |
| todo | 多候选、性别/人数冲突、跨书推断、C6 存疑 | 不入链或入"候选链"，人工复核 |

### 4.3 判定顺序（不可交换）

```text
L1 命中 → 定案（strong/ok）
  否则 L2 映射/回级唯一 → 定案（ok；映射直证 strong）
  否则 L3 跨书索引唯一且非同名异人 → 候选（ok/todo）
  否则 L4 人工（候选列表 + 证据片段）
```

> 与 03b 同纪律：**证据不足不猜**。宁可 todo，不可错挂——指代错挂会污染事件/关系/统计三条下游。

### 4.4 冲突检测（自动拦截）

- 性别/人数不一致（他 vs 她、单数 vs 复数）；
- 身份/门派不一致（"武当掌门"默认指代到少林人物）；
- 同名异人未加限定（C8）；
- 跨书指代未在互文表/系列索引中登记（C6）；
- 同一 mention 多 antecedent 且无 tie-breaker → todo。

## 五、L2 回级默认指代（武侠场景核心）

### 5.1 场景在场人物表（per 回/场景）

每回按 PN 段维护"在场人物 + 身份/称谓"表：

```json
{
  "book": "江湖三女侠", "chapter": 12,
  "scene_pn": "jianghu#pn-r12.3",
  "present": [
    {"entity": "吕四娘", "roles": ["掌门?"], "aliases_in_scene": ["吕四娘", "吕姑娘"]},
    {"entity": "冯瑛", "roles": ["弟子"], "aliases_in_scene": ["瑛儿"]}
  ],
  "role_defaults": {"掌门": "吕四娘", "师父": "吕四娘", "师兄": null}
}
```

### 5.2 默认指代规则

1. **唯一性优先**：同一称谓在场景内唯一指向 → ok；多个同称谓 → todo；
2. **身份约束**：称谓需与角色匹配（"掌门"→门派掌门；"师父"→师徒关系已登记或回内明示）；
3. **场景切换重置**：新 PN 段/新场景（"花开两朵"式转场、地点变化）→ 在场表重建；
4. **跨回不默认**：上一回的"掌门"默认不得带入下一回（除 03b 已核准映射）；
5. **群体称谓**（群豪/众弟子）：挂群体实体（◎/◆）或"在场集合"，不挂个人。

### 5.3 与 03a D1 的关系

- D1 规定**标注层不标**纯礼貌/纯关系/描述代称；指代层可消费这些词做消解，但**不得回标**；
- "掌门/师父/师兄"若在标注层已标 `〖;职衔〗`，指代层以职衔 token 为锚；未标则以词面 + 场景表为锚。

## 六、L3 跨书全局人物索引（L2.5 新层）

### 6.1 索引结构（v0.1 约定，目标对齐 D07 两表）

```json
{
  "series_id": "E-P-0007",
  "display_canonical": "飞红巾",
  "members": [
    {"book": "塞外奇侠传", "book_canonical": "哈玛雅", "aliases": ["飞红巾", "哈玛雅"], "conf": "strong"},
    {"book": "七剑下天山", "book_canonical": "哈玛雅", "aliases": ["飞红巾"], "conf": "ok"}
  ],
  "sources": ["registry", "series_identities(v1.0 后)"],
  "same_name_group": null
}
```

### 6.2 规则

1. **来源优先级**：D07 `series_identities`（v1.0 后）> registry canonical+aliases（v0.1 过渡，标 `merge_source=temp`）；
2. **同名异人**：不同 series_id，互不消解；跨书指代必须带限定（03b §六/跨书治理 §5.4）；
3. **跨书指代判据**：互文引用表 authorial（E1）> quoted（E3）> 读者推断（E4 不落盘）；C6 mention 挂系列身份需 03b 证据级支撑；
4. **展示 vs 索引**：跨书索引键用 canonical（本名优先，03b B-1 待确认口径），展示名可不同（B-1 展示层）；本文只消费键，不决定展示；
5. **同书内多 canonical**（晦明/岳鸣珂类）→ 先书内 canonical，再挂系列身份，禁止全库同一化。

### 6.3 与 03b 的分工

- 03b：称名→书内 canonical / 系列身份（生产登记层）；
- 02i：指代词/省略/跨书 mention→antecedent（消费登记层）；
- 两者共享"双层 canonical"与"同名异人"规则；02i **不重新判定身份**，只引用。

## 七、代词/称谓表（半保留原则）

### 7.1 可消解代词（保留）

| 类 | 词 | 备注 |
|---|---|---|
| 人称 | 他/她/其/之/我/你/我们/你们/他们/她们 | 单复数、性别约束 |
| 文言 | 其/之/彼/此/吾/汝/尔/君 | 梁书半文半白，保留但降置信（需 L1 强证据） |
| 群体 | 众人/群豪/众弟子/各派掌门/两人/三人 | 挂群体 |

### 7.2 不消解/不标（D1 一致性）

- 纯礼貌称谓（先生/小姐/前辈/阁下/老丈）→ 仅在对话对象明确时 ok，不默认；
- 纯关系词（父亲/儿子/师兄/岳父）→ 无姓名时按场景默认，但**不产生实体**；
- 评价代称（老贼/女魔头/蛮子）→ 只在回内唯一且前文已标实体时消解（todo 起步）；
- 描述代称（那汉子/白衣少女）→ 回内唯一性 + 描述特征匹配，否则 todo。

### 7.3 表维护

- 代词表/称谓表为 v0.1 静态种子（本文件 §7.1/7.2）；扩充走词表任务（WL 体系）；
- 任何新增需附一条语料反例；不得因"模型常见"而扩容（防白名单化）。

## 八、算法与流程（规则优先）

```text
① 预处理：读 struct（PN）→ 切句/段；读 tagged 令牌（实体/动词）→ 建 mention 候选
② L1：句内同位/并列 → 邻句 → 同段（最近先行词 + 性别/人数一致）
③ L2：映射表（03b）→ 称谓表 + 场景在场表（唯一默认）
④ L3：跨书索引/互文表（只对 C6/C8）
⑤ 冲突检测：§4.4 五条；冲突 → todo
⑥ 输出：指称链 + 报告（覆盖率/置信分布/待人工清单）
⑦ 抽检：strong ≥95%、ok ≥90%（抽 10%）
```

**自动化边界**：L1/L2 可规则化；L3 只产候选；L4 人工。**LLM 仅作候选生成/疑难复核，不入主链**（v0.1 定位：规则优先、可解释优先）。

## 十三、FAQ（首批 7 问）

**Q1 为什么不直接让 LLM 做指代消解？**
v0.1 以规则+可解释为先（下游是事件/关系/统计，错挂代价高）；LLM 只做候选/疑难复核，且需与规则结果对账。

**Q2 "掌门"到底指谁？**
看回级场景在场表：场景内唯一掌门 → ok；多个 → todo；跨回不默认。这是 docs/05 要求的"回级默认指代"。

**Q3 跨书指代（"当年白发魔女"）怎么挂？**
先查互文引用表 authorial/quoted + 系列索引（L3）；无证据不挂（E4 读者推断不入链）。

**Q4 描述代称（那汉子）能消解吗？**
能（回内唯一+特征匹配），但不回标实体令牌（D1）。

**Q5 指代链和 03b 的管道是什么关系？**
03b 生产"称名→canonical"映射；02i 消费它来消解代词/省略/称谓；02i 的链又可反过来给 03b 作回级证据。

**Q6 输出写哪里？会不会改 tagged？**
写 `registry/coref/<书>.json`（v0.1 约定）与报告；**只读 tagged/struct**，不改任何标注（剥标断言）。

**Q7 什么时候能用 L2.5 跨书索引？**
v0.1 用 registry aliases 临时聚合（标 `merge_source=temp`）；D07 `series_identities` 落地后切真源（标 `merge_source=series`）。
