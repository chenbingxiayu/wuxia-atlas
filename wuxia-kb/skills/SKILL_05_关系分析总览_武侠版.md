## 二、快速开始（五步操作序）

> 目标：对一本已有事件/动词标注的书，跑通关系层"候选→核验→落库→校验→消费准备"。命令只读或只写 registry 产物（N5 默认写 `registry/relations/`，不改语料）。

```powershell
cd C:\Users\YANG Ruosong\Documents\workspace\Wuxiaxiaoshuo\wuxia-kb
$env:PYTHONIOENCODING='utf-8'

# Step 1 前置就绪：结构门 + 动词校验（联动候选的上游）
python -X utf8 scripts\pipeline_wuxia.py 白发魔女传 check
python -X utf8 scripts\validate_verb_tagging_wuxia.py --book 白发魔女传

# Step 2 关系核验器自检
python -X utf8 scripts\relation_validator.py --selftest

# Step 3 单书/全部落库（--chapter 仅调试，写 logs/relations/_debug）
python -X utf8 scripts\relation_validator.py --book 白发魔女传
python -X utf8 scripts\relation_validator.py --all

# Step 4 读产物：counts / validation / derived / dropped
python -X utf8 -c "import json;d=json.load(open('registry/relations/白发魔女传.json',encoding='utf-8'));print(d['counts']);print(d['validation'])"

# Step 5 严格门禁（仅 27 行规则 + strong/ok；hard 校验失败 exit 1）
```

**判读口径**：Step 4 的 `counts` 看候选/落库/放弃比；`validation.hard_errors` 必须为 0；`dropped` 按原因分类（无事件层支撑的仇怨/毁损等只记候选放弃，见 docs/56 §五遗留）。**N5 尚无 pipeline 阶段**，不要写成 `pipeline relation-validate`（不存在）。

## 三、关系层架构（三层分治 + 双树 + 离线表）

### 3.1 三层分治（D06 §7.1 层别三分）

| 层 | 范围 | 谓词数 | 代表谓词 | 证据特点 |
|---|---|---|---|---|
| 事件层 | E↔E | 12 | sequel/causal/part_of/opposition/cross_ref/concurrent/inherit/foreshadow | 事件锚，明文为主 |
| 实体层 | 含 P→L、P→O、O→O、T→T、P→I 等 | 22 | 辖属/统属/山门/到达/离开/所在/掌握/持有/转移/组织成员/任职/隶属终止/异名 | 动作+共现可入 |
| 人物层 | P↔P/G 的名分与事实边 | 21 | 师承/传授/结义/结盟/敌对/配偶/婚约/收养/亲属/仇怨/同门/冒名/杀害/治愈/投毒/拘押/解救/押送/交手/点穴/同行 | 名分类须明文（E1） |

> 合计 **55 条 SPO 谓词 + 4 条离线接口行**（情感/恩义/背叛/主仆；不计入 SPO 数）。**谓词不混层、表结构分离**：事件关系边、实体关系边、人物关系边分别落表，不合并成一张大边表。

### 3.2 双树（D06 §五）

- **血缘树**：亲属（父子/母女/兄弟/祖孙…）+ 配偶 + 婚约 + 收养；婚姻边跨家族连接两棵子树。
- **师承树**：师承（含终止事由逐出/叛门/自立）+ 推导层（同门/辈分）；传授/修习**不入树**（非名分关系）。
- 两棵树都是 L2 关系层之上的**视图**：底层同用 55 谓词总表，不设第二套边表。

### 3.3 情义层离线表（D06 §六）

情感/恩义/背叛/主仆四类**不进行内标注、不进 lint 符号体系**，走离线关系表（稳定键 = subject, object, type, episode）。理由：四类是过程性/状态性关系（"救/叛/赠/辱/爱/恨"无单点文本锚点），本体是 states 时间序列，表结构才能承载状态机。

## 四、谓词总表分组速查（55 条，全表见 D06 §7.2）

### 4.1 事件层 12 条（E↔E）

| # | 谓词 | 方向/对称 | 要点 |
|---|---|---|---|
| 1 | sequel | →/✗ | B 晚于 A 且直接相承 |
| 2 | causal | →/✗ | 四步检查通过方立 |
| 3 | cross_causal | →/✗ | 五子类单选；cross_ref≠因果 |
| 4 | part_of | →/✗ | 粒度差 ≤1 层 |
| 5 | opposition | ↔/✓ | 双方行动均有记述 |
| 6 | cross_ref | ↔/✓ | 同一事件多叙述 |
| 7 | co_person | ↔/✓ | 候选边，**永不推人物关系** |
| 8 | co_location | ↔/✓ | 自动（共地+共人），高频加严 |
| 9 | concurrent | ↔/✓ | 两端时点键对齐 |
| 10 | inherit | →/✗ | 一对象一事件至多一传承源 |
| 11 | foreshadow | →/✗ | 须有回收端明文 |
| 12 | cross_book_ref | ↔/✓ | 跨书呼应，待 #7 |

### 4.2 实体层 22 条（D06 §7.2 #13-#34）

辖属（L→L）、统属（O→O）、山门（O→L）、练功地（P→L）、决战地（E→L）、到达、离开、所在、层级隶属（T→T）、创派（P→T）、归属（T→O）、掌握（P→T）、修习、持有（P→I）、制造、转移（施者→受者，物为参数）、组织成员、任职、继任、隶属终止、群组成员、异名（实体↔实体）。

> **转移**是三元谓词的二元核：`转移(赠者,受者)`＋物与 mode（赠/夺/借/传）为参数；九组动词全落位（D06 §7.3）。

### 4.3 人物层 21 条（D06 §7.2 #35-#55）

师承、传授、结义、结盟、敌对、配偶、婚约、收养、亲属、仇怨、同门（derived）、冒名、杀害、治愈、投毒、拘押、解救、押送、交手、点穴、同行。

> 关键裁决：**师承≠传授**（传授不自动建师承）；**交手不自动敌对**（一次交手只记交手边）；**仇怨 event_ids 必填**（须定位结怨事件）；**同门 derived 不直接登记**。

### 4.4 命名与落位纪律（D06 §7.1/§7.3/§7.4）

1. 谓词=双字中文动词性/名词性词；事件动词（夺/毁/铸/败）不作 SPO 谓词；
2. 每条谓词标主语类型→宾语类型（P 人物/O 组织/L 地点/I 物件/T 技术/E 事件/G 人物组）；
3. 04f 已用名**零改名**（师承/结义/配偶/任职/隶属终止/杀害/治愈/投毒/转移/押送/交手/点穴/掌握/传授/到达）；
4. 新增谓词须过命名检查（与 04f/01g 已用名冲突即弃用改词）。

## 五、双树与辈分推导

### 5.1 辈分推导规则（D06 §5.3，B1-B8）

| 规则 | 推导 | 条件 |
|---|---|---|
| B1 师祖 | A 师承 B ∧ B 师承 C ⇒ A 辈分含"师祖 C" | 两步均 active 或历史有效 |
| B2 师叔伯 | 师父的同门同辈者 ⇒ 我之师叔伯 | 同师或同派同辈档 |
| B3 亲同门 | 同一师父 ⇒ 亲同门（对称） | 双方师承边指向同一师 |
| B4 门派同门 | 同门派 ∧ 同辈分档 ⇒ 门派同门 | 明文同派+代数相同 |
| B5 长幼序 | 同师同辈按拜师事件时序排 | 拜师时点均有定位 |
| B6 辈分档 | 师承代数（自树根递减）决定辈分档 | 树根=创派祖师或最早明文师承 |
| B7 逐出/叛门 | 边 terminated；历史同门保留，现役派生失效 | 终止事由已登记 |
| B8 明文论辈 | 明文"论辈分/师侄"按明文记标签 | 有定位的明文 |

### 5.2 双树交叉裁决（D06 §5.4，X1-X4）

- **X1 父子同为师徒**：两树各建边，互不合并；师承边注"家传"；
- **X2 夫妻同门**：婚姻边+同门推导并存，默认血缘树主显；
- **X3 血缘辈分 vs 师承辈分冲突**：**不跨树对齐**，各树自洽；问答按语义选树；穿帮雷达只审树内一致性；
- **X4 收养+师承**：收养边入血缘树、师承边入师承树，并存。

### 5.3 同构映射要点（D06 §5.2）

血缘树已验证的传递推理/无环检测/辈分推导三机制可整体映射到师承树；唯一实质破缺="师父可换"带来的时段切片，以边状态（active/terminated）+时段字段解决，机制不新增。

## 六、情义离线表（D06 §六）

### 6.1 schema 要点

稳定键 `rel_id`=（subject, object, type, episode）；字段：subject/object（canonical）、type（情感/恩义/背叛/主仆）、subtype、direction（single/mutual/unknown）、states（[{state, book, loc, quote?, event_ids?}] 时间序列）、manner、conf、evidence（多条、跨回聚合）、event_ids、related_predicates、notes。

### 6.2 四类与状态机

| 类 | 子型 | 参考状态链 | 自动推导度 |
|---|---|---|---|
| 情感 | 爱慕/暗恋/单恋/情侣/被拒/悔 | 相识→定情→误会→决裂→相望 | 低（正则仅候选） |
| 恩义 | 救命/赠宝/知遇/收留/欠债 | 受恩→感念→报偿→两讫 | 中低 |
| 背叛 | 叛门/叛友/出卖/反目 | 共事→裂隙→背叛→决裂 | 中低 |
| 主仆 | 主仆/护法/僮仆/依附 | 依附→效忠→背离/终老 | 中 |

> 五项验证属性：方向性=direction；对称性由 direction 表达；**四类一律不传递、不派生新边**；同对同型同时段仅一个 active episode；states 链单调推进。

### 6.3 与 04f 联动候选的边界（D06 §6.4）

- 治愈 → SPO 治愈边 ＋ 恩义候选（离线表人工裁定）；
- 转移(赠) → SPO 转移边 ＋ 恩义候选；转移(夺) → 仅实体层转移，不生成情感候选；
- 杀害/投毒 → SPO 入表；死者亲属仇怨**候选**→人物层仇怨边（人工裁定）；
- 交手 → SPO 交手边，**不自动敌对**；多次+明文 → 仇怨候选；
- 结义 → SPO 结义边，不进离线表。

## 七、证据与验证（D06 §八）

### 7.1 证据三级

| 级 | 定义 | 可入位置 |
|---|---|---|
| E1 明文 | 文本直接陈述关系 | 直接入 SPO（conf=强） |
| E2 动作+共现 | 事件动词+语义角色明确+双方在场 | 事件事实类 SPO（杀害/治愈/交手/转移…）；**不得单独确立名分类关系** |
| E3 推导 | 规则派生，附推导链与规则号 | 推导层，不直接登记 |

**铁律**：共现本身永远只是候选来源，不是证据（01g）；"倾囊相授/日夜苦练"只产传授/修习候选，永不直接落师承边。

### 7.2 候选→核验→入表（D06 §8.2）

1. 候选生成（04f 联动/§8.4 语式/事件动词+双方在场）→ 2. 语义角色核验（施受方向、三元参数）→ 3. 五属性校验（方向/对称/传递/互斥/时序）→ 4. 证据定级（E1/E2/E3）→ 5. 置信分配（明文强/动作中/推导弱）→ 6. 落位分流（SPO 登记层/离线表/候选池）→ 7. 推导层派生（derived）→ 8. 回扫校验。

### 7.3 传闻与视角降权（D06 §8.3）

"听说/据说/传言/江湖传闻/风闻" → 候选 conf≤弱，不得直接入正式表；人物自述关系按单方视角 direction=single 候选；**对话贬称不生成任何关系**；"一日为师终身为父"不生成（格言非事实）。
