# META-04 柳叶刀方法（武侠版）

---

## 一、核心思想（照搬）

**柳叶刀方法**（The Lancet Method）：将复杂 AI 任务进行**精细分解**、并针对每个子问题选择**最优解决方案**（大模型/规则/代码）的知识工程方法论。

核心原则照搬：**"手术刀式精准切分，而非大锤式端到端"**——模块化分解、细粒度建模（专门化微模型协同）、混合驱动（LLM 泛化 + 规则精确 + 代码效率）、快速迭代。方法论来源声明照搬（鲍捷 RegTech 知识抽取实践；反对端到端黑箱、倡导流水线分解、支持先验融合、强调可解释性）。

**武侠版加注**：多书虚构宇宙的"先验"比史书更丰富也更陷阱重重——词表/门派谱系是高质量先验（作者造词规整），但**从史记直接移植的领域正则（军事动词等）是伪先验**（见 §六.2）。柳叶刀的"先验融合"必须区分"从本语料学到的先验"与"从其他语料移植的先验"。

|------|---------|------|

```

    │   ├─ 是 → 【规则+LLM 联合】（规则筛选候选 + LLM 复核 + 抽验）
```

## 五、方法论指导（框架照搬，武侠例替换）

### 5.1 MECE 分解原则（照搬）

互斥性/完备性/可测试三原则照搬。武侠版 MECE 示例（替换源版事件对分解）：

```
跨书实体对(A, B)
  ├─ 书内 surface 是否直接相等？ → 是：书内 canonical 唯一性检查（代码）
  ├─ 是否内联消歧已绑定？ → 是：直接采信（L1，META-08）
  ├─ 字符有重叠？ → 是：前缀/包含规则候选（代码）+ 独占性校验
  ├─ 零字符重叠？ → 是：语式锚定候选（WL-11 grep）→ S1-S5 流程
  └─ 无任何字面信号？ → E3/E4 候选池（LLM 初筛 + 只登记不归并）
```

覆盖度检查照搬：全对数 × 处理分工的量化估算——武侠版按部×回估算（试点期只做书内，1 部书 N 回 → 书内实体对约 C(N×每回实体数, 2) 的共现受限子集；跨书对自第二部书起，**先经互文引用表 1,904 边剪枝**再进归并候选——这是武侠版的"规则前置筛选"（源版模式 1 的图剪枝应用）。

### 5.2 方法选择矩阵（照搬）

六维矩阵（精度要求/泛化能力/可解释性/迭代成本/处理速度/适用场景 × 规则/代码/LLM/混合）**逐格照搬源版**，无武侠改动。成本效益分析的结构照搬、数字待试点（见 §六.2）。

### 5.3 LLM×规则三协同（模式定义照搬，流程图武侠化）

- **模式 1 规则前置筛选 + LLM 精炼**：全库词表扫描 → 候选 → LLM 精炼（实例 1）
- **模式 2 LLM 生成候选 + 规则验证**：LLM 候选 → 语式/独占性规则收窄 → 人工裁决（实例 2；源版别名检测的"长名必须包含短名"验证规则在武侠**失效**——零重叠绰号不满足字符包含，验证规则换为语式共现 + 独占性，这是模式 2 内容而非结构的改动）
- **模式 3 规则兜底 + LLM 补全**：查表 → 约束 → LLM 兜底 → 人工（实例 3、4）

三模式的覆盖率分层记录格式照搬源版（规则 ~X% / 代码约束 +Y% / LLM 补全 +Z% / 人工 W%）——数字待试点回填。

### 5.4 迭代优化三阶段（照搬）

冷启动（规则优先：先词表后 LLM；小样本 LLM 处理未覆盖残余；100 样本人工评估）→ 扩展（LLM 成功案例转化为新词表条目/规则——武侠版落点：进 `wordlists/*_source.md` 人工源，三档 watch→review→auto 升档走 D09 运营；异常沉淀；批量化与缓存）→ 收敛（词表固化覆盖 95%+，LLM 只处理长尾，分布偏移监控）。

### 6.1 分模块测试（照搬，武侠例）

```python
# 单元测试示例（结构照搬，断言武侠化）
def test_move_surface_match():
    assert surface_match("怪蟒翻身", "怪蟒翻身") == 1.0      # 精确命中
    assert surface_match("怪蟒翻云", "怪蟒翻身") < 0.8       # 近形不同招：不得自动判同

def test_alias_zero_overlap():
    # 零字符重叠对（玉罗刹↔练霓裳）禁止走字面相似度自动归并
    assert not auto_mergeable("玉罗刹", "练霓裳")

# 集成测试示例
candidates = wordlist_scan(book)          # 规则层
refined = llm_refine(candidates)          # LLM 层
assert recall(candidates, gold) > 0.9     # 词表层召回底线
assert precision(refined, gold) > 0.85    # 精炼层精度目标
```

### 6.2 对照实验与"$41,000 vs $380"教训（**保留 + 武侠化注解**）

**源版教训原文保留**：纯 LLM 方案成本 $41,000、耗时 11 小时；混合方案 $380、1 小时，精度/召回/成本三维最优。结论照搬：**结构化任务优先代码实现**。

**武侠化注解（迁移教训，本文件最重要的实例层记录）**：决策（"结构化任务用规则"）可以照搬，**规则内容不能照搬**。史记军事动词正则库（攻/伐/击/围/灭）移植武侠语料即失效：

| 失效方式 | 例 | 说明 |
|---|---|---|
| 高频动词语义更迭 | "攻山""攻破分舵"仍可复用，但**单挑动词全换**：使出/点倒/递招/劈掠/震住 | 战斗粒度从"万人大战"变"单挑/群殴/大战"三级，源版正则只覆盖最粗一级 |
| 动作-招式耦合 | "一剑刺出""掌力到处""使出天外飞仙"——动词与 ☆ 招式名黏连 | 源版"交战方正则"（邦国名+军事动词）在武侠连交战方都常是个人绰号 |
| 结果动词主导 | 点倒/制住/重伤/毙于掌下——武侠以**结果**定主域（04f"结果决定主域"三问） | 源版过程动词库无结果维度 |

**教训制度化**：领域模式库必须从目标语料重新学习（04f 六域种子词表约 140 词三档 = 重学习产物；触发语式进 WL-11 语式表而非硬编码正则）；对照实验（纯 LLM / 纯规则 / 混合三方案对比）的方法照搬，A/B 表结构保留，数字待试点。试运行前先做"移植正则召回率探针"——旧正则在 3-5 个试点回上的命中率低于阈值即弃用，防止伪先验静默拖垮召回。

### 6.3 可追溯性设计（照搬）

输出标记来源（`source: rule|code|llm|manual`、confidence、rationale、validation）的 JSON 结构照搬；审计报告结构照搬（来源分布表：auto_rule/auto_code/llm_infer/llm_refine 数量占比与平均置信度）。武侠增补一个来源档：`merge_evidence`（归并类输出额外记录 D07 证据级 E1-E4 与证据锚点——归并决策的追溯粒度比一般关系更严）。

## 七、典型反模式（照搬 + 武侠注解）

1. **过度依赖 LLM**——后果四条照搬（成本爆炸/速度慢/不稳定/难调试）。武侠例：用 LLM 判断"时点 A 是否早于时点 B"（D05 单调性校验是纯代码，0.001 秒）；正确做法照搬源版对照格式。
2. **规则过度工程**——为每个边界情况写规则，规则库膨胀。武侠例：为每个绰号各写一条别名规则（源版 644 条错误 ↔ 武侠版"为每部书硬编码武功/门派名单"）；正确做法：WL-01 数据表 + WL-11 语式 + 三档运营。
3. **黑箱流水线**——中间结果不可见/误差传播/无法归因。对策照搬：每阶段输出中间文件（词表 JSON、候选池、登记表），支持断点续跑。
4. **盲目端到端**——单大模型解决一切。对策照搬：模块化流水线 + 混合驱动。武侠加注：端到端在虚构宇宙的额外诱惑是"LLM 读过原著"——作者设定的长尾知识确实在模型参数里，但**不可验证、不可审计、版本漂移**，仍只能做兜底不能做主路径。

## 八、进阶：自动化决策框架（照搬）

任务特征向量（确定性/规则复杂度/语义深度/数据规模/时效要求/成本敏感度）六维定义照搬。

`select_solution()` 决策表**照搬**：

```python
def select_solution(task_features):
    if task_features['deterministic'] > 0.9:
        return 'rule_based'          # 例：朝代锚匹配、单调性校验
    if task_features['semantic_depth'] >= 2 and task_features['samples'] < 100:
        return 'llm_based'           # 例：跨书归并暗示复核（候选稀少）
    if task_features['scale'] > 100000 and task_features['latency'] < 60:
        return 'code_optimized'      # 例：1,378 回全库词表扫描
    if task_features['rule_complexity'] == 'high' and task_features['generalization'] == 'high':
        return 'hybrid'              # 例：绰号消解（语式规则 + 语义 + 人工）
    return 'hybrid'
```

动态调整与预算驱动降级照搬（精度不足升混合、召回不足 LLM 兜底；预算 50%/90% 两档切换 LLM→混合→规则）。武侠增补一条降级护栏：**降级只允许降"检查深度"，不允许降"归并裁决"**——预算耗尽时归并候选拿 E4 登记不入 canonical，宁可不归并不错归。

## 快速开始

1. **锁边界**：从 `docs/17` 拓扑表挑一个可切分节点（如 N4 时间轴、N8 穿帮引擎），写清"输入 / 输出 / 不做什么"三行，避免把整本书当一次任务。
2. **做 MECE 分解**：按「对象（实体/关系/事件/时间）× 范围（书内/跨书/系列）」切到叶子，每叶以"一人日可验证"为粒度（§三实例 1-4 即叶子样例）。
3. **选实现路线**：查 §5.2 方法选择矩阵，在 LLM / 规则 / 混合之间勾选一种；把选择理由与反例写进任务卡，不从"看起来高级"倒推。
4. **先冻结基准**：准备 3-5 回试点 + 独立金标准/人工抽样；所有指标同时给出分母与统计口径（§6.2、§6.3）。
5. **跑最小闭环**：一个节点 → 一个脚本或实验 → 一条指标回归 → 登记 `docs/17` 状态表与批次报告；未闭环不扩面。
6. **复盘升级**：未达「成功标准」时先排查 §七 反模式，再决定改方法/加数据/加人力，禁止直接堆人力。

## 成功标准

- **可复现**：同一问题在 3-5 回试点上重复 ≥2 次得到同类结论；换书后指标差异可解释。
- **有分母**：召回/精度/覆盖率/成本四类指标均给出分母与抽样口径，禁止只报分子。
- **可验收**：节点交付物通过 acceptance `hard=0`、五门 lint 全 0，抽样硬违例 0；回归前后对比有 JSON。
- **可复用**：沉淀 ≥1 条 03c1 候选规律或 `docs` 方法条目，被下一节点/下一部书直接引用。
- **可止损**：出现反模式或 G 源误报时能在一天内定位并回滚，不用"再试一次"掩盖问题。
