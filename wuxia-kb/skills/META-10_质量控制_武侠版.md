# META-10 质量控制（武侠版）—— 自动化质检体系与工具链设计

---

## 零、什么是质量控制（照搬）

**质量控制（QC）**是通过自动化脚本在数据生成/修正的每个环节进行格式/逻辑/一致性检查，及早发现错误，降低人工审核成本。

### QC vs 反思分工表（照搬）

| 维度 | 质量控制（QC） | 反思（Reflection） |
|------|-------------|------------------|
| 检查对象 | 格式、边界、数据完整性、规则违反 | 语义准确性、分类正确性、内容合理性 |
| 执行方式 | 规则脚本自动化（lint/validate） | Agent 驱动的智能审查 |
| 时机 | 每次数据变更后立即执行 | 初次生成后、迭代修正前 |
| 成本 | 极低（秒级，无 LLM 成本） | 中高（分钟级，有 LLM 成本） |
| 可解释性 | 100% 可解释 | 部分可解释 |
| 典型输出 | PASS/FAIL + 位置 + 修复建议 | JSON 修正建议 + 新错误模式 |

**协同三关系**（照搬）：QC 先行（格式错误 100% 消除才进反思）；反思发现的可规则化错误模式沉淀为新 QC 规则；QC 验证反思成果。武侠增补一条（D11 定版衔接）：**"设定内合理 ≠ 现实合理"的九类方向反转（一夜千里/闭关十二年/驻颜术等）默认不扫描**——QC 规则库中此类豁免条款必须显式登记，防止把设定内合理误报为 error（这是反思→QC 沉淀时最容易踩的方向性错误，见 D11 §1.4 方向反转总声明）。

## 一、质量控制的五个层次（骨架照搬；L4 武侠具体化）

```
L5  跨工序一致性（Cross-Phase Consistency）
     ├─ 标注文本 ↔ 实体登记表（书内层）双向一致
     ├─ 事件故事时间 ↔ 时间体系（D05）登记一致
     ├─ 关系三元组 ↔ 实体存在性 + D06 谓词总表合法
     └─ 书内 canonical ↔ 系列层归并状态一致（D07）

L4  业务逻辑验证 = 设定一致性（武侠具体化，源版为时序/年份逻辑）
     ├─ 人物年龄跨回自洽（D11 检查项一）
     ├─ 武功习得顺序：未学先使检测（D11 检查项二）
     ├─ 门派存续期：灭派后再出场（D11 检查项三）
     ├─ 死亡角色再出场（D11 检查项四）
     ├─ 称谓辈分错乱（D11 检查项五）
     └─ 朝代锚与外部史历校验（设定基准表，见实例 2）

L3  数据完整性（Data Integrity）
     ├─ 事件/登记条目必填字段非空（04a 36 行字段总表为 Schema 依据）
     ├─ 值域约束（回号 1-1378、置信档位枚举 strong/ok/weak、状态枚举）
     └─ 外键完整性（招式表 parent_art/sect → WL-07/WL-08）

L2  语法正确性（Syntax Correctness）
     ├─ 标注边界完整（〖〗⟦⟧〘〙成对闭合、无嵌套、不含标点）
     ├─ TYPE 位合法（15 实体码 + 6 动词码 + 修辞码；旧符号拦截）
     └─ Markdown 结构合法（围栏类型枚举、PN 两级编号、回目三约定）

L1  文本完整性（Text Integrity）
     ├─ 编码正确性（UTF-8 无乱码）
     ├─ 原文不变性（去标记后与底本逐字相同）
     └─ 文件存在性（config 注册表 34 部路径齐全）
```

**执行序（"低层不过不查高层"，照搬原则、链条武侠化）**：

```bash
python scripts/lint_text_integrity.py      # L1: 文本/底本完整性
  && python scripts/lint_symbol_conflicts.py   # L2: 符号/边界/旧符号
  && python scripts/lint_markdown.py           # L2: Markdown 结构
  && python <validate_schema 系>               # L3: 数据完整性（待建）
  && python scripts/lint_consistency.py        # L4: 设定一致性（N8，待建）
  && python <cross_validate 系>                # L5: 跨工序一致性（待建）
```

上一级 FAIL 即停（fail fast），避免噪音。L4 在武侠执行序中**前移到跨工序检查之前**且同样服从"低层不过不查高层"：L2 符号错误未清零时跑 L4，会把边界损坏误读成死亡再现（如闭合丢失导致出场事件解析错位）。

## 二、质量控制工具的设计模式（照搬）

### 2.1 设计规范（照搬）

- **命名规范**照搬：`lint_*.py`（工序内格式/语法）、`validate_*.py`（数据完整性与业务逻辑）、`cross_validate_*.py`（跨工序一致性）。
- **输入输出约定**照搬：单文件/目录/`--all` 三档；PASS 返回码 0，FAIL 返回码 1。武侠增补：`--book <书名>` 单书过滤为多书语料标配（已移植脚本均已实现）。
- **输出格式标准**与 **ERROR/WARNING/INFO 分级**照搬（ERROR 必须修复阻断发布；WARNING 应修复不阻断；INFO 仅提示）。输出示例武侠化：

```
文件：tagged/白发魔女传/001.tagged.md

❌ 错误 [L2-边界完整性]
  第 42 行：未闭合的人物标注
  位置：练霓裳纵身而出〖@白发魔女
  建议：补全闭合符号 → 〖@白发魔女〗

⚠️  警告 [L2-旧符号]
  第 87 行：TYPE 位出现已废弃历史符号（symbols.py LEGACY 实体码命中）
  内容：（示例略——具体码位以 symbols.py LEGACY_* 登记为准）
  建议：按现行符号表改标或删除（天象内容并入专门概念子型，不设顶层类型）

ℹ️  信息 [统计]
  实体标注：1,234 / 动词标注：356 / 修辞标注：42
  错误：2 / 警告：1
```

### 实例 1：`lint_symbol_conflicts.py` — 符号与边界检查（L1-L2，已移植）

**源版对应物**：`lint_markdown.py` 十八类符号正则检查。**武侠重写要点**（移植记录，脚本头注同步）：

1. **零内联字符类纪律**：源版 5 处内联实体字符类（与定版漂移、多处缺项）全部改为 `import symbols` 动态构建——TOKEN_RE 剥令牌，ENTITY/VERB/RHETORIC_CODES 构建检测正则。**这是源版"规则内嵌即腐化"教训的制度化**：符号定版改了，检测自动跟随。
2. **检查项**（对照源版四项，武侠增删）：
   - 原文字符完整性（L1，照搬）：底本字符不得被标注吞噬
   - 令牌闭合/嵌套/标点入标注/Markdown 入标注（L2，照搬）
   - 半角标点与直角引号检查（L2，武侠新增——章回体底本高频）
   - **旧符号拦截**（L2，武侠新增）：LEGACY_VERB_CODES（旧动词符号族，六枚）与 LEGACY_ENTITY_CODES（已废弃历史顶层符号族，五枚）出现在 TYPE 位即 ERROR；LEGACY_BRACKET_STYLES（旧式包裹风格）即 ERROR——史记体系残留检测，具体码位以 `symbols.py` 登记为准，本文不誊抄
   - 身份/称谓/群组、事件状态与时空五类语义检测（L2，照搬源版第五章思路，判定细则引 01g §五）

## 四、L4 设定一致性层（**补写：武侠硬缺口的方法论落位**）

### 4.1 为什么 L4 要重建

源版 L4 = 时序/年份业务逻辑（后序事件不早于前序、生年 ≤ 卒年）——它依赖**统一公元纪年**这一外部真值。武侠没有统一纪年（书内相对时间 + 可选朝代锚），却多出一类源版完全没有的逻辑约束：**作者设定内部的自洽性**。这一层已在 `SKILL_常识与设定一致性_武侠版.md`（D11，v0.3-draft 定版）完成设计，本节只做**映射**，不重复其规则内容。

### 4.2 D11 五项检查 → L4 检查清单映射

| D11 检查项 | L4 检查对象（消费的上游数据） | 严重度入口（D11 定版） |
|---|---|---|
| 检查项一：人物年龄跨回自洽 | D05 年龄锚差 vs 时点差（±1 年容差）；04a 叙述模式过滤豁免；闭关/驻颜照记不豁免数字自洽 | error=已核实级两锚矛盾；warning=声称级冲突；info=约数偏差 |
| 检查项二：武功习得顺序 | D04 习得/使用事件时点比对；跨书先经 D07 归并确认同一人物 | error=核心武功无习得先于使用；warning=模糊铺垫；info=同门基本功 |
| 检查项三：门派存续期 | D04 灭派/重建事件 + D06 组织边活跃度；"整建制"判定 | error=明文灭派后整建制再现无重建；warning=存疑记载；info=遗孤传人 |
| 检查项四：死亡角色再出场 | 01g 死亡登记 + D04 出场事件 + 叙述模式逐条过滤（回忆/梦境/戏中戏不算复活） | error=正常叙事活体行动；warning=存疑死亡/静态出现；info=传言转述 |
| 检查项五：称谓辈分错乱 | D06 关系边（师徒/父子/代际）× 对话称谓方向 | error=已核实级系统性冲突；warning=单次逆辈称呼；info=泛称/客套 |

外加 §实例 2 的朝代锚外部史历校验（归 L4 的"时代侧"）。

### 4.3 N8 引擎 → L4 工具

- **工具**：`scripts/lint_consistency.py`（N8 穿帮规则引擎，**待建**）——34 条种子规则 × 五项检查，消费 N4（时间解析）与 N5（关系校验）产出。
- **规则实现率分层**（D11 定版照搬）：可自动（纯数据比对/词表）进 CI 秒级扫描；半自动（机器初筛 + LLM 复核）进反思流程；人工为主项不进 lint。
- **评级对接**：D11 的 A-E 设定一致性评级是**聚合视图**，L4 的 error/warning/info 是**单条输出**——N8 输出单条分级，审计层聚合为 A-E；不要把 A-E 塞进 lint 返回码。
- **假阳性纪律**（D11 对 META-10 的反向约束，照录）：豁免性规则（W3/S8/J2/J8 方向反转条款）默认不扫描；翻案后文明写"原来当日未死"要能**撤回已报 error**（三分流判别：破绽/修辞/翻案）——lint 工具必须支持"规则触发 → 复核撤回"的状态流转，而不是一次性判决。

### 4.4 L1→L5 执行序（汇总）

**L1 结构 lint → L2 符号 → L3 完整性 → L4 一致性 → L5 业务/跨工序，低层不过不查高层。** L4 之前的层拦截"数据长得对不对"，L4 拦截"设定合不合"，L5 拦截"各工序互相咬不咬合"——三层失败模式不同，混跑会互相制造噪音。

## 五、跨工序一致性检查（L5，照搬思路、武侠化对象）

| 检查 | 双向验证对象 | 武侠化要点 |

### 7.2 五陷阱（照搬 + 武侠例）

1. **过度检查** — "可能"的问题留给反思。❌"这个绰号看起来不像本名"；✅"TYPE 位出现旧符号"
2. **检查不独立** — 每工具独立运行直接读源数据。❌ 依赖另一 lint 的中间产物
3. **输出不友好** — 位置 + 原因 + 建议。❌"检查失败"；✅"第 42 行：未闭合标注，建议补全〗"
4. **没有容差** — ❌ 年龄差 2 年就报 error（口述转述常见）；✅ 按 D11 分级：±1 年容差内 PASS、约数偏差 ≤3 年 info
5. **忽略边界情况** — 空文件报 warning 不 crash；空数组报 info；**武侠新增**：无朝代锚的书（纯相对纪律）不得触发朝代锚类检查——"缺锚"在该书是合法状态不是缺陷（D05 §2.6）

## 快速开始

1. **定层**：先明确本次质控覆盖 L1-L5 的哪几层（L1 结构 / L2 语义 / L3 统计 / L4 设定一致性 / L5 跨工序），避免用 L1 lint 冒充全部质量。
2. **选工具**：按 §六工具链表选已移植脚本（见下节），未建工具先记"人工检查"责任人与频次，不空转。
3. **设阈值与分母**：每个检查项写清 error/warning 分级、阈值、分母（文件数/段数/边数/章数）与快照版本。
4. **接入 CI**：把"可自动"项挂 `scripts/pipeline_wuxia.py` 的 check 阶段；半自动/人工项进批次报告，不阻塞提交但登记待办。
5. **跑批次并回填**：批次结束输出 JSON+MD 报告；工具误报归 G 源、规则缺口归 R/S、词表缺口归 W、结构缺口归 F，按 03c 归因顺序处理。
6. **回归**：修工具/规则后重跑同一批，比较前后 hard/warnings/抽样精度；指标回升才闭环。
