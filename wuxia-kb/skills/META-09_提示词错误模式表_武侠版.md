## 快速开始

1. **现象采集**：从 lint/accept judgment/qa 报告取可观测现象，写清计数与定位符（`书#pn-r{回}.{段}`）。
2. **归因定级**：按 §一模板填根因层（提示词/规则/词表/工具/流程/数据），并给分级：**阻塞**（hard、accepted 不成立）/ **告警**（judgment、warning）/ **提示**（style）。
3. **查重**：先查本表 A/B/C/D 与 `SKILL_03a` DEF 库、`SKILL_04f` §八错误库，避免同模式两个编号。
4. **定修法**：优先改规则文本/种子（可复用），其次改工具检查，最后才加提示词补丁；每条修法必须给回归方式。
5. **回归**：复跑对应门（accept/lint/qa）+ 关键指标（judgment 计数、hard、unsourced、token delta）。
6. **回填**：新书批次开工前，把本表对应类作为"预检清单"（§五）过一遍。

> 成功标准：新书冷启动时，本表"高频 8 条"预检后 hard 类错误 ≤1 条，口径类 judgment 不超过同体量书的 1.5 倍。

## 一、四段式模板（照搬）

| 字段 | 要求 |
|---|---|
| `pattern_id` | `A-01` / `B-01` / `C-01` / `D-01`，分区递增 |
| `现象` | 可观测、可计数、带定位符；不写"质量差" |
| `根因` | 写到层：提示词缺负规则 / 规则文本分裂 / 词表单主域 / 检查器未剥令牌 / 流程缺回填 |
| `修法` | 改什么文件哪条规则（条款号/行号）、是否降级为 warning、是否需重生成 few-shot |
| `回归` | 复跑命令 + 断言指标 + 期望值 |
| `分级` | 阻塞 / 告警 / 提示 |
| `来源` | docs 编号 / DEF 编号 / V 编号 / 批次 |

### 示例：一条完整条目（可直接套用）

```markdown
### A-01 计划/否定语境动词被误标

- 现象：白发 35 条、七剑 99 条、江湖 116 条 plan_negation_verb；
  定位示例 `七剑#pn-r012.4`（"正待下山"被标 ⟦■下山⟧）。
- 根因（层：提示词）：只给"触发词=事件入口"总则，缺"未发生"负规则。
- 分级：告警（judgment，不阻塞 accepted）。
- 修法：SKILL_03a v1.8 L127 负规则；04f §3.6 同步；accept 列 judgment。
- 回归：复跑 `python -X utf8 scripts/accept_batch.py --book 七剑下天山`，
  断言 plan_negation_verb ≤ 23、hard = 0、judgment 不高于 105。
- 来源：docs/48 §九；docs/45 §二。
```

## 九、成功标准

1. 本表条目与 DEF/V 编号无重复主编号，映射表 100% 可查；
2. 每条错误模式都有可复跑的回归方式与期望指标；

4. 每批新书新增/更新 ≥2 条模式（或明确"无新增"并说明）；
5. 外部模型复核意见采纳前 100% 经过程序核验（D-03）。
