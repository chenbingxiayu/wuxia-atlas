# SKILL 09g 武侠版：个性化 — 在"懂你"与"不越界"之间

> **上游声明**：本件属本批 C1 应用组新划定 09g，对应 docs/03 §3.10 原 09c 个性化阅读（中度 60-65：开关架构/映射法照搬）。**无专属设计稿且无埋点数据**：由站点现有内容数据（SKU/事件/系列/榜单）+ META-03 冷启动抽样 + 01g §9.10 发布/隐私精神综合而成；**v0.1 为骨架（推荐算法/埋点未实现）**，待补见附录 B。
> **接口**：N10 `registry/sku/cards.json`（人物/门派/武功卡）、EX-5 `registry/events`、EX-4 `graph.json`、EX-7 `universe.json`/`gazetteer`、`../site/data/characters/dossiers`、`../site/data/ratings`；META-03 冷启动抽样。
> **核心原则**：**推荐要能解释、偏好要能关闭、数据要留在本地。** 不靠隐蔽追踪，先做"显式偏好 + 内容特征"的轻量个性化。

## 一、定位与边界

### 1.1 工序位置

```text
内容数据（SKU/事件/系列/榜单） + 用户显式偏好
        ↓
09g 个性化（本文）→ 推荐列表/理由/开关 → 站点组件（EntityExplorer 等）
        ↓
隐私原则（本地/最小采集）+ 发布边界（01g §9.10）
```

### 1.2 本文做什么

1. **偏好模型**：显式偏好（书/人物/门派/武功/类型/时代）+ 隐式信号（仅当用户允许）；
2. **内容特征**：从 SKU 卡/事件/关系/系列提取特征向量（标签式，非黑盒）；
3. **推荐策略**：同类推荐（同门派/同系列/同类型）、继续阅读、冷启动；
4. **可解释性**：每条推荐带"为什么"（理由标签）；
5. **隐私与开关**：默认本地/最小采集、可关闭、可清除。

### 1.3 本文不做什么

| 不做 | 归属 |
|---|---|
| 改知识库数据 | 只读 |
| 埋点/用户数据平台 | 前端/产品（未实现） |
| 商业化推荐/广告 | 超范围 |
| 原文推荐（整段） | 禁（01g §9.10） |

### 1.4 关键约束（v0.1）

- **无埋点**：当前站点无行为采集；v0.1 只用**显式偏好**（用户勾选/本地存储）；
- **本地优先**：偏好存本地（localStorage/本地文件），不上传；
- **可关闭/可清除**：一键关闭个性化→退化为通用榜单/系列导航；
- **可解释**：推荐理由标签必须来自数据（同门派/同系列/同类型/同事件）。

| 统计热度（出现次数/榜单） | 03l / ratings |

## 四、推荐策略与可解释性

### 4.1 五类推荐

| 类 | 规则 | 理由标签 |
|---|---|---|
| 同门派 | 与偏好人物同 faction/门派 | "同门派" |
| 同系列 | 同一 universe line | "系列相连" |
| 同类事件 | 事件类型相似 | "同类型故事" |
| 关系邻近 | N5 边相邻（师承/结义/仇怨） | "关系相连" |
| 热门/榜单 | 出现次数/评分榜（需口径） | "高频人物/高评分" |

### 4.2 冷启动（META-03 抽样思路）

- 无偏好：展示系列主线（universe lines）+ 榜单 + 抽样人物卡（10% 确定性抽样）；
- 首次使用：引导勾选 3-5 项显式偏好；不强制。

### 4.3 推荐理由 schema

```json
{"rec_id":"REC-001","target":"card.person.xxx","reason":{"type":"same_faction","label":"同门派"},
 "source":{"pref":"faction:武当派","data":"registry/sku/cards.json"},
 "score":0.8,"explain":"你关注武当派，此人物属武当派"}
```

- 纪律：无理由不推荐；理由必须可追溯数据；不写"猜你喜欢"式黑盒话术。

## 五、隐私与开关

| 原则 | 实现 |
|---|---|
| 本地优先 | 偏好存 localStorage/本地文件；不上传服务端（v0.1） |
| 最小采集 | 只收显式偏好；不采集阅读时长/点击轨迹 |
| 可关闭 | 一键关闭→退化为通用导航/榜单 |
| 可清除 | 清除本地偏好即重置 |
| 透明 | 说明"用了哪些偏好、怎么推荐" |
| 不跨界 | 不把偏好用于发布/版权/画像分享 |

## 九、FAQ（首批 5 问）

**Q1 没有用户行为数据怎么推荐？**
v0.1 只用显式偏好+内容特征；冷启动用系列/榜单/抽样兜底；不做黑盒行为画像。

**Q2 偏好数据安全吗？**
本地存储、不上传、可清除；不用于发布或画像分享。

**Q3 推荐理由能不能编？**
不能。理由必须来自数据（同门派/同系列/同类型/关系邻近），可追溯。

**Q4 能不能推荐原文片段？**
不能。推荐只给结构化条目/页面跳转；原文禁止出口（01g §9.10）。

**Q5 个性化关闭后会怎样？**
退化为通用导航/榜单/系列页；不影响阅读。

## 结语

个性化的底线是**尊重**：只用你告诉我的（显式偏好），不偷看（埋点），不乱传（本地），随时可关，推荐必有理由。先做到"轻而可信"，再谈"越来越懂你"。
