# W13 覆盖度（武侠版）——用全文覆盖替代"外库对比"

> **本文是什么**：W 组的**覆盖度计量器**。它回答三个问题：**章节覆盖了多少回？类型覆盖了多少类？人物覆盖了多少个？** 并把缺口按优先级交回 W10 队列。
> **为什么不用外库对比**：史记有《汉书》可对比，武侠没有"权威外库"（金庸/梁羽生宇宙没有对应物）；按 `SKILL_08b_覆盖度评估_武侠版.md` 的裁定，改用**全文分母 + 类型目录 + 页面需求**三面镜子互照。
> **上游依赖**：`../site/data/books.json` + `chapters.json`（34 部/1,378 回）、`tagged/` 5 书 + `registry/structure/`（PN）、`registry/concordance/`（in-scope/registered/alias/unregistered）、`registry/events/`（22,985 条/13 类）、`logs/taxonomy/`（5 树 64 叶）、`registry/sku/cards.json`（1,509）、`content/`（1,526 页）。
> **一句话**：**覆盖率不是"标了多少字"，而是"该有的对象有没有、能不能用"；分母先定，再谈百分比。**
> **只读纪律**：只读 corpus/tagged/registry/EX/content；报告落 `logs/w_group/coverage_report.md` 与 `logs/coverage/`；v0.1 **不写** `registry/coverage/`（句子索引属后续批）。

## 三、三维覆盖公式

### 3.1 章节覆盖 CR

```text
CR(book) = 有 struct（PN）的回数 / 该书总回数
CR(lit)  = Σ 点亮书有 struct 回 / Σ 点亮书总回   # 151/151 = 100%
CR(all)  = 151 / 1,378 = 11.0%                  # 全库
```

章节覆盖再分三级：`struct`（PN 结构）→ `tagged`（标注）→ `events`（事件层）。当前 5 书三级齐全；29 书仅 `chapters`（回目元数据）。

### 3.2 类型覆盖 TR

```text
TR(entity) = 已实例化实体类型数 / 15          # 当前 8/15
TR(event)  = 已实例化事件类型数 / 13          # 当前 13/13
TR(leaf)   = 有实例的叶数 / 64                # 当前 63 叶有组织实例（含 1 未挂叶）
TR(page)   = 有页的类型数 / 有卡的类型数       # 当前 5/5（person/faction/art/artifact/manual）
```

**注意**：`TR(leaf)` 是"叶定义覆盖"与"实例覆盖"两件事，报告必须分开写（64 叶已定义 ≠ 64 叶都有实例）。

### 3.3 人物覆盖 PR

```text
PR(book) = (registered + alias_mapped) / in_scope      # 七剑 (322+35)/372 = 96.0%
PR(all)  = (582 + 86) / 1,357 = 49.2%
PR(page) = 有页的卡 / 卡总数                            # person 367/350（页多于卡，含补充页）
```

`in_scope` 定义：concordance 中属于该书 scope 的实体（5 书合计 1,357）；未登记 689 是主要缺口来源。

### 3.4 证据覆盖 ER（辅助）

```text
ER = 有 evidence[] 或 quotes[] 的页 / 总页
```

v0.1 全部 content 页 `demo:true` 且 `quotes[]` 待填，ER 仅作"待补"记录，不作发布依据。

## 四、句子索引与双 ID 体系

### 4.1 ID 规范

| 书类 | ID 格式 | 依据 | 现状 |
|---|---|---|---|
| 点亮 5 书 | `{book}.{chapter}.{para}.s{n}` | `registry/structure/<书>/NNN.structure.json` 的 PN 段 | ✅ 可建 |
| 未点亮 29 书 | `{book}.{chapter}.L{line}.s{n}` | 章回版行号（fallback） | 待建 |
| 表格单元（少） | `{...}.c{n}` | 02ab 表格规范 | 暂缓 |

### 4.2 `sentence_index.jsonl`（schema v0.1 约定，v0.1 不落 registry）

```json
{"id":"七剑下天山.004.12.s3","book":"七剑下天山","chapter":4,"para":12,"s":3,
 "pn":"七剑下天山#pn-r4.12","chars":37,"tagged":true,"event_ids":["004.012.02"],
 "entity_ids":["E0001"],"page_refs":["content/person/card.person.e0001.md"],
 "status":"covered"}
```

`status ∈ {covered, uncovered, excluded}`；`excluded` 用于围栏/标题/表格等非正文单元（分母剔除，须记录数量）。

### 4.3 双向映射

```text
句子 → 页面：sentence.page_refs（该句支撑了哪些页的断言）
页面 → 句子：页面 frontmatter evidence[]/quotes[] 的 loc_r（该页断言引用了哪些句）
```

双向映射是"未覆盖原文知识"的判据：**有句子、无 page_refs → 未覆盖**；**有 page_refs 但句子不存在 → 断链**。

## 十一、FAQ（首批 5 问）

**Q1：为什么不用外库对比？**
史记有《汉书》可对照，武侠没有权威外库；用外部研究专著作分母会把"别人的取舍"当成"应然"，所以改用全文/类型/页面三镜（08b 裁定）。

**Q2：覆盖率为什么只有 11%？**
章节覆盖按"有 struct 的回"算，只有 5 书点亮（151/1,378）；这是标注进度，不是知识库失败——29 书仍可用回目/提及级服务。

**Q3：人物覆盖 49.2% 低在哪？**
主要是 `unregistered` 689 个 in-scope 实体（江湖 321、白发 218、冰魄 101 等）；它们是标注里出现但未进 registry 的实体，属 P1 缺口。

**Q4：句子索引为什么 v0.1 不落 registry？**
`registry/coverage/` 属受管产物，写入需任务授权；本件先出 `logs/w_group/` 报告，索引 schema 冻结后由后续批落库。

**Q5：页面 1,526 > 卡 1,509 正常吗？**
正常：W8 页含补充页（person 367 vs 卡 350），且全部 `demo:true`；页面覆盖率因此 >100%，报告要单列"演示页"。

## 结语

覆盖度的意义不是"证明我们做了很多"，而是"指出还缺什么、先补哪个"。分母先定、三维分开、缺口分级——这三件事做到，覆盖率才是一张可执行的施工图，而不是一个好看的百分比。
