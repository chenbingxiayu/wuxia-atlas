# W1 资料地图（武侠版）—— 六源食物地图与数据契约

> **本文是什么**：W 组（Butler）的"食物地图"——去哪找、找什么、怎么排优先、取到的素材可信到什么程度。它不规定"怎么做"（那是 W2 原子动作目录），只规定"取什么、从哪取、什么条件下可入队"。
>
> **一句话**：Butler 是消化系统；本文件是食谱与食材验收标准。
>
> **只读纪律**：本文件涉及的全部上游（tagged/registry/references/docs/logs）**只读**；W 组产出只落 `content/` 与 `logs/w_group/`。

---

## 快速开始

> 每次需要"补充队列/检查素材/判定入队"时按 6 步执行。

1. **定源**：先查 §二 六源总表，确定候选来自哪一源（A registry / B tagged / C SKU / D references / E docs / F logs）。
2. **查质量门槛**：按 §二 对应行的"质量门槛"过滤（schema 版本、validation、置信度、更新日期、脱敏状态）。
3. **抽候选信号**：按 §三 信号表扫（如"高频实体无页面""卡 ready 但无页""断链指向高频实体"）。
4. **判队列**：P0（高价值缺口）/P1（结构内务）/P2（探索洞察）；写 queue item（§四 schema）。
5. **登记来源与期望**：每条队列项必须带 `source_ref`（路径/ID/PN）与 `expected_diff`（≤20 行；精品页例外）。
6. **更新 queue.md 与 food_scan.json**：只追加历史，不删旧项（关闭项标 `closed` + 证据）。

> **成功标准（W1 验收）**：① 每条入队项有 `source_ref` 与 `quality_gate`；② 六源均有扫描记录（可为 0 候选，但必须出现）；③ 队列无"无源项"；④ `food_scan.json` 可复跑且与 queue.md 一致。

### 2.1 A · registry 细目（结构化图谱）

- `registry/entities.json`：实体层（canonical/type/aliases）；**页面选题第一优先**（高频实体无页）；
- `registry/relations/<书>.json`：边含 `id`（`{书}#R{n}`）、subject/object/predicate/confidence/evidence.loc；**关系表/师承树素材**；
- `registry/intertext/intertext_loc.json`：互文边（N11）；跨书页互链素材；
- `registry/time/`（N4）：时点键/年龄锚；页面时间线素材；
- `registry/consistency/`（N8）、`registry/acceptance/`：质量与验收记录；决定"该不该碰"。

### 2.2 B · tagged 细目（5 书）

- 已点亮 5 书：白发魔女传/塞外奇侠传/七剑下天山/江湖三女侠/冰魄寒光剑；
- PN 锚格式 `{book}#pn-r{chapter}.{para}`（chapter 不补零；para=PN 段号）；
- 页面引文**只存指针**（`#pn-r...`），不贴原文；W7 核验输入可含短引文（≤60 字）。

### 2.3 C · SKU 卡细目（N10 五卡）

现仓实测（2026-11-05）：1,536 张 = person 367 / faction 70 / art 852 / artifact 226 / manual 21；`validation.passed=true`；person 卡 confidence：B 5 / C 362；`life_events`/`identity_tags` 全空（上游 #4a/#8 未建）；卡面按 R1/R2 脱敏（brief 不含原文片段）。

- 页面可用槽位以 `w8_w9_interface.W9_页型模板.slot_mapping[type]` 为准；
- D/E 置信卡不出页（W8 适用判断）；`publish_state` 非 approved 时页面可生成但不得发布。

### 2.4 D · references 细目（规律库）

- 统一 8 字段 schema（参见 `03c1`）：类别/现象/判据/动作/反例/来源/状态/编号；
- 编号只增不复用；状态 = 候选/已验证/已回写/已入库/待裁/废弃；
- W 组消费方式：反例→页面"已知冲突"；判据→页面口径；引文→W7 核验。

### 2.5 E · docs 细目（分析报告）

- 设计稿（docs/01/03/05/17/50/51）→ W 组节点与接口设计；
- 批次记录（docs/53-58）→ 口径与遗留；
- 复盘/裁决（docs/26/34/42/45/46/48/54/55）→ 规律库与边界；
- 消费纪律：引用页码/章节，不复制结论为事实（事实须回 registry/PN）。

### 2.6 F · logs 细目（运行日志）

- `logs/w_group/`（本组）：queue/actions/health/failures/quote_verify；批准后可直接回灌 P0；
- `logs/qa/`：W 组报告（如 `w_group_design_brief.md`、`w_wave1_report.md`）；
- `logs/acceptance/`、`logs/lint/`：质量警告→W4/W6 输入。

| 列表/专题页 | A/N5/N6 + EX 字段 | 查询字段可解析 | content/list/*.md（W12） |

### 4.4 W7 引文契约（frontmatter）

页面/卡面未来写引文时，frontmatter 必须带独立字段：

```yaml
quotes:
  - text: "≤60 字引文（可含省略号）"
    cited_pn: "白发魔女传#pn-r4.9"
    source: "SKU 卡 / W8 撰写"
quote_status: pending   # pending / verified / needs_review / rejected
```

- `text` 仅供 W7 消费（输入），页面正文只放指针+概括，不贴原文；
- 发布前 `quotes` 全部 hit（near 需人工复核，miss 拒绝）；`quote_status` 由 W7 回写。

### 4.5 demo 隔离契约

- 所有生成页默认 `demo: true` + `publish_state: draft`；
- demo 页永不进入发布库（R4/K3）；发布由人工签核后改 `demo: false` + `publish_state: approved`。

## 六、质量门槛（入队/入页/发布三档）

1. **入队门槛**：来源路径存在；schema 可解析；有 `source_ref`；质量字段（confidence/validation/lint）达标；同一目标不重复入队（按 source_ref 去重）。
2. **入页门槛**：字段有源；未知=未明示；无原文连续 ≥10 字；引文 quotes[] 有 PN；关系/事件只用 ID 不重算（K6）。
3. **发布门槛**：W3 质量档达标 + W7 `--strict` 通过 + EX 契约 dry-run 通过 + 人工签核（`publish_state: approved`，demo=false）。
