## 一、铁律：为什么它是全库核心不变量

### 1.1 标注的本质是语义标记，不是文本编辑

```text
底本:  卓一航提剑上山，直奔白云观。
标注:  [7] 〖@卓一航〗提剑上山，直奔〖=白云观〗。
剥标:  卓一航提剑上山，直奔白云观。   ← 必须与底本逐字相同
```

标注符号（`〖@练霓裳〗`式实体令牌、`[N]` 段号、`::: 词` 围栏）全部是**叠加层**。叠加层可以无限重刷，底本字符一旦被改动，每一层下游都被污染。

**违反铁律的后果**：

- ❌ 实体登记的定位锚点指向不存在的词句，出现次数统计失真；
- ❌ 事件抽取对应不到原文段落，证据不可追溯；
- ❌ 跨书互文引用（另一部书提及此人此事）对不上位置；
- ❌ 阅读器渲染"还原模式"时文本与读者手中的纸书不一致，丧失信任；
- ❌ 换底本重标时无法机械对账，只能全量人工重校。

### 1.2 完整性的定义（武侠口径）

**完整性** = 对标注文件剥除全部新增标记后，所得纯文本与锁定底本（`章回版/<书>/NNN*.txt`，config.CORPUS_ROOT 只读输入）**逐字相同**。

去除对象分三层（详见第四章"结构层完整性"）：

| 层 | 内容 | 剥除方式 |
|---|---|---|
| ① PN 段号层 | `# [0]` 回目、`[N]` 段号、`[N.M]` 子段号、`- [N.M]` 对话列表项 | 结构剥离（lint_text_integrity 内置） |
| ② 围栏行层 | `::: 词` / `::: 书信` / `:::` 等围栏标记行（`^:::.*$`） | 结构剥离（史记版规则免改照搬） |
| ③ 标注令牌层 | `〖TYPE显示串〗` 实体、`⟦TYPE触发串⟧` 动词、`〘※表达串〙` 修辞 | `symbols.strip_markup` 剥到显示串 |

Markdown 标题、列表符、粗体、分隔线等通用结构同样剥除。

**特殊处理**：

- **底本首行回目**：锁定底本首行通常是"第N回　回目对句"，对应标注文件的 `# [0]` 行，比对前自动跳过（武侠口径：首行含"第…回"即视为回目行；此规则**待试点校准**——若个别书首行格式不同，以该书记录为准）；
- **sidecar 不参与逐字比对**：`NNN.struct.json`（回目元数据/围栏清单/存疑清单）是派生数据，但必须与正文一致，由 `lint_purple_numbers.py` 的结构检查覆盖。

### 1.3 禁止引入半角符号（在严格模式下就是改字）

- 在使用编辑工具修改标注文件时，严禁引入半角引号、半角标点。武侠底本为现代标点排印本，底本里是弯引号就是弯引号、是全角就是全角；
- 默认字符级严格模式下（`--norm` 关闭），**任何标点/字形差异都会被记为差异**，不存在"可忽略"的灰区；
- 半角引号误入属于高频手误，用 `fix_halfwidth_quotes.py` 批量修复后重跑对账（详见 SKILL_01f 武侠版）。

### 1.4 底本指纹机制（武侠新增）

底本选择是 G0 拍板门的一次性决策，指纹把"用的是哪一版"固化为机器可验字段：

- `config.py` 的书目注册表含 `fingerprint` 字段；G0 未过时留 `None`（未锁定语义），底本锁定后由 `build_book_registry` 回填（sha256 或版本说明）；
- **每批次标注开工时，批次头记录当次使用的同一指纹**——可逆性基线。对账时"标注批次声称的指纹"与"config 当前指纹"不一致，先解决版本漂移再谈对账；
- 底本若走勘误流程（S-01b 乙类变更），指纹随之更新，全部已标注回目必须重新对账。

## 二、工具链

### 2.1 对账主工具 lint_text_integrity.py

```bash
# 检查全部已标注书、全部回
python scripts/lint_text_integrity.py

# 只查指定书
python scripts/lint_text_integrity.py --book 白发魔女传

# 查指定回（位置参数 = 回号列表，多书时配 --book）
python scripts/lint_text_integrity.py 001 002 013 --book 白发魔女传

# 显示标点/编码差异详情
python scripts/lint_text_integrity.py --all

# 顺带检测嵌套标注（令牌互嵌/跨层交叉）
python scripts/lint_text_integrity.py --check-nested
```

**输出格式**（示意）：

```text
  ✓ 白发魔女传 001（第一回　铁矢神弓　少年扶巨宦…）: 0处实质差异  0处标点  0处编码
  ✗ 白发魔女传 002: 1处实质差异  12处标点  0处编码
  ✓ 七剑下天山 003: 0处实质差异  0处标点  0处编码  校勘:2  嵌套:0
```

报告落 `logs/lint_text_integrity.txt`（全量）或带书名/回号后缀（指定范围）。多书时缺省扫 `config.DIR_TAGGED` 下全部书目录。

### 2.2 差异三分类

脚本把剥标后残差自动分为三类（分类框架照搬史记版）：

| 分类 | 说明 | 武侠版处置 |
|------|------|-----------|
| **实质差异** | 汉字/标点字符被增加、删除、改写 | 必须修复（最高优先级） |
| **标点规范化** | 全角↔半角、引号样式等价变体 | 详见 2.3——默认严格模式下**不豁免** |
| **编码规范化** | PUA 私用区字符→标准 Unicode 等价 | 同上 |

⚠️ **武侠纪律**：史记版把标点/编码类差异默认归为"可忽略"；武侠版**默认关闭规范化**（见下节），首轮对账中替换类差异一律先按实质差异处置——底本重审完成前不预设任何"等价"结论。

### 2.3 规范化映射：--norm 默认关闭

```bash
python scripts/lint_text_integrity.py --norm   # 启用规范化映射（重审完成前勿开）
```

- `_NORM_TABLE` 从史记版原样搬入但**逐条标注 TODO 待武侠底本重审**：史记文言的繁简对应、通假字结论（于/於、后/後、谷/穀等 14 组）对梁羽生白话底本**一律不预设成立**；
- 引号删除条目尤其可疑：史记原文无引号、标注可添引号，故对账时删引号；武侠底本自带标点引号，"删引号对账"不成立，此条必须重审；
- 结构性清理恒做（与 `--norm` 无关）：管道符、`[rN]` 行标、PUA 处理；
- **启用 `--norm` 的前置**：按 S-01b 流程对锁定底本重审映射表逐条，重新评审通过后在 git 记录决策，再全量开跑。

**收录原则（武侠化重申）**：新映射条目必须满足——梁羽生底本与参校版本中用法一致、语义等价、高频出现且经人工确认；任何"可能是录入讹误"的替换都不是规范化，是校勘（转 S-01b）。

### 2.4 白名单机制：清空待试点回填

已确认的**正确校勘**记入白名单，对账时自动跳过，避免误报。机制照搬史记版，**内容清空**——史记的校勘条目对武侠底本无一适用。

- 文件路径：`scripts/lint_whitelist.txt`（文件缺失 = 白名单为空，机制静默生效）；
- 格式（TSV，`#` 开头为注释）：`书名/回号<TAB>底本片段<TAB>标注片段<TAB>说明`；兼容旧式纯回号键作通配；
- 生效后输出尾注出现 `校勘:N`，表示 N 处差异被白名单吸收。

**回填流程（试点期纪律）**：

1. 对账出现差异，经 S-01b 互校确认是"底本有误、标注层已按权威依据补正"的正确校勘——**而不是标注手误**；
2. 同类案例累积 **3 例以上**才入白名单（孤例先留在存疑清单，防止把偶然手误固化成规则）；
3. 每条记录必须写明理由（依据哪个版本/哪条内证），可追溯；
4. 入单后重跑该回对账，确认输出从 `✗` 变 `✓` 且 `校勘:1` 计数正确。

## 三、修复流程

### 3.1 修复原则（七条）

1. **锁定底本为准** — 对账以 `章回版/<书>/NNN*.txt` 为唯一基准（只读）；
2. **区分三类差异** — 先判断是实质差异还是规范化差异，严格模式下从严处置；
3. **异体字/讹字疑惑时转介 S-01b** — 不在完整性流程里顺手"改正"，校勘判断归校勘工序；
4. **底本确有录入错误时走勘误流程** — 经互校确认后先按 S-01b 乙类变更更新底本并重算指纹，再同步所有派生，**不是**让标注文件迁就错误底本之外另写一份"对的"；
5. **保留已有标注** — 修复时只动文字部分，`〖@〗〖=〗〖☆〗` 等令牌与 PN 尽量原位保留；
6. **全回即时验证** — 每修一处立即重跑该回对账；
7. **记录校勘** — 正确校勘按 2.4 流程入白名单，确保可追溯。

### 3.2 典型案例（武侠化示意）

> 本文例句均为规则演示，不作为作品原文或情节证据。

**Lint 报告**：

```text
  ✗ 白发魔女传 007: 1处实质差异  0处标点  0处编码
  ■ 实质差异 1 处：
  [1] 替换
      底本上下文 : …练霓裳使出〖☆怪蟒翻身〗一式，剑锋反挑…
      标注上下文 : …练霓裳使出〖☆怪莽翻身〗一式，剑锋反挑…
```

**分析**：底本作"蟒"，标注文件误作"莽"（形近录入手误）。**不要**反过来想"莽字也通"——先查底本，再查该武功名在全书的其余出现（S-01b 内证），确认底本一致后只修标注文件。

**修复**：在标注文件该行恢复"蟒"字，保留 `〖☆〗` 令牌与段号不动。

**验证**：

```bash
python scripts/lint_text_integrity.py 007 --book 白发魔女传
# 输出: ✓ 白发魔女传 007: 0处实质差异  0处标点  0处编码
```

### 3.3 规范化与多版本互校的边界

```text
lint 报告实质差异
    ↓
该差异属于等价变体（引号样式/繁简/异体）？
    ├─ 否 → 标注手误，直接修复（本 SKILL）
    └─ 是/存疑 → 会不会是底本录入讹误？
          ├─ 只是样式差异 → 默认模式下按差异修复对齐底本；
          │                  --norm 启用后（重审完成）自动豁免
          └─ 疑似底本讹误 → 转介 S-01b 多版本互校
                ├─ 确认底本错误 → 乙类变更：改底本+重算指纹+全量同步
                └─ 确认标注错误 → 回到本 SKILL 修复
```

**判断要点**：完整性流程只回答"标注是否忠实于底本"；"底本本身对不对"是校勘问题，两个问题**不许**在一次修改里混着解决（01g §2.1 同一纪律的标点版）。

### 3.4 常见错误类型

| 错误类型 | 示例 | 修复方法 |
|---------|------|---------|
| **擅自改字** | 底本"玉罗刹"，标注写作"玉罗杀" | 恢复原字，保留消歧语法 `〖@玉罗刹|练霓裳〗`（`|` 后是登记名，不占显示串） |
| **擅自加字** | 底本"卓一航纵马"，标注"卓一航纵马而去" | 删去多出的"而去" |
| **擅自删字** | 底本"白发魔女"，标注剥标后剩"魔女" | 补回"白发"二字 |
| **标点转换** | 底本"？"被改成"!" | 恢复底本标点；句读问题转 S-01f，不在标注层改 |
| **引号误入** | 手误敲入半角引号 | `fix_halfwidth_quotes.py` 修复后重对账 |
| **剥标残留** | 显示串与登记名混淆，剥标后多出登记名 | 检查令牌 `|` 语法，确认剥标只留显示串 |

### 3.5 修复时严禁顺手做的事

- ❌ 顺手统一异体字（归 S-01b 校勘）；
- ❌ 顺手把直角引号换弯引号、半角换全角（01g §2.1 明令禁止；底本用什么保留什么）；
- ❌ 顺手补全"疑似脱字"（哪怕行文规律强烈暗示，也须走 S-01b 内证流程留档）；
- ❌ 顺手重排段落、增删空行（PN 不可变；结构问题走 02ab 变更治理）。

## 四、结构层完整性（武侠新增）

史记版只管字符对账。武侠版多出一整层结构标记——PN 段号与围栏行同样是"新增标记"，同样受铁律约束，因此完整性 = **字符层还原 + 结构层合规** 两件事都过。

### 4.1 三层剥除模型

一份合格的标注文件，剥除以下三层后必须逐字还原底本：

```text
# [0] 第一回　铁矢神弓　少年扶巨宦　金鞍宝马　大盗震虚声     ← ① 回目标题（PN 0）
::: 词                                                    ← ② 围栏行
[1] 一剑西来，千岩拱列……                                   ← ① 段号 PN 1（围栏内恰一 PN）
:::                                                       ← ② 围栏行
[2] 〖%凉秋九月〗，〖@练霓裳〗随师上了〖=天山〗。             ← ① 段号 + ③ 标注令牌
```

三层剥除全过才算还原：

1. **PN 层**：`[0]`/`[N]`/`[N.M]` 全部剥除，编号本身不占底本字符；
2. **围栏行层**：`::: 类型` 与 `:::` 标记行整行剥除（`^:::.*$` 规则从史记版免改照搬）；
3. **令牌层**：实体/动词/修辞令牌剥到显示串（`〖@练霓裳〗`→`练霓裳`；`〖@玉罗刹|练霓裳〗`→`玉罗刹`）。

### 4.2 生成时自检：generate_pn_wuxia --verify

结构层不是手工摆的，由 `generate_pn_wuxia.py` 流水生成（回目识别→章首探测→段落编号→围栏标注→**阶段 5 自检**）：

```bash
python scripts/generate_pn_wuxia.py --book 白发魔女传 --chapter 1 --verify
python scripts/generate_pn_wuxia.py --book 白发魔女传 --all --verify
```

阶段 5 内置可逆性检查：**产物剥除全部 PN 标记与围栏行后与底本逐字符比对，不一致报错退出 1**；`--verify` 显式报告比对结果。这是结构层的"出厂检验"——但出厂检验不能替代入库后的持续对账，标注作业会在结构文件上叠加令牌层，叠加之后仍要回 2.1 全量对账。

### 4.3 入库后结构检查：lint_purple_numbers E1-E17

```bash
python scripts/lint_purple_numbers.py --book 白发魔女传
python scripts/lint_purple_numbers.py 001            # 位置参数 = 单回编号
```

规则源：02ab §9.1。分级：E1-E11、E13、E16 为 error，E12/E14/E15/E17 为 warning；**退出码约定：存在 error → 1，仅 warning → 0**（02ab §8.1 验收门："error 清零，warning 有处置记录"）。要点摘录：

| 检查项 | 内容 | 级别 |
|---|---|---|
| E1-E5 | PN 格式、同层连续、父子关系、标题不含编号、无重复 | error |
| E6-E7 | 回目 `[0]` 恰一且在文件首；每书回号连续无缺号 | error |
| E8-E10 | 围栏成对闭合不跨回不嵌套；类型在枚举内（观察类须登记）；围栏内恰一 PN 在内容首行 | error |
| E13/E16 | 章首结构；**围栏内禁半角标点**（与 S-01f 共管，见彼篇） | error |
| E11/E12/E14/E15/E17 | 回末顺序、回末套语、韵文密度、伪信号误围栏、正文分母 | warning（阈值待试点校准） |

### 4.4 三道门分工

| 道门 | 工具 | 回答的问题 | 时机 |
|---|---|---|---|
| 出厂门 | `generate_pn_wuxia.py --verify` | 结构产物剥掉 PN+围栏后是否还原底本 | 生成时 |
| 结构门 | `lint_purple_numbers.py`（E1-E17） | PN/围栏/章回结构是否合规 | 每次改动后、每批次收尾 |
| 字符门 | `lint_text_integrity.py` | 叠加全部标注后剥净是否逐字还原 | 每次改动后、每批次收尾 |

**三道全过才算完整**。任一门报错，优先级：字符门实质差异 > 结构门 error > warning（有处置记录即可放行）。

## 五、检查清单

### 执行前（对账准备）

- [ ] 确认底本已锁定：`config.fingerprint` 非 None，批次头记录的指纹与之一致；
- [ ] 确认对账模式：默认字符级严格模式；`--norm` 仅在底本重审完成后启用；
- [ ] 白名单已读一遍：本回已有条目是否覆盖待判差异（避免重复分析）。

### 执行中（逐处差异）

- [ ] 每处实质差异先定性：标注手误（本 SKILL 修）还是疑似底本讹误（转 S-01b）；
- [ ] 修复只动字符，PN/围栏/令牌结构不动；
- [ ] 引号、标点差异一律恢复底本原样，不做"顺手规范化"；
- [ ] 正确校勘按 3+ 例纪律入白名单并写明理由。

### 执行后（批次收尾）

- [ ] `lint_text_integrity.py` 该书全回通过（0 处实质差异；校勘计数与白名单一致）；
- [ ] `lint_purple_numbers.py` error 清零，warning 有处置记录；
- [ ] `--check-nested` 无嵌套/交叉残留；
- [ ] 报告归档 `logs/`，git 提交附差异定性说明。

## 六、批量修复策略

1. **按书推进**：以书为单位清零（先试点书，后其余 33 部），避免跨书跳修丢上下文；
2. **按报告顺序逐回修复**：每回修完立即验证，再进下一回；
3. **每处差异都回看底本**：不凭记忆改字；
4. **累积白名单**：同类正确校勘满 3 例即入单，减少后续误报；
5. **每修完一部书跑一次全量对账**（含结构门），确保没有跨回副作用。

## 七、Agent 提示词模板

### 7.1 单回修复任务

```text
任务：修复《{书名}》第 {NNN} 回标注文件的完整性问题

背景：
- lint_text_integrity 报告该回有 {N} 处实质差异
- 铁律：剥除 PN/围栏行/标注令牌后必须与锁定底本逐字相同

1. 读取 lint 报告差异详情，逐处对照底本 章回版/{书名}/{NNN}*.txt

   疑似底本讹误（STOP，转介 S-01b 互校，不自行改字）
3. 修复时保留全部标注令牌与 PN 结构

   lint_purple_numbers {NNN} 验证

输出：
- 每处差异的定性与处理方式
- 最终两道门的验证结果（0 实质差异；error 清零）
```

```text
任务：对《{书名}》全书 {M} 回做完整性批量清理

- 逐回修复日志

```

## 八、校勘组分工与上游接口

```text
S-01b 多版本互校（底本对不对）         S-01f 句读标点（标点怎么定）
        │ 底本勘误/乙类变更                     │ 标点规范与修复工具
        ▼                                     ▼
S-01a 标注完整性维护（本文）：标注是否忠实于锁定底本
        │ 字符门 + 结构门
        ▼
01g 符号宪法（剥标还原总原则）/ 02ab（PN 与围栏的结构规则）
```

- 对 **S-01b**：完整性流程发现的疑似底本错误，全部转介互校；底本变更后本 SKILL 负责全量重新对账（指纹对齐）；
- 对 **S-01f**：标点差异的"怎么改才对"归句读标点技能；本 SKILL 只管"改完之后是否与底本一致"；
- 对 **01g**：`剥标还原` 是 01g 原则零与无损还原承诺的验收工序；令牌剥除一律走 `symbols.strip_markup`，任何脚本不得自带字符类；
- 对 **02ab**：结构门检查项与分级完全引用 02ab §9.1，本文不复述细则、不另立阈值。
