# META-13 技能迁移（武侠版）—— 跨项目复用方法论

---

## 一、核心思想（照搬）

> **"SKILL 文档是可迁移的知识资产"**

**技能迁移**（Skill Transfer）是将在一个项目/数据集中积累的 SKILL 文档、工具、方法论迁移到新的领域/数据集的过程。

### 1.1 应用场景（武侠化）

**现状**：shiji-kb 完成了《史记》130 篇的知识抽取，沉淀 151 个 skill 文件、228 个脚本与 14 份 META 元技能。

**未来目标**：
- **梁羽生武侠宇宙**（34 部 / 1,378 回，多书共享门派/武功/人物谱系）——本项目，迁移已启动
- 远期：其他虚构宇宙（不同作者的多部曲）——见 §八场景 3

**挑战**：
- 文体差异（纪传体文言 → 章回体白话，韵文密度约为史记 20 倍）
- 结构差异（单书 130 章平铺 → 34 部 × 1,378 回两级嵌套）
- **本体差异（最关键）**：真值来源从"史料互证"变为"作者设定"——见 §九
- 规模差异（130 篇 vs 1,378 回）

### 1.2 迁移纪律（本文件为全项目规定的通用格式）

凡从 shiji-kb 迁移的 SKILL，武侠版文件头部一律加"武侠适配说明"引用块，按四分法声明：

| 声明类别 | 含义 | 处置 |
|---|---|---|
| **已替换** | 案例层（worked examples、史记实测数字、硬编码词表） | 全部武侠化，不得残留史记专名 |
| **照搬** | 方法论框架层（流程模型、判断原则、数学模型、反模式） | 明确写"照搬"，与源版逐节可对照 |
| **补写** | 方法论硬缺口（史记场景无、武侠场景需要的新方法论） | 写清设计，并回链 doc04 对应缺口条目 |
| **待回填** | 需项目自己跑出数据才能写的内容 | 建占位结构，标注"上线后回填" |

这一纪律本身照搬源版 §九"迁移哲学"：迁移过程就是知识提炼过程，可对照性是提炼的前提。

## 二、迁移层次（三层模型，照搬）

### 2.1 Level 1 直接复用（>80% 相似度内容）

**可直接复用到武侠的内容**：
- **META 元技能方法论框架**：反思、迭代、冷启动、柳叶刀分解、质量控制五层、可读性原则（框架层占比 55%~85%，见 doc04 §一）
- **标注语法骨架**：`〖TYPE显示串〗` 令牌格式、内联消歧管道 `|规范名`、〖〗成对闭合（武侠在其上新增动词层 ⟦TYPE⟧ 与修辞层 〘※〙，见 META-08）
- **Lint 工具骨架**：`lint_text_integrity.py`、`lint_markdown.py` 等（已按 `symbols.py` 唯一符号来源移植，见 META-10）
- **基础设施**：紫色编号（PN 两级）、双格式输出、Git 工作流、双轨词表编译器 `wordlist_compiler.py`

### 2.2 Level 2 适配调整（有差异，需调整参数/规则）

**差异 1：结构变化（单书 → 多书）**

```markdown
《史记》结构：12 本纪、10 表、8 书、30 世家、70 列传（单书平铺 130 章）
武侠结构：34 部 × 回（两级嵌套，共 1,378 回；每部有作品 ID）
```

**调整逻辑**：所有路径脚本从单书模型改多书注册表（`config.py` C0a：34 部路径/回数/底本指纹）；消歧映射表键从章号改 **(书,回) 复合键**（见 META-08 §三）；锚点格式升 `{作品ID}#pn-r{回号}.{X}`（D04 定版）。

**差异 2：实体类型体系变化**

```markdown
史记 18 类：人名/地名/官职/身份/时间/氏族/邦国/名物/族群/器物/天文/生物/数量/神话/典籍/礼仪/刑法/思想
武侠 15 类实体 + 6 动词域：人物/人物群组/地点/组织/家族世系/族群/职衔/身份/武功技艺/器物/生物/作品文书/专门概念/时间/数量
                          ＋战斗交锋⊞/生命健康⊠/社会关系⊡/物件变化⊟/技术传习▣/行踪迁移■
```

**调整逻辑**：礼仪/律令/思想/天文不再占用顶层符号（并入专门概念子型）；新增武功技艺☆与人物群组◎；动词从"实体标注"中独立成层。类型表定版见 `SKILL_01g_标注符号集合原则.md`，推导过程记录见 META-08。

**差异 3：事件与动词模式变化**

史记战争动词正则（攻/伐/击/围/灭）在武侠语料召回崩塌，须整体重学（见 META-04 §六教训注解）；事件类型从史记 11 类换武侠 13 类（D03 定版）。

### 2.3 Level 3 重新设计（结构根本不同）

**需重新设计的内容**：

| 项 | 史记做法 | 武侠重设计 | 归属 |
|---|---|---|---|
| 多源融合哲学 | 史料多源无唯一真值，多数投票 + 冲突保留 | **作者权威真值**：正文字 > 作者修订 > 序跋 > 派生资料（权威四层，方向与史记相反） | D07 |
| 同一性判定 | 同一史实事件的多章记述互证 | 同一虚构人物跨书同一性：证据四级 E1-E4（正文明示 > 序跋 > 情节暗示 > 推断） | D07 |
| 时间体系 | 统一公元纪年，年表推算 | 双轨：故事时间（书内相对）+ 历史时间（朝代锚），无朝代锚书保持纯相对 | D05 |
| 业务逻辑检查 | 时序/年份约束（L4） | **设定一致性**：年龄跨回自洽/习得顺序/门派存续/死亡再现/称谓辈分——史记无对应物 | D11，见 META-10 |
| 消歧粒度 | 章级 | 书级 + 跨书归并级（双层 canonical：书内唯一层 + 系列唯一层） | D07 |

## 三、相似度评估矩阵（武侠维度新增）

源版将相似度压缩为一个百分位（>80% 直迁 / <60% 重设计），武侠版展开为七维矩阵——前四维对应源版原有维度，**后三维为武侠新增**（补写）：

| 维度 | 评估问题 | 高相似信号 | 低相似信号 | 本项目实测（史记→武侠） |
|---|---|---|---|---|
| **结构相似度** | 章节组织是否同构？ | 纪传体 ↔ 纪传体 | 纪传体 ↔ 编年体 | 低：单书章平铺 → 多书回嵌套 |
| **符号兼容度** | 标注语法是否可沿用？ | 同一 〖TYPE〗 体系 | 全新符号 | 高（骨架同）；动词层为增量 |
| **类型体系差异度** | 实体类型有多少可直接继承？ | 类型语义相近 | 需重推导 | 中：15+6 中 12 类可追溯到史记语义 |
| **文语差异** | 文言 ↔ 白话？ | 同语体 | 跨语体 | 中低：白话易懂但韵文/套语密度高 |
| **虚构程度**（新增） | 真值来源是外部史料还是作者设定？ | 有史可查 | 全凭设定 | 低（虚构）：须补权威层级方法论 |
| **设定连续性**（新增） | 目标数据集内部设定是否自洽可继承？ | 同一作者同一宇宙 | 多作者拼接 | 中：同一作者但跨书有疏漏与演化 |
| **系列关联度**（新增） | 语料单元之间是否共享实体谱系？ | 强共享（互文密集） | 互相独立 | 高：互文引用表 1,904 边、系列谱系 6 线 |

**用法**：逐维打分（高=+1 / 中=0 / 低=-1），合计 ≥ +4 视同 >80% 直迁；≤ -3 视同 <60% 重新设计；中间走适配。**新增三维中任一为"低"时，即使总分高，也必须触发 Level 3 检查**——虚构程度低相似意味着消歧/融合哲学要重审，这是源版阈值表的盲区。

## 四、试点驱动的迁移：六阶段（照搬框架，案例武侠化）

**核心**：不要一次性迁移全部，用小规模试点发现问题。**重点关注：实体类型是迁移第一关**——类型错误会沿工序传播（实体标注遗漏 → 事件抽取不完整 → 关系发现缺失 → 图谱质量低），必须在第一阶段解决。

> 武侠版的推论（补写）：**书间归并是第二关**——第 2 部书启动时，同一性问题（绰号↔本名、跨书同名异人）接棒成为错误传播源头。两级关口的时间序即 §八场景 4 的两级迁移。

### 阶段 1：选择试点回（3-5 回）

**选择原则**（照搬"覆盖多样性 + 难度分层"，抽样单元章 → 回）：
- **场景覆盖多样性**：选不同类型的回——战斗密集回（动词域压力测试）、传艺回（▣ 域与习得链）、开篇回（人物出场与朝代锚）、书信/韵文密集回（围栏与修辞层）
- **难度分层**：简单（人物少、单线叙事）→ 复杂（多线交织、绰号密集、回忆嵌套）

**试点候选示例**（以白发魔女传为默认试点书，终选归 G0）：
1. 第一回——开篇：朝代锚、人物出场密度、说书人套语
2. 某单挑回——战斗动词域、招式边界（☆ vs 动宾短语）
3. 某传艺回——师承关系、习得事件、秘籍器物
4. 某多线回——群组◎、职衔、场景切换
5. 某回忆嵌套回——叙述模式隔离、时间双轨

### 阶段 2：粗标试点（机器优先，快速迭代）

照搬"先粗标，观察差异，再精细化"四步：准备（复制 SKILL + 标注规范 + 试点回）→ 第一轮粗标（不追求完美）→ 并排对比（去标记原文 vs 标注文本，查遗漏/误标/模式）→ 抽样质检（每回抽查 100-200 个标注实体）。输出：初版标注、遗漏实体清单、误标案例清单、错误模式总结。

### 阶段 3：反思实体类型差异（Agent + 人工）——反思四问（照搬）

反思提示词四问结构照搬，武侠化的反思输入示例：

```markdown
# 任务：分析武侠试点回的实体类型需求

## 输入材料
1. 武侠标注体系：15 类实体 + 6 动词域（01g 定版）
2. 试点回原文与第一轮粗标结果
3. 遗漏实体清单 / 误标案例清单（人工观察）

## 反思四问（照搬源版结构）
1. 遗漏分析：哪些遗漏实体无法用现有 15 类标注？
   - 示例：阵眼、经脉、江湖规约 → 是否走 ^专门概念子型（词表硬前置）？
2. 类型冲突：是否有实体在武侠语境中类型不同？
   - 示例："金刀寨主"是绰号（@）还是组织+职位（◆+;）？——交 01g §2.2.1b 判定
3. 新增建议：是否需要新增实体类型？（提供候选 + 理由 + 影响回数）
   - 警惕：源版经验是"宁可先复用既有类型+子型，不轻言顶层新增"
4. 合并建议：是否有类型可以合并？
   - 示例：人物群组◎是否可并入组织◆？（定版结论：不并——群组无组织延续性）
```

人工审查照搬：检查建议合理性 → 评估成本 → 决策采纳/调整/拒绝。产出标注体系修订版（当前为 01g v0.3-draft 定版，后续演化按 META-08 §五流程）。

### 阶段 4：第二轮标注（应用反思结果）

照搬：更新 SKILL → 扩展词表（武侠走 `wordlists/` 双轨：人工源 + `wordlist_compiler.py` 编译）→ 重标试点回 → 对比 v1 vs v2（遗漏率降 50%+ / 误标率降 30%+）→ 抽样质检。质量未达标 → 回阶段 3。

### 阶段 5：记录所有问题（完整错误日志）

创建 `docs/transfer/史记→武侠_迁移日志.md`（**占位，待试点回填**）。条目模板照搬源版四要素（现象/原因/影响/修正方案 + 状态），武侠化条目示例：

```markdown
### 错误示例（格式演示，非实测——上线后回填）
**现象**：招式名"一剑刺出"被整体标为 ☆ 武功技艺
**原因**：动宾短语与招式名边界规则未进粗标提示词
**影响回数**：试点 5 回中 3 回出现，共 N 处
**修正方案**：粗标提示词补 01g §2.2.1b 判定第 6 步信号（有攻击动词则动词走 ⟦⊞⟧，短语不标 ☆）
**状态**：待修正
```

### 阶段 6：统计错误分布

照搬：按类型分组（词表不完整/新结构/标注类型缺失/关系类型扩展）→ 影响范围 → 修正工作量估算。产出分布表（**数字待试点回填**）。

## 五、反思驱动的适配与增量验证（照搬）

- **反思驱动适配**：错误日志 → Agent 反思（根因分析/共性模式/修正方案/优先级）→ 人工审查（不盲目接受）→ 修正 SKILL。反思报告格式照搬源版（`docs/transfer/反思报告_*.md`，**待试点回填实例**）。
- **增量验证**：每修正一个问题立即验证——重标试点回 → diff 前后差异 → 跑 lint → 人工抽查；验证失败回反思阶段。
- **扩展部署**：试点验证成功（错误率 <5%）后应用到全部 1,378 回；批量 lint 生成质量报告；分层抽查（建议每 10 回抽 1 回）；发现新问题重启反思循环（第二轮）。

## 六、典型场景

### 场景 1：系列内前作 → 后作（高相似度）

**类比**：史记 → 汉书。
**武侠例**：白发魔女传 → 塞外奇侠传 / 七剑下天山（同属天山谱系，人物/门派/武功直接接力——"前书末回写传人远走天山、后书开篇回指同人物"即 D05 接力锚场景）。
**策略**：直接复用约 80% 书内层资产与工序；词表增补后作新词汇；跨书实体经 D07 归并（证据驱动，不自动回写）。
**预期迭代**：2-3 轮。

### 场景 2：跨系列 / 跨时代背景（中等相似度）

**类比**：史记 → 资治通鉴。
**武侠例**：明末背景系列 → 清代背景系列（朝代锚体系、官职词表、江湖格局全换；清前中期 17 部可挂真实朝代纪年）。
**策略**：复用约 50-60%（标注语法、质量控制、时间双轨框架）；重设计门派/职衔词表与朝代锚登记；新增"跨系列换乘"实体归并。
**预期迭代**：4-5 轮。

### 场景 3：武侠宇宙 → 其他虚构宇宙（低相似度，远期）

**类比**：古文 → 现代文。
**武侠例**：梁羽生宇宙 → 其他作者多部曲宇宙（作者权威链断裂：跨作者无"作者序跋互证"，归并证据四级须重新定义；武功体系/门派命名习惯全部重建）。
**策略**：复用约 30%（META 元技能层 + 标注语法）；调整 40%（类型体系按三维度重推导——走 META-08 流程）；新增 30%（新宇宙的权威层级与编年）。
**预期迭代**：6-8 轮。

### 场景 4：多书虚构宇宙的两级迁移（**补写，源版无先例**）

源版六个字场景全部假设"目标是一本书/一套书，迁移一次完成"。多书虚构宇宙的迁移必须拆成**两级**：

```
级 1：书内标注迁移（每部书独立执行）
  史记方法论 → 单部武侠书
  产出：书内层资产（标注文本 / 事件 / 关系 / 实体登记，书内 canonical 唯一）
  关口：实体类型适配（§四"第一关"）
  迭代：每部书 2-3 轮（同系列后作更少，见场景 1）

级 2：书间归并迁移（跨书，只在 ≥2 部书有资产后执行）
  试点书资产 → 第 2..N 部书的归并
  产出：系列层资产（双层 canonical 的系列唯一层 / 互文引用 / 跨书谱系 / 宇宙编年）
  关口：同一性判定与权威裁决（"第二关"）
  方法论：完全归 D07 跨书治理——证据四级 E1-E4、权威四层、双层 canonical、
         绰号消解五步（S1-S5）、同名异人跨书限定、bare B0-B8 分流
  铁律：无证据不归并；E1/E2 可单独支撑归并，E3 须双辅证，E4 只登记不回写
```

**两级的关系**：
1. 级 1 未收敛（书内错误率未达标）的**不得**进入级 2——书内错传到系列层会批量污染多部书；
2. 级 2 产出的归并结论**反向约束**级 1（后作归并发现前作登记错误 → 回修前作，走增量验证）；
3. 宇宙编年（D05 §2.7）是级 2 的前置工程——史记的跨章对齐依赖统一公元纪年，武侠须先建作品宇宙编年（系列谱系考订表 14 时代段是雏形），源版无此步骤。

### 场景 4 附：试点书选择策略（**补写；终选归 G0 拍板**）

源版试点选择原则只覆盖"一本书内选哪些章"（§四阶段 1），从未回答"多书宇宙先标哪本书"。三种策略的建议矩阵：

| 策略 | 候选 | 优势 | 风险 | 适配条件 |
|---|---|---|---|---|
| **系列枢纽** | 天山系列枢纽部（七剑下天山 / 云海玉弓缘） | 跨书归并收益最大——枢纽部是系列谱系 6 线中最多边的节点，一部书验证最多归并路径 | 设定强依赖前作，书内层 L1-L4 自洽性验证不完整；首标即遇"前作未标"的悬空引用 | 已有 ≥1 部前作资产后再启动 |
| **独立部** | 时代/地理相对独立、系列入边少的部 | 无跨书依赖，可完整闭环验证级 1 全链路（冷启动→反思→收敛），方法论干净 | 归并方法论（级 2）完全无法验证；延后第二关风险 | 适合做**第一本**试点 |
| **代表作/既有资产** | 白发魔女传（已拆分章回、现有管线 `pipeline.py` 已跑通、有既有标注资产可对账） | 启动成本最低；新旧标注对账本身就是免费的错误日志 | 早期作品，天山系列源头地位需考订确认；代表作地位与"信息密度"不一定相关 | **当前默认**（tagged/ 已有该书包） |

**建议**：以白发魔女传（既有资产延续）完成级 1 试点收敛 → 第二部书从天山谱系后作（塞外奇侠传或七剑下天山）启动，顺势验证级 2 归并 → 独立部穿插在第三、四部验证跨系列迁移（场景 2）。**终选顺序归 G0 拍板门**（底本锁定 + 试点书 + 附录 B 集中裁决），本文件只提供矩阵不拍板。

## 七、对源版 §8.3"不要选小说"判定的正面修正（**补写**）

源版 §8.3（试点选择原则）明文：

> "❌ 不要选择：小说/文学作品（虚构，实体关系弱）"
> §8.6："娱乐小说（虚构，应用价值低）"列为低价值场景。

**若照搬原文，本项目立项论证自相矛盾**——我们的目标语料正是小说。修正如下：

| 源判定的论据 | 武侠场景复核 | 结论 |
|---|---|---|
| "虚构，实体关系弱" | **不成立**。34 部共享门派/武功/人物谱系：互文引用表 1,904 边、系列谱系 6 线、师承谱系、神兵传承链、武功层级（父术-子式）——关系密度实测不低于史书；且谱系是作者刻意设计的结构化对象 | 关系不弱，反而更规整 |
| "无外部真值可校验" | **成立但已解决**。真值来源从"史料互证"变为"作者设定"——不是真值缺失，而是真值换源。D07 权威四层（正文字 > 作者修订 > 序跋 > 派生资料）给出与史记"多源无真值"方向相反但同样严格的裁决体系 | 换源，非缺源 |
| "娱乐小说应用价值低" | **价值主张不同**。本项目目标即武侠知识库（人物档案/江湖问答/穿帮雷达/说书人专栏/可视化），价值独立于源版设想的学术出版场景；"低价值"判定只在源版的 ROI 参照系（领域知识图谱/思想体系图谱）内成立 | 参照系替换 |

**修正后的判定**（替换源版 §8.3 的"不要选择"清单）：

- ❌ **仍不选**：无系列结构的单本通俗小说——无共享设定、无跨书谱系，实体关系确实弱（源判定对此类**仍然成立**）；
- ✅ **可选**：同一作者的**多部曲/系列宇宙**——共享设定制造了高密度结构化关系，作者权威提供了真值锚点；
- ⚠️ **附加义务**：虚构宇宙迁移必须补齐源版没有的三件套——权威层级（D07）、书间归并两级迁移（§八场景 4）、设定一致性检查层（D11，见 META-10）。

**修正性质声明**：这是对源版判定的**限定条件修正**（"小说"→"无系列结构的单本小说"），不是推翻——方法论骨架（试点驱动、反思迭代、Human-in-the-loop）不受影响。

## 八、迁移成本估算（公式框架重标定；数字待试点回填）

### 8.1 源版公式（史记 130 篇标定，保留作对照基准）

```
总工作量(小时) = 冷启动(20h) + 试点标注(30h) + 错误分析(15h)
                + 反思迭代(N轮 × 25h) + 扩展部署(50h) + 质量验证(40h)
史记→汉书预估：230 小时 / 约 6 周（相似度 85%，2-3 轮收敛）
```

### 8.2 武侠重标定（公式框架；**全部系数待试点后回填**）

量纲换算：史记 130 篇 ↔ 武侠 1,378 回（1 篇 ≈ 10.6 回，仅作量级参考——回均字数、白话密度与韵文占比均不同，**不可直接线性折算**）。

```
总工作量(小时) = S_cold(冷启动)
              + S_pilot × n_p(试点标注，n_p=试点回数 3-5)
              + S_error × n_p(错误分析)
              + N_round × S_refine(反思迭代，N_round 预计 2-3 轮)
              + S_scale × (1378 - n_p) × η(全库部署，η=扩展期效率系数)
              + S_verify(质量验证)
              + S_merge × n_books(书间归并——源版没有的新增项，见场景 4 级 2)
```

| 系数 | 含义 | 状态 |
|---|---|---|
| S_cold | 冷启动成本 | **预期低于源版 20h**：12 件设计稿 + P0 地基（config/symbols/masker/wordlist_compiler + 本波 4 META）已完成大半 |
| S_pilot / S_error | 单回粗标与错误分析 | 待白发魔女传试点实测 |
| S_refine / N_round | 单轮迭代成本与轮数 | 待实测；同系列后作预期递减（场景 1） |
| S_scale × η | 全库部署 | 待试点外推；η 随词表成熟度上升 |
| S_merge | 单部书归并成本 | 待第二部书启动实测（依赖 D07 工具 N6 merge_crossover.py 建成） |

### 8.3 成本效益与收益递增（照搬框架，结论武侠化）

- 不迁移从零构建 vs 迁移构建的对比逻辑照搬（源版结论"迁移节省 50%+"预期在武侠更强——设计稿已吸收源版全部教训）；
- 收益递增照搬：第一部书（试点）成本最高 → 同系列后作递减 → 第 N 部书趋向标准化 SOP；长期收益是"虚构宇宙知识工程工具链"。

## 十、总结

### 核心要点（源版八条照搬 + 武侠两条补写）

1. **实体类型优先**（照搬）：类型差异极大，先粗标→观察→反思四问→定类型体系
2. **书间归并第二关**（补写）：第 2 部书起，同一性/权威裁决接棒成为错误传播源头
3. **机器 + 人工协作**（照搬）：机器粗标，人工对比观察，识别模式
4. **反思与迭代贯穿全程**（照搬）：每工序走"粗作→观察→反思→精作→质检"
5. **分层迁移**（照搬）：直接复用 → 适配调整 → 重新设计；七维矩阵判定（含武侠三维）
6. **试点驱动**（照搬）：3-5 回试点；多书宇宙拆两级（书内标注 + 书间归并）
7. **增量验证**（照搬）：每修正一个问题立即对比 v1 vs v2
8. **Human-in-the-loop**（照搬）：观察/抽样/决策三职责归人工；归并裁决（E1 语式 + S3 唯一性双过才可半自动）与试点书终选（G0）必须人工
9. **真值换源不等于关系弱**（补写）：§七修正——虚构宇宙的谱系密度可以高于史书，代价是必须自建权威层级
10. **迁移纪律可对照**（补写）：武侠适配说明四分法（已替换/照搬/补写/待回填）是全项目 SKILL 的头部标准格式

### 迁移哲学（照搬）

小步快跑：试点 → 反思 → 修正 → 扩展；拥抱失败：失败案例是学习机会；知识沉淀：每次迁移形成可复用资产。

> **核心洞察（照搬原文）**：SKILL 文档不是一次性设计，而是在多项目迁移中持续演化的知识资产。

### 与其他元技能的关系

- **→ META-08 标注体系设计**：迁移第一关（实体类型）的方法论主场
- **→ META-10 质量控制**：迁移后验证质量不倒退；L4 设定一致性层是武侠新增的验收维度
- **→ META-04 柳叶刀方法**：分层迁移对应分层分解；试点粗标即柳叶刀"规则先行"
- **← 冷启动**：迁移 = 加速的冷启动；试点书选择策略与 M03 书维度抽样共用 §八附矩阵
- **→ M12/D07 跨书治理**：场景 4 级 2 的方法论主场（M12 概念已被 D07 吸收设计）

## 成功标准

- **判级准确**：相似度矩阵四维评分有证据（类型表差异/结构件差异/事件域差异），Level 判定经第二人复核。
- **试点达标**：3-5 回试点二轮后 precision/recall 不低于源项目基线的 90%（或差异可解释且经负责人签字）。
- **错误可归类**：错误分布 ≥90% 落入已知类别（类型/边界/管道/动词/结构），剩余逐条标注"新类别候选"并进 03c1。
- **成本可估算**：迁移总成本=结构适配+标注+反思+回归四项，公式系数由试点回填，误差 ≤30%。
- **可复用**：产出 ≥1 套可复用资产（类型表补丁/词表/种子/结构脚本）+ 1 条迁移日志，下一部书可直接引用。
- **治理合规**：涉及规范/类型/registry 的改动均走 G0 或对应轴裁定，不自行改规范（§1.2 迁移纪律）。
