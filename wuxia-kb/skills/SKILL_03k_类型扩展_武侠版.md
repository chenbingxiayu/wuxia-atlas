# SKILL 03k 武侠版：类型扩展（三问裁定法）

> **上游声明**：本文是 D08 分类树五件套（`SKILL_分类树五件套_武侠版.md`，v0.3-draft）§5.3「三问裁定法」、§6.2「升级三信号」、§6.6「跨树指认」的执行件，回答"什么时候该扩类型、扩什么、怎么拒绝"。01g 顶层类型与符号铁律由 `SKILL_01g_标注符号集合原则.md`（D01）定版：**不新增顶层类型/不新增行内符号**；类型新增必须证明旧类型、子型和关系确实无法表达目标（01g 附录 B 关闭事项要求）。树结构见 `SKILL_03h_实体子类_武侠版.md`，登记见 `SKILL_03i_分类登记_武侠版.md`。
> **移植依据**：`docs/05-管线技能与脚本逐项改造分析.md`（分类树配套裁定法）；`docs/17` §2.5（S-03k ←D08）；`docs/12` 双稿评审（类型/属性边界裁决记录）。
> **核心原则**：**能用属性就不建类型，能用子类就不建顶层，能用关系就不建类型，通名一律不登记**。类型扩展是最后手段，不是第一反应。

## 一、技能定位与边界

### 1.1 工序位置（类型闸门）

```text
新词/新现象（来自标注、词表候选、页面需求、评审意见）
        ↓
S-03k 类型扩展（本文）：三问裁定 → 四象限落位（类型 / 属性 / 子类叶 / 通名不登记）
        ↓
S-03h 建树/变更 ── S-03i 登记 ── S-06e 颗粒度审查 ── N9 校验
        ↓
01g 符号体系（顶层类型不新增；新叶只进登记层）
```

- **前置**：01g 15 类符号定版、D08 五树定稿、D09 词表 schema 可用。
- **后继**：S-03h（建叶/变更）、S-03i（登记）、S-06e（颗粒度）、词表 WL-15~19 同步。
- **现行事实（2026-11-05）**：N9 内嵌五树 64 叶映射，结构 PASS；类型/属性边界裁决已在 D08 定版（真实性/邪正/品类/存续/性别均属属性）；真开放项 9 项见 D08 附录 B。

### 1.2 本文做什么（五件事）

1. **三问裁定**：给每个"扩类型"动议一个可复核的判决（通过/拒绝/转属性/转子类/转关系）；
2. **四象限落位**：类型 / 正交属性 / 子类叶 / 通名不登记；
3. **升级判定**：招式→武功、子类→叶、叶→树等层级升判的三信号；
4. **跨树指认**：暗器（器物）vs 暗器手法（武功）等跨类同形归属；
5. **拒绝与留痕**：拒绝理由模板、版本与规则累积日志。

### 1.3 本文不做什么（边界，越界即错）

- **不新增行内符号**：任何"给新类型加 〖符号〗"一律驳回（01g 铁律一）；
- **不直接建叶**：裁定通过后由 S-03h 执行建叶/变更；
- **不处理同一性**：同名/同形消歧见 `SKILL_03j_同形异义_武侠版.md`；
- **不重开已定版裁决**：真实性/邪正/品类/存续/性别=属性、镖师双轨、宗室爵位归身份等已定版项不重开。

## 二、快速开始（四步裁定序）

> 目标：对一批"扩类型"动议跑完"列动议 → 三问 → 四象限落位 → 留痕/复验"。命令只读或写报告。

```powershell
cd C:\Users\YANG Ruosong\Documents\workspace\Wuxiaxiaoshuo\wuxia-kb
$env:PYTHONIOENCODING='utf-8'

# Step 1 列动议：从词表候选/标注疑问/评审意见收集，逐条写"动议卡"（附录 A）
# Step 2 三问裁定：是类型吗？已有类型/子型/关系能表达吗？实例 ≥10 吗？
# Step 3 四象限落位：类型 / 属性 / 子类叶 / 通名不登记（附正误例）
```

**判读口径**：三问任一为"否"即不得建类型（转属性/子类/关系/不登记）；建叶后 N9 结构 error 必须 0；规则累积日志只记已发生的变更。

## 三、三问裁定法（D08 §5.3）

### 3.1 三问定义

| 问 | 内容 | 判据 | 否决后果 |
|---|---|---|---|
| **Q1 是不是类型？** | 该词是"实体类型/分类维度"还是属性值/状态/评价/通名 | 类型=可稳定挂叶、可穷举、可判定；属性=随语境变化 | 转属性字段（邪正/真实性/品类/存续/性别） |
| **Q2 已有类型/子型/关系能表达吗？** | 15 类符号、64 叶、55 谓词边是否已能承载 | 有现成类型/叶/关系可表达 → 不新增 | 转子类叶或关系边 |
| **Q3 实例是否 ≥10？** | 预计实例数（跨 34 书）是否达 06e 门槛 | <10 → 不单列叶（合并或观察位） | 转观察位/并入邻叶 |

### 3.2 四象限落位（裁定输出）

| 落位 | 条件 | 动作 | 例 |
|---|---|---|---|
| **类型（顶层）** | Q1 是 + Q2 无现成表达 + 01g 批准新增顶层 | **原则上不允许**；须走 01g 附录 B 关闭事项四要素 | 无（15 类已定版） |
| **子类叶** | Q1 是（分类维度）+ Q2 无现成叶 + Q3 ≥10 | S-03h 建叶 + S-03i 登记 | "镖局车店"叶 |
| **正交属性** | Q1 否（属性/状态/评价） | 属性字段赋值（默认未定） | 邪正/真实性/品类/存续/性别 |
| **通名不登记** | 泛称/方位泛指/评价代称 | 不进树、不进弃权通道；进 #9 候选表观察池 | 武林/江湖/山下/女魔头 |

> 第五种出口：**关系边**（Q2 命中）——如"任职"用关系边而非职衔叶；"组织成员"用边而非身份叶。

### 3.3 正误例

| 动议 | 裁定 | 理由 |
|---|---|---|
| 新增"魔教中人"类型 | ❌ 拒绝 → 属性（邪正）+ 关系边 | 立场随剧情变，先邪后正者无叶可挂（T2） |
| 新增"隐世门派"叶 | ❌ 拒绝 → 存续状态属性 | 状态随剧情变，叶频繁迁改（T9） |
| 新增"侠女"身份叶 | ❌ 拒绝 → 性别属性 | 与性别属性完全重复（T8） |
| 新增"轻功"心法层 | ❌ 拒绝 → 品类属性 | 品类当层级（T13） |
| 新增"镖局车店"地点叶 | ✅ 通过 → 子类叶（≥10，判定信号独立） | 06e 达标 |
| "暗器"归武功树 | ❌ 拒绝 → 跨树指认：暗器=器物、暗器手法=武功层 | T11 |
| "武林/江湖"登记为势力 | ❌ 拒绝 → 通名不登记 | T1 |

## 四、升级判定与跨树指认

### 4.1 升级三信号（D08 §6.2，武功树）

招式 → 武功（层级升判）须 **≥2 独立信号**：

| 信号 | 内容 | 例 |
|---|---|---|
| S1 跨书独立引用 | 该招式被 ≥2 书独立引用（非同一底本互见） | 两书各出现完整招式名 |
| S2 谱系/传承证据 | 有师承/传授/秘籍记载（关系边或秘籍卡） | "传了七十二手连环剑" |
| S3 情节功能独立 | 该招式有独立情节功能（决战胜负手/成名绝技） | 决战中以该招定胜负 |

- 升级必走**升级专用日志**（触发案例必填，T14）；单招被引用一次即升级 = 违例（T3）；
- 降级（武功→招式）同样留痕。

### 4.2 跨树指认（D08 §6.6）

| 同形 | 归属 | 规则 |
|---|---|---|
| 暗器（飞刀/袖箭） | 器物树/`•` | 器物子型 |
| 暗器手法（满天花雨/袖里乾坤） | 武功树·招式层/`☆` | 技艺，不是器物 |
| 阵法（物品/图） | 器物/文书 | 载体归器物/文书 |
| 阵法（结阵技法） | 武功树·阵法层/`☆` | 技艺 |
| 组织名（锦衣卫/东厂） | 势力树/`◆`；人物为 `;`/`#` | 组织与个体不互挂（T16） |

## 五、新增流程与留痕

### 5.1 建叶/新增流程（裁定通过后）

1. 写**动议卡**（附录 A）：三问结论 + 四象限落位 + 正误例 + 预计实例；
2. 若建叶：按 S-03h 定义叶（父分支/判定信号 ≥2/正误例/稀疏理由）；
3. 规则累积日志追加一行（日期/树/版本/变更/触发案例/生效范围/动因）；
4. WL-15~19 词表同步（叶子清单 + 种子词）；
5. N9 复跑：结构 PASS、无兜底叶、文-码漂移 PASS；
6. 若涉及属性/关系：更新属性字段字典或 55 谓词表（走 D09/D06 版本流程）。

### 5.2 拒绝留痕

拒绝也必须留痕（防重复动议）：`{动议, 裁定, 理由, 替代落位, 日期, 裁定人}`；拒绝清单建议落 `logs/qa/type_extension_decisions.md`。

### 5.3 版本与日志纪律

- 树版本升 MINOR（新增/合并叶）或 MAJOR（分支/维度变更）；词表版本按 D09 协议；
- 只记已发生变更；示例行标"格式示例"；禁止预填未来日期（防伪日志）。

## 十、成功标准（Success Criteria）

1. **零符号新增**：顶层类型与行内符号改动 = 0。
2. **裁定可复核**：100% 动议有三问结论 + 四象限落位 + 依据；拒绝有留痕。
3. **属性纪律**：属性维度入树 = 0；默认值偷懒 = 0。
4. **门槛合规**：新建叶 100% 满足 ≥10（或稀疏理由）；树深 ≤4。
5. **升级合规**：升级 100% 有 ≥2 信号 + 专用日志。
6. **接口一致**：词表/N9/01g 无漂移。
