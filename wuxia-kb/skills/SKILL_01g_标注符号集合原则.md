# SKILL 01g：武侠实体、事件与标注符号规范

> **核心原则**：原文不改，标注可剥离；实体、动词、修辞分层；名称不等于身份，提及不等于事实，事件不等于一个动词。

> **类型设计原则**：只为具有独立身份、独立判断边界或独立下游用途的对象设置类型。可以用子型、属性或关系表达的信息，不另设标注符号。

> **适用范围**：武侠小说本地标注、实体登记、事件抽取、跨书知识图谱、本地阅读器及公开知识库的数据生产。

## 一、问题诊断

### 1.1 为什么需要统一的标注规范

武侠小说标注的困难，不只是“找到人名、地名和武功名”，还包括以下问题：

1. **同一人多种称名**：本名、法号、化名、绰号与临时称呼并存。
2. **同一个词多种指称**：名称可能指人物、武功、兵器或组织。
3. **同名不等于同一实体**：不同书中的同名人物、同名兵器可能没有身份连续性。
4. **武功与秘籍不同**：技术本身、记载技术的文本、某一册纸本是不同对象。
5. **集体名号不是个人**：固定人物组合不能套用个人年龄、婚姻与死亡字段。
6. **打斗不是动词计数**：一场战斗可能包含数十次攻击，也可能只有一句概述。
7. **意图不是事实**：“要杀”“未杀”“传闻已杀”不能生成相同知识。
8. **相对时间有叙事线**：“三个月后”的锚点不能机械取全文最近时间。
9. **地名具有多重作用**：少林寺可以指建筑，也可以指组织。
10. **原文与标注不能混写**：补字、改标点、展开简称都会破坏定位。
11. **类型过多会失控**：细分颜色、词表、页面和规则的成本会沿管线累积。
12. **类型过少同样危险**：把固定群组当个人、把死亡漏在动词域之外，会污染推理。

**示例一：称名与身份混淆**

```text
❌ 错误
将“玉罗刹”“白发魔女”“练霓裳”建立为三个互不关联的人物。

✅ 正确
〖@玉罗刹|练霓裳〗
〖@白发魔女|练霓裳〗
〖@练霓裳〗
三种提及指向同一个稳定人物 ID。
```

**示例二：动作与事实混淆**

```text
❌ 错误
“若他再来，我便杀了他。”
生成：甲杀死乙。

✅ 正确
这是条件性威胁。
不生成已发生的死亡事件。
```

**示例三：词形与类型混淆**

```text
❌ 错误
遇到“小李飞刀”一律标武功。

✅ 正确
〖@小李飞刀〗走进客店。
他练成了〖☆小李飞刀〗。
他拾起那柄〖•小李飞刀〗。
分别根据当前指称判定。
```

> **示例说明**：本文件例句为规则演示，不作为作品原文或情节证据。“小李飞刀”“降龙十八掌”等跨作品种子只用于压力测试，不据此登记进梁羽生宇宙。

### 1.2 统一规范的优势

✅ **无损还原**：去除新增标注与元数据后，可以逐字符恢复锁定底本。

✅ **身份稳定**：实体 ID 不随本名、绰号、页面标题变化。

✅ **类型可控**：本规范设置 **15 个实体类型、6 个动词域、1 个修辞类型**。

✅ **事件完整**：战斗、生命健康、社会关系、物件变化、技术传习、行踪均有明确入口。

✅ **事实可追溯**：每条关系和事件都保留来源、定位、状态与核实程度。

✅ **跨书可扩展**：新书增加提及与证据，不必反复重建实体身份。

✅ **未知可表达**：所指、年代、胜负或地点性质不明时，允许保留未知。

✅ **发布可隔离**：本地原文层与公开图谱层具有不同的数据出口。

## 二、三大符号集合定义

### 2.1 标点符号集合（Punctuation Set）

**定义**：原文中用于断句、引用、语气及补充说明的字符。

标点属于原文，不属于新增标注。

| 符号 | Unicode | 名称 | 用途 |
|------|---------|------|------|
| `。` | U+3002 | 句号 | 句子结束 |
| `，` | U+FF0C | 逗号 | 句内停顿 |
| `、` | U+3001 | 顿号 | 并列分隔 |
| `；` | U+FF1B | 分号 | 复句分隔 |
| `：` | U+FF1A | 冒号 | 提示、引出 |
| `？` | U+FF1F | 问号 | 疑问 |
| `！` | U+FF01 | 叹号 | 感叹 |
| `“` | U+201C | 左双引号 | 引用开始 |
| `”` | U+201D | 右双引号 | 引用结束 |
| `‘` | U+2018 | 左单引号 | 内层引用开始 |
| `’` | U+2019 | 右单引号 | 内层引用结束 |
| `《` | U+300A | 左书名号 | 作品标题开始 |
| `》` | U+300B | 右书名号 | 作品标题结束 |
| `——` | U+2014 × 2 | 破折号 | 插说、转折 |
| `……` | U+2026 × 2 | 省略号 | 省略、语气延续 |
| `（` `）` | U+FF08 / U+FF09 | 圆括号 | 补充说明 |
| `「` `」` | U+300C / U+300D | 直角引号 | 部分版本的引用 |
| `『` `』` | U+300E / U+300F | 双直角引号 | 部分版本的内层引用 |

**规范**：

- ✅ 锁定底本使用什么标点，标注层就保留什么标点。
- ✅ 新写说明、原创分析与规范文档使用统一中文标点。
- ❌ 不在标注过程中把直角引号替换为弯引号。
- ❌ 不在标注过程中把半角标点批量改成全角。
- ❌ 不删除所谓“多余标点”后继续沿用旧定位。
- ❌ 不把引号、书名号、句末标点包入实体边界。

**正误对照**：

✅ 底本为 `「玉罗刹来了。」`，标注为 `「〖@玉罗刹|练霓裳〗来了。」`。

❌ 标注时改为 `“〖@玉罗刹|练霓裳〗来了。”`，却未声明建立了校勘版本。

**理由**：

标点统一属于校勘工序，原文无损属于标注工序。两者不能混在一次变换中。

### 2.2 标注符号集合（Annotation Set）

**定义**：新增的语义标记及其受控元数据。

本规范区分三层：

| 层 | 标记格式 | 对象 |
|----|----------|------|
| 实体层 | `〖TYPE显示串〗` | 人物、地点、武功、物件等对象 |
| 动词层 | `⟦TYPE触发串⟧` | 已进入事件抽取范围的动作或状态变化 |
| 修辞层 | `〘※表达串〙` | 成语、固定熟语等语言表达 |

**三层关系**：

- 实体标注回答“这段文字指什么对象”。
- 动词标注回答“这里出现什么类型的事件入口”。
- 修辞标注回答“这里用了什么固定语言表达”。
- 完整事实还需要参与者、状态、来源和定位。
- 同一字符区间不允许三层重叠。

#### 2.2.1 实体标注符号（〖TYPE〗格式）

**外层括号**：

- 左括号：`〖`，U+3016。
- 右括号：`〗`，U+3017。

> **📌 类型定版记录**
>
> - 采用 15 类实体，不机械继承历史语料的全部分类。
> - 新增“武功技艺”和“人物群组”两个具有独立边界的类型。
> - 保留人物、地点、组织、家族、族群、生物、器物、文书、职衔、身份、时间、数量。
> - 礼仪、律令、思想、天文等不再分别占用顶层符号，符合条件时进入“专门概念”及其子型；**词表硬前置**：专门概念首批词表必须包含江湖规约子表（盘点 P2-7“江湖规矩”维度的采集前提）、穴位经脉与刑名律令子表。
> - 神话人物按其指称对象进入人物，另记神话性质或叙述模式；不另设“神话”顶层类型。
> - 专门概念只标技术性、制度性或被明确对象化的概念，不泛标普通抽象名词。
> - 对象的真实/虚构、邪正、品类、材质、功能、历史性均为属性，不另设符号。
> - 既有高频符号尽量保留，避免为了形式统一制造大规模学习和迁移成本。
> - 动词统一采用方形外轮廓符号，不再与组织（`◆` 菱形系）共用形状系列。

**实体类型表**：

| 符号 | 类型 | 说明 | Markdown冲突 |
|------|------|------|-------------|
| `@` | 人物 | 被文本具体指称的个人，包括本名、法号、化名、绰号及可确认的人物称名 | 常规 Markdown 无特殊语法；部分平台可能扩展为提及 |
| `◎` | 人物群组 | 具有稳定集体名称、以特定人物组合为核心的群组 | 无常规冲突 |
| `=` | 地点 | 被具体指称的地理地点、建筑、场所及空间单元 | 行首特殊形式可能参与标题语法；标注令牌内不按 Markdown 解析 |
| `◆` | 组织 | 有独立组织身份和延续性的国家、政权、门派、帮会、机构、军队等 | 无常规冲突 |
| `&` | 家族世系 | 以血缘、婚姻、收养或谱系认同构成的具名家族 | 涉及 HTML 字符实体处理，须由受控解析处理 |
| `~` | 族群 | 具名民族、族群及族群性共同体 | 部分 Markdown 扩展用于删除线 |
| `;` | 职衔 | 可以担任、履任、继任或任命的朝廷及江湖职位 | 无常规冲突 |
| `#` | 身份 | 非具体职位的职业类别、社会身份、法定身份或处境身份 | 标题字符，但 TYPE 位不是标题 |
| `☆` | 武功技艺 | 可命名、修习、传授或施用的武功、套路、招式、战斗阵法及其他专门技艺 | 无常规冲突 |
| `•` | 器物 | 具体指称的兵器、暗器、宝物、药物、材料及其他非生物物件 | 无常规冲突 |
| `+` | 生物 | 被具体指称的动物、植物及具名生物 | 可用于列表，TYPE 位不是列表 |
| `{` | 作品文书 | 作为内容对象的秘籍、书籍、诗词作品、书信、图画、账册、告示等 | 部分扩展使用花括号属性 |
| `^` | 专门概念 | 技术、医学、制度、规约、学说等领域的稳定术语或被明确对象化的概念 | 部分扩展使用脚注或上标 |
| `%` | 时间 | 日期、时点、时期、相对时间、年龄和真实时间长度 | 无常规冲突 |
| `$` | 数量 | 计数、金额、长度、招数、距离及非真实时间量的程度表达 | 部分扩展用于数学公式 |

**封闭性与标注方式**：

- **半封闭**：词表与规则可以稳定召回候选，但仍需要上下文消歧。
- **开放**：名称和实例不断增长，需要人工或模型识别。
- “可词表驱动”不意味着允许脱离上下文直接定类。
- 人工或模型负责判断，登记表负责约束已确认身份。

| 类型 | 封闭性 | 可驱动的候选 | 必须上下文判断 |
|------|--------|--------------|----------------|
| 人物 | 开放；已登记名称半封闭 | 人名、法号、绰号词表 | 所指、同名异人、称呼性质 |
| 人物群组 | 开放 | 已登记集体名号 | 固定群组与组织、临时集合 |
| 地点 | 开放 | 地名、建筑名、场所名 | 地点与机构、同名地点 |
| 组织 | 开放 | 门派、机构、政权词表 | 延续性、组织与建筑 |
| 家族世系 | 开放 | 家族名、谱系名 | 家族、住宅、复姓个人 |
| 族群 | 半封闭 | 民族、族群名称 | 族群与政权、地名 |
| 职衔 | 半封闭 | 官职、江湖职衔词表 | 称呼、冻结绰号、职位边界 |
| 身份 | 半封闭 | 职业、身份与处境词表 | 实际身份与评价描写 |
| 武功技艺 | 开放；登记后半封闭 | 武功、招式、阵法、技艺名 | 同形词、技术层级 |
| 器物 | 开放；类别半封闭 | 兵器、药物、材料词表 | 实例、动作工具义、内容载体 |
| 生物 | 开放；物种半封闭 | 动植物名称 | 真实生物与招式意象 |
| 作品文书 | 开放 | 作品标题、文书名称 | 内容对象与纸本副本 |
| 专门概念 | 半封闭且可扩展 | 穴位、经脉、制度、学说术语 | 技术指称与普通议论 |
| 时间 | 半封闭 | 时间词、数词和单位 | 年龄、时长、锚点、名称数字 |
| 数量 | 半封闭 | 数词、量词和计量单位 | 时间量、名称成分、功力量 |

**类型存在性与下游用途**：

| 类型 | 独立设置的必要性 | 主要下游用途 |
|------|------------------|--------------|
| 人物 | 个人拥有独立身份、生平与跨书连续性 | 人物档案、关系网、问答、游戏 |
| 人物群组 | 不能套用个人生平，也不等于持续组织 | 集体名号搜索、群组页、协同行动 |
| 地点 | 是行踪、空间关系与虚构地图的对象 | 地图、路线、地点页 |
| 组织 | 成员、职位与沿革具有持续性 | 门派页、阵营、掌门谱系 |
| 家族世系 | 血缘谱系不同于组织成员关系 | 族谱、继承、亲属网络 |
| 族群 | 民族共同体不能压缩成政权或职业 | 民族关系、历史背景分析 |
| 职衔 | 任职关系必须连接职位与组织 | 历代掌门、官职与江湖履历 |
| 身份 | 职业、俘虏等不应伪装成任命岗位 | 人物身份、社会结构分析 |
| 武功技艺 | 技术具有可传授、可修习的独立谱系 | 武功页、成长曲线、传艺问答 |
| 器物 | 物件拥有制造、转移、毁损链 | 神兵谱、宝物、药物记录 |
| 生物 | 活体拥有生命状态和行动能力 | 坐骑、动物伙伴、生态对象 |
| 作品文书 | 内容可以跨副本传播，并支撑技术来源 | 秘籍页、文书证据、知识来源 |
| 专门概念 | 技术机制、穴位与制度不是物件或武功 | 武功说明、概念检索、制度分析 |
| 时间 | 年龄、相对时序与时期支撑约束推理 | 编年、成长、穿帮检查 |
| 数量 | 数量指标不能全降为普通文本 | 招数、物价、距离、统计分析 |

**不新增顶层类型的对象**：

| 对象 | 表达方式 | 理由 |
|------|----------|------|
| 兵器、暗器、丹药 | 器物子型 | 同属物件，生命周期机制相通 |
| 剑法、掌法、内功、轻功 | 武功技艺子型 | 技术对象相同，只是品类不同 |
| 战斗阵法 | 武功技艺子型 | 可布设、传授、破解的技术 |
| 阵法中的阵眼、方位原理 | 专门概念 | 是机制，不是完整技术 |
| 拜师礼、江湖规约 | 专门概念子型 | 名词制度与实际仪式事件分开 |
| 刑名、律令 | 专门概念子型 | 低频制度对象，不必单独颜色 |
| 侠义理念、武学学说 | 专门概念子型 | 仅在被明确对象化时标注 |
| 神祇、传说人物 | 人物加性质属性 | 指称对象仍然是人物 |
| 天体、星象 | 专门概念或地点，按实际指称 | 不为低频主题单独设置类型 |
| 关系、事件、阵营、胜负 | 登记层 | 通常不是连续名词对象 |
| 真实、虚构、邪正 | 属性与评价记录 | 不改变实体基本类型 |

**逐类正误对照**：

| 类型 | ✅ 正例 | ❌ 反例 |
|------|---------|---------|
| 人物 | 〖@白发魔女\|练霓裳〗来了 | 把“那老者”自动建立为永久别名 |
| 人物群组 | 〖◎麦氏三雄〗一同现身 | 把“众镖师”建立为固定群组 |
| 地点 | 他来到〖=秘魔崖〗 | 把泛称“山”登记为地点 |
| 组织 | 〖◆丐帮〗传来消息 | 因“七人同行”建立组织 |
| 家族世系 | 〖&慕容氏〗世代习武 | 把复姓个人整体标为家族 |
| 族群 | 此地住着〖~蒙古族〗居民 | 把蒙古政权一律当民族 |
| 职衔 | 他接任〖;总镖头〗 | 把“前辈”当职衔 |
| 身份 | 他本是个〖#镖师〗 | 把赞语“好汉子”当身份 |
| 武功技艺 | 他使出〖☆怪蟒翻身〗 | 从真实蟒蛇动作判出招式 |

### 2.2.1a 名称、规范名与实体身份

**基本格式**：

```text
〖TYPE显示串〗
〖TYPE显示串|规范名〗
```

**显示串**：

- 必须是原文中的连续字符。
- 不补字、不换字、不展开简称。
- 不含外部标点和 Markdown。
- 不把上下文省略的字补回显示串。

**规范名**：

- 是登记表中批准的展示名称。
- 人物优先使用有可靠证据的本名。
- 无可靠本名时，使用稳定法号、通行化名或专名。
- 不猜造俗名、全名或姓氏。
- 规范名可以因证据完善而变更，但身份 ID 不变。
- 同名异人用登记表限定词消歧，不靠覆盖旧实体处理。

**稳定身份**：

- 每个实体具有不可复用的 `entity_id`。
- 名称类管道目标必须能唯一解析到登记实体。
- 页面地址由稳定 ID 或锁定的页面映射承担。
- 不把可变规范名直接当作跨书同一性的唯一依据。
- 规范名变更保留旧名搜索与旧链接重定向。

**管道的用途**：

1. 名称类：指向已确认的规范名。
2. 时间类：使用受控标签 `年龄`、`时长`、`时点`（📌 G0 终裁 2026-11-03 扩展：`|时点|` 用于朝代年号/具体时点/时令锚，申请与裁决记录见 `SKILL_时间体系_武侠版.md` 七、7.1 与 `docs/18-G0拍板决议记录.md`）。
3. 不承担任职、成员、出生、胜负等多字段记录。

**正误对照**：

✅ `〖@玉罗刹|练霓裳〗`。

❌ `〖@玉罗刹|别名|练霓裳〗`，禁止多管道。

✅ `〖◆武当|武当派〗`，显示串不补“派”。

❌ 原文只有“武当”，却写成 `〖◆武当派〗`。

✅ `时年〖%二十|年龄〗`。

❌ `时年〖%二十岁|年龄〗`，原文没有“岁”却补字。

**别名与语境称谓分开登记**：

- 稳定绰号、法号、化名进入全局别名表。
- “练姐姐”等语境称谓可以指向人物，但不必成为全局搜索别名。
- 管道表明“本次提及指向谁”，不自动证明“这是该人的永久别名”。
- “妖女、老贼”等临时评价代称不因能解出所指而自动标人物。

**正误对照**：

✅ `〖@练姐姐|练霓裳〗`，登记为语境称谓。

❌ 自动把“姐姐”加入练霓裳的全局别名表。

### 2.2.1b 同形异类判定

**判定对象**：当前出现的连续词汇 X，而不是词表中抽象的 X。

**决策顺序**：

1. **是否属于结构文字或非正文示例？**
   - 目录、链接、编辑器说明不作正文语义标注。
   - 诗词、书信等需先识别文本模式，不机械豁免全部内容。

2. **是否是更长冻结名称的一部分？**
   - 是：保留完整名称，先不拆数字、意象和称谓后缀。

3. **当前句是否明确以 X 指称个人？**
   - 信号：说道、走来、姓、名、绰号、受伤、拜某人为师。
   - 落到人物。

4. **当前句是否明确以 X 指称固定人物组合？**
   - 信号：合称、并称、二人/三人固定名号。
   - 落到人物群组。

5. **是否指持续组织、家族、族群或地点？**
   - 组织：成员、制度、沿革、组织行为。
   - 家族：谱系、血缘、世代。
   - 族群：民族共同体。
   - 地点：位于、进入、离开、宫内、山前。

6. **是否指可学、可传、可施用的命名技术？**
   - 信号：使出、练成、传授、某式、某功、布阵。
   - 落到武功技艺。

7. **是否指可拿取、铸造、存放、毁坏的物件？**
   - 信号：柄、把、枚、铸、拾、折断。
   - 落到器物。

8. **是否指文本或图文内容？**
   - 信号：书中、信内、记载、卷、篇、题名。
   - 落到作品文书。

9. **是否指职位、身份或专门概念？**
   - 用履任、类别判断、技术机制和制度指称消歧。

10. **是否为时间或数量？**
    - 先排除名称内部数字，再判时间量和其他计量。

11. **是否只是成语、比喻或描述性代称？**
    - 修辞另标；普通代称不标。

12. **仍不能唯一判定？**
    - 登记争议及候选解释，不强行落类。

**优先级**：

- 明确语义角色和谓词信号优先于词表默认类型。
- 一词多类允许，不要求词形终身绑定一种类型。
- 没有证据时，不用网站已有页面反推类型。

**正误对照表**：

| 场景 | ✅ 正确 | ❌ 错误 | 信号 |
|------|---------|---------|------|
| 小李飞刀是人物 | 〖@小李飞刀〗冷冷说道 | 标武功 | 发言者 |
| 小李飞刀是技术 | 他练成〖☆小李飞刀〗 | 标人物 | 修习技术 |
| 小李飞刀是物件 | 拾起那柄〖•小李飞刀〗 | 一律标武功 | 柄、拾起；须确为物件称名 |
| 金刀寨主是绰号 | 人送绰号〖@金刀寨主〗 | 拆掉冻结绰号 | 明示绰号 |
| 金刀寨主是职位短语 | 〖◆金刀寨〗〖;主〗召集部众 | 重复使用“寨”字 | 确认组织名和职位结构 |
| 少林寺指建筑 | 他走进〖=少林寺〗 | 默认组织 | 空间进入 |
| 少林寺指组织 | 〖◆少林寺〗派出弟子 | 默认建筑 | 组织派遣 |
| 子招式完整名称 | 〖☆降龙十八掌第十三式〗 | 拆数量、嵌套父术 | 完整技术指称 |
| 引号招式 | 使出“〖☆怪蟒翻身〗” | 包入引号 | 技术施用 |
| 无引号招式 | 使出〖☆怪蟒翻身〗 | 因无引号漏标 | 同上一行 |
| 真正动物动作 | 那〖+怪蟒〗翻身卷向树干 | 整体标招式 | 生物行为 |
| 成语 | 他这是〘※毛遂自荐〙 | 抽出毛遂人物 | 惯用表达 |

**金刀寨主的字符完整性规则**：

- 原文为“金刀寨主”，且组织名为“金刀寨”时，可标 `〖◆金刀寨〗〖;主〗`。
- 该处职位“主”可在登记层规范化为寨主。
- 原文为“金刀寨寨主”时，标 `〖◆金刀寨〗〖;寨主〗`。
- 不能把一个“寨”同时用于组织与职衔。
- 若整串为冻结绰号，完整标人物，不拆。

**武功层级规则**：

- 连续完整子式名整体标一个技术实体。
- 父术、子式、变式关系在登记层表达。
- “降龙十八掌”中的“十八”不标数量。
- 单独“第十三式”仅在父术已确认时归并。
- 父术不明时保留书内临时技术 ID，不猜父术。

✅ `〖☆第十三式|降龙十八掌第十三式〗`，前文父术唯一明确。

❌ 只因最近提过某剑法，便把一切“第十三式”归入该剑法。

#### 2.2.2 修辞标注符号（〘TYPE〙格式）

**外层括号**：

- 左括号：`〘`，U+3018。
- 右括号：`〙`，U+3019。

| 符号 | 类型 | 说明 | Unicode |
|------|------|------|---------|
| `※` | 固定表达 | 成语及经核定的固定熟语，不直接指称内部人物或地点 | U+203B |

**使用规则**：

- 后置启用，不影响实体和事件主任务完成。
- 不把所有四字词都当成语。
- 武功名优先作为技术实体，不重复标修辞。
- 实际讲述历史人物时，不以成语形式掩盖真实指称。
- 不承诺该字符绝不会出现在底本；须扫描碰撞。

✅ `他这是〘※毛遂自荐〙。`

❌ `他这是〖@毛遂〗自荐。`

✅ `使出〖☆白虹贯日〗`。

❌ 同一区间又标 `〘※白虹贯日〙`。

**扩展治理**：

- 典故、谚语、切口措辞可以登记为修辞子型。
- 暂不分别设置新符号。
- 对联、诗词、歌词优先属于结构层。
- 切口制度归专门概念，具体措辞可归修辞；两者不是同一对象。

#### 2.2.3 动词标注符号（⟦TYPE⟧格式）

**外层括号**：

- 左括号：`⟦`，U+27E6。
- 右括号：`⟧`，U+27E7。

**六个动词域**：

| 符号 | 动词域 | 说明 | Unicode | 外形 |
|------|--------|------|---------|------|
| `⊞` | 战斗交锋 | 交战、比武、攻击、防御性对抗、战斗控制及明确战斗结果 | U+229E | 方框加号 |
| `⊠` | 生命健康 | 出生、死亡、杀伤、致残、中毒、治疗、救活及健康状态变化 | U+22A0 | 方框叉号 |
| `⊡` | 社会关系 | 拜师、结义、婚姻、任命、继任、入派、叛离、结盟等关系建立或变更 | U+22A1 | 方框点 |
| `⊟` | 物件变化 | 制造、取得、赠借、买卖、夺取、返还、丢失、毁损等物件状态或归属变化 | U+229F | 方框减号 |
| `▣` | 技术传习 | 传授、修习、偷学、悟得、练成、失去或恢复技术能力 | U+25A3 | 方框内方形 |
| `■` | 行踪迁移 | 到达、离开、迁居、押送、追踪等具有行程意义的位置变化 | U+25A0 | 实心方形 |

**设置理由**：

- 战斗域承担交锋，不承担全部死亡和伤病。
- 生命健康域覆盖自然死亡、出生、治疗，避免只标杀戮而漏掉生平核心。
- 社会关系域覆盖制度和稳定关系变更，不只覆盖册封。
- 物件变化域统一物件生命周期；交易、强夺、制造、毁损使用子型区分。
- 技术传习域直接支撑武功成长和习得审计。
- 行踪迁移域提供地图与路线的明确入口，不把行踪关系藏在无规范的后处理里。
- 不另设“救援域”：救出、救活、救回物件分别依主要结果进入相应域。
- 救援的情愿、不情愿与暗救（盘点决策点② manner 字段），交战的压制、险胜等修饰，属事件登记属性，不改变动词域归属，也不新增域。

**逐域正误对照**：

| 域 | ✅ 正例 | ❌ 反例 |
|----|---------|---------|
| 战斗交锋 | 两人⟦⊞交手⟧；他⟦⊞击败⟧对手 | 将“想比武”计为已交战 |
| 生命健康 | 他⟦⊠病逝⟧；她⟦⊠治愈⟧伤者 | 将“险些死去”记为死亡 |
| 社会关系 | 他⟦⊡拜⟧某人为师；她⟦⊡继任⟧掌门 | 将礼貌拜见记为师承 |
| 物件变化 | 匠人⟦⊟铸成⟧宝剑；他⟦⊟夺走⟧宝刀 | 将“取出自己的剑”记为归属转移 |
| 技术传习 | 师父⟦▣传授⟧剑法；他⟦▣练成⟧内功 | 看过一招便判为掌握 |
| 行踪迁移 | 他⟦■抵达⟧秘魔崖；众人⟦■离开⟧京城 | 把侧身、退半步当旅行 |

**领域之间的主域裁决**：

| 动作 | 主域 | 补充登记 |
|------|------|----------|
| 杀死某人 | 生命健康 | 可关联所属战斗 |
| 砍断宝剑 | 物件变化 | 可关联战斗与攻击方式 |
| 擒住对手 | 战斗交锋 | 状态为被控制；必要时另记拘押状态 |
| 把某人押往京城 | 行踪迁移 | 强制性、押送者、起讫地点 |
| 救出被囚者 | 社会关系 | 子型为解除拘禁；可另有离开事件 |
| 救活重伤者 | 生命健康 | 治疗者、方法、恢复程度 |
| 抢回宝物 | 物件变化 | 转移方向、取得方式 |
| 拜某人为师 | 社会关系 | 建立师承；不自动证明已经学会武功 |
| 传授某剑法 | 技术传习 | 不自动建立正式拜师关系 |
| 结阵迎敌 | 战斗交锋 | 使用的阵法为武功实体 |
| 学会某阵法 | 技术传习 | 技术掌握状态 |
| 被逐出门派 | 社会关系 | 组织成员关系终止 |

**触发词边界**：

- 取最小而能表达主要动作或结果的连续单位。
- “杀死、夺走、救活、练成”保留结果补语。
- 不含主语、宾语、普通程度副词和标点。
- 否定、条件、未来标记在外，但必须进入事件状态判断。
- 一个触发区间只标一个主域。
- 复合动作确有两个连续事实时分别标注。

✅ `他⟦⊞击倒⟧对手，随后⟦⊠杀死⟧了他。`

❌ 将“击倒杀死”整串标为一个模糊动作。

✅ `她⟦▣传授⟧〖☆某剑法〗。`

❌ `⟦▣传授某剑法⟧`，吞入技术宾语。

**不是所有动作都标**：

- 日常吃饭、喝茶、转头、抬手不进入六域。
- 战斗中的侧身、跃起、退步一般不单独标。
- 有战术结果的招架、格挡、反击可以进入战斗域。
- 战斗总结“双方僵持不下”可登记状态，但不必强造一个动词触发词。
- 某些事实来自名词谓语或状态句，允许没有动词标注入口。

**正误对照**：

✅ “他已是掌门。”可以抽取任职状态，原文不必出现任命动词。

❌ 为了凑动词标注，把“是”标为社会关系触发词。

### 2.2.3a 动词、事件与事实状态

> **📌 接口章**：本节是“动词触发即事件入口”的最低契约，正式主场在事件类型学规范（任务 #3）；该规范立项时本节迁出，本文件仅保留锚点。**outcome 值集合以本节五值为准**（胜/负/平/未决/未知）；盘点 P1-4 草案中的“险胜/不分胜负/压制”作为判定依据注记，不作 outcome 取值。

**动词提及**不等于**已核实事件**。

本规范允许标注明确的动词提及，但必须区分其断言状态。

**最低状态集合**：

| 字段 | 允许值示例 | 含义 |
|------|------------|------|
| 发生状态 | 已发生、正在发生、计划、条件、未发生、未知 | 动作是否成为故事事实 |
| 完成状态 | 完成、未遂、中断、未知 | 已施行动作是否达到结果 |
| 信息来源 | 叙述、人物发言、书信、告示、转述、回忆 | 谁在提供信息 |
| 可信状态 | 已核实、来源声称、存疑、相互冲突 | 是否可以发布确定结论 |
| 叙述模式 | 正常叙事、回忆、梦境、假想、戏中戏 | 所属故事世界与时间模式 |

**默认生产策略**：

- 已发生或正在发生且属于六域的动作，正常标注。
- 明确未发生、纯计划、纯条件动作，实体照标，动作默认不标。
- 已实际施行的未遂动作可以标，必须记未遂。
- 传闻和文书中对已发生动作的声称可以标，但不能直接升级为事实。
- 梦境、假想中的动作只在项目启用对应叙述层时标，不能并入主故事事实。

**正误对照**：

✅ “他⟦⊞刺⟧向对手，却未刺中。”记录已攻击、未命中。

❌ 由上一句生成杀死事件。

✅ “信中说他已⟦⊠身亡⟧。”记录文书声称的死亡。

❌ 不核实便关闭人物生存状态。

✅ “若他来了，我就杀他。”不标事实动作。

❌ 用条件句增加杀戮密度。

**完整事件最低字段**：

- 稳定 `event_id`。
- 主域与子型。
- 参与者及语义角色。
- 相关武功、器物、组织、地点。
- 书、回、段与原文字符区间。
- 故事时间、叙述位置与叙事线。
- 发生、完成、来源和可信状态。
- 所属战斗或复合事件。
- 结果及结果依据。
- 规范与数据版本。

**未知原则**：

- 不明参与者保留未知角色。
- 不明地点不继承全文最近地点。
- 不明时间不补公历日期。
- 不明结果不强判胜负。
- 未核实声称不进入确定性问答答案。

### 2.2.3b 实体-动词协调设计原则

**形状与作用域原则**：

1. 实体使用独立外括号 `〖〗`。
2. 动词使用独立外括号 `⟦⟧`，TYPE 统一为方形外轮廓。
3. 修辞使用 `〘〙` 与非实体、非动作标记。
4. 不要求全部实体符号属于单一几何族。
5. 不允许实体 TYPE 使用现行方形动词符号。
6. 颜色可以辅助，不能成为唯一辨层手段。

**保留混合实体系的理由**：

- `@、%、$、☆`已有较强语义联想。
- 为了单一几何族改成大量近似圆形代码，会增加类型识别成本。
- 真正需要防止的是跨层高相似，以及低字号下无法辨认。
- 外括号、TYPE 形状与受控渲染共同承担区分，不依赖一条形式约束。

**视觉预审矩阵**：

- `低`：无明显轮廓或内部结构近似。
- `中`：内部线条或填充相似，必须重点测试。
- 本表是设计预审，不是实际测试结果。

| 实体符号 | `⊞` | `⊠` | `⊡` | `⊟` | `▣` | `■` |
|----------|-----|-----|-----|-----|-----|-----|
| `@` | 低 | 低 | 低 | 低 | 低 | 低 |
| `◎` | 低 | 低 | 中 | 低 | 中 | 低 |
| `=` | 中 | 低 | 低 | 中 | 低 | 低 |
| `◆` | 低 | 低 | 低 | 低 | 中 | 中 |
| `&` | 低 | 低 | 低 | 低 | 低 | 低 |
| `~` | 低 | 低 | 低 | 中 | 低 | 低 |
| `;` | 低 | 低 | 中 | 低 | 低 | 低 |
| `#` | 中 | 低 | 低 | 低 | 低 | 低 |
| `☆` | 中 | 中 | 低 | 低 | 低 | 低 |
| `•` | 低 | 低 | 中 | 低 | 中 | 中 |
| `+` | 中 | 低 | 低 | 低 | 低 | 低 |
| `{` | 低 | 低 | 低 | 低 | 低 | 低 |
| `^` | 低 | 中 | 低 | 低 | 低 | 低 |
| `%` | 低 | 中 | 低 | 低 | 低 | 低 |
| `$` | 低 | 低 | 低 | 低 | 低 | 低 |

**重点相近对及处理**：

| 相近对 | 风险 | 处理 |
|--------|------|------|
| `◎` / `⊡` | 圆框点与方框点 | 依外轮廓区分，低字号实测 |
| `◎` / `▣` | 同心结构 | 圆/方轮廓必须完整显示 |
| `◆` / `■` | 同为实心四边形 | 菱形与正方形需测试，禁止倾斜字体 |
| `◆` / `▣` | 多边形与方形内核 | 保持方框外缘，不以填充颜色辨层 |
| `•` / `⊡` | 点状内核相近 | TYPE 不缩成只有中心点 |
| `•` / `▣` | 小字号下内方可能退化成点 | 外方框必须清楚 |
| `•` / `■` | 实心图形大小近似 | 采用稳定字体尺寸，不人为放大圆点 |
| `+` / `⊞` | 内部均为加号 | 外框与括号双重区分 |
| `#` / `⊞` | 交叉线条近似 | 类型内部网格与方框加号分开 |
| `=` / `⊟` | 横线近似 | 双横线与方框短横分开 |
| `=` / `⊞` | 共享横向线条 | 关注竖线及外框 |
| `~` / `⊟` | 小字号可能只见横向笔画 | 不使用模糊符号回退字体 |
| `;` / `⊡` | 小型点结构 | 分号无方框，需保留正常字宽 |
| `☆` / `⊞` | 星形可能近似交叉 | 五角星与方框十字分开 |
| `☆` / `⊠` | 星形与叉形 | 重点检查粗体和灰度 |
| `^` / `⊠` | 斜线成分 | 单尖角与方框叉号分开 |
| `%` / `⊠` | 斜线成分 | 两个小圆与方框叉号分开 |

**动词域内部风险**：

- `⊞、⊠、⊡、⊟`共享方框，内部符号需清楚。
- `▣`不得渲染成实心 `■`。
- 辨层与辨动词域是两个测试目标。
- 不能只测试“知道这是动作”，却忽略动词域认错。

**视觉验收**：

1. 使用实际编辑器与阅读器字体。
2. 采用 0.5 秒并列辨层任务。
3. 至少 10 名参与者。
4. 覆盖全部实体—动词组合及高风险层内组合。
5. 同时测正常配色、灰度和无底色条件。
6. 辨层总错误率低于 10%。
7. 报告各相近对错误率，不用平均值掩盖失败组合。
8. 失败时先调整字体和字号；仍失败则迁移相关符号。
9. 不以本矩阵代替测试，不声称未经执行的测试已经通过。

## 三、Disjoint 原则规范

### 3.1 核心原则

**理想目标**：

```text
P ∩ A = ∅
P ∩ M = ∅
A ∩ M = ∅
```

其中：

- P：原文标点。
- A：新增标注语法。
- M：Markdown 结构语法。

**实际工程约束**：

- 原文可能包含 ASCII 字符和稀有括号。
- 现行实体 TYPE 保留部分 Markdown 字符。
- 管道同时用于标注消歧和 Markdown 表格。
- 因此不能宣称字符集合完全两两不相交。
- 必须实现的是**作用域明确、解析顺序固定、原文来源可区分**。

**受控解析顺序**：

1. 识别原文与新增结构的来源。
2. 识别完整标注令牌及内部元数据。
3. 将令牌作为不可分割语义单元。
4. 处理外部 Markdown。
5. 渲染实体、动词与修辞。
6. 保持显示串可逐字符还原。

✅ `〖@玉罗刹|练霓裳〗`中的管道属于标注。

❌ 普通 Markdown 先拆表格，再尝试恢复内部管道。

### 3.2 符号选择策略

#### 策略1：原文标点不改，新增标点统一

**规范**：

- 新增规范文本使用统一中文标点。
- 原文字符不因冲突而替换。
- 校勘版本另建映射，不覆盖原始底本。

✅ 保留原版「」引号。

❌ 为符合排版规则改字后仍沿用旧字符定位。

#### 策略2：三层使用独立外括号

**规范**：

- 实体：`〖〗`。
- 动词：`⟦⟧`。
- 修辞：`〘〙`。
- 不使用书名号、普通方括号替代标注括号。
- 原文已有保留字符时，使用来源区间或明确的字面字符声明。

✅ `《〖{某剑谱〗》`。

❌ 直接把所有 `《……》`当成作品实体令牌。

#### 策略3：稳定性优先于无收益的全面换符号

**规范**：

- 保留已形成认知的高频实体符号。
- 动词采用独立方形系列。
- 新符号不得与现行符号同号异义。
- 不因输入方便私设简写。
- 不把“括号包住”误认为普通 Markdown 会自动忽略内部字符。

✅ 受控解析 `〖$三十招〗`。

❌ 让任意数学插件先处理标注正文。

### 3.3 当前符号冲突分析

#### 冲突1：`$`与数学公式

**现状**：数量使用 `〖$三十招〗`。

**分析**：部分 Markdown 扩展会处理 `$`，稀有括号不构成通用屏蔽保证。

**结论**：先识别标注令牌；本地正文禁用不受控数学处理。

#### 冲突2：`#`与标题

**现状**：身份使用 `〖#镖师〗`，标题仍使用 `#`。

**分析**：TYPE 位与标题位不同，但必须由解析器按作用域区分。

**结论**：标题文本不因含姓名、数字便自动进行行内标注。

#### 冲突3：`|`与表格

**现状**：管道用于规范名与解释标签。

**分析**：普通表格解析可能拆开标注内部管道。

**结论**：语料解析先于表格解析；规范文档中的演示管道按文档语法转义。

#### 冲突4：`{`与属性扩展

**现状**：作品文书使用 `〖{某剑谱〗`。

**分析**：部分扩展使用花括号。

**结论**：类型字符只能在完整实体令牌的 TYPE 位生效。

#### 冲突5：`~`与删除线

**现状**：族群使用 `〖~蒙古族〗`。

**分析**：扩展可能把波浪线解释为删除线。

**结论**：禁用对标注令牌内部的删除线处理。

#### 冲突6：`^`与脚注、上标

**现状**：专门概念使用 `〖^膻中穴〗`。

**分析**：部分扩展使用该字符。

**结论**：脚注与上标只作用于外部结构。

#### 冲突7：`&`与 HTML 实体

**现状**：家族使用 `〖&慕容氏〗`。

**分析**：HTML 转义或反转义可能改变显示串。

**结论**：只对渲染输出转义，不改原文或登记名称。

#### 冲突8：`=`、`+`与结构语法

**现状**：地点与生物保留对应符号。

**分析**：行首、独立行可能有特殊含义；令牌内部不按行结构解释。

**结论**：不得跳过令牌识别直接运行通用结构解析。

#### 冲突9：其他 TYPE 与底本碰撞

**现状**：`@、◎、◆、;、☆、•`无主要常规 Markdown 冲突。

**分析**：部分平台仍可能扩展提及、图标或列表处理；底本也可能已有这些字符。

**结论**：低冲突不等于零冲突，仍执行来源与作用域检查。

### 3.4 符号冲突总结

| 维度 | 评估 | 说明 |
|------|------|------|
| 原文完整性 | 强制 | 不因冲突改原文 |
| 严格字符分离 | 未完全达到 | 保留高频实体符号及管道 |
| 作用域分离 | 强制 | 标注令牌优先解析 |
| 实体—动词区分 | 设计明确 | 独立括号，动词统一方形 |
| 视觉实测 | 待验收 | 不用理论矩阵冒充实测 |
| 字体兼容 | 待验收 | 需明确符号回退字体 |
| 迁移成本 | 可控 | 避免无收益全面换符号 |
| 维护性 | 版本治理 | 同步语料、登记表、工具与 UI |

### 3.5 符号候选与迁移

#### 3.5.1 现行新增与动词符号

| 符号 | 用途 | 选择理由 |
|------|------|----------|
| `☆` | 武功技艺 | 视觉醒目，具有技艺联想 |
| `◎` | 人物群组 | 不同于人物符号，强调组合节点 |
| `⊞` | 战斗交锋 | 交叉接触，方形动词族 |
| `⊠` | 生命健康 | 状态改变与伤亡，方形动词族 |
| `⊡` | 社会关系 | 关系确立节点，方形动词族 |
| `⊟` | 物件变化 | 物件状态或归属变化，方形动词族 |
| `▣` | 技术传习 | 结构中的知识核心，方形动词族 |
| `■` | 行踪迁移 | 独立位置状态节点，方形动词族 |

**注意**：

- 符号语义联想仅辅助记忆。
- 类型定义不能依靠图形猜测。
- `■`不是所有移动动作的标记，只标行程级位置变化。

#### 3.5.2 候选符号登记原则

候选符号库是工具，不是规范本体。

**候选必须记录**：

- 字符与 Unicode。
- 实际字形。
- 预期用途。
- 与现行符号的相近对。
- 字体覆盖情况。
- Markdown 冲突。
- 是否曾用于其他类型。
- 试点与批准状态。

**禁止**：

- 因候选库建议“天文”便固定该字符只能表示天文。
- 因候选库有 100 个字符便不断扩充类型。
- 在现行规范中混入候选符号。
- 用图片图标替代语料中的稳定字符。

✅ 候选字符未批准，只出现在候选登记表。

❌ 标注人员自行采用一个“更好看”的新符号。

#### 3.5.3 符号选择指南

**优先级**：

1. 解析确定性与原文无损。
2. 跨层和层内视觉区分。
3. 字体可用性。
4. 类型语义稳定性。
5. 语义联想。
6. 输入便利。

**要求**：

- 目标字体真实测试，不假定中文字体全覆盖。
- 编辑器、阅读器、导出环境均检查。
- 灰度下仍可辨层。
- 不使用只能靠左右微小填充差异区分的高风险组合，除非实测合格。
- 修改一个符号必须同步所有生产示例和消费枚举。

#### 3.5.4 类型新增、变更与迁移流程

**总原则：先清理存量，再新增类型。**

**第一步：侦察**

- 收集跨书误标、漏标和下游缺口。
- 判断问题来自类型缺失、边界不清、词表不足还是身份登记错误。
- 新类型不能用来收容尚未解决的歧义。

✅ 武功长期被器物吞并，提出技术实体类型。

❌ 某条规则难判断，便新建“其他特殊实体”。

**第二步：设计**

- 写定义、排除项、封闭性和正误例。
- 说明为什么子型、属性、关系不足以表达。
- 列出删除或不新增会损失的能力。
- 评估符号与页面成本。

✅ 固定群组独立，因为不能套个人或组织字段。

❌ 因“阵法很重要”便不检验其是否已属于武功技艺。

**第三步：试点**

- 冻结人工金标准。
- 覆盖对话、打斗、韵文、文书、时间和跨书同一性。
- 分类型统计精确率、召回率、争议率。
- 做视觉、字体、定位与页面回归测试。

✅ 在独立验证样本上检查泛化。

❌ 只挑成功例句展示。

**第四步：迁移**

- 区分符号迁移与语义迁移。
- 符号迁移可按已批准映射处理。
- 语义拆分必须重新审查片段，不能只换字符。
- 保留语料、登记表、定位与图谱快照。
- 核对原文还原、实体 ID、事件数量和页面链接。

✅ 旧“人物”中的固定群组逐项迁入群组类。

❌ 把所有带“三、七、双”的人物名机械迁为群组。

**第五步：文档同步**

- 同步本文件与实体、事件、时空规范。
- 同步词表、金标准、阅读器、搜索、游戏卡和审计。
- 更新版本、迁移记录、旧链接与回滚条件。
- 全链路一致后开放生产。

✅ 工具与语料声明相同规范版本。

❌ 文档已改，阅读器继续按旧符号解释。

## 四、符号使用禁忌

### 4.1 禁止情况

| 禁止情况 | ❌ 错误 | ✅ 正确 |
|----------|---------|---------|
| 改写原文 | 补“派”、补“岁”、改引号 | 显示串保持底本，规范化放登记层 |
| 标点包入实体 | `〖@练霓裳，〗` | `〖@练霓裳〗，` |
| Markdown 放实体内部 | `〖@**练霓裳**〗` | `**〖@练霓裳〗**` |
| 嵌套标注 | 在武功名内标数字 | 整体标武功，层级另记 |
| 跨句或跨段 | 一个实体覆盖两句 | 按连续指称边界分别标 |
| 重复使用字符 | 一个“寨”同时属于两个标注 | 组织与职位按真实字串拆开 |
| 无证据挂管道 | 蒙面客直接挂已知人物 | 临时 ID 与待核同一性 |
| 同号异义 | 一个符号表示两个类型 | 一符号一现行类型 |
| 多管道记录 | 名称、身份、成员全部塞管道 | 多字段进入登记表 |
| 把群组当个人 | 群组拥有个人年龄 | 群组独立成员关系 |
| 把动作当事实 | “欲杀”生成已杀 | 保留发生状态 |
| 用 UI 图标代替 TYPE | 图标随主题变化 | 语料字符固定，图标属展示 |

### 4.2 符号层次规则

**准确结构**：

- Markdown 格式在标注外。
- 单个标注只包住显示串或触发串。
- 引号、书名号、句末标点与标注相邻。
- 引号可以包围含标注的整个句子。
- 三种标注彼此不嵌套、不交叉。

```text
✅ 正确
**〖@练霓裳〗说道：“〖@晦明禅师〗可曾回来？”**

✅ 正确
他展开《〖{某剑谱〗》。

❌ 错误
〖@**练霓裳**〗

❌ 错误
〖{《某剑谱》〗

❌ 错误
〖@练霓裳说道〗
```

**理由**：

标点包围含标注的句子完全合法。不能把“引号在标注外”误写成“引号不得包围标注”。

## 五、符号冲突检测方法

### 5.1 检测逻辑

#### 检测1：原文字符完整性

- 剥离新增标记与元数据后，逐字符对照底本。
- 检查补字、删字、换字、标点、空格和换行。
- 校勘版必须有独立版本与映射。

✅ 原文“武当”还原后仍是“武当”。

❌ 原文“武当”变成“武当派”。

#### 检测2：保留字符与作用域

- 检查标注括号是否配对。
- 检查原文同字符是否误判为新增语法。
- 检查 TYPE 是否属于当前版本。
- 检查管道是否只出现一次且目标合法。

✅ 原文已有 `◎`，按字面字符处理。

❌ 看到 `◎`就认为是群组标注。

#### 检测3：标注边界

- 不吞标点、主谓宾或普通修饰成分。
- 不跨句、跨段或跨结构块。
- 检查名称内数字是否错误拆开。

✅ `〖☆降龙十八掌〗`。

❌ `降龙〖$十八〗掌`。

#### 检测4：Markdown 与三层关系

- 格式不插入标注内部。
- 三层不交叉重叠。
- 管道不被表格拆开。
- 数学、删除线、脚注等扩展不处理令牌内部。

✅ 标注令牌完整后再渲染粗体。

❌ 渲染器先改写显示串。

#### 检测5：身份、称谓与群组

- 规范名与 ID 唯一对应。
- 同名异人不强并。
- 对话称呼遵守 D1。
- 固定群组遵守 D2。
- 管道不自动新增永久别名。

✅ “练姐姐”只登记语境称谓。

❌ 把“姐姐”永久归入某一个人物。

#### 检测6：事件状态与时空

- 计划、条件、否定不污染已发生事件。
- 传闻与文书保留来源。
- 相对时间有明确锚点。
- 行踪变化有行程意义。
- 胜负有参照方和证据。

✅ “逼退三步”只记局部结果。

❌ 直接判整场战斗负。

### 5.2 检测工具规划

**规划职责**：

| 工具职责 | 检查对象 |
|----------|----------|
| 完整性检查 | 原文还原、字符与定位 |
| 语法检查 | 括号、TYPE、管道、版本 |
| 身份检查 | 规范名、别名、群组、同一性 |
| 事件检查 | 参与者、状态、来源、结果 |
| 时空检查 | 锚点、叙事线、地点性质 |
| 发布检查 | 原文泄露、证据状态、公开字段 |

**报告最低字段**：

- 文件、作品、回、段、区间。
- 规则编号。
- 当前标注。
- 错误类别。
- 建议处理。
- 是否阻断构建。
- 人工裁决状态。

**报告示意**：

```text
【武侠标注检查报告】
规范版本：0.3-draft
检查范围：试点语料
执行状态：格式示意，尚未运行

原文完整性：待检查
语法与作用域：待检查
称谓与群组：待检查
事件状态：待检查
相对时间：待检查
字体与视觉：待验收
```

**禁止事项**：

- 不把规划工具写成“已经实现”。
- 不编造检查数量或通过率。
- 不把随机抽查替代高风险类型分层抽查。

### 5.3 与其他规范的关系

**检查顺序**：

1. 原文完整性。
2. 结构与标注语法。
3. 实体类型与身份。
4. 事件、关系及证据。
5. 时间、空间与推理。
6. 页面回归。
7. 公开发布审核。

**优先级**：

- 完整性错误先修。
- 身份错误先于关系推理。
- 证据错误先于问答发布。
- 类型规则冲突先修规范，不靠加长提示词掩盖。

## 七、FAQ

### Q1：招式名带引号和不带引号采用不同规则吗？

**A**：不采用。类型取决于技术指称，引号只是原文标点。

✅ `使出“〖☆怪蟒翻身〗”`。

✅ `使出〖☆怪蟒翻身〗`。

❌ 因没有引号就漏标。

### Q2：对白中的绰号标不标？

**A**：稳定称名照标，纯礼貌或关系称呼不标。对白位置不改变规则。

✅ `“〖@玉罗刹|练霓裳〗，请留步。”`

❌ `“〖@前辈|练霓裳〗，请留步。”`

详见 D1。

### Q3：“麦氏三雄”“武当七侠”归哪里？

**A**：固定人物组合归人物群组 `◎`，不是个人，也不自动是组织。

✅ `〖◎麦氏三雄〗`。

❌ `〖@麦氏三雄|某成员〗`。

详见 D2。

### Q4：为什么新增人物群组，而不把它放在人物子型？

**A**：

- 群组没有单个人的出生、年龄、配偶和死亡。
- 群组事件不能自动传播给每个成员。
- 群组与个人的页面、问答和评分约束不同。
- 单独符号可以在逐字标注阶段直接发现错误，而不依赖后续字段补救。

### Q5：“小李飞刀”到底是什么类型？

**A**：按当前句的指称判定。

- 发言者、行动者：人物。
- 可学、可使的绝技：武功技艺。
- 有量词和持有动作的具体刀：器物。
- 信息不足：待核，不猜。

### Q6：历史成语里的人名标不标？

**A**：成语意义下不标内部实体；实际历史叙述另判。

✅ `〘※毛遂自荐〙`。

❌ 从惯用成语抽出毛遂人物。

### Q7：武功秘籍标武功还是文书？

**A**：文本内容归作品文书；其中记载的技术归武功技艺。

✅ `《〖{某剑谱〗》记载〖☆某剑法〗。`

❌ 因标题含剑法就把整本秘籍标武功。

### Q8：秘籍的一册纸本如何记录流转？

**A**：

- 内容身份是作品文书。
- 具体册本是物件副本。
- 文书提及可通过“本次指向的副本”字段连接具体物件。
- 同一区间只作一次行内实体标注，不重叠标两种类型。

✅ 某册剑谱被夺，事件关联该副本 ID。

❌ 所有同名剑谱共用一个物件生命周期。

### Q9：“丐帮帮主”“少林方丈”如何标？

**A**：组织前缀与职衔分开，不能合成一个职位实体。

✅ `〖◆丐帮〗〖;帮主〗`。

✅ `〖◆少林|少林寺〗〖;方丈〗`，前提是该处确指组织。

❌ `〖;丐帮帮主〗`吞掉组织。

### Q10：“晦明禅师”要拆法号和职衔吗？

**A**：作为稳定人物称名时整体标人物。不是见到“禅师”就拆。

✅ `〖@晦明禅师〗`。

❌ `〖@晦明〗〖;禅师〗`，没有职位结构证据却碎拆。

### Q11：“练剑十年”和“十年功力”有区别吗？

**A**：有。

✅ `练剑〖%十年|时长〗`：真实时间长度。

✅ `有〖$十年功力〗`：功力量表达。

❌ 从“十年功力”推断此人实际练剑十年。

### Q12：自然死亡、出生和疗伤需要标吗？

**A**：需要，归生命健康域。

✅ `⟦⊠病逝⟧`、`⟦⊠出生⟧`、`⟦⊠治愈⟧`。

❌ 只标“杀”，导致自然死亡与治疗不进入生平。

### Q13：“跃起”“闪过”为什么一般不标？

**A**：它们通常是姿态和局部动作，不独立改变故事关系或行程。

✅ 已产生独立战术结果的格挡、反击可以标战斗。

❌ 把每个退步都当行踪迁移。

### Q14：诗词和口诀内是不是一律不标？

**A**：不是。

- 结构标题、行号不标。
- 明确指称真实对象或已登记技术的文字可以标。
- 意象、修辞及假想动作不变成故事事实。
- 韵文提及默认不计入正文事件密度。
- 口诀中的技术关系要有明确语义，不能按词表机械抽取。

### Q15：相对时间可以直接换成公历吗？

**A**：有可靠锚点才可以，且须保留换算依据。

✅ “三个月后”记录锚点和偏移。

❌ 仅凭朝代背景猜具体年月日。

### Q16：地图需要新的真实地点和虚构地点类型吗？

**A**：不需要。统一地点类型，登记真实、虚构、原型改造或未定属性。

✅ 陌生地名先保留性质未知。

❌ 名字陌生便判虚构并猜坐标。

### Q17：谁杀了某人，可以由实体共现回答吗？

**A**：不能。必须有已核实死亡事件、施事、受事和定位。

✅ 依据事件回答，缺证时答“现有数据不能确定”。

❌ 同回有两个名字和“杀”字就生成答案。

## 八、类型判断原则与负规则

> **本章可独立作为标注工作页。**
> 判断顺序：先结构与文本模式，再当前指称，再边界，再身份，最后事件与事实状态。

### 8.1 判断原则

#### 原则零：结构字符不作语义标注，文学内容不机械豁免

**原则陈述**：

标题符、段号、链接、目录和格式字符不标。诗词、口诀、书信内容按其真实指称与文本模式判断。

✅ `# 第一回`保持结构；诗中明确写到某已知人物时可标人物。

❌ 从标题编号抽数量；或把全部口诀技术提及一律删除。

**适用信号**：结构位置、块类型、叙述模式。

#### 原则一：标具体对象，不标所有普通名词

**原则陈述**：

普通名词只有在具体指称对象、明确身份或受控概念时才标。

✅ `他拿起那柄〖•长剑〗。`

❌ `一〖•剑〗刺出`，把工具性动作表达当独立物件。

**适用信号**：指示词、量词、持有、存放、毁损、身份判断。

#### 原则二：人物、组织与职衔可分则分

**原则陈述**：

可独立识别的组织、职位和人物分别标注。

✅ `〖◆武当|武当派〗〖;掌门〗〖@紫阳真人〗`。

❌ 无冻结称名证据时整体标人物。

**适用信号**：组织前缀、履任岗位、具名人物。

#### 原则三：完整绰号、法号和化名不碎拆

**原则陈述**：

冻结称名取最小完整单位。

✅ `〖@白发魔女|练霓裳〗`。

❌ 将“魔女”独立标身份。

**适用信号**：号称、绰号、法号、稳定称名。

#### 原则四：本名优先，不凭常识猜名

**原则陈述**：

可靠本名作规范名；没有可靠本名时用稳定专名。

✅ `〖@晦明禅师〗`，未有俗名证据不强挂管道。

❌ 为法号人物编一个俗名。

**适用信号**：明确身份揭示、登记证据。

#### 原则五：管道解决本次所指，不自动扩大别名表

**原则陈述**：

管道指向已确认实体；全局别名与语境称谓分别登记。

✅ `〖@练姐姐|练霓裳〗`，仅登记语境称谓。

❌ 自动把“姐姐”加入全局别名。

**适用信号**：称名性质、上下文所指、别名证据。

#### 原则六：对白与叙述采用同一称名规则

**原则陈述**：

稳定识别称名照标，纯礼貌、关系和临时评价代称不标。

✅ `“〖@玉罗刹|练霓裳〗，且听我说。”`

❌ `“〖@贤弟|某人〗，且听我说。”`

**适用信号**：本名、法号、绰号、带姓名称谓；不是“说道”本身。

#### 原则七：个人、固定群组、组织和家族分开

**原则陈述**：

个人归人物，固定组合归群组，延续机构归组织，谱系共同体归家族。

✅ `〖◎麦氏三雄〗`、`〖◆丐帮〗`、`〖&杨家〗`。

❌ 三者全部标人物。

**适用信号**：固定成员、组织延续、谱系认同。

#### 原则八：职位与身份按制度作用区分

**原则陈述**：

可履任岗位归职衔；职业类别和处境归身份。

✅ `〖;总镖头〗`；`〖#镖师〗`；`〖#俘虏〗`。

❌ 将俘虏当任命岗位。

**适用信号**：任命、继任、职责，或“是某类人”。

#### 原则九：组织前缀拆开，完整职位词不拆碎

**原则陈述**：

丐帮与帮主分开，总镖头等完整职位保留整体。

✅ `〖◆丐帮〗〖;帮主〗`；`〖;总镖头〗`。

❌ `〖;丐帮帮主〗`；`总〖;镖头〗`。

**适用信号**：独立组织名与职位词表。

#### 原则十：技术、文本与物件副本分层

**原则陈述**：

技术可学，文本可记载，具体副本可流转。

✅ `《〖{某剑谱〗》记载〖☆某剑法〗`。

❌ 把剑法、剑谱及某册剑谱合并一个实体。

**适用信号**：传授、记载、册本、销毁、内容传播。

#### 原则十一：技术名称内部数字与意象不拆

**原则陈述**：

完整名称整体标，父子层级另记。

✅ `〖☆降龙十八掌第十三式〗`。

❌ 拆“十八”“十三”数量或“龙”生物。

**适用信号**：命名技术与子式结构。

#### 原则十二：年龄、时长、日期和非时间量分流

**原则陈述**：

真实时间归时间，功力量和招数归数量。

✅ `时年〖%二十|年龄〗`；`练剑〖%十年|时长〗`；`〖$十年功力〗`。

❌ 三者全部标数量或全部标时间。

**适用信号**：时年、历时、之后、功力、招数、银两。

#### 原则十三：边界不含非对象成分

**原则陈述**：

最小完整单位，不含谓词、普通副词和外部标点。

✅ `他握住〖•长剑〗，一剑⟦⊞刺⟧出。`

❌ `〖•一剑刺出〗`。

**适用信号**：对象边界与动作边界。

#### 原则十四：嵌套拍平，内部关系转登记层

**原则陈述**：

同一区间只归一个主类型。

✅ 子式整体标，父术关系另记。

❌ 在绰号内嵌套身份，在秘籍名内嵌套武功。

**适用信号**：完整名称包含其他类型词形。

#### 原则十五：动作、结果和可信状态分别判断

**原则陈述**：

已攻击不等于已杀死，来源声称不等于已核实。

✅ `⟦⊞刺⟧而未中`记录未遂攻击。

❌ 从攻击动词直接生成死亡。

**适用信号**：结果补语、否定、转述、文书、条件。

### 8.2 D1：对话称呼裁决

**结论**：

> 具有稳定识别信息、能够确认所指的称名照标；纯礼貌、关系称呼和临时评价代称不标。对白与叙述适用同一规则。

**触发条件**：

- 本名、法号、化名、完整绰号：所指明确即标。
- 带姓或名字的关系称谓：可以标本次人物提及。
- 单独职位称呼：按职衔标，不转成个人别名。
- 前辈、贤弟、晚辈、师父、姐姐：默认不标人物。
- 妖女、老贼、那汉子：默认不标人物。
- 稳定贬称只有具备别名证据才标，不能仅因当前场景只有一个候选人。
- 语境称谓不自动进入永久别名表。

**三个正例**：

1. ✅ `“〖@玉罗刹|练霓裳〗，你终于来了。”`
2. ✅ `“〖@晦明禅师〗，弟子有一事请教。”`
3. ✅ `“〖@练姐姐|练霓裳〗，你先走。”`

**三个反例**：

1. ❌ `〖@前辈|晦明禅师〗`：纯礼貌称呼。
2. ❌ `〖@贤弟|某人〗`：纯关系称呼。
3. ❌ `〖@妖女|练霓裳〗`：无稳定称名证据的评价代称。

**职位补例**：

✅ `“〖;掌门〗，请定夺。”`

❌ `“〖@掌门|紫阳真人〗，请定夺。”`

**执行说明**：

指代解析可以记录“前辈指向谁”，但这不意味着“前辈”需要人物标注或永久别名。

### 8.3 D2：集体名号裁决

**结论**：

> 固定人物组合的稳定集体名号归人物群组 `◎`；具有独立组织延续性的共同体归组织；临时泛称不标。

**触发条件**：

- 原文明确合称、并称或稳定使用集体名称。
- 名号核心是若干特定人物的组合。
- 成员可以暂未知，但固定组合性质须有证据。
- 带门派或姓氏前缀不自动决定组织或家族类型。
- 管道只归并群组自己的别名，不能挂单个成员。
- 群组战绩不自动分配给全部成员。

**三个正例**：

1. ✅ `〖◎麦氏三雄〗`：固定三人的并称。
2. ✅ `〖◎武当七侠〗`：固定七人的集体名号。
3. ✅ `〖◎塞外双鹰〗`：假设原文明说某二人合称。

**三个反例**：

1. ❌ `〖◎众镖师〗`：临时职业群体。
2. ❌ `〖◎丐帮〗`：持续帮会应归组织。
3. ❌ `〖◎麦氏三雄|某一雄的本名〗`：群组不能归并到个人。

**群组登记约束**：

- 不设个人出生、年龄、配偶字段。
- 群组解散不等于成员死亡。
- 成员死亡不自动意味着整个群组死亡。
- 成员关系保留有效时间与证据。
- 群组可以有协同行动事件。
- 搜索、卡片和页面使用群组模板。
- 个人总数不包含群组。

### 8.4 负规则：不标清单

#### 负规则一：描述性代称不标

✅ **不标**：那汉子、老者、那姑娘、蒙面人，作为临时描述时。

❌ **误标**：自动挂已知人物管道。

**例外**：原文将某称呼确立为稳定称名，另按称名规则处理。

#### 负规则二：纯礼貌、关系称呼不标人物

✅ **不标**：贤弟、前辈、晚辈、师父、姐姐。

❌ **误标**：`〖@前辈|某人〗`。

**例外**：带姓名称谓按 D1；实际职位按职衔。

#### 负规则三：通名和不定类别不标

✅ **不标**：“找一家镖局”“翻过一座山”“入了一座城”。

❌ **误标**：把未确定的山、城、镖局建立为唯一实体。

**例外**：有必要的具体地点实例可以建立书内临时 ID，但不能把每个泛称都实体化。

#### 负规则四：冻结名称内部成分不单标

✅ **不标内部数量**：降龙十八掌的十八，武当七侠的七。

❌ **误标**：将内部数字计入招数或人数统计。

#### 负规则五：武功意象不拆对象

✅ **不标内部生物或神话人物**：怪蟒翻身、观音坐莲、白鹤亮翅。

❌ **误标**：从技术名抽蟒、观音、白鹤。

#### 负规则六：纯计划、条件、否定动作默认不标

✅ **不标动作**：欲杀、若能夺得、明日传你、从未学过。

❌ **误标**：进入已发生事件统计。

**例外**：项目另做言语行为或计划分析时，建立独立记录，不并入事实事件。

#### 负规则七：日常微动作不泛标

✅ **不标**：转头、抬手、跃起、退半步、侧身。

❌ **误标**：每次姿态变化均增加打斗或行踪计数。

**例外**：有明确独立战术结果的格挡、反击可标战斗。

#### 负规则八：普通身体与心理描写不标概念

✅ **不标**：心头一惊、眼中含泪、抬起手来。

❌ **误标**：心头、眼、手全部归专门概念。

**例外**：穴位、经脉和明确技术机制可以标。

#### 负规则九：普通评价不标身份或理念

✅ **不标**：好汉子、真高明、十分厉害。

❌ **误标**：高明、厉害成为思想实体。

**例外**：被明确论说的“以柔克刚”可登记专门概念。

#### 负规则十：成语内部假指称不标

✅ **不标内部实体**：毛遂自荐、三顾茅庐、项庄舞剑，作为惯用表达时。

❌ **误标**：从成语抽出人物和地点。

**例外**：实际历史叙述按真实指称处理。

#### 负规则十一：诗词意象不当事实

✅ **不标事实动作**：诗中“剑斩浮云”“梦里归乡”等意象。

❌ **误标**：登记斩杀或真实回乡事件。

**例外**：明确人物、作品或技术提及可标，且保留韵文模式。

#### 负规则十二：书信和告示不自动核实

✅ **不标为事实**：信中声称某人身亡，尚无其他确认。

❌ **误标**：立即生成确定死亡结论。

**处理**：实体可标，已发生动作声称可标；来源与可信状态必须保留。

#### 负规则十三：回目预告与回末套语不抽事件

✅ **不标事实事件**：“欲知后事如何，且听下回分解”。

❌ **误标**：根据回目和预告补出下一回事实。

#### 负规则十四：不明身份不挂确定管道

✅ **不标确定归并**：蒙面客疑似某人。

❌ **误标**：凭读者猜测挂本名。

**处理**：具体人物可建临时 ID，身份猜测进入待核记录。身份揭露发生时（易容揭穿、真名公布），回填对应待核记录并升级为确认归并；揭露场面联动场面表 `type=揭露`（离线，盘点 P0-3/P2-9）。

## 九、知识登记与下游契约

> **📌 接口章**：本章是下游登记层的最低契约（对应盘点 P0-1 社会关系表、任务 #6 关系类型学、任务 #12 SKU 卡片）。相应专项规范立项时逐节迁出，本文件仅保留锚点；冲突时以专项规范为准并回写本文件。

### 9.1 标注层与登记层的边界

| 层 | 职责 | 不承担的职责 |
|----|------|--------------|
| 原文层 | 保存锁定底本 | 不因知识需要改写 |
| 结构层 | 作品、回、段、文本模式、叙事线 | 不自动证明事件发生 |
| 标注层 | 提及类型、边界、动词入口、修辞 | 不单独证明关系 |
| 登记层 | 身份、别名、实例、属性、层级 | 不无证据补剧情 |
| 事件关系层 | 参与者、时空、状态、来源、结果 | 不把共现当关系 |
| 推理层 | 年龄、死亡、习得时序等约束 | 不覆盖原始证据 |
| 发布层 | 图谱、统计、定位、原创分析 | 不发布原文和标注正文 |

### 9.2 人物关系最低集合

- 师承与正式拜师。
- 传授与修习。
- 亲属、婚姻与收养。
- 结义、结盟、敌对。
- 情感（爱慕/暗恋/单恋/情侣/被拒/悔）、恩义（救命之恩/赠宝之恩/知遇/收留/欠债）、背叛（叛门/叛友/出卖/反目）、主仆依附四类人物—人物关系状态；附 `direction`（single/mutual/unknown）、`states` 时间序列、`manner`（willing/reluctant/secret）、`conf` 字段，schema 采盘点 P0-1 草案。**登记层契约，不设行内符号。**
- 组织成员、任职、继任、退出。
- 群组成员。
- 杀伤、救治、拘押与解救。
- 持有、制造、夺取与赠借物件。
- 到达、离开、所在与同行。

**关系约束**：

- 正式师承与单次传授分开。
- 一次交手不自动成为永久敌对。
- 一次救助不自动成为长期友盟。
- 情感与恩义类自动推导度低：语式正则初解（报 X 之仇/受 X 大恩/结为兄弟）只作候选，须经人工裁定（考订 TSV 稳定键机制）；对话贬称与称呼语不得作为生成依据（对应 D1 与负规则二）。
- 关系具有时间、视角和证据状态。
- 不从共同出现推断亲属、同门或阵营。

✅ 某人传授一招，登记传授关系。

❌ 自动登记收徒关系。

✅ 情感关系登记为 states 时间序列：相识→定情→误会→决裂→相望，direction=mutual，conf=ok，各态附定位符。

❌ 把对话贬称（如“妖女”）直接登记为情感或敌对永久别名。

### 9.3 武功与专门技艺登记

**技术层级**：

- 技术体系。
- 功法或完整套路。
- 子式。
- 变式。
- 组合技。
- 战斗阵法。
- 其他具名专门技艺。

**最低属性**：

- 规范名与别名。
- 品类。
- 父技术与变体关系。
- 归属或来源。
- 修习者、传授者、创制者。
- 修习和掌握时间。
- 技术限制与机制。
- 证据状态。

**限制**：

- 名称相似不证明同源。
- 同名技术不证明跨书完全相同。
- 使用某招不自动证明掌握整套功法。
- 看过、听过、记住、修习、练成是不同阶段。
- 邪正评价保留评价者与时段，不当恒定本质。

### 9.4 物件与生物实例

**区分**：

- 类别：长剑、白马、某种药材。
- 具名对象：某把神兵、某匹坐骑。
- 具体实例：即使无专名，也可能有独立流转或生命历史。
- 文本内容：某剑谱。
- 物件副本：某册剑谱。

**规则**：

- 不要求每个普通物件都建立全球档案。
- 需要流转、毁损、归属或生命事件时建立实例 ID。
- 同名神兵归并必须有传递链或明确同一性证据。
- 活体归生物；制成药物或材料状态按器物判断。
- 变形、炼制或状态改变用关系连接，不通过改写旧身份掩盖。

✅ 一株药草作为活体归生物；采制成某份药材后关联器物实例。

❌ 所有同名药材都当同一个物件。

### 9.5 时间与叙事线

**两条时间轨**：

1. **故事时间轨**：相对时间、先后关系、年龄、时长。
2. **历史时间轨**：朝代、年号、明确日期及有证据的历史锚点。

**最低字段**：

- 原始时间表达。
- 时间类型。
- 锚点事件或时期。
- 偏移与单位。
- 精度。
- 历法。
- 叙事线。
- 换算依据。
- 未确定原因。

**规则**：

- 叙述顺序不等于发生顺序。
- 回忆中的人物出现不等于死后复活。
- “次年”可能只有年份关系，不能补具体日。
- “三个月后”不能跨线寻找最近日期。
- 历史背景可为区间，不必精确到年。
- 书中出现绝对日期时照标，不以“武侠通常无纪年”为由漏标。

### 9.6 地理与行踪

**地点性质**：

- 真实。
- 虚构。
- 真实原型改造。
- 未定。

**空间信息**：

- 真实坐标。
- 相对方位。
- 上下级地点。
- 相邻、距离、路线。
- 小说陈述与现实地理是否一致。
- 证据与精度。

**行踪事件**：

- 到达、离开、停留、迁居。
- 押送、追踪、同行。
- 起点、终点、途经地。
- 时间区间与叙事线。
- 主动或强制。

**限制**：

- 陌生地名不自动判虚构。
- 虚构地点不随意给精确经纬度。
- 提到地点不等于人物到过。
- 梦中、信中和计划路线不并入实际行踪。
- 战斗退步不算行程变化。

### 9.7 战斗、回合与胜负

**分层对象**：

- 战斗：具有参与方和持续边界的对抗。
- 阶段或回合：战斗中的局部单元。
- 动作：施击、格挡、破阵等入口。
- 结果：局部效果与整场 outcome。

**outcome 可用值**：

- 胜。
- 负。
- 平。
- 未决。
- 未知。

**规则**：

- 必须指定参照方。
- 双方停手不自动为平。
- 后退、逃走、兵器被夺不自动为整场负。
- 明确局部失利与最终结果分开。
- 围攻中的胜负可以是阵营级，不自动分给每个人。
- 群组胜负不自动传播成员。
- 非同条件战斗不得直接当作武力排行证据。

✅ 原文明说甲胜乙，记录甲胜、乙负。

❌ 甲被逼退三步便判甲战败。

### 9.9 SKU 与可复跑原创分析

**SKU 最低字段**：

- 稳定单元 ID。
- 原创命题或结构化事实。
- 支撑实体、关系与事件。
- 来源定位。
- 可信状态。
- 数据版本。
- 规则版本。
- 分析方法与统计分母。
- 发布许可状态。

**规则**：

- “出现最多”必须说明统计提及还是去重实体。
- “打斗密度”必须说明数动作、回合还是战斗。
- 韵文、回目、梦境和文书是否计入必须明确。
- 不以未核实归并支撑确定原创结论。

### 9.10 公开发布边界

**允许的项目出口**：

- 经审核的结构化实体属性。
- 关系与事件三元组。
- 统计。
- 不含正文的定位。
- 原创分析。
- 数据与方法版本。

**禁止的项目出口**：

- 原文正文。
- 标注正文。
- 可逐步还原正文的连续片段数据。
- 大量逐字证据摘录伪装成图谱。
- 尚未核实却表述为确定事实的问答。

**版权说明**：

- 版权期限和具体利用方式应由项目权利审核确认。
- “图谱”“统计”“原创分析”不自动意味着任何发布方式都无风险。
