# W5 新动作与新页型（武侠版）—— 让流水线自己长出"新菜"

> **本文是什么**：W 组的**进化引擎**。W2 的 24 个动作是"固定菜单"；当 W4 失败聚类、W6/W7 问题清单、W10 预警反复指向"菜单里没有的菜"时，由 W5 走完 **发现 → 提案 → 试验 → 固化**，把"新动作/新页型/新阈值"变成 W2/W9/脚本里的正式条目。
> **上游依赖**：`skills/W2_动作库_武侠版.md`（24 动作现状）、`skills/W4_评估_武侠版.md`（failures.jsonl/四问结果）、`skills/W3_质量四档_武侠版.md`（质量档与断言标准）、`skills/W6_离线质检_武侠版.md`（批量问题清单）、`scripts/verify_quotes.py`（W7 near/miss 输入）；设计源 `logs/qa/w_group_design_brief.md` §二 W5。
> **一句话**：**W5 不直接改页面，它改"以后怎么做页面"的规则；每次只动一小块，试验过再固化，随时可回滚。**
> **只读纪律**：候选与试验阶段只读上游/只写 `logs/w_group/w5/` 与少量试验页（demo 隔离）；固化阶段才修改 W2/W9/脚本等规范件，且须版本化 + 人工复核（W5 自身修改必须人工）。


## 一、定位与边界

### 1.1 工序位置（"规则进化"环）

```text
W2 24 动作执行 → W4 在线评估 → failures.jsonl / W3 质量门
      ↑                                  │
      │                            W5 发现→提案→试验→固化（本文）
      │                                  │
W2 动作库/ W3 阈值/ W9 页型/ references ←┘  （固化产物）
      ↑
W6 离线质检 · W7 引文核验 · W10 健康度 · W14 洞察 · 人工反馈（发现源）
```

- **W4 vs W5**：W4 判"这次动作收不收"；W5 判"这类动作以后还要不要/怎么改"。
- **W9 vs W5**：W9 改"页面图式/模板"（内容性反思，每轮）；W5 改"动作/规则/阈值"（系统性反思，周期触发）。新页型若只是**新模板**→W9；若需要**新动作/新流程/新脚本**→W5。
- **W10 vs W5**：W10 发现"指标越线"并派单；W5 决定"是否长出新动作来根治"。

### 1.2 本文做什么（五件事）

1. **发现**：候选信号清单与触发条件（§二）；

## 二、发现：候选信号与触发

### 2.1 触发条件（任一满足即进入 W5 流程）

| 触发 | 条件 | 来源 | 动作 |
|---|---|---|---|
| **失败聚集** | 同一 action type 连续 fail ≥3 次，或同 target 类型失败率 >30% | `logs/w_group/failures.jsonl` | 检查是否动作前置/步骤缺失 |
| **成功未规则化** | 某类手工/探索做法连续 3 次成功且质量档上升 | `evaluations.jsonl` + 质量快照 | 提案把做法固化为 W2 动作或 W3 加分项 |
| **阈值失调** | 某指标连续 2 周期红/黄（W10）且样本显示规则过严/过松 | `health.jsonl` | 提案调阈值（优先于改结构） |
| **问题清单聚集** | W6 housekeeping/citation_issues 同类 ≥5 条无对应动作 | `logs/w_group/issue_*` | 提案新增内务/质检动作 |
| **引文技术缺口** | W7 technical near/miss 重复出现同类（如标注符号/省略号） | `quote_verify.json` | 提案预处理/规范化规则（非放宽核验） |
| **洞察候选** | W14 洞察队列中 ≥2 条无法用现有动作落页 | `logs/w_group/insight_queue.md` | 提案新页型/新动作（交 W9 定模板） |
| **人工/Lead** | 用户明确要求、复盘决议 | 对话/复盘 | 直接建 proposal |
| **周期强制** | 每 20 次 action 或每 10 轮（与 W10 对齐；shiji 原为 mod 29 轮） | 计数 | 至少检查一次候选池 |

### 2.2 候选类型（W5 管的三类）

| 类型 | 例子 | 固化目标 |
|---|---|---|
| **新原子动作** | "display 双实体页互链""PN 引文自动回锚""跨书互见补链" | W2 动作表（编号 25+） |
| **动作修改** | 动作 2 扩写人物页加"卡面摘要槽位"；动作 10 引文格式改为 quotes 字段 | W2 对应行 + 版本号 |

## 三、提案：模板、编号与保守原则

### 3.1 提案模板（`logs/w_group/w5/proposals/W5-P-NNN.md`）

```markdown
---
proposal_id: W5-P-0001
date: 2026-11-05
source_signals: ["W7-technical-miss×2", "W6-housekeeping-未生成", "人工"]
type: new-action | action-change | new-page-type | threshold
status: proposed   # candidate → proposed → piloting → promoted | rejected | rolled_back
owner: （提案人）
---

## 症状（可观测）
- 事实/数据：<引用日志行/统计；如 "3 条 technical miss 均含『|』管道符号">
- 影响面：<页面数/轮次/用户可见性>

## 现有动作为何不够
<W2 哪条动作、缺哪一步；或 W3 哪条阈值不适用>

## 拟新增/修改
- 动作名：<如 A25 · 引文技术预处理>
- 前置：<素材/字段/工具就绪条件>
- 步骤：<1-5 步，含 diff 预算与 WU>
- 产物：<content/… 或 logs/…>
- 依赖：<W1 源/W7 引擎/N* 产物>

## 验收指标（可复跑）
- 主指标：<如 technical miss 从 3→0；页面引文 hit 率 ≥95%>
- 对照：<旧动作/无动作基线>
- 观察窗：<2-3 轮 / 5-10 页>
- 回滚条件：<指标恶化/失败率上升/越界>

## 风险与回滚
- 风险：<版权/编造/结构冲突/成本>
- 回滚：<revert 提案/恢复 W2 版本/删除试验页>

## 保守性自检
- [ ] 优先调阈值而非重写结构
- [ ] 本次反思修订 ≤3 条（结构级提案另计，须 Lead 批准）
- [ ] 不改变 W0 六不变量与发布边界
- [ ] 不触碰 tagged/registry/site
```

### 3.2 编号与状态机

```text
W5-C-NNN   候选（candidates.jsonl）
  └→ W5-P-NNN 提案（proposals/，≤3 条/次反思）
       ├→ pilot（pilots/，样本/指标）
       │    ├→ promoted（changes.jsonl，W2 编号/版本）
       │    └→ rolled_back（记录原因+回滚点）
       └→ rejected（记录"已排除"原因，防重复提案）
```

- **同一反思 ≤3 条修订**（shiji 保守原则）；架构级/新页型提案不计入限额，但须 Lead 批准。
- **W5 自身修改 → 人工审批**（不自我修改）；版本号写入 frontmatter 与 changes.jsonl。

### 3.3 保守原则（必须遵守）

1. **先阈值、后结构**：能用调阈值/加后置检查解决的，不改动作结构；
2. **小步**：新动作先以"可选动作"（optional）试运行，不直接并入默认菜单；
3. **可逆**：每个固化动作/页型都为独立 commit（或规范文件备份），可 revert；
4. **不降质量门**：不得为通过率下调 W3/W7 硬门；只能改流程或新增校验；
5. **不碰内容事实**：W5 只改规则/流程/模板，不写事实、不改上游数据；
6. **留痕**：候选、提案、试验、固化四类记录全部落 `logs/w_group/w5/`。

## 四、试验：pilot 协议

### 4.1 样本与对照

| 项 | 规则 |
|---|---|
| 样本量 | 3-5 页/1 类动作；新页型 2-3 页（同构类型） |
| 样本选择 | 混合：1 高价值页 + 1 边缘页 + 1 曾失败页（覆盖失败场景） |
| 对照 | A：旧动作/现状；B：新动作/新模板；同页前后对比优先（减少样本偏差） |
| 观察窗 | 2-3 轮 / 1 个 W10 周期；期间不清理中间产物 |
| 指标 | W3 质量档、W4 四问通过率、W7 hit/near/miss、W6 issue 数、diff/WU、耗时 |
| 停止条件 | 指标恶化、失败率上升、越界（触碰 tagged/registry/site）、版权风险 |

### 4.2 pilot 记录 schema（`logs/w_group/w5/pilots/W5-P-NNN.json`）

```json
{
  "proposal_id": "W5-P-0001",
  "phase": "pilot",
  "started": "2026-11-05",

  "decision": "promote | reject | continue",
  "notes": "对照/异常/回滚点"
}
```

## 五、固化：让新动作正式生效

### 5.1 固化清单（按类型）

| 类型 | 固化动作 | 版本/记录 |
|---|---|---|

| 动作修改 | 修改 W2 对应动作行 + 附录 A 说明；重跑该动作样例 | 同上 |

| 阈值/口径 | 修改 W3/W10/W7 附录参数；保留旧值对照 | 各 SKILL 版本 + 附录 A |
| 脚本实现 | 新动作若需脚本：落 `scripts/`，`--help/--selftest` 可复跑；在 W2 工具表登记 | 脚本版本 + 依赖 |
| 规律沉淀 | 把可复用规律写入 `references/03c1_反思规律库_武侠版.md`（8 字段 schema） | references 条目编号 |

### 5.2 固化验收（promote 条件）

1. pilot `decision=promote` 且主指标达标（见提案 §验收指标）；
2. W4 四问在新动作样例上全过；W7 硬门未降；
3. 文档/版本/引用同步（W2/W9/references/脚本至少 2 处生效记录）；
4. 回滚路径验证（删新动作/恢复旧版本可复跑）；
5. Lead/人工复核通过（新页型/架构级必须）。

## 八、检查清单（每次 W5 反思/提案）

- [ ] 触发条件成立且记录了来源信号（W4/W6/W7/W10/W14/人工）；
- [ ] proposal 含症状、影响面、现有动作为何不够、验收指标、回滚；
- [ ] 优先检视"调阈值/加后置检查"是否足够（先阈值后结构）；
- [ ] 本次修订 ≤3 条（结构级/新页型另计并 Lead 批准）；
- [ ] pilot 样本 3-5、有对照、有 before/after、观察窗 ≥2 轮；
- [ ] promote 前 W4 四问 + W7 硬门通过；文档/版本/引用 ≥2 处同步；
- [ ] 未触碰 tagged/registry/site；未改写事实；
- [ ] changes.jsonl 记录回滚点与 reviewer；
- [ ] W5 自身修改走人工审批。

## 九、成功标准（W5 上线判据）

1. 每个新动作/新页型/阈值调整都有 proposal + pilot + changes 三段证据；
2. pilot 失败 100% 回滚且有记录；rejected 不重复提案（去重率 ≥80%）；
3. 固化后 W2/W3/W9/references 的版本与引用一致（抽查 100%）；
4. 每 20 action/10 轮触发率 100%；≤3 条/次修订合规率 100%；
5. 固化后一个 W10 周期内主指标改善（或至少不恶化）；
6. 越界（tagged/registry/site 写入、无源断言、原文片段）为零。
