# W7 引文核验（武侠版）—— 每一句"原文"都要能对回底本

> **本文是什么**：W7 是防"看似原文、实为编造"的引文核验引擎。它把目标文件里的引号片段抽出来，经**归一化 → 精确匹配 → 近似匹配（ratio/块长/上下文三阈值）→ 省略号分段核验**，给出 hit/near/miss 与定位符；并按 narrative（叙事引文）/technical（术语转写）分流判定是否编造。
> **上游依赖**：34 部锁定底本（`config.CORPUS_ROOT`）+ 5 书 `tagged/*.struct.md`（PN 映射）；`scripts/verify_quotes.py`（引擎）；`skills/W6_离线质检_武侠版.md`（批量 detect-only 消费 W7）；`logs/qa/w_group_design_brief.md` §三。
> **一句话**：**W7 只回答"这段引文在底本里有没有、在哪"，不回答"它对不对"，更不输出原文。**
> **只读纪律**：底本/目标文件只读；唯一写入 `logs/w_group/quote_verify.{json,md}`；**JSON/报告不含原文**（只有长度/hash/定位符/ratio/统计）。

## 快速开始

````text
1. 选目标   --all（SKU 卡+references）/ --sku（卡面）/ --file <页面或稿件>（可重复）
2. 跑核验   python scripts/verify_quotes.py --all --strict
3. 读报告   logs/w_group/quote_verify.md：抽取/跳过/核验/hit-near-miss/编造判定/定位符
4. 分流处置 narrative miss→拒绝发布；near→标 needs_review；technical→只记录
5. 接门禁   发布前 --strict（narrative miss 时 exit 1）；页面引文必过 W7（W3/W4/W8 挂点）
````

```powershell

# 全量（SKU 卡 + references）核验；叙事 miss → exit 1
```

**成功标准**：① 目标中的引号片段全部被抽取/显式跳过（占位符/过短有计数）；② narrative miss=0（或已人工处置）；③ 报告不输出原文（只长度/hash/定位符/ratio）；④ 分段核验（省略号）无"任一段 miss 仍判 hit"；⑤ `--strict` 对 narrative miss 返回非 0；⑥ 输出 schema/统计闭合（抽取=跳过+核验）、自检 12/12 PASS。

## 二、三层流水线（缓存 → 规则 → 证据）

### 2.1 层定义

| 层 | 名称 | 内容 | 实现 |
|---|---|---|---|
| **L0** | 语料缓存 | 34 书/1,378 回底本一次性载入内存；归一化（NFKC+只保留汉字/字母/数字）；5 书 struct 建行→PN 映射 | `CorpusIndex`/`Chapter`/`normalize` |
| **L1** | 规则匹配 | ①精确：归一化子串逐回检索；②近似：首/中/尾锚点→等长窗口 difflib；③分段：省略号引文按段核验 | `search_exact`/`search_near`/`split_segments`/`verify_segment` |
| **L2** | 证据判定 | narrative/technical 分流；定位符输出；hit/near/miss 与编造判定；统计闭合 | `verify_records`/`quote_kind`/`build_payload`/`report_md` |

> 与 shiji W7 对照：shiji 三层为 L0 sha256 缓存 → L1 find_pn 规则（score≥0.90 ok/0.55-0.90 近似/<0.55 miss）→ L2 LLM 二审；武侠 v0.1 实现前两层，第三层以**确定性证据判定**替代（LLM 二审后续，near/miss 清单即输入）。

### 2.2 阈值（引擎常量）

| 阈值 | 值 | 作用 |
|---|---|---|
| `NEAR_RATIO` | **0.90** | difflib `SequenceMatcher.ratio()` 下限 |
| `LEN_RATE_MIN` | **0.90** | 匹配块总长/引文归一长度下限（防散点噪声） |
| `CONTEXT_RATIO` | 0.85 | 上下文窗口相似度门槛（防跨句拼接误判） |
| 最短引文 | **≥8 字** | 过短跳过（无法可靠核验） |
| 最长块 | ≥min(10, 60% 段长) | 近似匹配的最长连续块要求 |
| 候选上限 | ≤5 定位 | 精确层记录全部候选（报告只列前 5） |

## 三、引擎实现（scripts/verify_quotes.py v0.1）

### 3.1 主要函数与数据流

```text
输入目标（--sku/--all/--file）
  → iter_sku_quotes / iter_markdown_quotes / iter_json_quotes / iter_file_quotes  （抽取引号片段）
  → extract_quotes / split_segments / is_placeholder  （分段/占位符过滤）
  → normalize  （NFKC + 只保留汉字/字母/数字）
  → CorpusIndex.verify_segment  （精确→近似→分段核验，返回 hit/near/miss + 定位）
  → quote_kind  （narrative/technical 分流）
  → verify_records → build_payload → report_md → write_outputs
```

### 3.2 目标源

| 参数 | 目标 | 说明 |
|---|---|---|
| `--sku` | `registry/sku/cards.json` 的 brief/summary(+meta.proposition) | 卡面 R1/R2 脱敏 → 预期"零引文" |
| `--all`（默认） | SKU 卡 + `references/**/*.md` | 规律库引文为主要可核对象 |
| `--file`（可重复） | 任意 .json/.md/.txt（页面/稿件） | W3/W4/W8 页面引文核验入口 |
| `--corpus-root/--sku-path/--refs-dir/--out-dir` | 路径覆盖 | 校准/迁移用 |

### 3.3 输出

| 产物 | 字段（不输出原文） |
|---|---|
| `logs/w_group/quote_verify.json`（schema `quote-verify-v1`） | quote_len/quote_hash/kind/status(hit|near|miss)/ratio/locator/segments/统计 |
| `logs/w_group/quote_verify_report.md` | 抽取/跳过/核验统计；hit/near/miss 清单（小节标题只取 A01/B03 等编号，防标题内嵌引文泄漏） |

### 3.4 CLI 与退出码

| 参数 | 说明 |
|---|---|
| `--all` / `--sku` / `--file` | 目标选择 |
| `--strict` | narrative miss → **exit 1**（发布门禁用） |
| `--selftest` | 合成语料 12 项断言（不写盘） |
| `--corpus-root` / `--sku-path` / `--refs-dir` / `--out-dir` | 路径覆盖 |

## 四、narrative / technical 分流

### 4.1 分类规则（`quote_kind`）

| 类 | 判定 | 例 | miss 处置 |
|---|---|---|---|
| **narrative**（叙事引文） | 普通文字引文（人物对白/叙述/诗文） | "……（原文语句）" | **疑似编造** → `--strict` exit 1，禁止发布 |
| **technical**（术语转写） | 含 ASCII/管道/箭头/字段术语的规则转写 | `canonical|id`、"A→B"、"字段=…" | 只记录，不判编造 |

### 4.2 省略号分段（防"省略号掩盖编造"）

- 含 `…/……/...` 的引文 → 按段拆分逐段核验；
- **各段全 hit = hit；任一段 miss = miss**（禁止"第一段命中就判整体 hit"）；
- 分段统计单独输出（seg_stats）。

### 4.3 判定纪律

1. narrative miss 一律按"疑似编造"处理——除非人工将该条转为 technical（需理由）；
2. near 只表示"近似"（标点/异体/轻微改写），入库需标 `needs_review`（W3）；
3. 占位符（「未明示」等）跳过并计入统计，不算 miss；
4. 卡面 R1/R2 脱敏 → 卡面"零引文"是预期，不是工具失效（见 §八）。

## 五、定位符体系（W10l 对齐）

### 5.1 两类定位符

| 对象 | 格式 | 来源 |
|---|---|---|
| **5 书**（有 struct） | `{book}#pn-r{chapter}.{para}` | tagged/*.struct.md 行→PN 映射 |
| **其余 29 书**（无 struct） | `{book}#ch{NNN}@L{行}` | 底本行号（人类定位符） |

### 5.2 与 cited PN 的比对（W10l 下一步）

- 引文若自带 `cited_pn`（如页面 quotes[] 里的 `text+cited_pn`），W7 应输出 actual anchor，并与 cited 比对：
  - 一致 → ok；
  - 不一致 → `PN_MISMATCH` warning/error（分级待 W10l 定）；
- v0.1 状态：**actual anchor 已输出，cited 比对未实现**（附录 B）。

## 六、不输出原文纪律（硬规则）

| 规则 | 说明 |
|---|---|
| JSON/报告不含原文 | 只有 quote_len/quote_hash/定位符/ratio/统计 |
| 报告小节标题只用编号 | A01/B03 等，防标题内嵌引文泄漏 |
| hash 不可逆 | sha256 短 hash 作同一性标识 |
| 日志/报错不回显原文 | 异常信息截断/哈希化 |
| 对外审计 | 可用 `--no-provenance-whitelist`（copyright gate）做发布前复核 |

> 原因：引文即原文衍生；W7 若回显原文，等于绕开 01g §9.10 发布边界。

| # | 挂点 | 条件/动作 |
|---|---|---|
| 1 | **W3 质量标准** | 页面引文必须 hit；near 可入库但标 `needs_review`；narrative miss 一律拒绝发布 |

## 十二、FAQ（首批 6 问）

**Q1 为什么进入核验只有 5 条？**
抽取 2,383 条中：1,470 条是占位符（「未明示」等）、908 条 <8 字（无法可靠核验）；剩余 5 条才是可核引文。卡面 R1/R2 脱敏后本身几乎无引文——这是预期，不是工具没用。

**Q2 W7 会不会自己编原文来比对？**
不会。它只用锁定底本（34 书）与 struct 做核验；输出只有长度/hash/定位符/ratio，不回显原文。

**Q3 narrative 和 technical 有什么区别？**
narrative 是叙事引文（判编造）；technical 是规则转写（含 ASCII/管道/术语，只记录）。technical 的 miss 不算编造，但不能当叙事引文用于页面。

**Q4 near 是什么？**
近似匹配（标点/异体/轻微改写），ratio≥0.90 且块长率≥0.90；可入库但必须标 needs_review（W3）。

**Q5 定位符为什么有两套？**
5 书有 struct（行→PN 映射）：`book#pn-r{ch}.{para}`；其余 29 书无 struct，用底本行号 `book#ch{NNN}@L{行}`；两套都算可回溯。

**Q6 现在能当发布门禁吗？**
可以：`verify_quotes.py --all --strict`（叙事 miss → exit 1）；但 content 页面 quotes[] 尚未填写，目前主覆盖是 references（附录 B）。

## 结语

引文核验是知识库的"防伪印章"：把每一句"原文"对回底本，把每一处"近似"标成待复核，把每一条"术语转写"分流处理，并且**绝不回显原文**。W7 不生产内容，只回答"这句真的存在吗、在哪"——这正是发布前最需要的一道门。
