# SKILL 09k 武侠版：文献写作 — 让每一句结论都过得了核验

> **上游声明**：本件属 S 组 P5 应用层，对应 docs/03 §3.10 原 09k 文献写作（**✅ 照搬：88-100%**，八个照搬文件之一；仅换名称/基线/示例）。**设计依据**：shiji 09k 文献写作的写作学框架 + 本项目 `01g §9.10` 发布边界、W7 `scripts/verify_quotes.py` 引文核验、`07e` A-E 真实性评级、`03l/08b` 统计口径、09i 引用与检索工具（v0.1 框架）。
> **与 09i 的分工**：09i 学术工具管**工具与规范**（怎么检索、引用格式、导出、诚信硬规则）；本件管**写作产出**（怎么组织综述、怎么论证、怎么引、交付前过哪道门）。写作中需要的检索与导出直接调 09i。
> **接口**：`registry/intertext/intertext_loc.json`（loc_r）、`registry/sku/cards.json`（sources/supported_by）、`registry/relations`（evidence/loc）、`registry/events`（loc_r）、`../site/data/*.json`（EX 导出）、`logs/w_group/quote_verify_report.md` + `quote_verify.json`（W7）、09i 检索工作台。
> **核心原则**：**没有定位符的论断是意见，没有过 W7 的引文是风险。** 写作可以有个性，但证据必须可回锚、可复现、可核验。

## 一、定位与边界

### 1.1 工序位置

```text
09i 检索/引用工具（取数与定位符）
        ↓
09k 文献写作（选题 → 证据表 → 六段结构 → 写作 → W7 核验 → 交付）
        ↓
研究产出（综述/报告/书评/长文）+ 可复现声明 + W7 报告
```

### 1.2 本文做什么

1. **写作类型与结构**：五类产出的结构模板（综述六段、专题、书评、数据报告、科普长文）；
2. **论证纪律**：论断-证据-定位符三级表，禁止以论代证；
3. **引用规范**：接 09i 的定位符体系与引用模板，本件规定"什么时候必须引、引到什么粒度"；
4. **W7 硬门**：交付前必须过引文核验，阈值与处置规则见 §五；
5. **边界守卫**：不代笔、不伪造、不越版权、不把 demo/推演/低置信当考订；
6. **可复现声明**：数据版本、规则版本、查询命令三件套。

### 1.3 本文不做什么

| 不做 | 归属 |
|---|---|
| 改知识库/数据 | 只读（写操作需授权，属 P4 回写） |
| 检索工具与引用格式实现 | 09i（`SKILL_09i_学术工具_武侠版.md`） |
| 原文提供/全文发布 | 禁（`01g §9.10`） |
| 论文代笔/枪手式生成 | 超范围；本件只给写作规范与核验 |
| 版权/许可决策 | 权利审核 |
| 真实性评级重算 | `SKILL_07e_真实性评级_武侠版.md` |

### 1.4 关键约束（硬规则）

- **一论断一证据**：每个结论句必须有 `evidence`（数据字段或定位符）或显式标"推测/待证"；
- **引文必过 W7**：所有直接引文/片段在交付前过 `scripts/verify_quotes.py`，miss 即回改；
- **定位符优先**：能用 `loc_r/PN/ID` 说清的，不引原文；必须引原文时，责任在作者与权利审核；
- **不伪造**：不得虚构引文、定位、统计数字、二次文献；
- **不越级**：demo 卡、推演结果、低置信事件不得写成"考订结论"；
- **可复现**：统计类结论附数据版本 + 规则版本 + 查询命令。

## 二、快速开始（六步）

````text
Step 1 定题   写清问题、范围（书目/年代/主题）、产出类型（§三）
Step 2 取数   走 09i 检索：实体/关系/事件/主题，每条结果带 loc/loc_r + confidence
Step 3 建表   论断-证据-定位符三级表（§四），无证据的论断标"待证"
Step 4 写作   按六段结构成文；引文进 quotes 清单（≥8 字、带定位符）
Step 5 核验   W7：--file 产出文件，ratio≥0.9 / 匹配块≥0.9 / miss 清零
Step 6 交付   可复现声明 + 诚信检查 + W7 报告挂附件
````

W7 核验命令（只读，不输出原文）：

```bash
# 核验产出文件（.md/.json/.txt 均可，可重复 --file）
python -X utf8 scripts/verify_quotes.py --file "logs/writing/review_draft.md"

# 核验知识库默认目标（SKU 卡 + references 规律库）
python -X utf8 scripts/verify_quotes.py --all

# 严格模式：叙事引文疑似编造（miss）时退出码 1 —— 交付门禁用它
python -X utf8 scripts/verify_quotes.py --file "logs/writing/review_draft.md" --strict
```

> 报告落 `logs/w_group/quote_verify_report.md`（可用 `--out-dir` 改目录）。**报告与 JSON 均不含引文原文**，只给长度/hash/定位符/统计——这是隐私纪律，也是"核验不等于提供原文"的边界。

## 三、五类产出与结构模板

### 3.1 类型选择

| 类型 | 适用 | 主要证据 | 交付物 |
|---|---|---|---|
| 综述 `review` | 某主题/门派/年代的研究现状 | 事件/关系/实体统计 + 二手研究 | 综述稿 + 证据表 + W7 报告 |
| 专题研究 `study` | 单一问题（如"某书对局胜负分布"） | 数据统计 + 定位符 + 反例 | 研究稿 + 复现命令 |
| 书评 `review-book` | 单部作品评述 | 章节结构 + 事件/人物数据 | 书评稿 |
| 数据报告 `data-report` | 知识库统计/覆盖度/质量 | EX 导出数据 + 口径声明 | 报告 + 数据表 |
| 科普长文 `essay` | 面向大众的解读 | 已核验事实 + 通俗转写 | 长文 + 事实核对表 |

### 3.2 综述六段结构（照搬框架）

```text
① 问题与范围：研究问题一句话 + 书目/年代/主题边界 + 不做什么
② 数据与口径：数据版本、规则版本、统计口径（03l/08b）、样本量
③ 现状梳理：按主题/年代/门派分组，每组给"共识 / 分歧 / 空白"
④ 争议与反例：至少 1 条反例或反证，说明为何不推翻主结论
⑤ 空白与下一步：明确"本库数据不能回答什么"
⑥ 结论：只写证据支持的结论；推测单列并标注
```

**照搬要点**：六段顺序与"共识/分歧/空白"三分法照搬 shiji 09k；替换项仅为书名、年代、门派与示例数据。

### 3.3 各类型的最小骨架

- **专题研究**：问题 → 数据与方法 → 结果（表/图）→ 反例检验 → 结论与局限；
- **书评**：作品定位（年/系列）→ 结构（回目/章法）→ 人物与事件数据 → 文学判断（标明主观）→ 版本说明；
- **数据报告**：口径 → 总量/分布 → 异常与缺口 → 结论 → 复现命令；
- **科普长文**：钩子 → 3-5 个事实点（每个带定位符）→ 常见误解澄清 → 延伸阅读（不引全文）。

## 四、论证纪律：三级证据表

### 4.1 证据三级

| 级别 | 证据类型 | 示例 | 使用规则 |
|---|---|---|---|
| E1 一手数据 | 知识库导出字段/统计 | `matches.meta.totals.matches=341` | 可直接支撑统计结论；附 `data_version` |
| E2 原文定位 | `loc_r`/PN/ID（不引原文） | `七剑下天山·004:63` | 支撑"书中发生过"；可回锚即可 |
| E3 二手研究 | 已发表研究/评述 | 学术论文、专著 | 必须给完整出处；不得冒充 E1/E2 |

**禁止**：用 E3 冒充 E1（"研究表明"却无出处）、用 E1 支撑价值判断（"因此这部书更好"）、用 E2 支撑统计结论（单条定位不能代表分布）。

### 4.2 论断-证据表（写作前必建）

```json
{
  "claims": [
    {"id": "C1", "claim": "该书对局以 T01 单挑为主",
     "evidence": [{"level": "E1", "ref": "registry/events#T01 count=8997", "version": "data_version=2026-11-05.01"}],
     "counter": [{"ref": "T03=2356", "note": "群体战占比不可忽略"}],
     "status": "supported"},
    {"id": "C2", "claim": "某角色武功当世第一",
     "evidence": [], "counter": [], "status": "待证", "note": "价值/排序判断，本库不支撑"}
  ]
}
```

`status ∈ {supported, partial, 待证, rejected}`；`待证` 论断**不得**写成陈述句进入正文（只能进"推测"小节）。

### 4.3 统计口径四问

任何统计结论必须能回答：① 分母是什么（全书/五书点亮集/全部 34 部）？② 单位是什么（事件/回/千字）？③ 去重规则是什么（canonical/别名）？④ 数据版本与规则版本是什么？四问答不全，结论降级为"初步观察"。

## 五、W7 引文核验硬门（交付阻断）

### 5.1 阈值（与 W7 实现一致）

| 项 | 阈值 | 说明 |
|---|---|---|
| 近似匹配 ratio | ≥ 0.9 | 归一化后近似比 |
| 匹配块长度率 | ≥ 0.9 | 省略号截断按段核验（段 ≥4 字） |
| 引文长度 | ≥ 8 字 | 短于 8 字不入核验（无法判真） |
| 精确命中 | 归一化子串 | 命中即通过 |
| 叙事引文疑似编造 | **必须为 0** | `--strict` 下退出码 1 |
| 输出 | 无原文 | 只给长度/hash/定位符/统计 |

### 5.2 处置规则

1. **hit**：通过，保留定位符；
2. **near（≥0.9）**：人工复核，确认是否转写误差；复核记录进证据表；
3. **miss**：**不得交付**。三条路——改引文使其与底本一致 / 改为定位符转述 / 删除该引文；改完重跑；
4. **技术/规则转写引号**（术语、规则名）：不参与"编造"判定，但需在报告中单列；
5. **占位符与短引文**：W7 会跳过（当前 1,470 占位符、908 条 <8 字），作者须自行确认这些不是伪造引文。

### 5.3 交付门禁

```text
写作稿 → W7 --file（非 strict 预检）→ 修正 → W7 --file --strict（退出码 0）
      → 挂 quote_verify_report.md → 交付
```

`--strict` 退出码非 0 时**禁止交付**；报告须随稿归档（路径写进交付说明）。

## 六、写作边界（不可越线）

| 边界 | 规则 | 违反后果 |
|---|---|---|
| 不代笔 | 本件给规范与核验，不生成"可署名论文" | 学术不端风险 |
| 不伪造 | 引文/定位/统计/二次文献全部真实 | 一票否决 |
| 不以论代证 | 价值判断标"主观"；排序判断需方法 | 结论不可复现 |
| 不越版权 | 原文引用片段责任在作者/权利审核；本库只给定位 | 侵权风险 |
| 不越级 | demo 卡/推演/低置信事件不得写成考订 | 误导读者 |
| 不隐口径 | 统计必须四问齐全 | 结论失真 |
| 不引全文 | 不提供整章/整回原文 | 违反 `01g §9.10` |

## 十二、FAQ（首批 5 问）

**Q1：09k 和 09i 是不是重复了？**
不重复。09i 是工具（检索、引用格式、导出、诚信规则），09k 是写作产出规范（结构、论证、W7 门、边界）。写作时先用 09i 取数，再用本件成文与核验。

**Q2：W7 只核验了 5 条引文，说明库里的引文很少？**
不是。W7 报告显示抽取 2,383 条引号片段，其中 1,470 条是占位符、908 条 <8 字被跳过；当前 SKU 卡与 references 以结构化字段为主，直接引文本就少。写作产出新增引文时 W7 会重新抽取。

**Q3：引文核验通过就能公开发布原文吗？**
不能。W7 只证明"引文与底本一致"，不解决版权。公开发布原文片段的责任在作者与权利审核；本库工具只给定位与核验结果。

**Q4：可以用"据说/一般认为"代替引用吗？**
不可以。这是 LW-02 的变体；要么给 E3 出处，要么标"待证"进推测小节。

**Q5：数据报告也需要 W7 吗？**
报告若含直接引文则需要；纯统计报告以口径与复现声明为主，但仍须过证据表与"不越级"检查。

## 结语

文献写作在知识库项目里是"最后一公里"：数据再多，写不出可核验的结论就没有公共价值。守住三条——**每条论断有证据、每段引文过 W7、每份统计有口径**——写作才能既好看又站得住。
