# SKILL 01b 武侠版：多版本互校与底本锁定

> **上游声明**：本文从 shiji-kb `SKILL_01b_多版本互校底本.md` 移植重造，移植依据见 `docs/05-管线技能与脚本逐项改造分析.md`（中度 50:50：内证/外证校勘方法论、派生同步 SOP、AI 替换安全守则是金块；版本清单按梁羽生版本实况重建）与 `docs/17-技能脚本改造实现图与拓扑排序.md`（S-01b 中度依赖，**前置 G0 底本拍板门**）。
> **上游规范（已定版）**：SKILL_01g 武侠版 v0.3-draft（§2.1：**校勘版本另建映射，不覆盖原始底本**）；SKILL_02a/02b 武侠版 v0.3-draft（附录 B1 底本版本锁定：换底本视为乙类变更；§3 PN 不可变性）。
> **联动脚本（wuxia-kb/scripts/）**：`config.py`（C0a：书目注册表与 `fingerprint` 字段）、`generate_pn_wuxia.py`（N1：勘误后 `--verify` 重建结构层）、`lint_text_integrity.py`（全量字符对账）、`lint_purple_numbers.py`（结构门）。

> **核心理念**：互校回答的是"底本对不对"。武侠库中底本是**锁定只读资产**（G0 拍板、指纹固化），因此互校的产物默认不是"改底本"，而是**校勘记录与映射**；只有经乙类变更通道批准的勘误才落底本——落一次，指纹重算一次，全部派生重新对账一次。

## 一、技能目标与定位

### 1.1 目标

对 34 部书的锁定底本做多版本互校，产出可追溯的校勘记录，为实体标注、事件抽取提供可信文本基础。

### 1.2 与史记版最大的不同

史记版流程是"互校 → 直接修改底本 → 同步全部派生文件"；武侠版底本已锁定（`章回版/<书>/NNN*.txt`，只读输入，`config.fingerprint` 固化身份），因此：

| | 史记版 | 武侠版（本文） |
|---|---|---|
| 互校结论落地 | 直接改底本 | 旁路校勘记录（默认） |
| 改底本 | 常规操作 | 乙类变更通道（例外，需批准） |
| 改后动作 | 同步派生 | 重算指纹 + 重跑结构层 + 全量对账 |
| 指纹 | 无 | 每批次标注记录同一 `fingerprint` |

### 1.3 与上游的衔接

- **对 01g**：§2.1 划界——"标点统一属于校勘工序，原文无损属于标注工序"。本文是校勘工序的主体：所有"底本字符应不应该改"的判断从这里走，标注层永远忠实于当前底本；
- **对 02ab**：PN 不可变性把底本选择放大为一次性决策（附录 B1），换底本 = 全量 PN 迁移风险，故底本勘误必须走乙类变更而非随手改；
- **对 S-01a**：完整性对账只认"当前底本+当前指纹"；本文裁决的疑误在落地前，一律按底本原样标注（"欲如"类疑误字原样保留，02ab §4.2 铁律 5）。

## 二、核心原则

1. **底本优先**：锁定底本为主校本；互校是为了验证它、不是为了随手替换它；
2. **多版本对校**：每个疑误点至少 3 个版本交叉（初刊/修订/电子三类框架，见第三章）；
3. **异文必录**：所有文字差异详细记录（位置/各版本字形/上下文/依据/状态）；
4. **字形以底本为准**：武侠底本为现代排印本，无批量繁简转换工序；个别异体字按"底本原样保留、记录存疑"处理；
5. **标点审慎 + 标点符号禁令**：❌ 绝对禁止修改标点类型（全角↔半角、引号样式）；❌ 绝对禁止增删标点；✅ 只允许记录标点差异供人工裁决（句读裁决规范见 S-01f）；
6. **校勘另建映射**：互校结论默认写入校勘记录文件，不覆盖锁定底本（01g §2.1）。

## 三、版本清单（占位结构，待 G0 回填）

### 3.1 三类版本框架（先立骨架，实况待拍板）

梁羽生作品的版本传承按三类框架管理——**34 部书各自的实况（哪些书有哪个版本、路径何在）一律待 G0 底本拍板后回填**：

| 类别 | 说明 | 预期角色 | 实况 |
|---|---|---|---|
| **初刊版** | 报刊连载或初版单行本，最接近作者原始发表状态 | 权威参校本（获取难度高，可能仅部分书可得） | 待调研回填 |
| **通行修订版** | 作者晚年系统修订的通行本，通常自认最完善的形态 | **底本首选/主校本候选** | 待调研回填 |
| **电子录入版** | 网络电子文本，易获取但形近讹误、脱字、错标点最多 | 参校本 + 讹误对照样本 | 待调研回填 |

### 3.2 现状

- 锁定底本（`章回版/<书>/NNN*.txt`）34 部 1,378 回已就位，是当前唯一对账基准；
- `config.py` 的 `fingerprint` 字段留 `None`（G0 拍板门未过）；锁定后由 `build_book_registry` 回填；
- `config.BOOK_OVERRIDES` 供个别书人工覆盖（slug/指纹/回数），自动发现失败时登记。

### 3.3 参考版本定义（武侠化照搬）

**是"其他版本"**（可作校对依据）：不同排印/录入传承系统的版本——初刊影印或转录、修订版纸书对照本、其他电子录入源、权威纸书。

**不是"其他版本"**（同一底本的派生，字应一样，不构成证据）：

| 路径 | 说明 |
|---|---|
| `tagged/<书>/NNN.tagged.md` | 标注文件（底本 + 新增标记） |
| `tagged/<书>/NNN.struct.md` / `.struct.json` | 结构层产物与 sidecar |
| `registry/`、`wordlists/` | 登记层与词表（引用底本字形，不独立于底本） |

```text
用户问："这个字在其他版本里是什么？"
✅ 正确理解：查初刊/修订/另一电子源等不同传承系统的版本
❌ 错误理解：查 tagged/ 或 struct/（同一底本，字必然一样，无证据价值）
```

## 四、互校工作流程

### 4.1 四阶段（照搬，不写实现代码）

1. **准备**：按回对齐——统一空白与换行、按回目锚定段落；跨版本段落不对齐时人工锚定，不机械推进；
2. **逐字对校**：底本与各参校版本逐字比对，产出异文清单（位置、上下文、各版本字形）；自动化比对脚本属后续移植项（docs/05 规划），当前允许人工 + grep 检索比对；
3. **异文判定**：按下表逐点定性；
4. **生成校对报告**：每书每回一份，落 `logs/`（或后续规划的校勘记录目录）。

### 4.2 异文判定表（武侠化）

| 异文类型 | 处理方式 | 武侠示例 |
|---|---|---|
| **异体字** | 底本原样保留，记录 | 底本"沈"作姓氏用字不改"沉" |
| **形近录入讹误** | 择善而从，走勘误通道 | "怪蟒翻身"误录"怪莽翻身" |
| **音同误写** | 依版本多数裁决 | 人名"岳鸣珂"误录"岳鸣柯" |
| **脱字/衍字** | 参考多数版本 | 电子源多打一个"了"字 |
| **称谓/名号不一致** | 先查是否同一人（01g 身份规则），再判讹误 | "玉罗刹/练霓裳"是同名异称，不是异文 |
| **标点差异** | ⚠️ 只记录，禁止修改 | 引号样式、句读位置分歧 |

**判定原则**：

1. 多数版本一致 → 采用多数（记录依据）；
2. 版本各异 → 参考权威纸书/修订版；
3. 仍无定论 → 存疑清单挂起，底本原样，标注照标。

### 4.3 校对报告要点（格式从简）

```markdown
# 《{书名}》第 {NNN} 回 校对报告
**底本指纹**: {config.fingerprint，G0 前写"未锁定"}
**参校本**: A 初刊… B 修订… C 电子…（实况回填）
## 异文详表
[异文01] 第 n 段第 m 字：蟒（底本）/ 莽（电子源C）
判定：形近录入讹误；内证：本武功名全书其余 12 处皆作"蟒"
处置：建议勘误（乙类变更），状态：已裁决/存疑
## 标点差异
[标点01] 位置 + 双方样式 + 裁决建议（只记录）
## 存疑清单
……
```

## 五、内证与外证校勘方法论（金块，照搬）

| 类型 | 依据 | 武侠示例 | 适用场景 |
|---|---|---|---|
| **外证校勘** | 参考其他版本 | 电子源作"莽"、修订版纸书作"蟒" → 从"蟒" | 版本之间有差异 |
| **内证校勘** | 文本内部规律 | 招式名全书 12 处皆作"蟒"，唯独 1 处作"莽" → 判讹 | 所有版本（含电子源同源）一致但疑似有误 |

**内证判定标准（四条全满足才可判）**：

1. 上下文有明显规律（招式名、人名、地名全篇统一）；
2. 疑误处打破规律（唯独一处不同）；
3. 无其他合理解释（不是化名、笔误修辞、口语变体）；
4. 补正后符合文义与全书设定。

**注意事项**（照搬）：内证没有版本依据，须更谨慎；报告必须写明规律与反例；优先外证，内证补充。

**武侠特有提示**：

- 名号判断先过 01g 身份规则——"同名异称"（本名/绰号/法号）不是异文，误判会把设定当成讹误；
- 章回套语（回目对句、回末套语）存在作者固有变体（02ab §6.3 词族），不得按"规律统一"强行改齐；
- "疑似讹字一律保留原样"（02ab §4.2 铁律 5）在互校裁决前绝对成立。

## 六、校勘结论的落地路径（武侠新增核心节）

### 6.1 双轨制

**轨道一：旁路校勘记录（默认）**

- 校勘结论写入按书组织的校勘记录文件（位置、底本字形、建议字形、依据、状态：存疑/已裁决）；
- 标注层遇该位置**仍按底本字符标注**（S-01a 铁律），不做任何"顺手补正"；
- 下游消费方（阅读器渲染、公开图谱）可选择性应用映射，应用与否不影响语料层；
- 悬置的疑误进存疑清单，试点期数据同时供 S-01a 白名单回填参考。

**轨道二：底本勘误（乙类变更，例外通道）**

触发条件：高置信裁决（外证多数或内证四条全满足）+ 影响标注或定位质量。流程：

1. 校勘报告定稿，裁决记录归档；
2. 更新底本该回文件 → `config.fingerprint` 重算回填；
3. 重跑 `python scripts/generate_pn_wuxia.py --book {书} --all --verify` 重建结构层——**换字不影响分段则 PN 不动**；若影响分段（如修复断行错误），升级为 02ab 结构变更治理；
4. 同步 `tagged/` 标注文件（见第七章 SOP）；
5. 全量验证：`lint_text_integrity.py` 0 实质差异、`lint_purple_numbers.py` error 清零、git diff 只有字符替换；
6. 该书后续标注批次头部换记新指纹；旧批次按计划重标或登记过渡差异（S-01a 白名单收窄用途，见 6.2）。

### 6.2 与 S-01a 白名单的分工

武侠库中"标注文件与底本不一致"在稳态下**不存在合法场景**（标注必须逐字忠实底本）。S-01a 白名单的收窄用途：已批准勘误落地后、旧批次尚未重标的**过渡期差异登记**，以及试点期经互校确认的少量正确校勘。任何白名单条目必须能在本文的校勘记录中找到对应的裁决出处。

## 七、派生同步 SOP（金块，武侠化）

### 7.1 派生体系

```text
章回版/<书>/NNN*.txt        ← 锁定底本（只读；乙类变更时才改）
        │ generate_pn_wuxia.py
        ▼
tagged/<书>/NNN.struct.md + .struct.json   ← 结构层（PN + 围栏）
        │ 标注作业（01g 符号体系）
        ▼
tagged/<书>/NNN.tagged.md   ← 标注文件
        ▼
registry/（登记层）  wordlists/（词表）
```

### 7.2 同步原则（照搬）

1. **只替换字符，不改格式**：PN 不动、围栏不动、令牌不动、空行不动；
2. **格式特征保持**：struct 层结构不变；tagged 层全部 `〖〗⟦⟧〘〙` 令牌原位保留；词表仅更新受影响词条的引用字形；
3. **标注符号铁律**：任何替换不得触碰令牌结构；消歧语法 `〖TYPE 显示名|登记名〗` 中显示名随底本字改，登记名（实体 ID 绑定）**不改**。

### 7.3 SOP 步骤（乙类变更执行时）

1. **校勘报告定稿**：列出全部字符变更（如：莽→蟒，3 处）；
2. **更新底本 + 重算指纹**（§6.1 轨道二第 2 步）；
3. **重建结构层**：`generate_pn_wuxia.py --book {书} --all --verify`，核对 PN 与围栏零漂移；
4. **同步标注文件**：精确替换（保留令牌），替换前先 `grep` 统计目标字形出现次数，替换后核对数目一致；随后 `fix_nested_annotations.py --dry-run` 自查令牌完整性；
5. **全量验证**：`lint_text_integrity.py --book {书}`（0 实质差异）+ `lint_purple_numbers.py --book {书}`（error 清零）+ git diff 审查（只有字符替换，无行数增减）；
6. **更新校对报告**：记录同步状态、指纹版本、验证结果。

### 7.4 质量保证清单

- [ ] 校对报告已定稿并审核（含依据与状态）；
- [ ] 底本已修改且指纹已重算回填；
- [ ] struct 层重建通过 `--verify`，PN/围栏零漂移；
- [ ] tagged 层令牌数量前后一致（左右括号计数相等）；
- [ ] git diff 显示只有字符替换；
- [ ] 关键替换 grep 验证通过，原错误字形已清零；
- [ ] 两道 lint 全部通过（error 清零，warning 有处置记录）；
- [ ] 批次头指纹已更新，旧批次处置有记录。

## 八、AI 替换安全守则（金块，照搬 + 武侠化强化）

**适用对象**：AI 助手执行自动化校勘替换时。人工校勘用支持 Unicode 的编辑器并逐字核对。

1. **只匹配需要修改的汉字**：查找串尽量短、最小上下文；
2. **绝对避免跨标点**：查找/替换字符串不得跨越逗号、句号、冒号，**尤其不得包含任何引号**——引号是最危险字符：弯引号（U+201C/U+201D）极易被工具规整为 ASCII 引号（U+0022），一旦发生即违反标点符号禁令，且 S-01a 对账必报差异；
3. **全文替换须先预检**：武侠白话底本字词重复率远高于文言底本，盲目全文替换误伤风险更高——替换前 grep 统计命中数，命中处必须全部是同一讹误才可全文替换，否则逐处带独特锚（人名/武功名上下文）替换；
4. **修改后必须验证**：git diff 审查 + 字节级抽查（对比修改前后行的高亮字节，应只有汉字字节变化，标点字节不变）；
5. **发现标点被误改，立即回退**：`git checkout HEAD -- <file>`，回退后重新用更窄的匹配执行。

**关键记忆点**：

> 在底本校勘替换中，查找和替换字符串**只能包含汉字和必要的全角标点**，**绝对不能包含引号与冒号**；一次替换只解决一个问题，校勘（本文）与标注（S-01a 域）不许混在一次变换里。

## 九、质量控制

### 9.1 底本质量分级（照搬，阈值待试点）

| 等级 | 标准 | 说明 |
|---|---|---|
| A 级 | 异文率 < 0.1% | 录入质量极高，仅需微调 |
| B 级 | 异文率 < 0.5% | 较可靠，少量校正 |
| C 级 | 异文率 < 1% | 基本可用，需仔细校对 |
| D 级 | 异文率 ≥ 1% | 问题严重，优先安排系统互校 |

### 9.2 人工审核要点（武侠化）

- **重点审核**：全部建议勘误、存疑异文、标点重大差异；
- **抽检**：每回随机抽 10% 段落，重点关注人名、武功名、地名、门派名（实体登记的直接上游）；
- **交叉审核**：不同书由不同人审核；试点书全量精校，其余书按 D→C→B 优先级推进。
