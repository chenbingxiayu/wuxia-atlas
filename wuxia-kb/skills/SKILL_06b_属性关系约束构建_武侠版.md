# SKILL 06b: 属性、关系、约束构建（规划）

> 为本体添加属性定义、关系类型和完整性约束，构建语义丰富的知识图谱。

---

## 一、功能概述

本体分类只是知识图谱的骨架，还需要为实体和类别添加属性、关系和约束，才能构建完整的语义模型。本功能计划实现：

- **属性定义**：为实体类型定义属性（如人物的门派、师承、书内初登场回、年龄段等）
- **关系类型**：定义实体间的关系类型和约束（如师承、同门、亲子、敌对、情义恩仇等）
- **完整性约束**：定义数据的一致性规则（如年份范围、关系互斥等）

---

## 二、核心功能

### 2.1 属性定义

**目的**：为实体类型定义结构化属性

**功能**：
- **数据属性（Datatype Property）**：文本、数字、日期等值类型
  - 人物：本名／字号／绰号（@管道三分离）、门派、师承、书内时点
  - 地点：别名、所属区域（=树层级）、虚实字段（nature，D10）、经纬度（时空地图）
  - 职衔：品级、职责、履任区间（;树，区间字段见分类树五件套 §3）
- **属性域和值域**：定义属性可用于哪些类，值的类型是什么
- **属性约束**：必填/可选、唯一性、取值范围

**应用场景**：
- 结构化存储实体信息
- 支持属性查询和过滤
- 数据质量验证

### 2.2 关系类型定义

**目的**：定义实体间的语义关系

**功能**：
- **对象属性（Object Property）**：实体间的链接
  - 人物关系：师徒、同门、亲子、配偶、敌对、庇护（D06 谓词总表）
  - 地理关系：属于、相邻、包含
  - 时间关系：先于、同时、后于
- **关系约束**：
  - 对称性（如"兄弟"）
  - 传递性（如"师承"——师父的师父是师祖）
  - 逆关系（如"师父"↔"弟子"）
  - 函数性（如"书内初登场回"只能有一个值）
- **关系域和值域**：定义关系的起点和终点类型

**应用场景**：
- 人物关系网络可视化
- 关系推理（如祖父母推理）
- 关系一致性检查

### 2.3 完整性约束

**目的**：定义数据一致性规则

**功能**：
- **基数约束**：属性的数量限制
  - 人物只能有一个生年
  - 人物可以有多个官职
- **值约束**：属性值的取值范围
  - 书内时点必须落在该书纪年范围内（N4 time_resolver 时点键口径）
  - 职衔必须是职衔树（;二级树）已登记叶（N9 挂叶检查）
- **关系约束**：关系的一致性规则
  - 师承关系不能成环
  - 师承／效力关系的时间必须重叠（N4 时点键可比）
- **类约束**：类的互斥和覆盖
  - 实体不能跨层双标（同形异类按 01g 附录细则裁）
  - 职衔必须挂得到建制（朝廷／门派／帮会，◆组织）

**应用场景**：
- 数据导入时的验证
- 数据修改时的一致性检查
- 错误数据自动发现

## 三、技术基础

### 3.1 本体语言

计划使用的本体表达语言：

- **OWL（Web Ontology Language）**：标准的本体建模语言
  - OWL DL：描述逻辑子集，支持自动推理
  - 属性和关系的形式化定义
  - 约束的声明式表达
- **RDFS（RDF Schema）**：轻量级的类和属性定义
- **SHACL（Shapes Constraint Language）**：数据验证和约束

### 3.2 数据准备

本功能依赖已完成的工作：

- **本体分类**：实体类型层次（见 `SKILL_06a_本体总览_武侠版.md` 与 `SKILL_分类树五件套_武侠版.md` 五棵树）
- **实体关系**：已提取的关系数据（见 `SKILL_05_关系分析总览_武侠版.md`；现役 N5 910 边）
- **属性数据**：已标注的实体属性（见 `SKILL_03a_实体标注.md`；登记层 `registry/entities.json`）
