## 一、定位与边界（v0.1 骨架声明）

> ⚠️ **v0.1 说明**：本文为**骨架稿**。核心方法论（三阶段修复、修饰词整体标注、主动搜索文化）来自 docs/05 判定与既有反思实践；武侠专属的模式词表、probe 清单、量化基线仍待补（附录 B）。引用本文时以"v0.1 骨架"口径对待。

### 1.1 反思环中的"边界轴"

```text
S-03a 标注 ──→ accept/QA（结构门/语义门）──→ S-03c 按章反思（章级）
```

### 1.2 本文做什么

1. **主动搜索**（probe）：不等检测器报警，按模式清单在语料/词表/tagged 里主动搜同类；
2. **归因**：区分四源——规则缺陷（R）、词表缺陷（W）、示例/种子缺陷（S）、结构/围栏缺陷（F）；
3. **三阶段修复**：定位 → 规则化 → 全库回归；
4. **联动**：把修复回填 03a DEF 库、03c 反思清单、03c1 规律库，并把可机械化的部分沉淀进 C20/五门 lint；
5. **量化**：每批记录边界错误密度与修复率（META-10 §九指标）。

## 四、两条核心方法（docs/05 判定）

### 4.1 "修饰词整体标注"原则

- **定义**：修饰语与中心语构成一个语义单位时整体标注，不拆碎（"玉面妖狐凌霄"整体显示串、本名入管道，DEF-12；"金刀寨主"按 03b §八 判定）；**但**方式修饰/介词/动态助词留在外面（"纵马⟦■过来⟧""迈步⟦■入内⟧"，03a 动词边界规则）。
- **判据**：拆开后①任一片段不再是独立语义单位，或②拆开破坏原文连续区间 → 整体标；反之拆。
- **反例**：`〖@卓一航〗提剑` ✅ vs `〖@卓一航提剑〗` ❌；`⟦⊠害死⟧` ✅ vs `⟦⊠害⟧死` ❌（固化动宾整体收录，03a P3-4）。

### 4.2 "主动搜索优于被动检测"审查文化

- **原理**：C20 八模式是**有限探针**；模型/规则会以同型错误出现在检测器覆盖不到的位置。反思必须主动构造搜索（grep/统计/词表交叉），而不是只清报告条目。
- **probe 清单**（每批至少跑以下 8 类）：

| # | probe | 方法 | 目标模式 |
|---|---|---|---|
| PR-01 | 实体令牌前后 1-2 字是否为动词/语气/介词 | 正则扫描 tagged | P1/P2/P3 |
| PR-02 | `〖;`/`〖#` 后接人名、`〖@` 内含职衔字 | 统计交叉 | P4/P7 |
| PR-03 | 单字实体显示串清单 | 词频扫描 | P5 |
| PR-04 | 显示串含中文标点 | 正则 | P6 |
| PR-05 | 围栏/回末块内令牌（非实指例外） | 结构+令牌交叉 | P8/P12 |
| PR-06 | 管道显示串≠原文连续区间 / 管道目标不在原文 | 回锚校验 | P10 |
| PR-07 | 称谓词白名单外的新词（"X寨主""X前辈"） | 词表差集 | P4/P9 |
| PR-08 | 机械修复前后差异（dry-run 0 变更说明规则已覆盖） | diff | 全模式 |

> 纪律：**主动搜索发现的条目必须给出 probe 编号**；否则视为"顺手改"，不进回归统计（防止无证据的批量改动）。

### 4.3 三阶段修复法（v0.1 归纳）

| 阶段 | 动作 | 产出 | 纪律 |
|---|---|---|---|
| **E1 定位** | 逐条拉原文上下文（tokenized 检索，非 `str.find`；单字显示串必须令牌化定位） | 定位表（书/回/段/span/上下文） | 不得凭记忆写定位（DEF-13） |
| **E2 规则化** | 按归因四源选择修法：规则（补正则/豁免）、词表（增删条目/负规则）、种子（few-shot 示例）、结构（围栏/PN） | 修法清单 + 影响面 | 个案不写规则；同模式 ≥3 才规则化 |
| **E3 全库回归** | 修复器/脚本 apply（备份+剥标断言）→ 5 书 accept + 五门 lint + C20 复跑 | 回归报告 | 逐段 `strip(new)==strip(old)`；失败回滚 |

## 五、归因四源（R/W/S/F）

| 源 | 含义 | 修法 | 回写点 |
|---|---|---|---|
| **R 规则** | 标注规则/边界定义有缺口或过宽 | 改 03a/04f/03b 规则条款；补正反例 | 03a §四 DEF 库 / 04f 错误模式 |
| **W 词表** | 词表缺条目/多条目/负规则缺 | 补 `wordlists/*_source.md` → 编译 | 词表规划 WL 条目 |
| **S 示例/种子** | few-shot 种子或正反对照含坏例 | 修种子（人工复核）→ 重跑 `build_03a_fewshot.py` 再生成 | 03a §五/版本锁定 |
| **F 结构/围栏** | 结构层误判导致边界错（围栏内标） | 修 02ab 检测树/脚本；回灌 tagged | 02ab §四/§九、docs 记录 |

> 判据：同一错误在**不同模型/批次**重复出现 → 优先 R/S；只在特定词上出现 → W；只在特定结构块出现 → F。

## 十、FAQ（首批 7 问）

**Q1 本文没有设计稿，算不算"计划外"？**
不算。docs/17 §四 P2 波次明确列 S-03f；只是 §2.5 分层表漏列且无设计稿（计划内部不一致，已记录 docs/42 §4.2、docs/_audit §3.4）。v0.1 为骨架稿，规范源由 03a DEF + C20 + 反思实践合成，待补见附录 B。

**Q2 边界错误和"漏标/误标"什么关系？**
边界错误是**令牌区间**错（吞/粘/拆/覆盖），漏标/误标是**语义判定**错。前者归本文，后者归 03c；同一处可能叠加（如"金刀寨主"既是类型判定又是边界拆分）。

**Q3 为什么一定要主动搜索？**
检测器规则有限。实测教训：C20 修后 16 条，但 accept judgment、管道冲突里仍有同模式变体（docs/47/49）；只清报告会"报告清零、错误继续"。

**Q4 修复一定要改 tagged 吗？**
不一定。四源里只有 F（结构）与部分示例 needing 重标线段才动 tagged；R/W/S 的修复在规则/词表/种子上，通过重标或下一批生效。动 tagged 必须备份+剥标断言。

**Q5 白名单能随便加吗？**
不能。白名单是"已知不误报"证据清单，每条须有一条反例；无证据扩充会掩盖真实误标（BND-10）。

**Q6 和 03b 的边界怎么分？**
管道/显示串/规范名类（P7/P10/P9）归 03b；令牌区间（P1-P6/P8）归本文。两者共享"显示串=原文连续区间"契约。

**Q7 多久做一次？**
每批 accept 收口后一次；跨书批次合并做（同模式跨书统计）；复发率不降时升级为专项。

## 结语

边界错误是标注体系里最"便宜也最昂贵"的错误：便宜在每处只差一两个字，昂贵在它会让实体、事件、统计全部失真，且极易复发。**检测器负责可疑，反思负责搜尽，规则化负责不再犯。** 本文 v0.1 先把方法论与流程立起来，模式与基线随批次继续补。
