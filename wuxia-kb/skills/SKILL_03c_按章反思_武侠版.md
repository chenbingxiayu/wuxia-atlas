## 一、定位与边界

### 1.1 工序位置（反思环中的"章级轴"）

```text
S-03a 标注（LLM+词表+种子）
      ↓
五门 lint（结构门）→ accept_batch / qa_annotation_report（语义门/抽样门）
      ↓
S-03c 按章反思（本文，逐章）：六问 → 归因四源 → 修正/候选
      ├─→ S-03e 类型反思（类型体系轴，跨章）
      ├─→ S-03f 边界错误反思（边界轴，跨章）
      ├─→ S-03b 人名消歧（管道/跨书 canonical）
      └─→ references/03c1 规律库（条目化沉淀）+ SKILL_03a DEF/04f 域表/词表
      ↓
重跑 accept/lint/concordance（回归），下一批标注受益
```

### 1.2 本文做什么（六件事）

1. **逐章审查**：对单章 tagged 全量逐段读一遍，按六问（§四）找"标错/漏标/该改类型/该摘管"；
2. **报告驱动**：以 lint/coverage/accept/qa 的实际数字为信号源（§三），不凭印象找问题；
3. **归因四源**：每条发现落 R（规则）/W（词表）/S（示例种子）/F（结构围栏）（§五）；
4. **规律沉淀**：系统级（同模式 ≥3 处）发现写成 `03c1` 规律条目（§六）；
5. **回写闭环**：R→03a/04f 条款；W→wordlists；S→few-shot 种子重建；F→02ab/脚本；registry/display 类→S-03b 接口；
6. **量化与复核**：记录每章修正数、规律候选数、复发率，支撑 META-10 §九指标与 P4 抽样精度验收。

### 1.3 本文不做什么（越界即错）

| 不做 | 归属 |
|---|---|
| 决定"某类型该不该存在/怎么切"（如 ☆ 内部层级、◆ 内部切分） | S-03e 类型反思 |
| 系统性边界错误（吞动词/粘语气/拆字/覆盖称谓）的主动搜索与全库修复 | S-03f 边界错误反思 |
| 管道规范名/跨书 canonical/帝王年号/registry 合并 | S-03b 人名消歧 |
| 围栏类型定义、PN 规则、章回结构本身 | S-02a/02b |
| 改规范（03a/04f/01g 正文）而不留证据/不复跑 | 任何人——规范改动必须走行文 + 版本 + 回归 |
| 直接改 tagged 正文/凭记忆改 | 任何人——只动令牌，备份 + 剥标逐字断言（§七.4） |
| 修脚本/工具 bug | 工程任务（本文只登记"工具缺陷"信号与证据） |

### 1.4 与既有资产的关系

| 资产 | 用途 | 本文角色 |

## 二、快速开始（五步）

````text
Step 0 预备   读 03c1 规律库（按书/章风险激活子类）+ 五书全局口径（§三）；确认备份点
Step 1 信号   读本章 lint/coverage/accept/qa 报告 → 六问矩阵（§四）逐项标记可疑信号
Step 2 全查   逐段读 tagged（对照 struct 底本），标错/漏标/类型/管道/语义/结构六类全查
Step 3 归因   每条落"六问 × R/W/S/F"；个案(1-2)/系统(≥3) 分级；系统级写 03c1 候选条目
Step 4 修正   机械项走修复器（剥标断言）；语义项逐条改令牌；回写规范/词表/种子/registry
Step 5 回归   五门 lint + accept + concordance 复跑；规律条目入库/状态流转；写章级/批次报告
````

## 三、输入：报告矩阵与读取顺序

### 3.1 报告清单（批次必读）

| 报告 | 路径 | 读什么 | 频率 |
|---|---|---|---|
| 验收 JSON | `registry/acceptance/<书>_<范围>.json` | `summary`（hard/warnings/pipe_unsourced/judgment）、`chapters_data[ch]`（逐章 judgment/pipe/warnings）、`pipe_sources`、`qa_probe` | 每批 |
| 验收报告 MD | `logs/acceptance/acceptance_report_<书>_<范围>.md` | 风险八类表、§6.2 unsourced 明细、§6.3 冲突 | 每批 |
| 覆盖率报告 | `logs/coverage/汉字标注覆盖率统计报告_*.md` | 五书实体/动词密度、类型分布、缺口 | 每批 |
| 结构 A/B | `logs/qa/qa_structure_A_B_*.md` | 剥标≠底本、管道问题、围栏/回目令牌 | 每批 |
| concordance | `registry/concordance/<书>.json` | `summary`（registered/alias_mapped/unregistered）、高频实体、`type_counts` | 每批 |
| 边界报告 | `logs/boundary/<书>.{md,json}` | C20 P1-P8 条目与证据 | 边界批次 |
| 动词复核 | `logs/verb_validation/<书>.json` | 域冲突/词表候选 | 事件批次 |
| 既有反思 | `docs/26/34/45/46/48-S2/54/55` | 先例、已裁口径、复发模式 | 批次前 |

### 3.2 读取顺序（"先清源头再反思"）

1. **结构/围栏先**：结构错（围栏/PN/剥标）会让后续所有统计失真——先跑五门 lint + qa 结构 A/B，确认剥标=底本；
2. **lint 次之**：五门 lint 的硬错误清零后，再看 warning（E12 词族、fence 限实指等，warning 不阻塞但要逐条归因）；
3. **accept 再之**：hard=0 是前置；judgment_items 是语义待裁清单；pipe_unsourced 是管道缺来源清单；
4. **coverage/concordance 最后**：看召回短板与登记异常（unregistered 高、type_counts 异常）；
5. **先清源头再反思**：若前一层仍有硬错误，不得把其后果当"标注错误"写入规律库（会把结构问题误归因成语义问题；docs/46 误报教训）。

### 3.3 报告可信度纪律

- **数字以 JSON 实测为准**，文档摘要只作线索：docs/45 §1.1 曾出现任务书 87/37 vs acceptance JSON 实测 85/35，最终以 JSON 为准；
- 文档要给**快照口径**：同一批两次快照可能差 warnings（docs/46 §二-15：22:17 warnings 0 / 22:19 warnings 2，检查项新增所致，非矛盾）；
- 报告若含硬编码批次事实（如"无来源 0 条"写死），先当**工具缺陷**登记（docs/46 P1-2），不得据此下结论。

## 四、六问（Q1-Q6）— 逐章审查的统一提问

> 六问是"每章都要过一遍"的检查面，不等于六类修法。每问给出**信号→典型错误→归属**；同一条错误可跨问（如"金刀寨主"既是 Q3 类型又是 Q2 边界），以主因落位。

| # | 问题 | 主信号（报告/字段） | 典型错误 | 主归属 |
|---|---|---|---|---|
| **Q1** | **有没有漏标？** | coverage 密度、concordance unregistered、类型召回、人工对照 | 通名类 `#/;/•/{` 漏标、单处提及漏标、省称/另称漏标 | 03c 本文（语义漏标） |
| **Q2** | **边界对吗？** | C20 P1-P8、边界 grep、剥标 A/B | 实体吞动词（`〖@卓一航提剑〗`）、粘"道/了/着"、介词误入、标点内嵌、覆盖称谓 | 03f 边界轴 |
| **Q3** | **类型对吗？** | type_counts、易混对清单 | `#` vs `;`（职业/建制职）、`~` vs `&`/`#`（族群/家族/身份）、`^` vs `☆`（总称/分项）、`%` vs `$`（时间/数量）、`•` vs `{`、`=` vs `◆`（地点/组织） | 03c（判据）+ 03e（类型体系） |
| **Q4** | **管道/消歧对吗？** | pipe_unsourced、pipe_mapping_conflict、registry alias、display | 无来源管道、反向管道、通称当单值别名、同名管道、显示串≠原文 | 03b 人名消歧 |
| **Q5** | **事件/动词语义对吗？** | judgment_items（plan/quantity/time/domain/wordlist）、verb_validation | 计划/否定/条件动词误标、战斗粒度、攻防/致残域、信息传递误标、密谋聚合误标 | 04f + 03c（裁决先例） |
| **Q6** | **结构与格式对吗？** | 五门 lint、fire/fence、PN、qa A/B | 围栏内令牌、回目行令牌、回末套语、半角引号、括号误写、占位符泄漏 | 02ab + 03a DEF / 工程 |

**六问执行纪律**：

1. **逐段读**：不得只看报告；报告是搜索线索，语义误标必须回读原文与上下文包（前后段）；
2. **先证据后判断**：每条发现写 `书:回[段] + 显示串 + 原文片段`，无 loc 不写；
3. **不越层裁决**：Q2 问题归 03f、Q4 归 03b；03c 只在章内做"发现 + 修正建议"，跨章系统问题交对应轴；
4. **六问全绿才算本章通过**：允许有"保留（有据）"项，但每条保留要有先例或条文（docs/45 §三方法）。

## 五、归因四源（R/W/S/F）与修法矩阵

> 定义与判据引自 `SKILL_03f_边界错误反思_武侠版.md` §五（本文引用不重定义），此处补武侠操作化。

| 源 | 含义 | 判据（怎么识别） | 修法 | 回写点 |
|---|---|---|---|---|
| **R 规则** | 03a/04f/03b/02ab 的规则条款缺口、过宽、互斥 | 同一错误**不同模型/不同批次**重复出现；或规则正反例可清晰覆盖 | 改规则条款（03a §二/04f §3.x/03b §八）；补正反例；版本行注记 | 03a §四 DEF 库 / 04f 错误模式 / 对应 SKILL 正文 |
| **W 词表** | 词表缺条目/多条目/负规则缺失（identity 212、kinship 62、new_entity_types 268 等） | 错误集中在**特定 surface**；同字串在其他语境正确 | 补 `wordlists/*_source.md` → `python scripts/wordlist_compiler.py --name <表>` 编译；负规则同批 | 词表规划 WL 条目 + 编译产物 |
| **S 示例/种子** | few-shot 种子/正反对照含坏例或未覆盖新现象 | 模型"看例子模仿"出错的模式；改规则无效但改种子有效 | 改 03a 种子 → `python scripts/build_03a_fewshot.py` 重建（断言）→ 版本锁定 | 03a §五 few-shot / 版本锁定 |
| **F 结构/围栏** | 检测树/围栏/PN/回目结构误判导致边界错 | 错误**只在特定结构块**（围栏内/回目/回末）出现 | 修 02ab 检测树/生成器；重生成 struct；回灌 tagged（剥标断言） | 02ab §四/§九 + 结构脚本 + docs 记录 |
| （扩展）**G 工程/工具** | 报告/脚本/loader/工具缺陷造成的假信号 | 数据本身正确，报告数字错误（docs/46 误报、硬编码） | 登记缺陷 → 工程任务修工具；反思报告注明"工具缺陷，非标注问题" | docs/46 类复核清单 / 对应脚本 issues |

**判定顺序**（避免误归因）：

1. 先排除 G（工具误报/口径混用）：换快照/复跑/人工核对 JSON；
2. 再看 F（结构）：是否只在围栏/回目/回末/特定框内出现；
3. 再看 W（词表）：是否集中于特定 surface；
4. 再看 R/S：跨模型/跨批重复 → R；示例缺位/坏例 → S；两者常同时存在（同批修 R+S）。

**个案 vs 系统**：1-2 处 = 个案（记录不写规则，防"个案当系统"，03f BND-04）；同模式 **≥3 处** = 系统，必须至少回写一处（规则/词表/种子/工具），并写 03c1 条目。

## 六、规律条目：与 `references/03c1` 规律库的接口

### 6.1 何时写条目

满足以下**任一**即建候选条目（宁多登记、勿漏沉淀）：

- 同模式 ≥3 处（系统级）且修法可复用；
- 新类型/新词表/新围栏规则的**判据边界**被本次反思首次明确（即使只有 1 处）；
- 已有规律在本次适用/失效/需修订（状态流转，见 §6.3）；
- 反例陷阱（"看起来像 X 实际是 Y"），即使只 1 处——反例本身就是资产。

不写条目的情形：纯个案笔误（按 DEF 库已有条目处理即可）；工具缺陷（登记到工具侧）；正文作者写法（穿帮/设定冲突，归 N8/关系层，不改文本）。

### 6.2 条目 schema（固定 8 字段）

```yaml
### A01 · 条目标题（一句话判据）
- 类别: A 类型判断 / B 跨书与管道 / C 边界与格式 / D 事件与动词 / E 结构与围栏 / F 工程与流程
- 现象: 错误的标注长什么样（给可检索的模板，如 〖@X弟〗）
- 判据: 判定规则（正例/反例 + 上下文条件 + 优先级）
- 动作: 修法（机械修复命令 / 改哪个 SKILL 哪一节 / 补哪张词表 / 摘管或改管）
- 反例: 至少 1 条"看似适用其实不适用于此"的反例（防过度泛化）
- 来源: 书:回[段] 实测 + docs/xx §y + 先例编号（DEF/BND/先例）
- 状态: 候选 / 已验证 / 已回写 / 已入库 / 废弃 / 待裁（见 §6.3）
```

### 6.3 ID 分配与状态机

- **编号规则**：`<区字母><两位序号>`，区字母 = A/B/C/D/E/F；编号**只增不复用**（史记 03c1 v2 教训：编号不连续是历史正常现象，不得重排/复用）；
- **状态流转**：
  - `候选`：本次反思首次发现，证据 1 批；
  - `已验证`：≥2 批/≥2 书复现，或 1 批 + 条文/先例支持；
  - `已回写`：已落到 03a/04f/词表/种子/工具并回归通过；
  - `已入库`：`03c1` 条目 + 回写点 + 回归证据三件齐备（= 归档完成）；
  - `待裁`：涉及治理口径（如政权/朝代是否归 ◆、纯衔能否入 aliases），须上抛用户/Lead 拍板，不得自行改规范；
  - `废弃`：被新条目取代/证伪；保留编号，正文标注"并入 X"/"被 X 取代"（史记 v2 治理做法）。

### 6.4 去重与合并（防规律库膨胀）

1. 新建前先按关键词/类别在 `references/03c1_反思规律库_武侠版.md` 检索既有条目；
2. 同主题多条目 → 保留一条主条目，其余**编号保留、正文改为指针**（"见 A04"），不删编号（史记 03c1 16 组重叠合并为指针的做法）；
3. 与 03a DEF 库重叠的，条目 `来源` 标 DEF 号，不重复抄写缺陷描述；
4. 与 03e TRE / 03f BND 重叠的，交叉引用即可（各库有自己的命名空间）。

### 6.5 与 03a DEF / 04f / 词表 的映射（回写清单）

| 规律类别 | 主要回写点 | 同步动作 |
|---|---|---|
| A 类型判断 | `SKILL_03a` §二类型行 / §四 DEF 库；`SKILL_01g` 附录裁定 | 更新 few-shot 种子（如涉及典型例）→ 重建 |
| B 跨书与管道 | `SKILL_03b` §八/§九；`registry/entities.json`（alias/canonical）；`registry/display_canonical.json`（展示层） | 改 registry 需备份 + 唯一性断言 + 受影响书 accept 复跑 |
| C 边界与格式 | `SKILL_03a` §四 DEF；`fix_annotation_mechanical.py` 规则 | 修复器 dry-run → apply（备份 + 剥标断言） |
| D 事件与动词 | `SKILL_04f` §2.x/§3.x 域表；`SKILL_04a` 事件状态 | 词表（verbs.json）同步；accept 复跑 |
| E 结构与围栏 | `SKILL_02a_02b` §四/§九；`generate_pn_wuxia.py`/`detect_verse_wuxia.py`/`symbols.py` | 重生成 struct → 回灌 tagged（剥标断言）→ lint/accept |
| F 工程与流程 | 脚本/报告/loader；`docs/xx` 复核记录 | 修工具 + A/B 回归；报告注明旧口径 |

### 6.6 回写纪律（缺一即未闭环）

1. **一笔条目 = 一处规范/数据改动 + 一处回归证据**；只写库不改规则（或反之）视为未闭环；
2. 机制类条目（如"报告不得硬编码"）若一时无法改工具，须在条目 `状态=候选` + `动作` 写"待工程任务"，并在批次报告"遗留"列出；
3. 任何 registry/display/tagged 改动必须：备份 → 剥标/唯一性断言 → 受影响书 accept 复跑（docs/54 §1.1、task-8/task-12 流程）；
4. 回写后更新相关 SKILL 的 `last_updated` 与版本行；`references/README.md` 的库索引/条目计数同步。

## 七、抽样策略

### 7.1 三级抽样（按风险分配精力）

| 级别 | 范围 | 方法 | 产出 |
|---|---|---|---|
| **L1 全章全查**（默认） | 新书首批、刚改过规则的批次、judgment/unsourced 异常章 | 逐段读 tagged；六问全过 | 章级反思报告 |

### 7.2 抽样纪律

- **seed 固定**（`--seed 20261104` 等）且与上一批一致，否则前后不可比；
- 抽样**不改变抽样数**做覆盖补充替换（accept 的 coverage_swap 机制）；
- 抽检样本要**分层**（实体类型 × 动词域 × 结构块 × 书），防止只抽易读段；
- 人工精度抽检：P4 验收要求"抽样 50 例人工复检精度 ≥90%"（docs/02 P4 验收口径），低于则回到规则/种子修。

### 7.3 高风险全查清单（不抽样）

- `pipe_unsourced` / `pipe_mapping_conflict` 全部条目；
- 围栏内令牌（fence_entity_real_only / fence_forbidden_verb / tao_token）；
- 回目行令牌（title_token）与回末套语段；
- judgment_items 全部（语义边界）；
- C20 boundary error 全部；
- concordance unregistered 中高频实体（前 20）。

### 7.4 质量基线（参考，不作硬指标）

- 史记口径：正常章 30-80 处修正，<20 处需逐段复查；武侠对话密集体预期 **20-60 处/章**（docs/02 R1 预估）；
- 武侠实际批次：G2 首轮（docs/26）四回产出 16 条规律种子；judgment 批次（docs/54）3 书 75 token/41 文件——**以"规律条目 + 回写数"为主指标，不以修正数论英雄**；
- 薄章（短回/结构章）修正少属正常，须在报告注明"薄章豁免"理由。

## 九、示例（真实案例，docs/26/34/45/46/48-S2/54）

### 9.1 示例 A：数量新口径——信息承载原则（Q3/Q5 × R+S）

- **现象**：机器批把裸数词/裸量词当 `$`（`〖$一〗/〖$个〗/〖$块〗`），或反之把承载情节信息的计数漏标。
- **裁决**（docs/26 RD-2 / R-009）：承载情节信息的计数独立标 `$`，不论随附名词是否标注（伤势/名单/人员构成）；边界：标签字数/群像描写不标。
- **执行**：docs/45 数量 13 条真违规全摘；docs/48-S2 §5.3 R3 金标准 C1 清洗摘 509 token；后续批次仍复发 → 验证"规则已入 03a 但种子未更新"是根因（S 源）。
- **规律**：A10（$ 信息承载）、D01（计划否定）、F04（只动标记+断言）。

### 9.2 示例 B：战斗粒度——逐式 + 微动作排除 + 招式名 ☆ 每现必标（Q5 × R）

- **现象**：同一场战斗，有的批次逐式标（锁/推/劈/点），有的合并；姿态微动作（合拢/转身/退半步）被误标；招式名 `☆` 漏标。
- **裁决**（docs/34 §3.1 R-013，2026-11-04 终裁 + 03a v1.8 成文）：主/近景交锋**逐式标**（攻/防/闪避/擒控入口每式标）＋**招式名称 ☆ 每现必标**＋**姿态微动作不标**＋远景/群战只标主干。
- **验证**：全库姿态类战斗事件 0 命中；未标引号短语 330 条扫描无招式名 → 无回溯。
- **规律**：D04（战斗粒度三分）。

### 9.3 示例 C：judgment 118 → 27（Q5 × R，先例直判）

- **现象**：accept judgment_items 118 条（白发 020-032），类别为数量/计划否定/域风险/词表候选/时间/围栏。
- **方法**（docs/48-S2 §一）：逐条回读原始 token 语境 → 先例同例直判（docs/45 §三）+ 规则类机械执行；**不依赖报告"前接关键词"结论**（同段多 token 常只指一处，docs/45 §1.2：020[16] 回到 2 处只摘后一处"若回到"）。
- **结果**：摘 79 / 改域 4 / %→$ 2 / fence 2；留 27 条全部有据（如 `⟦■掳去⟧`=强制迁移 ■ 成立）。
- **规律**：D01（计划否定）、D02（既成保留）、D05（致残 ⊠）、D06（逐出 ⊡）、E02（围栏实指）、F02（定位修复）。

### 9.4 示例 D：围栏漂移——剥离 6 保留 2（Q6 × F）

- **现象**：白发/七剑重生成 struct 后新增围栏内令牌 10 个（docs/54 §2.2）。
- **处置**：剥 6（彩笔/⟦■闯出⟧/大牢/八十年来/轻功/十年，含动词与泛指/修辞）；留 2（金环、天山为实指 → judgment 限实指）；令牌总量七剑 28,936→28,930（恰为剥离数）；PN 变动 1 回需下游扫描（docs/55 §2.2）。
- **规律**：E02（韵文实指）、E03（围栏动词剥）、E05（围栏漂移/PN）。

### 9.5 示例 E：词表建议不采纳——天山剑法父式双标（Q3 × W，需裁）

- **现象**：外部复核建议删除词表中"天山剑法"（疑为通名/父式误收）（docs/46 §二词表专项 G7）。
- **核验**：SKILL_03a v1.7 G-29 明确"父术+子式双层双标"，词表 note 已标 `parent_art` → **不采纳删除**；同类"寨主/宫主/管家 `#` vs `;`"、"政权/朝代 `◆`"等属治理待裁，不得由反思自行改规范。
- **规律**：A11（政权/朝代待裁）、F07（系统缺陷回写须有规范依据）。

### 9.6 示例 F：跨书管道 82 条 unsourced（Q4 × R/W）

- **现象**：江湖 82 条 `pipe_unsourced`，几乎全是帝王名→本名（康熙→玄烨/崇祯→朱由检/顺治→福临/雍正→胤禛）与通称（皇上/皇帝）管道。
- **处置**（docs/55 §1）：registry 校准（本名 canonical + 年号 alias）→ 56 条保留管道 + 按回补 mapping；26 条通称**禁入单值映射**→ 摘管道保留实体标注；`pipe_unsourced` 82→0、hard 0、judgment 不升。
- **教训**：第一版把通称写入映射快照 → loader 单值摊平导致 qa `pipe_issues` 136→**321** 假冲突；撤回后 134（优于基线）——**通称/歧义 surface 只做回级注记，不做单值映射**。
- **规律**：B01/B05/B06/B07。

### 9.7 示例 G：报告硬编码与工具误报（Q6/F × G）

- **现象**：accept 报告把"无来源 0 条"写死、案例写死（docs/46 P1-2）；C18 `--apply` 与 scan 掩码语义不一致会把词插入围栏（docs/46 P1-1）；lint_symbol_conflicts 未剥令牌产生 170 处假阳性（DEF-11）。
- **反思动作**：先判 G（工具缺陷）→ 登记 → 工程任务修复；**不得据此写"标注规律"**；修复后 A/B 复跑证明。

| RFL-08 | 通称/歧义 surface 写入单值映射 | qa pipe_issues 暴涨/跨回假冲突 | 禁入 aliases/映射，回级注记或摘管（B01/B05） |
| RFL-09 | 规律库膨胀：重复条目/编号重排/只写库不改 | 同主题多条目；编号不连续被"整理" | 去重合并为指针、编号只增不复用（§6.4） |
| RFL-10 | 文档/报告快照口径不明 | 两次数字矛盾（87 vs 85；warnings 0 vs 2） | 报告标注 generated_at/快照口径；以 JSON 为准（F01/F07） |

## 十三、成功标准（可量化）

1. **覆盖**：本批纳入反思的章节 100% 有章级报告；六问零"其他"；
2. **闭环**：系统级发现 100% 有 03c1 候选条目，且 ≥1 处回写（规则/词表/种子/工具/数据）；
3. **回归**：受影响书 accept `hard=0`、五门 lint 0、`pipe_unsourced` 不升、judgment 不升高；剥标逐字等式 100%；
4. **复发率**：下一批同模式新增数下降（或稳定在基线内）；抽检 50 例人工精度 ≥90%；
5. **可追溯**：每条规律/修正可回溯到 `书:回[段]` + docs/先例 + 回写 commit/记录。

## 十五、FAQ（首批 8 问）

**Q1 按章反思和 accept 是什么关系？**
accept 是"门"（硬错误 + 抽样 + 语义清单），按章反思是"引擎"（逐章找系统问题 + 沉淀规律）。accept 通过不代表标得好，只代表没触发硬门/抽样门。

**Q2 每章都要全查吗？**
新书首批、规则刚改批次、异常章必须全查（L1）；稳定批次可 L2 抽样 + L3 跨书复核，但高风险清单（§7.3）永远全查。

**Q3 修正数不达标怎么办？**
不追数。武侠基线 20-60 处/章是参考；薄章/结构章少属正常。若连续多章 <10 且 coverage 无异常，重点转向"规律条目/回写"而非硬凑修正。

**Q4 发现的问题该记 03c1 还是 03a DEF？**
缺陷**模式**进 03a DEF（编号体系、拦截手段）；**可复用判据/动作/反例**进 03c1（按 A-F 区）。同一发现可双登记但正文不重复（§6.4）。

**Q5 规律库条目何时算"入库"？**
条目 + 回写点 + 回归证据三件齐备。只有条目没有回写 = 候选；只有回写没有条目 = 易失传。

**Q6 通称/歧义 surface 怎么处理？**
禁入 aliases/单值映射（docs/55 教训）；能定则按回级文内证据挂管道/注记，不能定则摘管道保留实体标注（03b §8.7）。

**Q7 反思能否改 tagged 正文？**
不能。只动 `〖〗/⟦⟧/〘〙` 令牌；改后 `strip(new)==strip(old)` 逐字断言；备份先行。正文问题（错字/穿帮）登记、不修。

**Q8 与 03f 边界反思的先后？**
先结构（lint/qa A/B）→ 再边界（C20 全查）→ 再按章语义。边界系统问题交 03f 批处理，03c 不重复做全库边界搜索。
