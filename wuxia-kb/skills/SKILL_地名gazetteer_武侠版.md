# SKILL 地名 Gazetteer（武侠版）——双图层地名库 · 显式弃权 · 无损迁移

> **版本状态**：v0.3-draft（2026-11-03），双稿合并定稿。骨架取 v1（GLM 子 agent，全量提示词，784 行，M01-M13 迁移映射建立在 `kb/gazetteer.json` 实测底账上，统计经合并评审逐项核对吻合）；v2（deepseek，399 行，低于合同下限 600）的独立亮点全部回收、缺陷全部修复，逐条裁决见 `docs/14-SKILL_地名gazetteer双稿对比分析与合并说明.md`。两稿以 `_v1`/`_v2` 存档。相对 v1 的实质变更：①id 定版"中文规范名原样保留、永不改写"（新增 G13 主键改写，否决 v2 的拼音 slug 方案）；②conf 枚举对齐 #9 定稿的全库档位字典 strong/ok/weak（原 B09 定版）；③补 unlocatable 派生布尔、锚点 distance 单位增"日路程"、类型学"渲染侧重"列、别名挂接出处纪律、候选池按书集分批消化（v2 回收）；④few-shot 两处示例修复（天山 books 重复追加、风砂堡锚点跳级）；⑤错误模式库扩至 13 条（新增 G13）；⑥附录 B 收紧为 12 项真开放（B04/B09 转定版）。

## 一、技能定位

### 1.1 一句话定位

本技能定义《梁羽生武侠全集》知识库的**地名登记表（gazetteer）规范**：一张"真实地理 + 虚构地名混用"世界的地名库。它是行踪地图 /atlas 的地基——主角轨迹串真实地理，虚构地名按相对方位安放；同时支撑地点筛选着色、人物/事件定位、江湖问答与跨书地点治理。

武侠世界的地理是**半真实**的：天山、北京、宣武门真实可挂经纬度；秘魔崖、风砂堡式的虚构驻地只能给相对锚点。**双图层是本规范的核心设计**，一切字段、流程与渲染协议围绕它展开。

### 1.2 为什么必须双图层

| 世界特征 | 若只有单一坐标图层 | 双图层解法 |
|---|---|---|
| 真实地名占绝大多数（650 条实测中 624 条 real=true） | 可用，但虚构点无处安放 | 真实图层续用既有经纬度资产 |
| 虚构点（风砂堡、喀沁草原式）文中不出现坐标 | 硬猜坐标=编造（违反 01g"虚构地点不随意给精确经纬度"） | 虚构图层只记相对锚点，渲染时借真实图层落位 |
| 虚构点嵌在真实地貌上（天山派驻地在真实的天山） | 同名实体被拆成两条互不相干记录 | 两层嵌套条目 + 锚点链互指 |
| 部分地名无线索定位 | 乱放坐标或漏登 | 显式弃权 unlocatable（见第四章） |

### 1.3 管线位置图

```
01g 标注层（15类实体，`〖=天山〗` 式地点标注；陌生地名不自动判虚构）
    ↓ 扫描产出候选
02a/02b 结构层（`书名#pn-X.Y` 全站定位符；首现定位=书:回/段锚点）
    ↓
任务 #9 词表体系（已定稿：地名候选表是词表族一员：surface/type/canonical/refs + 兜底）
    ↓
★ 本技能：gazetteer 登记表（双图层；schema 见第二章）
    ↓ 渲染消费协议（§6.5）
行踪地图 /atlas（轨迹串真实地理 + 虚构点按锚点落位 + 降级显示）
    ↘ 横向衔接：#8 分类树（kind/nature 同源，已定稿）· #7 跨书治理（同名消歧/冲突类型学，已定稿）
```

### 1.4 与 650 条既有数据的迁移关系声明

既有资产 `kb/gazetteer.json`（650 条：id/name/aliases/kind/real(bool)/books{书:回列表}/count/status/verified/lat/lng/precision，另有 source 证据对象）**不是本规范的对立面，而是真实图层的既有底座**：

1. **无损迁移**：11+1 个既有字段逐一映射进新 schema（第二章 §2.5 迁移总表 M01–M13），不丢任何字段、不静默改值；
2. **续用**：真实图层的坐标（619 条有 lat/lng）、坐标缓存（`kb/校订/gazetteer-cache` 639 份 Nominatim 结果）、行程链锚点（`gazetteer-seeds.tsv` 20 条）全部续用；
3. **扩充**：新增 nature 四值（01g 对齐）、图层归属、相对锚点、首现锚点、驻地双身份等字段；
4. **归一**：kind 现存 70 余种脏值（中文类名与 OSM 英文标签混用）按 §2.4 归一映射，归一前原值不删；
5. **复核而非推翻**：自动地理编码的可疑匹配（如"京师"被配到四川景市镇）不删除、不静默改坐标，进待审复核队列（§6.2）。

### 1.5 设计纪律（承接前六条）

- **01g 不可减**：地点性质四值（真实/虚构/真实原型改造/未定）；陌生地名不自动判虚构；虚构地点不随意给精确经纬度；
- **显式弃权**（08f 弃权原则迁移）：无法定位记 unlocatable，不乱放坐标；
- **前人实验四条结论**：正规则清单、few-shot、无内部矛盾、词表兜底——本规范即正规则清单，第八章给 few-shot，地名候选接口归 #9（已定稿）；
- **版权红线**：登记内容仅为地名与定位元数据，不得整段复制原文（文证字段只存锚点与短语引句）；
- **不写实现代码**：本规范是设计文档，渲染/校验逻辑以规则表述，不含程序代码。

## 二、登记表 Schema（Q1）

### 2.1 定版字段总表

登记表为 JSON 条目数组。字段编号 F01–F20，"条件"表示仅特定 loc_mode/layer 必填。

| 编号 | 字段 | 类型 | 必填 | 定版语义 |
|---|---|---|---|---|
| F01 | id | string | 是 | 主键=规范名，**中文，原样保留，永不改写**（既有 650 条 id 全为中文地名；拼音/slug 式改写=主键全库失效，错误模式 G13）。跨书同名消歧拆分时加限定符（`龙门镇@白发魔女传`，§5.4） |
| F02 | name | string | 是 | 规范名：取小说正文高频用名。今名/史籍名/俗称一律入 aliases，不占 name |
| F03 | aliases | array[string] | 否 | 别名集：异代名、今名、俗称、简称、异译。扁平列表不分级；指向本条的全部叫法；**每条挂接须注出处**（§5.5） |
| F04 | kind | enum | 是 | 地点类型，13 值封闭枚举（§2.3，与 #8 地点树同源） |
| F05 | nature | enum | 是 | 地点性质四值：真实/虚构/真实原型改造/未定（01g §9.6 对齐，**权威列**） |
| F06 | real | bool/null | 兼容 | **兼容派生列**：真实→true；虚构/原型改造→false；未定→null。由 nature 派生，禁止脱离 nature 手改（§2.2） |
| F07 | layer | enum | 派生 | 图层归属 real/fiction。真实→real；虚构/原型改造→fiction；未定→随 loc_mode（coord→real，anchor/proto/none→fiction）。渲染端可自行派生，登记端不必手填 |
| F08 | books | object | 是 | 所属书集：`{"书名": [回号数组]}`。结构原样保留既有格式（含 0 号回，口径随既有导出脚本） |
| F09 | first_seen | string | 新增 | 首现锚点 `书名#pn-X.Y`（02ab 定版格式）。人工登记时填，不从 books 自动推导 |
| F10 | count | int | 是 | 语料出现次数（扫描统计） |
| F11 | status | enum | 是 | 登记状态：auto/待审/已核准/已弃用（§6.3 档位定版；missing_coord 为兼容输入值） |
| F12 | verified | bool | 是 | 校验布尔：true ⟺ status=已核准 且 定位字段经人工核验。语义定版见 §6.3 |
| F13 | loc_mode | enum | 是 | 定位方式四值：coord（真实坐标）/proto（原型示意坐标）/anchor（相对锚点）/none（弃权）。三选一不许空悬 |
| F14 | lat / lng | number | 条件 | loc_mode=coord 必填；loc_mode=proto 可选（原型示意）；anchor/none **禁写**（写入即违规 G05） |
| F15 | precision | enum | 条件 | 坐标精度五级：exact/approx/shifted/region/proto（§3.2 分级表；loc_mode=anchor/none 时不填） |
| F16 | anchor | object/array | 条件 | 相对锚点（§3.3）：{ref, bearing, distance, text, evidence, chain}。loc_mode=anchor 必填；允许多锚点数组，渲染取 conf 最高者 |
| F17 | unlocatable_reason | enum | 条件 | loc_mode=none 必填：no_clue/contradictory/chain_broken/legendary（§4.2） |
| F18 | source | object | 建议 | 证据与来源：{engine, display, type, importance, n_candidates, note, checked}。引擎枚举见 §3.2；人工裁决写 reviewer 与日期 |
| F19 | hq_of | array[string] | 新增 | 门派驻地双身份：挂组织 canonical（如 `["天山派"]`），对接门派登记表（§5.3） |
| F20 | conf | enum | 派生 | 置信三档 strong/ok/weak（对齐 #9 定稿全库档位字典），派生规则见 §6.4 |

**unlocatable 派生布尔注记**：`unlocatable ⟺ loc_mode=none`——不作为独立登记字段（权威结构是 loc_mode+reason 枚举），但渲染端/检索端可按此派生布尔直接过滤（true→问号标记/D3 显示）。两种表述同源，不双轨维护。

**登记条目示例（真实图层，kind=山）**：

```json
{"id": "天山", "name": "天山", "aliases": [], "kind": "山",
 "nature": "真实", "real": true, "loc_mode": "coord",
 "lat": 42.213, "lng": 80.71, "precision": "approx",
 "books": {"七剑下天山": [0,1,3], "塞外奇侠传": [1,2], "江湖三女侠": [1], "白发魔女传": [4]},
 "count": 295, "status": "auto", "verified": false,
 "source": {"engine": "nominatim", "checked": null}}
```

**登记条目示例（虚构图层，相对锚点）**：

```json
{"id": "风砂堡", "name": "风砂堡", "aliases": [], "kind": "寨堡",
 "nature": "虚构", "real": false, "loc_mode": "anchor",
 "anchor": [{"ref": "天山道", "bearing": "北", "distance": {"value": null, "unit": "里", "tier": null},
             "text": "天山道以北（天山南麓道中）", "evidence": "白发魔女传#pn-31.0", "chain": 2}],
 "books": {"白发魔女传": [31,32]}, "count": 11,
 "status": "auto", "verified": false, "hq_of": []}
```

> 注：示例中锚点文证为格式示意；实际登记必须以校订时核实的 `书名#pn-X.Y` 为准。风砂堡的直接参照物是虚构条目"天山道"（chain=2），其自身锚点挂在真实图层"天山"（chain=1）——两级链规则见 §3.4。

### 2.2 nature 四值与 real 兼容列的裁决

**裁决 R1（本稿核心裁决）**：**新增 `nature` 四值列为权威列；既有 `real: bool` 保留为兼容派生列，不再承载判断。**

理由：

1. bool 只有真/假两值，表达不了 01g 已定版的四值（真实/虚构/真实原型改造/未定），23 条 real=null 条目已证明 bool 不够用；
2. "原型改造"是武侠地名的高频形态（秘魔崖、白驼山式总舵），判真判假都失真；
3. 保留 real 为派生列，渲染端与旧脚本零改动（继续读 real），人工裁决只写 nature，二者由规则锁死，不会分叉。

**派生规则与迁移裁决（双向锁死）**：

| nature（权威） | real（派生） | 650 条迁移裁决（M05） |
|---|---|---|
| 真实 | true | real=true 的 624 条 → nature=真实（**暂定**，进复核队列，复核可改判原型改造） |
| 虚构 | false | real=false 的 3 条（木什塔克/风砂堡/喀沁草原）→ nature=虚构（暂定，复核可改判原型改造，如木什塔克疑似慕士塔格原型） |
| 真实原型改造 | false | **不自动产生**。仅人工复核时改判：原型可考且小说功能/位置有改造（判据见 §5.6 案例 2、3） |
| 未定 | null | real=null 的 23 条 → nature=未定 |

✅ 正例：复核确认"秘魔崖"原型为北京西山秘魔崖、小说功能有改造 → nature 由"真实(暂定)"改判"真实原型改造"，real 随之 false，原坐标转 proto 语义（§3.7）。
❌ 反例：为了"让地图好看"把未定条目的 nature 手工填成"虚构"，real 却留着 true——两列分叉，违规。

### 2.3 kind 枚举定版与 #8 地点树同源映射

**裁决 R2**：kind 是 #8 地点树**维度 A（地貌/功能类型）叶子的扁平投影**，封闭 13 值；#8 的维度 B（真实性）不入 kind，由 nature 承载（正交，见 #8"双维度正交设计"）。

| 编号 | kind 值 | 对应 #8 地点树节点 | 典型条目（真实/虚构） |
|---|---|---|---|
| K01 | 山 | 山峰/山脉 | 天山（真实）/ 白驼山式总舵山体（虚构） |
| K02 | 水域 | 水域 | 黄河、洞庭湖 |
| K03 | 城镇 | 城镇/关隘（城镇侧） | 北京、西安、龙门镇 |
| K04 | 关隘 | 城镇/关隘（关隘侧）+ 城门 | 潼关、山海关、宣武门、七盘关 |
| K05 | 宫廷 | 建筑/场所 › 宫廷建筑 | 乾清宫、大明宫 |
| K06 | 山庄园林 | 建筑/场所 › 山庄/园林 | 拙政园；虚构庄院 |
| K07 | 客栈 | 建筑/场所 › 客栈/酒馆 | 悦来客栈（虚构连锁） |
| K08 | 寺观 | 建筑/场所 › 寺庙/道观 | 少林寺、五台山清凉寺 |
| K09 | 寨堡 | 建筑/场所 › 特化叶子（武侠补） | 风砂堡、山寨 |
| K10 | 遗址战场 | 建筑/场所 › 战场/遗址 | 土木堡、雁门关古战场 |
| K11 | 秘境洞府 | 秘境/洞府 | 秘魔崖（虚构功能体）、冰窟 |
| K12 | 区域 | 区域 | 中原、江南、回疆、陕北、大理国 |
| K13 | 其他 | （待审兜底，不允许长期滞留） | OSM 噪声标签暂存区 |

映射纪律：

- #8 的"城镇/关隘"一个节点拆为 K03/K04 两个 kind 值——**拆分仅发生在 gazetteer 投影层**，向 #8 回溯时 K03/K04 同归"城镇/关隘"节点，树本身不动；
- K09 寨堡是 gazetteer 对 #8"建筑/场所"的武侠特化叶子（堡、寨、硐），#8 若后续收编则并入其下（收编时机见附录 B07）；
- kind 与 nature 任意组合合法（虚构的宫廷、真实的客栈、原型改造的山庄）——**禁止**造"虚构宫廷"这类复合 kind 值（错误模式 G05 族）。

✅ 正例：`〖=乾清宫〗` → kind=宫廷，nature=真实。
❌ 反例：kind="宫廷(虚构)"——把维度 B 混进维度 A，违背 #8 正交设计（同 T04）。

### 2.4 既有 kind 脏值归一映射表

650 条实测 kind 有 70 余种取值：中文类名（山 87/政区 72/水域 41/寺观 24/聚落 21/关隘 12/边域 11/泛称 8/场景 3/地名 15）与 OSM 英文标签（administrative 117/village 43/hamlet 22/town 20/yes 15…）混用。**归一原则：按条目本名与上下文重判，不照抄 OSM 功能标签**（京师被 OSM 标为 town、陕北被标为 civil，皆噪声）。

| 既有值（族） | 归一到 | 说明 |
|---|---|---|
| 山、peak、mountain_range、glacier、cliff | 山 K01 | 名含"山/峰/岭/崖"优先 |
| 水域、lake、bay、canal、dam | 水域 K02 | |
| 政区、administrative、city、town、suburb、quarter、neighbourhood、residential、locality、place、civil、地名 | 城镇 K03 | "yes"式空标签按名称重判 |
| village、hamlet、聚落 | 城镇 K03 | 村镇归聚居点，不另设 kind |
| 关隘、city_gate、gatehouse、citywalls、wall、motorway_junction | 关隘 K04 | 七盘关被 OSM 标为高速枢纽点，按本名归关隘 |
| palace | 宫廷 K05 | |
| 寺观、religious、place_of_worship | 寺观 K08 | |
| 边域、泛称 | 区域 K12 | 回疆→区域 |
| 场景（现有 3 条虚构条目） | 按类型学重判 | 风砂堡→K09；喀沁草原→K12；木什塔克→待审 |
| station、bus_stop、train_station、aerodrome、hotel、school、university、college、museum、park、attraction、monument、memorial、artwork、government、post_office、industrial、construction、military、building、castle 等现代设施标签 | 其他 K13 → 待审复核 | 多为地理编码误配的副产物，复核时按本名重判或判误配剔除 |

✅ 正例：`陕北` kind=civil → 按本名判**区域 K12**，precision 升 region。
❌ 反例：照抄 OSM 标签 kind=bus_stop 入库——G08 错误。

### 2.5 650 条无损迁移映射总表（M01–M13）

**硬约束：3.1 实测 schema 的每个字段都必须出现在本表；迁移不丢字段、不静默改值。**

| 编号 | 既有字段 | 迁移去向 | 规则 |
|---|---|---|---|
| M01 | id | F01 id | 原样保留（**中文规范名即主键，永不改写为拼音/slug/序号**，G13）。仅当同名消歧触发拆分时（§5.4），原 id 归主条目，拆出条目加 `@限定符`；旧引用不失效 |
| M02 | name | F02 name | 原样保留。复核时若发现 name 用了今名/史籍名而正文用别名（如伊吾/哈密类），按 F02 规则换规范名，原值转 aliases，变更入校订台账 |

| M05 | real(bool) | F06 real（兼容列）+ F05 nature | 按裁决 R1：true→nature=真实(暂定)；false→nature=虚构(暂定)；null→nature=未定。real 值迁移期原样保留 |
| M06 | books{书:[回]} | F08 books | **结构原样保留**（含 0 号回口径）。新登记条目沿用同构；首现另记 F09，不回填改写 books |
| M07 | count | F10 count | 原样保留；新书扫描后累加 |
| M08 | status | F11 status | auto→auto；missing_coord（9 条）→auto，"缺坐标"信息由 lat/lng 缺失本身承载，条目进"真实图层补坐标队列"。新增档位 待审/已核准/已弃用 从此启用 |

| M10 | lat | F14 lat | 有值条目（619 条）原样保留，语义=真实图层坐标（WGS-84/EPSG:4326，沿用既有 meta.coord_system）。nature 复核改判原型改造后，坐标语义转 proto（§3.7），值不删 |
| M11 | lng | F14 lng | 同 M10 |
| M12 | precision | F15 precision | approx(371)/shifted(245)/exact(3) 原值保留；null(31) 待复核补档。region/proto 为新增值，仅复核后使用（既有三值语义不重定义） |
| M13 | source | F18 source | 实测另有该字段（619 条含 engine/display/type/importance/n_candidates/checked/note），提示词 3.1 未列但**一并无损迁移**；新增 engine 枚举值 tantu/chgis/manual 备用 |

迁移操作三条纪律：

1. **只增不改**：首轮迁移只加 nature/loc_mode/layer 等新列，不改任何既有值（含 id——G13）；
2. **暂定标记**：M05 产生的"真实(暂定)/虚构(暂定)"必须在复核队列中排队，暂定不是终审；
3. **台账留痕**：一切改判（暂定→终审、kind 归一、坐标复核）写入校订 TSV（沿用 `gazetteer-考订.tsv` 台账约定：键/kind/real/…/裁决/reviewer/日期），与既有 meta.tsv_rulings 指向一致。

### 2.6 首现锚点与 books 的分工

- `books`（F08）：**书集归属与出现密度**，服务跨书检索与筛选，回号列表是粗粒度索引；
- `first_seen`（F09）：**叙事首现的精确定位**，服务 02a/02b 的"首现定位（书:回/pn 锚点）"，格式 `书名#pn-X.Y`（X=回号，Y=段号，如 `白发魔女传#pn-1.3`）。

✅ 正例：books 记 `"白发魔女传": [1,4,7]`，first_seen=`白发魔女传#pn-1.3`。
❌ 反例：用 first_seen 替代 books（丢失全书分布），或从 books 最小回号自动推导 first_seen（段号无据，属脑补）。

## 三、双图层策略（Q2）

### 3.1 图层归属总规则

| nature | loc_mode | 图层 | 定位载体 |
|---|---|---|---|
| 真实 | coord | real | lat/lng + precision |
| 真实（区域类） | coord（region 级） | real | 区域代表点 + region 圈 |
| 虚构 | anchor | fiction | 相对锚点（无坐标） |
| 虚构 | none | fiction | 弃权（unlocatable） |
| 原型改造 | proto 或 anchor | fiction | 原型示意坐标（加徽标）或锚点 |
| 未定 | coord/anchor/none | 随 loc_mode | 暂按 loc_mode 渲染，条目加"待审"徽标 |

✅ 正例：天山（真实+coord）在真实图层；风砂堡（虚构+anchor）在虚构图层。
❌ 反例：给风砂堡配 lat/lng（虚构点乱放坐标，违反 01g 限制与 G02）；给天山写 anchor（真实点已有坐标还绕锚点，两层混写 G05）。

### 3.2 真实图层：坐标来源登记与 precision 分级

真实图层**继续挂经纬度**，坐标系沿用既有 WGS-84（EPSG:4326）。坐标来源（source.engine）登记枚举：

| engine | 来源 | 说明 |
|---|---|---|
| seed | 行程链锚点（人工拾取器实测） | 既有 seeds.tsv 20 条，如北京/洛阳/西安 |
| nominatim | OSM 地理编码缓存 | 既有 gazetteer-cache 639 份；n_candidates>1 或 display 语义不符者必入待审 |
| manual | 人工坐标拾取器核验 | 复核后的最终坐标 |
| tantu | 《中国历史地图集》（谭图） | 史籍点来源，09j 方法论继承 |
| chgis | CHGIS 中国历史地理信息系统 | 史籍点来源 |

**precision 五级定版**（既有三值保留原语义，新增两值）：

| precision | 语义 | 判定 | 既有条目示例 |
|---|---|---|---|
| exact | 实测点 | 权威来源或人工拾取且核验，误差可忽略 | 嵩山（34.504,113.032） |
| approx | 约测点 | 编码/缓存匹配可信但未人工核验 | 天山、秘魔崖（approx） |
| shifted | 移位点 | 现代匹配点与小说/史籍位置有偏移，人工挪移过 | 北京城（shifted 至通州侧） |
| region | 区域代表点 | kind=区域 K12 的广域地名：记代表点（治所或几何中心），渲染画范围圈不画针 | 陕北（复核后由 approx 升 region） |
| proto | 原型示意点 | **仅 loc_mode=proto**：原型改造条目的原型坐标，非小说精确位置 | 秘魔崖（复核改判后） |

粒度纪律（G09 防）：区域给 exact=错；具体建筑给 region=错；precision 必须与 kind 的粒度匹配。**相对锚点永不折算坐标**——"从'京师以西三百里'反推经纬度"式约测是被禁止的操作（虚构点坐标乱放，G02；示意落点只存在于渲染期，§3.5 J 纪律）。

### 3.3 虚构图层：相对锚点语法

虚构图层**不配坐标**，配**相对锚点**。锚点=三元组语法：

> **锚点 := 参照物 ref + 方位 bearing + 距离档 distance**

| 要素 | 取值 | 规则 |
|---|---|---|
| ref（参照物） | 已登记条目 id | **优先真实图层**（天山/京师/昆仑山系）；虚构参照须已登记且 loc_mode≠none |
| bearing（方位） | 八方位：东/南/西/北/东北/东南/西北/西南；拓扑关系词：之麓/之上/之内/之外/沿岸/沿线/之间/近郊/境外/相邻 | 八方位构成可计算的示意矢量；拓扑词不构成矢量，distance 免填 |
| distance（距离档） | 三档：**近 ≤50 里；中 50–500 里；远 >500 里**；文中给确切里数时记 value+unit 并归档。**unit ∈ {里, 日路程}**：unit=日路程 时 value=文中日数，档位暂归"中"，换算口径注 source.note（拍板项见附录 B14） | 里制按华里（1 里≈500 米）口径，换算依据写 source.note |
| text | 原文表述还原 | 如"京师以西三百里""天山以北" |
| evidence | 文证锚点 `书名#pn-X.Y` | **无文证的锚点不得登记**（防脑补） |
| chain | 链深整数 | 一级锚点=1（参照物在真实图层）；≥2 见 §3.4 |

多锚点：同一虚构条目允许多条锚点（不同书、不同回各有表述），登记为 anchor 数组；渲染取 conf 最高者，其余为备选证据。多锚点互相矛盾时不悄悄取舍——按 #7 冲突类型学登记（G11）。

✅ 正例：`"京师以西三百里"` → ref=北京（真实图层，kind=城镇）、bearing=西、distance={value:300, unit:"里", tier:"中"}、evidence=实际回段锚点。
❌ 反例：把"京师以西三百里"折算成精确经纬度写进 lat/lng——虚构点乱放坐标（G02），且 300 里在地图上是一个不确定带，不是一个点。

✅ 正例：`"天山以北"` → ref=天山、bearing=北、distance={value:null, tier:null→默认近带}, text="天山以北"。
❌ 反例：ref 填一个未登记的"北庭故城"——参照物必须已登记，未登记先补登再引用。

### 3.4 多级锚点（锚点链）处理

虚构参照物本身可能是虚构地（风砂堡在天山道以北，天山道在天山南麓）——形成**锚点链**。

规则：

1. **链深上限 3 级**：`风砂堡 ← 天山道(虚构,chain2) ← 天山(真实,chain1)`。超过 3 级视为定位失败证据不足，按 chain_broken 弃权或要求补一级真实参照；
2. **逐级降信**（§6.4）：链深每 +1，conf 降一档；渲染落点半径按链深放大（语义上"更不确定"，不写实现数值）；
3. **禁止循环**：锚点链不得成环（A 引 B、B 引 A）——发现即双条目转待审（G06）；
4. **链上禁断**：链上每个中间节点必须已登记且有锚点；断链按 §3.6 降级。

✅ 正例：秘境冰窟 ref=天池(虚构,chain2)，天池 ref=天山(真实,chain1)——两级落位，conf=weak。
❌ 反例：为省事给冰窟直接编一个"天山坐标"——跨层混写（G05）。

### 3.5 两层 join 规则（渲染落位五步）

行踪地图渲染时，虚构点借真实图层落位，按序执行：

| 步 | 规则 | 内容 |
|---|---|---|
| J1 | 直连真实 | ref 为真实图层条目且有坐标 → 以参照坐标为原点，按 bearing+distance_tier 生成**示意落点**（虚构样式：虚线轮廓+锚点环，环径随距离档放大） |
| J2 | 递归解析 | ref 为虚构条目 → 递归解析其锚点，chain+1，conf 降档；回到 J1 直到挂上真实坐标 |
| J3 | 原型直落 | nature=原型改造 且 loc_mode=proto → 直接用原型坐标落点，必须带"原型示意"徽标，不走锚点矢量 |
| J4 | 未定暂挂 | nature=未定 且 loc_mode=coord → 按真实图层样式渲染，加"待审"徽标（不因未定而拒绝渲染，也不伪装成已核准） |
| J5 | 失败降级 | 任一环 loc_mode=none、未登记或循环 → join 失败，进 §3.6 降级显示 |

**join 纪律**：join 只发生在渲染期，**落位结果不回写 gazetteer**——示意落点永远是派生物，不是登记数据（防"渲染坐标回流污染登记表"）。

### 3.6 join 失败的降级显示（D1–D3）

| 档 | 触发 | 显示行为 |
|---|---|---|
| D1 聚合标注 | 锚点链中断，但链上**前级参照物可渲染** | 不落点；在最近可解析参照物的 tooltip 中聚合列出："附近（书中言 X 以北）：风砂堡 等 N 处" |
| D2 书内示意 | 参照物本身不可渲染（无坐标/未登记/区域级过粗） | 不上全图；仅在书内行程页/详情卡以纯文本方位呈现（"书中言：天山以北"） |
| D3 纯列表 | loc_mode=none（弃权） | 仅检索/列表可见，不上图；问答按 §4.4 话术降级回答 |

降级不是惩罚而是诚实：宁可少画一个点，不可编造一个点（08f 弃权原则的渲染面）。

### 3.7 边界案例示范：天山与天山派驻地（两层嵌套）

"天山派驻地"是虚构点，坐落在真实山脉天山之上——**同一叙事对象横跨两层**。裁决：

1. **真实图层**：`天山` 条目（K01，nature=真实，coord，approx）——山脉本体，既有 650 条中的 295 次出现全部记在这里；
2. **虚构图层**：`天山派驻地` 条目（K11 秘境洞府或 K06 山庄园林，nature=虚构，loc_mode=anchor，ref=天山、bearing=按文中方位、拓扑词"之上/之麓"）、hq_of=["天山派"]；
3. **互指**：驻地条目 anchor.ref=天山；天山条目不反向写坐标级引用，仅可在 source.note 提示"有驻地类虚构点挂靠本条"；
4. **渲染**：J1 直连真实图层落驻地示意点；组织页经 hq_of 双向跳转（§5.3）。

✅ 正例：拆两条、锚点互指、书集出现各记各的（山脉的出现回≠驻地的出现回）。
❌ 反例：把"天山派驻地"合并进"天山"条目并改其坐标为"驻地位置"——真实山脉坐标被虚构功能体污染（G05）。

### 3.8 锚点登记正误例集（对照 3.3 语料实测）

| 原文型表述 | 正确登记 | 错误登记 |
|---|---|---|
| 天山以北 | ref=天山，bearing=北，拓扑默认近带 | 猜一个北纬 43° 坐标 |
| 京师以西三百里 | ref=北京，bearing=西，300 里/中档 | ref=京师（未规范化名，应挂北京条目 aliases） |
| 大巴山脉沿线 | ref=大巴山，bearing=沿线（拓扑词），distance 免填 | bearing=西（臆造方向） |
| 昆仑山系 | ref=昆仑山（若未登记先补登真实条目），bearing=之内 | ref=昆仑（简称漂移，应走 aliases 归并） |
| 风砂堡在天山道以北 | 两级链（§3.4）：ref=天山道 chain=2，天山道 ref=天山 chain=1，conf=weak | 直接 ref=天山 跳级（丢失中间锚点证据） |

## 四、显式弃权（Q3）

### 4.1 弃权原则（08f 迁移）

**无法定位时，显式记 unlocatable（loc_mode=none），而不是乱放坐标。** 弃权是可审计的正向登记动作（loc_mode=none + 原因枚举），不是"漏登"或"留空"。三句铁律：

1. 宁可弃权，不可编造（01g：虚构地点不随意给精确经纬度）；
2. 弃权条目仍是**正式登记条目**，检索、统计、消歧照常可用（§4.4）；
3. 弃权可升级（§4.5），升级前 reason 必填。

### 4.2 unlocatable 判据（U1–U4）

| 编号 | 判据 | 典型情形 | reason 值 |
|---|---|---|---|
| U1 | 无方位线索 | 专名出现过但上下文没有任何参照物/方位/里数 | no_clue |
| U2 | 文中自相矛盾 | 两处方位表述冲突且无法裁定先后/谁对（如甲回言"城东"乙回言"城南"） | contradictory（同时按 #7 冲突类型学登记"穿帮候选"，G11） |
| U3 | 参照物失效 | 锚点链断裂：参照物未登记/本身 unlocatable/循环 | chain_broken |
| U4 | 设定性不可定位 | 文中明言"无人知晓所在/传说之地/世外秘境"，作者有意悬置 | legendary |

✅ 正例：某山庄仅在一句闲谈中出现，无任何方位线索 → 登记之，loc_mode=none，reason=no_clue，D3 显示。
❌ 反例：因为"反正说不清"就随手给它配一个区域中心坐标——G02/G10。

### 4.3 不登记 vs 弃权登记的界线

| 情形 | 处置 |
|---|---|
| 纯通名/方位泛指："山下""城中""村口""关外"（不指特定地点） | **不登记**（G03）。它们是位置描述词，不是地名实体——通名不进弃权通道（弃权只对已登记专名条目），进 #9 候选表观察池 |
| 有专名但无定位线索："落霞山庄"（假名示例）出现 3 次 | **弃权登记**：建条目，loc_mode=none |
| 出现 1 次、专名性弱："某小镇""无名山谷" | 默认不登记，入 #9 候选表观察；若后文升级为关键地点再登记 |

界线口诀：**通名不登记，专名必登记；定位不了就弃权，弃权也要留全名。**

### 4.4 unlocatable 条目的保留价值

弃权≠废条目，以下能力全部保留：

1. **检索与归并**：name/aliases 照常入索引，后续再出现可累计 count、并回同条；
2. **消歧**：跨书同名时，unlocatable 条目照样参与书集维度消歧（§5.4），防止"无线索同名"被盲并；
3. **问答降级话术**：江湖问答对 unlocatable 条目回答"书中未交代确切位置"+ 已知线索（首现、出现回目、关联门派），而不是编一个方位；
4. **统计完整性**：地点总数、分书地点分布不因弃权而漏计。

### 4.5 升级路径

unlocatable → 定位成功的唯一通道是**新文证**：

1. 后续书/后文出现方位表述（"原来那山庄在天山以北"）→ 补 anchor，loc_mode: none→anchor，reason 清空，status: auto→待审→已核准；
2. 考证发现原型（对应史料/今地）→ 若判原型改造：nature 改判 + loc_mode=proto；若判真实：nature 改判真实 + coord；
3. 一切升级走校订台账留痕（§2.5 纪律 3），不原地静默覆盖。

### 4.6 unlocatable 与 nature=未定 的字段关系

**正交，不是一回事**：nature 管"是不是真实世界的地方"（真实性判疑），loc_mode=none 管"能不能定位"（定位判疑）。四组合：

| 组合 | 例子 | 处置 |
|---|---|---|
| nature=真实 + unlocatable | "关外某卫城"史有其名但小说语境无法对号 | 登记真实图层语义，coord 暂缺，U1 弃权 |
| nature=虚构 + unlocatable | 传说中的海外仙岛（U4 legendary） | 虚构图层弃权，D3 显示 |
| nature=未定 + unlocatable | 陌生地名且无线索（双料暂缓） | 最常见弃权形态；先弃权，真实性随复核 |
| nature=未定 + 有锚点 | 陌生地名但方位明确 | 有锚点先锚定，nature 待复核——**有锚点不许弃权**（G10） |

✅ 正例：两个维度各填各的，四组合语义清晰。
❌ 反例：把 nature=未定 当成"无法定位"的替身（未定≠弃权），或反过来用 unlocatable 表示"真实性存疑"；亦不得反向强制——未定且无线索的条目不许为凑 anchor 而乱挂参照物（G10）。

## 五、虚构地名类型学与衔接（Q4）

### 5.1 虚构地名类型学

虚构地名（nature=虚构/原型改造）按叙事功能分五型；**类型不替代 kind**——每条虚构地点仍必须填 §2.3 的 kind，类型学决定的是登记与渲染侧重：

| 类型 | 识别信号 | kind 常见落点 | 登记要点 | 渲染侧重 | 示例 |
|---|---|---|---|---|---|
| 门派驻地 | "总舵/总坛/山门/祖庭"+组织上下文 | 山/宫廷/寺观/寨堡/秘境洞府 | 必填 hq_of（§5.3）；锚点常为多级链 | 门派徽记描边+点击跳组织页 | 天山派驻地、白驼山式总舵 |
| 秘境 | 隐蔽、与世隔绝、藏经藏宝 | 秘境洞府 | 常配 U4 legendary 或多级锚点 | 低置信弱化样式/按书集渐进显示 | 冰窟、无名山洞 |
| 虚构国 | 国号+宫廷/边域叙事 | 区域（K12） | nature=虚构的广域条目，precision 语义按 region 处理（锚点画范围带） | 范围带而非针点 | 大理国式架空政权（若虚构） |
| 虚构城/镇 | 城镇通名+专名，实无其地 | 城镇/寨堡 | 锚点常挂真实官道/大城 | 城堡图标+虚线轮廓 | 风砂堡、龙门镇（若判定虚构） |
| 虚构关隘 | 关/口/隘口通名+专名 | 关隘 | 多挂防线/山河参照 | 关隘图标+锚点环 | 文中所称某新设关 |

（渲染侧重为语义约定，图标/半径/徽标文案等数值归 /atlas 页面侧标定——附录 B11。）

### 5.2 与 #8 地点树的对齐声明

1. kind（F04）=#8 地点树维度 A 的扁平投影（§2.3 映射表），双向可回溯；
2. nature（F05）=#8 地点树维度 B 的四值原样承接（真实/虚构/真实原型改造/未定），判据沿用 #8 定稿的四步裁决（史籍可查→真实；小说明言→虚构；原型可考→原型改造；无法判断→未定）；
3. #8 的判定信号表（名称含"山/江/城/宫/寺/洞"等）是 kind 初判的第一信号，与 §2.4 归一映射同源；
4. 本规范不修改 #8 已定版的树结构；投影层拆分（K03/K04）与特化叶子（K09）已在 §2.3 声明回溯关系。

### 5.3 门派驻地的双重身份（hq_of）

驻地既是**地点**（地图渲染、kind 着色），又是**组织**的属性（门派页"驻地"栏、组织色着色）。裁决：

1. **不设 kind="门派驻地"**——驻地是组织-地点关系，不是地貌/功能类型（一座山可以同时是驻地与山峰）；关系由 F19 `hq_of` 承载；
2. **双向链接**：地点条目 hq_of=["天山派"]；门派登记表的"驻地"字段（字段名建议 headquarters，契约归组织表，本规范只约定读取方向）读 gazetteer（组织页跳转到地点页，地点页跳回组织页）；
3. **渲染**：有 hq_of 的地点在 /atlas 用所属组织色描边/徽标（组织色系统由门派页定义，本规范只约定读取 hq_of）；
4. **一派多驻地/迁驻**：hq_of 允许多组织多驻点；迁驻（老山门废弃、新山门启用）建两个地点条目，各自记 books 出现区间，不覆盖同条（是否引入时间区间字段见附录 B08）；
5. **组织本身不入 gazetteer**：◆武当派是组织实体，"武当山"才是地点；组织页的地名信息一律落到地点条目。

✅ 正例：`天山派驻地` 条目 kind=秘境洞府、hq_of=["天山派"]、anchor 挂天山。
❌ 反例：kind 填"门派驻地"（枚举外值，K 枚举封闭）；或把 `◆天山派` 直接塞进 gazetteer 当地点（两层实体混写）。

### 5.4 跨书同名地点消歧（书集维度，对接 #7）

多书共享宇宙的默认假设是**同一地点跨书共享**（天山跨四书即同条）。同名异地（两书各有一个"龙门镇"）按下述流程裁决：

1. **默认合并**：字面同名先查地理线索（锚点参照物、方位、所属区域）、势力线索（周边门派/政权）、人物往来合理性——**相容则合并**，books 聚合（防 X01"字面同名就归并"的反向错误：也不可字面同名就拆分）；
2. **冲突拆分**：线索不相容（一在陕甘官道、一在滇黔边地；或分属敌对势力且无迁徙证据）→ 拆两条：主条目保留原 id，拆出条目 id 加书集限定符 `龙门镇@白发魔女传`（限定符语法已定版：书集维度，不用序号——序号不可读不可回溯，见 G13 转出说明）；两互条目在 source.note 互记 "disambig: 同名异地，见 X"；
3. **拆分登记**：两条件的 books 各记各书；**aliases 不互挂**（避免检索串味）；/atlas 各落各点；渲染按当前浏览书集经 books 过滤；
4. **对接 #7**：拆分/合并裁决同步登记到 #7 跨书治理台账，冲突类型按其类型学（呼应/翻案/穿帮）归类；
5. **时间维度同名**（上京/汴梁式）：同一城名跨朝代（辽上京/金上京/渤海国上京）不拆条，按 §5.5 异代同名处理——除非两书叙事明确指认两处不同城（朝代限定符议题见附录 B10）。

### 5.5 历史地名异代同名与别名挂接

武侠叙事常以明代背景用古地名/今名混称（哈密卫/哈密/伊吾）。规则：

1. **name 取小说高频用名**；异代名、今名、史籍名全部入 aliases（F03）：如 name=哈密，aliases=[哈密卫，伊吾（古称）]；
2. **一地一条**：异代同名不拆条（同一地理实体的时间变体）；朝代归属写 source.note（"明为哈密卫"）；
3. **坐标随小说时代**：真实图层坐标优先对齐**小说叙事时代**的治所/城址（谭图/CHGIS 按朝代取点），今址仅作 fallback；
4. **跨朝代同名异地**（上京式）：若小说语境可判定所指（按书的时代背景），所指写 source.note；不可判定时按 §5.4 规则 5，必要时 id 加朝代限定符（B10 待拍板）；
5. **别名挂接须注出处**：每条 alias 的挂接依据（书证锚点或史籍来源）记 source.note 或校订台账，无出处不挂——防"天山/雪山"式同名异挂串味。

## 六、运营与数据管线（Q5）

### 6.1 候选 → 登记 → 校准 流程

```
① 产生候选 ──► ② 判重归并 ──► ③ 初判登记（auto）──► ④ 人工校准 ──► ⑤ 终审入库 ──► ⑥ 渲染消费
   〖=〗扫描        与650条比对       nature/kind 初判      status:待审         status:已核准      /atlas等页面
   01g别名表        canonical归并      loc_mode 定位方式      坐标/锚点核验       verified=true      降级显示
   #9词表兜底        (防重复建条)       无据不定位            台账留痕            回退通道保留
```

各步纪律：

1. **产生候选**：三个来源——01g 标注扫描（`〖=〗`实体）、01g 别名表四列（surface/type/canonical/refs）、#9 词表兜底；候选先进观察池（对应既有 `gazetteer-候选.tsv`，647 条缓存），**候选不是条目**（不设表内"草稿"层——候选在池不在表）；
2. **判重归并**：候选与既有 650 条 canonical 比对（含 aliases 归并：伊吾→哈密），命中即累计 count/books 不建新条；
3. **初判登记（auto）**：nature 按裁决 R1 暂定；kind 按 §2.3/§2.4 初判；**定位三选择**——有坐标证据→coord；有文证锚点→anchor；两者皆无→none 弃权（不许空着 loc_mode）；
4. **人工校准（待审）**：核实文证锚点、复核可疑坐标（§6.2 队列）、改判 nature/kind；一切变更入校订台账；
5. **终审入库（已核准）**：verified 置 true 的唯一时机；
6. **回退**：已核准条目遇新冲突证据（新书写了矛盾方位）→ 回退待审，冲突入 #7。

### 6.3 status / verified 档位语义定版

实测 status 混用（auto 641 / missing_coord 9），verified 全 false 且语义空转。定版：

**status（登记生命周期，四档单轨）**：

| 档 | 语义 | 进入条件 | 退出条件 |
|---|---|---|---|
| auto | 自动登记，未人工复核 | 初判登记 | 进入人工校准 |
| 待审 | 人工校准队列 | auto 条目入队列；已核准回退 | 裁决完成 |
| 已核准 | 人工裁决完成 | 校准通过，台账留痕 | 新冲突证据回退 |
| 已弃用 | 误登/通名/重复 | 裁决剔除 | 仅存档，渲染端必须过滤，不物理删除（保引用） |

- `missing_coord` **不再是 status 值**：9 条迁移为 auto，缺坐标信息由 lat/lng 缺失承载（M08）；
- **不引入 draft/review/published 等第二档位词汇**：与既有 auto 双轨并存必生歧义（auto 与 draft 边界不明、旧条目永难升档）；"未成条候选"由候选池承载（§6.1 纪律 1）；
- **verified（兼容布尔，定版语义）**：true ⟺ status=已核准 **且** 定位字段（coord/anchor/proto 之一）经人工核验；auto/待审条目一律 false；弃权条目（loc_mode=none）没有"定位核验"，verified 恒 false，其"已核准"指弃权裁决本身被确认；
- **禁配对**：auto+verified=true、待审+verified=true、已弃用+verified=true 皆违规（G12）。

### 6.4 conf 置信分档（派生；枚举对齐 #9 定稿全库档位字典）

| conf | 判定 | 典型 |
|---|---|---|
| strong | coord+exact/region，或一级锚点+文中确切里数 | 嵩山 exact；"京师以西三百里" |
| ok | coord+approx/shifted，或一级锚点+档位无里数 | 天山 approx；"天山以北" |
| weak | 链深≥2 的锚点，或拓扑词模糊参照，或 nature=未定 | 冰窟两级链 |

conf 是渲染排序与问答话术的依据（weak 不进"精确位置"类回答），由规则派生，不手填。枚举与 #9 词表体系的 conf（strong/ok/weak，招式表图例出处）同名同序——跨表联查与问答置信传递同构（#9 WL-20 接口注记互指）。

### 6.5 行踪地图渲染消费协议（必读字段）

渲染端**必读**（缺则降级）：

| 字段 | 用途 |
|---|---|
| status≠已弃用 | 过滤弃用条目（硬过滤） |
| nature / layer | 图层分流与样式（虚构样式/原型示意徽标/待审徽标） |
| loc_mode（或派生布尔 unlocatable） | coord→真实落点；proto→原型落点+徽标；anchor→join 流程（§3.5）；none→降级 D3 |
| lat/lng + precision | 真实图层落点；region 画范围圈 |
| anchor（ref/bearing/distance/evidence/chain） | 虚构图层 join 落位 |
| kind | 分类着色（K01–K13 色板，页面侧定义） |
| name/aliases | 标签与搜索匹配 |
| books | 按书过滤显示（书集维度） |

渲染端**选读**：hq_of（组织色描边）、conf（weak 弱化样式）、first_seen（详情跳转 02ab 锚点）、unlocatable_reason（D3 话术）、source.note（tooltip 考据注记）。

**消费红线**：渲染派生的示意落点不回写登记表（J 纪律）；已弃用条目必须过滤；unlocatable 条目不得出现在地图层。

## 七、工作流程（地名登记 Agent 操作序）

1. **取候选**：从 #9 候选池/01g 扫描结果取一批待登记地名（含 surface 与出处锚点）；
2. **查重**：对既有 gazetteer 的 id 与 aliases 归并比对；命中→仅更新 count/books，不建新条；
3. **判通名**：按 §4.3 口诀过滤纯通名/泛指（山下/城中/村口）；通名进观察池，不登记；
4. **初判 nature**：按 #8 定稿四步裁决（史籍可查→真实；小说明言→虚构；原型可考→原型改造候选；无法判断→**未定，不自动判虚构**）；
5. **初判 kind**：按 §2.3 枚举与 §2.4 归一信号；拿不准→其他(K13)+待审；
6. **定 loc_mode**：有坐标证据→coord（真实候选）；有文证方位→anchor（按 §3.3 语法逐要素填写，evidence 必填）；皆无→none+reason（§4.2）；
7. **写锚点链**：虚构参照逐级解析，chain≤3；发现循环/断链即止并按 U3 处置；
8. **写驻地关系**：识别门派驻地语义→hq_of 挂组织 canonical；
9. **落 status/conf**：新条目 status=auto，conf 按 §6.4 派生；
10. **自检**：过第十章清单（前/中/后）；错误模式 G01–G13 逐条对号；
11. **输出登记**：按 §2.1 字段表输出条目（或"更新差异"），**不输出坐标脑补、不输出现实考据长文**；
12. **记录存疑**：无法裁决的边界案例写入待拍板/台账，不擅自定案。

### Few-shot 示例

**例 1（区域粒度）**：
> 三人自西安取道商州，入陕南界。

分析：`陕南`是区域名——kind=区域(K12)、nature=真实、precision 用 region 级（代表点+范围圈），**不**给 exact 点坐标（G09）。

**例 2（原型改造）**：
> 卓一航上得西山，寻至秘魔崖下。

分析：`秘魔崖`名称与地点原型可考（北京西山），小说中用作虚构功能体——nature=真实原型改造；迁移期先保持"真实(暂定)"，复核改判后 loc_mode=proto，渲染带"原型示意"徽标。

**例 3（弃权）**：
> 传说海外有一仙山，无人知其所在。

分析：专名性弱且作者明言"无人知其所在"——若后文立名则登记为 nature=虚构、loc_mode=none、reason=legendary（U4），问答用降级话术。

**例 4（同名异地）**：
> 甲书言"龙门镇在潼关道上"；乙书言"龙门镇地处滇南瘴乡"。

分析：地理线索不相容——拆分：主条目 `龙门镇`（潼关道），拆出 `龙门镇@乙书`（滇南），两互注记 disambig，同步 #7 台账（§5.4）。

## 十一、FAQ

**Q1：天山派驻地到底登记成什么？**
A：两条目方案（§3.7）：真实图层的"天山"（山脉本体）+虚构图层的"天山派驻地"（anchor 挂天山、hq_of 挂天山派）。合并会污染真实山脉坐标，只建驻地一条会丢失山脉的 295 次出现统计。

**Q2：秘魔崖到底放真实图层还是虚构图层？**
A：迁移期保持"真实(暂定)+coord"（无损原则）；复核确认原型可考（北京西山）且功能被小说改造后改判 nature=真实原型改造，loc_mode 转 proto，坐标不删、渲染加"原型示意"徽标（§2.2、§3.5 J3）。判虚构与判原型改造的口径在三处文档中必须一致（§5.6 案例 2 单一口径）。

**Q3：白驼山式总舵判虚构还是原型改造？**
A：判据是**原型可考度**，不是感觉：有可考原型且功能被改造→原型改造；不可考→虚构。方向已由 #8 定稿四步裁决锁定；"可考到什么程度"的阈值细则见附录 B01。同一模式不同条目分别裁决。

**Q4："京师以西三百里"的 300 里怎么换算？**
A：登记记 value=300、unit=里、tier=中（50–500 里档），不折算经纬度。渲染端示意环径按档取值；换算依据（1 里≈500 米）写 source.note（§3.3）。

**Q5：unlocatable 和 nature=未定 有什么区别？**
A：正交两维（§4.6）：未定=真实性存疑，unlocatable=定位失败。真实地点可以 unlocatable，虚构地点可以有精确锚点。四组合各有处置表。

**Q6：为什么 kinds 里没有"门派驻地"？**
A：驻地是组织-地点**关系**而非地貌类型；由 hq_of 字段承载（§5.3）。一条"武当山"与"武当派驻地"若是同一实体，则在武当山条目上挂 hq_of=["武当派"]，不另建 kind。

**Q7：两书各有一个"龙门镇"，合并还是拆分？**
A：先查相容性（地理/势力/人物往来），相容合并（books 聚合），冲突拆分（`@书` 限定符）并同步 #7 台账（§5.4）。**字面同名既不是合并理由也不是拆分理由**。

**Q8：650 条里 kind 怎么有 bus_stop、civil 这种值？**
A：自动地理编码把 OSM 功能标签抄进了 kind（G08）。§2.4 给出全量归一映射，原值留档 source.legacy_kind，复核时按条目本名重判。

**Q9：status=missing_coord 的 9 条怎么办？**
A：missing_coord 退役为兼容输入值（M08）：迁移为 auto，缺坐标由字段缺失表达，进"真实图层补坐标队列"逐条人工定位或判弃权。

**Q10：锚点的参照物还没登记怎么办？**
A：先登记参照物再引用。参照物本身不可考（U3 chain_broken）→ 本条弃权并走升级路径，不得跳级挂一个更远的真实点伪造一级锚点。

**Q11：书里给的里数和真实地理对不上怎么办？**
A：以**书中数字**为准登记（value=文中里数），现实距离差异是武侠叙事常态；若构成地理硬伤（同一行程距离自相矛盾），按 U2/#7 登记穿帮候选，不静默修改文证。

**Q12：渲染时虚构点会画出真实经纬度吗？**
A：会画出**示意落点**（join 派生，虚线样式+锚点环），但派生坐标永不回写登记表（J 纪律）；join 失败按 D1–D3 降级，不出现在地图层（§3.6）。

**Q13：books 里的回号 0 是什么？**
A：沿用既有导出脚本的回号口径（含 0，疑为楔子/序回），迁移不改写（M06）；first_seen 按 02ab 锚点由人工登记，不从 books 自动推导（§2.6）。

**Q14：gazetteer 和 #9 词表是什么关系？**
A：地名候选表是词表族一员（前人实验结论 4"词表兜底"）：#9 管词形层（surface/canonical/refs，管"哪些字符串指同一地"），本规范管实体层（定位/图层/性质，管"这个地在哪里、真不真"）。别名归并以 #9 词表的 canonical 归并结果为输入，登记表不重复维护别名词形变体；conf 枚举已与 #9 全库档位字典对齐（strong/ok/weak，§6.4）。

**Q15：id 为什么保留中文、不改拼音 slug？**
A：三条理由：①既有 650 条 id 全是中文地名，改写即全库主键失效（G13）；②中文 id 与 name/正文用名同形，人工校订与台账检索零转换；③消歧拆分用 `@书名` 后缀已解决同名冲突，不需要新键型。稳定性优先于"键型美观"。

**Q16：unlocatable 布尔和 loc_mode=none 什么关系？**
A：同一事实的两种视图：loc_mode=none+reason 是登记端权威结构（可审计、可升级），unlocatable=派生布尔（⟺ loc_mode=none）供渲染/检索直接过滤。不双轨登记（§2.1 注记）。
