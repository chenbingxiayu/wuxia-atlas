# SKILL 06d: 推理机构建（规划）

> 构建推理引擎，执行本体推理、规则推理和约束验证，实现知识的自动化处理。

---

## 一、功能概述

推理机是知识图谱的"大脑"，能够基于本体定义和规则自动推导新知识、检测矛盾、验证数据。本功能计划构建推理引擎系统，实现：

- **本体推理**：基于OWL语义自动推理类关系和属性
- **规则推理**：执行自定义规则，推导领域知识
- **约束检查**：验证数据完整性和一致性
- **冲突检测**：发现知识库中的矛盾

---

## 二、核心功能

### 2.1 本体推理

**目的**：基于OWL语义自动推导知识

**推理类型**：

**类推理**：
- 子类传递：如果A是B的子类，B是C的子类，则A是C的子类
- 类归属：如果实体满足某类的定义条件，则自动归入该类
- 类等价：识别定义等价的类

**属性推理**：
- 属性传递性：如果"师承"关系是传递的，自动推导师承链（师祖/徒孙）
- 属性对称性：如果"同门"关系是对称的，自动补全反向关系
- 逆属性：自动推导逆关系（如"师父"的逆是"弟子"）

**实例推理**：
- 类成员推断：根据属性值推断实例所属类
- 同一性推断：识别指向同一实体的不同名称

**应用场景**：
- 自动补全类层次
- 推导隐含关系
- 实体自动分类

### 2.2 规则推理

**目的**：执行自定义推理规则

**推理模式**：

**前向推理（Forward Chaining）**：
- 从已知事实出发，应用规则推导新事实
- 适用于知识补全和批量推理
- 例：从师承关系推导师祖—徒孙关系

**后向推理（Backward Chaining）**：
- 从目标出发，反向查找支持证据
- 适用于查询回答和解释生成
- 例：为什么X被评 07e"可信"？追溯评级依据链（书证+规则）

**混合推理**：
- 结合前向和后向推理
- 优化推理效率
- 处理复杂查询

**应用场景**：
- 执行领域规则（参考 `SKILL_06c_规则构建_武侠版.md`）
- 回答复杂查询
- 生成推理解释

### 2.3 约束检查

**目的**：验证数据符合定义的约束

**检查类型**：

**结构约束**：
- 属性基数：必填/可选、单值/多值
- 属性类型：值的数据类型
- 关系域值域：关系的起点和终点类型

**语义约束**：
- 类互斥：实体不能同时属于互斥类
- 属性互斥：某些属性不能同时存在
- 值范围：属性值必须在合法范围内

**领域约束**：
- 时间一致性：生卒年、事件时间的合理性
- 关系一致性：关系链不能成环、矛盾
- 历史合理性：历史事实的合理性检查

**应用场景**：
- 数据导入验证
- 数据修改前检查
- 定期数据质量审查

### 2.4 冲突检测

**目的**：发现知识库中的矛盾

**冲突类型**：

**逻辑冲突**：
- 类冲突：实体同时属于互斥类
- 属性冲突：属性值矛盾（如初登场回晚于成名回）
- 关系冲突：关系链矛盾（如A是B的师父，B也是A的师父——师承环）

**知识冲突**：
- 多源数据冲突：不同来源的数据矛盾
- 推理冲突：推理结果与已知事实矛盾
- 规则冲突：不同规则得出相反结论

**处理策略**：
- 冲突报告生成
- 冲突优先级排序
- 建议修正方案

**应用场景**：
- 数据清洗
- 知识融合
- 质量监控

## 七、推理示例

以下为推理场景的概念性示例：

### 示例1：本体推理
```
已知：刘邦 属于 帝王类
本体定义：帝王类 是 人物类 的子类
推理结果：刘邦 属于 人物类
```

### 示例2：规则推理
```
已知：刘邦 是 刘盈 的父亲
已知：刘盈 是 刘恭 的父亲
规则：如果 A 是 B 的父亲，B 是 C 的父亲，则 A 是 C 的祖父
推理结果：刘邦 是 刘恭 的祖父
```

### 示例3：约束检查
```
已知：人物A 生年 = 前100年
已知：人物A 卒年 = 前150年
约束：生年 必须 <= 卒年
检查结果：约束违反，报错
```

### 示例4：冲突检测
```
已知：项羽 攻打 刘邦（事件1发生在前206年）
已知：刘邦 生于 前256年
已知：项羽 生于 前232年
推理：前206年时，刘邦50岁，项羽26岁，双方都活着
检查结果：时间一致性通过
```
