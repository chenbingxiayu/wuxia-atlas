## 快速开始

1. **定层级**：项目级（阶段/里程碑）/ 批次级（一书或一批）/ 技能级（一份 SKILL/脚本的版本迭代）——先定层级再选模板。
2. **收素材**：验收 JSON、五门 lint、qa 报告、成本日志、遗留清单、决策记录（docs 编号）。
3. **写四段**：结果（数据）→ 差距（计划 vs 实际）→ 归因（口径/流程/工具/规则）→ 行动（谁、何时、回填到哪）。
4. **留证据**：每条结论带数据源路径与复现命令；不允许"感觉良好"式结论。
5. **回填**：行动项落 docs/任务/规则文件，未闭环项进"遗留与下一步"并在下轮复盘首查。

> 成功标准：批次复盘 100% 含"结果表 + 遗留 + 复现命令 + 证据路径"四件；行动项闭环率 ≥ 80%。

## 一、三级复盘（职责与节奏）

| 层级 | 触发 | 主持 | 输入 | 产出 | 频率 |
|---|---|---|---|---|---|
| 项目级 | 阶段里程碑（G0/G1/G2/G3）、重大路线调整 | Lead | docs 阶段记录、验收总表、成本总账、审计报告 | 阶段复盘 docs（如 docs/26 G2 首轮、docs/34 G2 二轮、docs/42 审计、docs/50 剩余清单） | 每阶段 1 次 |
| 批次级 | 每批标注/改造收口 | Lead + 执行者 | accept/qa/lint 报告、批次日志、遗留清单 | 批次记录 docs（docs/53/54/56/57/58 为模板） | 每批 1 次 |
| 技能级 | SKILL 版本升级、脚本重写、缺陷入库 | 技能 owner | lint 结果、案例、错误模式、回归数据 | 版本变更记录（frontmatter version + 附录 A/B）+ 案例/规律条目 | 每次版本变更 |

> 纪律：**三级不混写**——项目级只谈路线与阶段目标，批次级只谈本批数据与遗留，技能级只谈该件规则与案例；跨级引用用编号（docs/DEF/RC/V）。

## 二、项目级复盘：五步法

1. **目标回放**：本阶段计划做什么（引 docs/17 波次表或 docs/50 工单）；
2. **结果对账**：accepted/hard/judgment/unsourced/lint/成本/墙钟逐项对目标（数据源 registry/acceptance + logs）；
3. **差距归因**：差距按层归类（口径/流程/工具/规则/资源），每类给证据；
4. **决策点复盘**：本阶段的关键拍板（如 docs/51 方案 C、docs/56 B-1~B-6 推荐、G0 底本）是否仍成立，若否给替代方案；
5. **行动与回填**：行动项写成"动作 + 责任 + 期限 + 回填位置"，未闭环进遗留。

> 真实案例：**docs/26 G2 首轮反思**（两粒种子 + 004 试点 → 规律库种子 R-001~R-016）、**docs/34 G2 二轮收口**（G-17~G-31 状态 + R-013 逐式裁定 + 密谋归关系层）、**docs/42 实现完整性审计**（198 节点实现 46 个 ≈23%，据此重排 docs/50 剩余清单）。

## 三、批次级复盘：模板（docs/53-58 实证结构）

```markdown
# NN · <批次名>（YYYY-MM-DD）

> **范围**：本批做什么（引工单/上一批遗留）
> **结论**：N/N 完成 / 部分完成；关键数字（accepted/judgment/成本/构建）
> **执行**：Lead + 哪些 teammate；是否调用 LLM

## 一、分项结果（每项：做了什么 → 数据 → 验证）
## 二、集成与全局状态（5 书 accept / lint / 站点 / 规模）
## 三、遗留与下一步（编号 + 类型 + 建议）
## 四、复现命令（可直接粘贴）
## 五、证据路径（表：证据 → 路径）

*执行：…；依据：docs/…；用户授权：…*
```

> 结构纪律（从 docs/53-58 六份记录归纳）：
> 1. 开头三行必写 **范围/结论/执行**；
> 2. 每项结果必须带"前后对照表"（如围栏 64→67、PN 2263→2263）；
> 3. **遗留与下一步**必须编号，并区分"本批引入/既有挂账"；
> 4. **复现命令**可直接执行（PowerShell 段）；
> 5. **证据路径**表必须能落到 `logs/`、`registry/`、`backup/` 真实文件；
> 6. 文末注明执行者、依据文档、用户授权语句。

## 五、真实复盘案例（武侠 5 例）

### 案例 1 · docs/53 半日收尾（2026-11-05 下午）

- 范围：B1-3 族群类型建议 + 书名行修复 + 塞外/冰魄围栏修复 + judgment 终签工具化 + 站点文案 data-driven；
- 结果：4/4 完成；塞外围栏 1→6、冰魄 0→2、两书 accept 28/28、12/12；站点 1508 页 exit 0；书名行实修 8 部（比 docs/49 记载多 1 部《广陵剑》）；
- 复盘要点：**"记载 vs 实测"必须复核**（7 部→8 部）；**工具默认 dry-run + 备份 + 写后断言**成为后续批次标准；judgment 336 条 dry-run 与 docs 逐书一致（115/103/47/44/27）。

### 案例 2 · docs/54 judgment 落地与围栏漂移

- 结果：judgment 338→263（75 token/41 文件，应摘 75/改域 0，残留 0）；白发围栏 64→67（PN 不变）、七剑 29→54（PN 2394→2392）；5 书 accepted 131 全绿；
- 复盘要点：**机械处置必须幂等**（二次 apply 0 变更）；**口径漂移要单列**（七剑 PN−2 的下游锚点）；**人工项与机械项分开计数**（7 条人工裁定 vs 75 条机械）。

### 案例 3 · docs/56 loader 性能"回归"复核

- 现象：loader 回级改造后 accept 江湖 48 回由 ~1 分钟变 ~7.5 分钟（≈7x），疑为 scoped 视图重复构建；
- 复盘结论：**误报**——空闲期 A/B 实测 162.0s（改前）vs 163.4s（优化后）= 1.009x；高负载期用改前脚本同样 6m55s，系 site build + N4/N5 + 多代理 CPU 争用；
- 真实热点：accept 94–96% 耗时在全局门 `lint_text_integrity --book X` 双 glob 同一回计两次（江湖 48→96 回，153.7s）；
- 复盘要点：**性能结论必须给 A/B 与负载条件**；**"怀疑"不能进结论**（task-16 用 idle A/B 证伪）；一行去重后 integrity 174.7s→87.0s（docs/57）。

### 案例 4 · docs/57 依赖分波与 8 路并行

- 结果：8 路全部完成；EX-4 接入导出（489 节点/907 边）；display 字段进 site/data；站点 1476 页 exit 0；5 书 accept/judgment/unsourced 不变；
- 复盘要点：**并行前先画依赖波次**（W0 无依赖全并行、W2 site/data 由 Lead 串行收口）；**写范围互斥**（每路独立文件/目录）；**高负载期计时不可作基线**（check 3798s 系争用）。

### 案例 5 · docs/58 第六波（N10/EX/18SKILL/META 二波）

- 结果：8 路全完成；N10 1,536 张 SKU 卡；18 SKILL + META 二波 4 件 lint 全 PASS；站点 1476 页；
- 复盘要点：**产物登记滞后**（skills/README、scripts/README 需 Lead 收口补登）；**规模统计要注明时点**（69 脚本/60 skills，随后第三波继续增长）；**SKU 卡数两处口径不一致**（docs/58 1,536 vs scripts/README 1,457，须统一后再引用）。

## 九、成功标准

1. 每批收口 24h 内产出批次记录，结构符合 §三 六条；
2. 项目级阶段复盘至少覆盖"结果对账 + 决策点复盘"两项；

5. 每季度把高频差距提炼为规则/检查项（回填 META-01/03c1）。
