# W4 评估（武侠版）—— 一个动作做完了，收不收？

> **本文是什么**：Butler 的"质量闸门"。W2 动作产出后，W4 按**验收四问**逐项核验：引文过 W7 吗？事实有 registry/PN 证据吗？结构/链接/分类过 lint 吗？diff 是否 ≤20 行且只追加不替换？四问全过=accept；任一不过=fail→回滚；失败聚类交 W5。
> **上游依赖**：`skills/W2_动作库_武侠版.md`（动作期望）、`skills/W3_质量四档_武侠版.md`（质量档/断言分级）、`skills/W6_离线质检_武侠版.md`（批量质检）、`scripts/verify_quotes.py`（W7）。
> **一句话**：**W4 不判断"写得好不好"，只判断"这次动作用没有越界、有没有证据、能不能留"。**
> **只读纪律**：评估只读页面/日志/质检结果；评估记录落 `logs/w_group/evaluations.jsonl`、`failures.jsonl`；不在评估中改内容。

## 快速开始

````text
1. 收动作  从 actions.jsonl 取未评估动作（target/diff/action/WU）
2. 四问核验 ①引文 W7 ②事实有源 ③结构/链接/分类 lint ④diff ≤20 且只追加
3. 判档    全过→accept；任一不过→fail（记原因）
4. 回滚    fail 且有内容改动→回滚到上一快照/备份；记 failures.jsonl
5. 周期评估 每轮末出健康度六指标快照 → W10 队列
````

## 二、验收四问（核心）

| # | 问题 | 通过条件 | 工具/证据 | 不过处置 |
|---|---|---|---|---|
| ① 引文 | 页面引文是否过 W7？ | hit/near 可接受；**miss 拒绝** | `verify_quotes.py --file <page>` | fail/回滚/删引文 |
| ② 事实 | 事实是否挂 registry/PN 证据？ | 每条断言有 ①②级源（W3） | registry/relations/events/SKU ID + PN | fail/补源 |
| ③ 结构 | 页面结构/链接/分类是否过 lint？ | N8/N9/02ab 无 error；链接目标存在；分类有叶 | `lint_consistency.py`/`lint_taxonomy.py`/链接清单 | fail/修 |
| ④ diff | 是否 ≤20 行且只追加不替换？ | diff_lines ≤20（精品页例外）；无替换/删除 | actions.jsonl + 页面 diff | fail/拆分/回滚 |

### 2.1 特殊情形

- **精品页（动作 17）**：diff 允许 >20 行，但必须有 W8 流程记录与 W4 例外批准；
- **引文类动作（10/11/23）**：① 为硬门，miss 直接 fail；
- **内务动作（18-22）**：④ 的"只追加"可放宽为"可合并/重定向"，但需内容零丢失断言；
- **属性动作（7/15）**：② 必须 registry ID 可回溯（不接受"口头来源"）。

## 三、判定与回滚

### 3.1 判定状态机

```text
动作提交 → 四问核验
  ├─ 全过 → accept（留痕，更新质量档）
  ├─ ①失败 → fail（引文 miss）→ 回滚/删引文
  ├─ ②失败 → fail（无源断言）→ 回滚/补源后重评
  ├─ ③失败 → fail（结构/链接/分类）→ 回滚/修复
  └─ ④失败 → fail（超预算/替换）→ 回滚/拆分动作
```

### 3.2 回滚

| 情形 | 回滚动作 |
|---|---|
| 内容被改坏 | 恢复上一快照/备份文件（W0 留痕纪律） |
| 引文 miss | 删除该引文块或改概括+回锚 |
| 超 diff | 回滚后拆分为多个原子动作 |
| 链接/分类错误 | 回滚到动作前版本 |

- 回滚后记录 `rolled_back` 状态与原因；同一动作重试需新记录。

### 3.3 记录 schema

```jsonl
{"eval_id":"E-20261105-001","action_ts":"…","target":"content/person/card.person.e0001.md","action":"build_stub",
 "q1_citation":"hit|near|miss|n/a","q2_evidence":"pass|fail","q3_structure":"pass|fail","q4_diff":{"lines":8,"append_only":true},
 "quality_before":"stub","quality_after":"basic","result":"accepted|failed|rolled_back","rollback":null,
 "reason":null,"data_version":"2026-11-05.01","rule_version":"w4@v0.1"}
```

### 3.4 失败聚类（交 W5）

- `failures.jsonl`：按 `reason_class` 聚合（引文类/无源类/结构类/预算类）；
- 同因 ≥3 → W5 反思（改规则/改动作/改模板）；
- 聚类统计进入 W5 的 `failures_summary.json`。

## 九、FAQ（首批 6 问）

**Q1 四问里哪一问可以放宽？**
都不放宽；仅精品页（动作 17）在 W4 批准下放宽④，内务动作在"内容零丢失"断言下放宽④的追加限制。

**Q2 fail 一定要回滚吗？**
有内容改动的 fail 必须回滚到动作前；纯记录/只读动作 fail 只记失败。

**Q3 健康度六指标在哪定义？**
本文与 W10 共享（W10 §健康度六指标）；本文负责每轮采集与快照。

**Q4 评估和 W6 离线质检什么关系？**
W4=动作级在线评估（即时）；W6=批量离屏质检（周期）；W6 发现的问题可反哺 W4 规则。

**Q5 失败聚类为什么要交 W5？**
单动作失败可能是偶然，同因 ≥3 是规则/模板缺陷，须 W5 改规则（W5 改规则、W9 改模板）。

**Q6 现在没有评估器怎么执行？**
v0.1 按本文 schema 人工/脚本化试制；评估器实现见附录 B。

## 结语

评估的意义不是"挑错"，而是**让每个动作都可收、可退、可复盘**：四问是尺子，回滚是保险，健康度是仪表盘。Butler 可以慢，但每一步都要站得住。
